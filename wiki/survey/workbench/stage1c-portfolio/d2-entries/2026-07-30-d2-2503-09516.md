## 1. 方法本质

Search-R1 把搜索引擎当成**环境的一部分**，用结果奖励的 RL 直接训练策略 LLM 学会"什么时候搜、搜什么、
搜几轮"。rollout 是交错的：模型生成 `<think>…</think>` 推理，需要外部知识时写 `<search>query</search>`，
harness 检测到 `</search>` 即调检索器、把 top-3 段落包在 `<information>…</information>` 里原样追加回
序列，继续生成；直到模型写出 `<answer>…</answer>` 或撞上**硬动作预算 B=4**；格式非法时注入一句脚本化
的 "My action is not correct. Let me rethink."。三项设计要点：(i) **检索 token loss masking**——策略梯度与
KL 只在 LLM 自己生成的 token 上计算，检索回来的 token 被 mask 掉（式 4/5 的 `I(y_t)` 指示函数）；
(ii) **纯结果奖励**，`r = EM(â, a*)`，无格式奖励、无过程奖励、**无神经奖励模型**（作者明确避开，理由是
奖励形式敏感 + 重训成本）；(iii) 与 PPO / GRPO 都兼容，默认 PPO。可视为 DeepSeek-R1-Zero 在
"推理 + 检索"场景的扩展。

## 2. 三轴定位

| 轴 | Search-R1 的位置 |
|---|---|
| **供给决策由谁做** | **被 RL 训练出来的策略 LLM**——不是规则、不是阈值、不是冻结模型的自由生成。决策分布本身就是训练对象（§3.1/§3.2）。**这条是 R2 红线的正对面**：R2 不训练模型，Search-R1 的全部贡献就是训练那个做供给决策的模型。训练对象与冻结对象见 §3 第 6 条。附带一条重要的方向性事实：**奖励里没有成本项**，于是学到的方向是**多搜**——§5.3 + Figure 2(d) 明确写 "the LLMs learn to call the search engine more times as the training proceeds"，响应长度在前 100 步下降后转为显著上升（因为检索段落变多）。 |
| **触发与停止判据** | **触发＝符号检测**（`</search>`，同 Search-o1 的 harness 形态）。**停止＝三条**：(a) 模型生成 `<answer>`；(b) **硬动作预算 B=4**（附录 §B.2 明确 "The maximum action budget B is set to 4"）——这是三篇里**唯一给出具体数值上限**的；(c) 训练模板里写"你可以搜任意多次"（Table 1），即软层面无鼓励也无抑制。**判据里没有价值/成本/预算权衡**：B 是一个硬截断，不是价格；奖励不含 token/延迟/调用数惩罚。→ **"被强化的获取"≠"被定价的获取"。** |
| **使用侧准入/纠正** | **完全没有**。检索结果**原样**包进 `<information>…</information>` 追加到序列（§3.2 + Algorithm 1 第 12 行），无打分、无过滤、无拒收、无冲突处理、无来源权重、无 abstain。唯一对检索内容的"处理"是 **loss masking——那是训练期的梯度装置，不是推理期的准入门**。→ Search-R1 是纯供给侧论文：把供给决策搬进权重，使用侧原封不动。**这正好是 R2 主创新两半中"证据准入"那一半的空白对照。** |

## 4. DFS 四问

**方法**：把不可微的检索操作圈进 RL 环境，用交错 rollout + 检索 token loss masking 让"何时/如何调用
搜索"成为可被结果奖励直接优化的行为；用规则 EM 奖励规避奖励模型的复杂度与污染风险；用硬动作预算
B=4 与脚本化的格式纠错兜住轨迹发散。

**局限**：(a) **供给决策进权重后不可移植**——换骨干、换检索器、换语料都要重训，论文的 3B/7B/14B ×
base/instruct 六个组合就是六次 500 步 8×H100 训练；(b) **奖励无成本项 → 学到的是多搜**（§5.3 明说），
所以它无法产出"定价"，只能产出"更多获取"；(c) **使用侧完全裸奔**：检索段落原样进上下文，无准入、无
冲突、无来源质量；(d) 奖励用 gold EM，是典型的**训练期 gold 依赖**；(e) 小骨干上泛化差且不稳定
（3B-base Bamboogle 0.088，被 training-free 基线 0.320 反超）；(f) RL 不稳定与人工选检查点；(g) 成本
记账缺 GPU-hours/wall-clock/检索调用数；(h) 基线复现口径需谨慎（见 §5.2 F4）；(i) 相对增益声明的基线
不一致（§3 第 4 条）；(j) 附录 caption 的 "consistently" 与自身表格冲突（§3 第 7 条）。

**改进空间**：把成本/预算做进奖励（当前 B=4 是硬截断而非价格），使策略学会"少搜但搜对"而不是"多搜"；
补一个使用侧准入（哪怕是 Search-o1 式的零训练拒收门）——Table 7 的 top-5 掉点说明噪声段落既伤推理又
伤训练，一道准入门可能同时改善两端；把 in-weights 的调度换成 in-context 的调度以恢复可移植性；报出
GPU-hours 与检索调用数以便与 training-free 路线做同尺度对比。

**可借鉴**（在不越红线的前提下）：① **Algorithm 1 的动作预算 B 与格式纠错注入**是 harness 层的设计，
与训练无关，可直接搬（三篇里只有它给出了具体的 B=4）；② **同检索器/同语料/同篇数/同骨干/同训练数据
的"五同"对照口径**（§4.2 末）是本件最规范的实验协议，R2 的对照臂应照此写死；③ **Table 7 的 top-k
非单调 + Table 8 的组大小反向**是"更多不等于更好"的两个独立读数，可与 VOI-search 的"中预算胜高预算"
并列作为效果论据；④ **loss masking 的存在本身**说明"检索回来的 token 与自生成 token 性质不同"，这条
认识在 training-free 侧的对应物就是上下文准入——同一个洞察的两种实现，R2 可据此论证准入的必要性。

### 5.2 深读后新增的、R2 应该知道的事实

**F1（训练对象与成本，正面回答任务提问）— 训练的是策略 LLM，PPO 下还多一个 critic；检索器与语料
不训练；无神经奖励模型。** 成本：单节点 **8×H100 × 500 步**，batch 512/256/64，seq 4,096（响应 ≤500、
检索内容 ≤500 tokens），FSDP+CPU offload+梯度检查点，vLLM rollout；GRPO 每 prompt 采 5 条。
**GPU-hours / wall-clock / 检索调用总数未报**。且论文覆盖 3B/7B/14B × base/instruct **六个训练组合**，
每个都是一次完整 RL 运行。**外加一项常被忽略的成本：训练不稳定**——GRPO 长训奖励崩塌，检查点每
100 步一存，发散时"按训练奖励曲线取最近的稳定检查点"（附录 §B.2），即需要人工介入的检查点选择。
→ 这就是 R2 red-line 对照臂的成本基线：**R2 侧的同类改造是零 GPU-hours、零检查点选择、零重训移植成本**，
该对比可以直接量化陈述。

**F2（对照价值之一：training-free 路线的收益是能力门控的）** Search-R1 表里的 Search-o1 基线：
7B **0.206** < RAG 0.304；3B **0.255** < RAG 0.270；14B **0.310** > RAG 0.281。→ **agentic training-free
路线在小骨干上是负收益、跨过某个能力门槛后转正。** 这条对 R2 是**双刃但净正**的证据：它解释了为什么
R2 必须押在强冻结骨干（Qwen3-Omni-30B 口径）上，也给出了 R2 必须自己回答的问题——在目标骨干上
先验证"agentic 获取 > 固定检索"这一前提成立，再谈调度与准入的增量。**不要把这条藏起来**：外审只要
翻到 Search-R1 Table 2 就会看到 training-free 基线输给普通 RAG。

**F3（对照价值之二：RL 训练的供给策略可以泛化更差）** 3B 档 Bamboogle：**Search-o1 0.320（该分块
全场最好，论文自己加粗）vs Search-R1-base 0.088 / Search-R1-instruct 0.264**；Musique 3B：
Search-R1-base 0.049，低于 IRCoT 0.067 / Rejection Sampling 0.059 / R1-base 0.055 / Search-o1 0.054
（仅高于 RAG 0.047）。→ **把供给决策烧进权重会带来 OOD 脆性**；training-free
的 in-context 调度在最难的 OOD 多跳集上反而更稳。这是 R2 可以正面主张的一条**方法学优势**（不是效果
优势），且证据来自对手论文自己的表。

**F4（引用这些数字时必须一并声明的口径限制）** Search-R1 表里的 Search-o1 是**复现实现**，配置与
