## 2. 方法本质

系统 = SLAM-ASR 骨架 + 一个跨模态关键词检索器 + 一个三路加权融合器。L126 自述四部件：
"our system consists of four key components: Speech Encoder, LLM, Projector, and Keywords
Retriever."

- **骨架**（§2.1 L129）："Our ASR system skeleton adopts the basic SLAM-ASR architecture,
  which consists of an audio encoder, a projector, and an LLM decoder." Projector 为
  conv+MLP，把语音嵌入对齐到 LLM 嵌入空间。编码器 = `whisper-large-v3-turbo`（**只用
  encoder**，L147）；LLM = `Phi-4-mini-Instruct`（3.8B，L147）。
- **检索器**（§2.2 L132）：CLAP 式对比学习双塔——"the speech processing tower utilized the
  Whisper model and its supporting Projector in the SLAM architecture, whereas the text
  processing tower directly employed the LLM itself"，再经 pooling 层投到共享嵌入空间。
  图 1(b) caption（L116）："Keyword retrieval via cross-modal similarity."
- **库**（§3.2 L151）："The keywords' embeddings we obtained are stored by FAISS for efficient
  retrieval."
- **融合**（§2.3 L135）："We use a weighted fusion module to integrate three intermediate
  recognition outputs into the final transcription, namely the output from the whisper
  decoder, the output from the original LLM, and the RAG-based output. Note that the output
  based on RAG is given a higher weight."

### 2.1 内部不一致：摘要口径 ≠ 方法节口径（如实记录，两处）

**不一致 A（库的内容物）**。摘要 L88 称库中是音频-文本对与领域词：
> "Each partial ASR hypothesis queries a vector store of **audio–text pairs and domain
> terms**, and the retrieved results are fused with the live ASR hypotheses to fix
> recognition errors."

而方法节 §2.2 与配置节 §3.2 **只描述关键词嵌入库**：训练目标是 "identify possible
**keywords** directly from speech"（L132），入库物是 "The **keywords' embeddings** we
obtained are stored by FAISS"（L151），负例采样单位是 "one positive and ten randomly
selected negative **keywords** per sample"（L151）。**全文再无 "audio–text pair" 的第二次
出现，也无该类条目的构造、规模、对齐或检索协议。** 即摘要宣称的 audio-text pair store 在
方法层无对应实现描述。

**不一致 B（查询侧模态）**。摘要说查询来自**文本部分假设**（"Each partial ASR hypothesis
queries…"），方法节说检索是**从语音直接出关键词**的跨模态相似度（L132 "directly from
speech" + 图 1(b) caption）。两者的查询模态相反。此外，"on the fly"/"live ASR hypotheses"
的**流式**主张在 §2/§3 无任何机制描述——没有部分假设的切分/触发条件、没有增量解码接口、
没有一个延迟或吞吐数字。

**处置**：R2 引用本篇机制时，**必须按方法节口径**（语音侧跨模态嵌入 → 关键词 FAISS 库 →
三路加权融合），并注明摘要口径与之冲突；不得沿用「流式部分假设查 audio-text pair 库」这一
仅存在于摘要的描述（§8 据此对矩阵第 4 格判 CORRECTED）。

## 3. 训练态与信息访问边界

**四处训练组件，逐个引证**：

1. **SLAM-ASR Projector**（§2.1 L129 + §3.2 L149）："The projector, which plays a bridge role
   in connecting embedding spaces, is trained using the AdamW optimizer with the following
   parameters: an initial learning rate of 3e-4 and a weight decay of 0.01. The learning rate
   scheduler uses the Cosine decay strategy with a warm-up ratio of 0.01." 训练在单张
   NVIDIA RTX 3090 上完成（L149）。
2. **CLAP 式跨模态检索器 + 其 pooling 层**（§2.2 L132 + §3.2 L151）："We trained the keyword
   retriever using a CLAP-style contrastive learning approach…"；"we train the retriever using
   contrastive learning with one positive and ten randomly selected negative keywords per
   sample. The retriever shares the same projector structure with SLAM-ASR, and **its pooling
   layer is jointly trained** to fit the retrieval task better."
3. **LLM Adapter（LoRA）**（§2.2 L132）："To implement the LLM generation process to optimize
   the information from keywords, **we fine-tune an LLM Adapter using LoRA technique**."
4. **2,000 样本 LLM 纠错微调**（§3.2 L151）："Last, we **manually selected 2,000 high-quality
   keyword correction samples and fine-tuned LLM for 5 epochs**, achieving better error
   correction capabilities."

**信息访问边界 = 重度白盒，API-only 下零可运行**，五处依赖：(i) 需 Whisper **encoder** 的高维
特征（"We only use its encoder to extract high-dimensional acoustic and semantic features"，
L147）；(ii) 需在编码器与 LLM 之间插入并训练自有 projector（LLM 输入嵌入空间可写）；
(iii) 需把 **LLM 本身当文本塔**取表示（L132 "the text processing tower directly employed the
LLM itself"）；(iv) 需 LoRA 权重挂载 + 全参微调许可；(v) 融合器需**同时**拿到 Whisper decoder
的输出流（§2.3），即还要绕开自己「只用 encoder」的路径另跑一次解码。

**训练依赖是本篇自我宣告的必要条件**，非我方推断——见 §3.3 观察 2（L180）：
> "Context helps, but only after co-training. **Raw RAG degrades performance; guided
> fine-tuning (ours, Keyword-RAG w FT) is essential for harnessing external knowledge.**"

表头两列指标：WER（主）、SEM（自设的 Semantic Consistency Metric，用

"the Keywords RAG methods are based on Phi-4-mini-Instruct and Whisper Large-v3-turbo"。

| 组 | 配置 | WER | SEM |
|---|---|---|---|
| Challenge Baseline | Vanilla Whisper-large-v3 | 14.14 | / |
| Challenge Baseline | **Baseline-Qwen** | **13.83** | / |
| Challenge Baseline | Baseline-Llama | 16.97 | / |
| Whisper | tiny | 33.66 | 0.8217 |
| Whisper | large-v3-turbo | 26.67 | 0.8940 |

| Proposed | **RAG-Boost** | **11.67** | 0.9132 |

**承重负结果（本条目的第一价值）**：

1. **未训练的关键词 RAG 使 WER 恶化 2.4 倍**：Keywords RAG **w/o FT = 32.98** vs 挑战赛最强
   baseline **Baseline-Qwen = 13.83**，比值 **2.38×**、绝对 **+19.15 WER 点**；对比其带训练
   版 **w FT = 16.06**，未训练版是它的 **2.05×**。
2. **同骨干口径下的比值更干净（本条目新增，round-13 未记）**：与 RAG 分支共用同一骨干
   （Phi-4-mini + Whisper-large-v3-turbo）的**无 RAG** 对照是 SLAM-ASR **phi+large-v3-turbo
   = 15.09**。**15.09 → 32.98 = 2.19×**。这是「同系统内加/不加未训练检索」的**近似受控**
   对照，比跨系统的 13.83→32.98 更适合承重（后者换了 baseline 家族）。
3. **未训练 RAG 把系统打回 tiny 档**：32.98 已逼近 Whisper-**tiny** 的 33.66，且劣于
   Whisper-large-v3-turbo 单独解码的 26.67——**注入未经训练的检索关键词，比根本不检索、甚至
   比换用一个弱一个数量级的编码器还差**。SEM 同向（0.8085 vs 无 RAG 同骨干 0.8762）。
4. 论文自身的结论句（§3.3 观察 2, L180）精确引用：**"Raw RAG degrades performance; guided
   fine-tuning (ours, Keyword-RAG w FT) is essential for harnessing external knowledge."**

**同样承重、但论文未讨论的第二负结果（本条目新增）**：

5. **即使训练后，RAG 分支单独仍不如同骨干的无 RAG 版**：Keywords RAG **w FT 16.06** >
   SLAM-ASR **phi+large-v3-turbo 15.09**（劣 +0.97 WER 点），SEM 亦劣（0.8726 vs 0.8762），
   且劣于 Baseline-Qwen 13.83（+2.23）。即**「引导式微调」把检索从灾难性（32.98）救回到
   可用，但没救到超过「不检索」**。
6. **最终 11.67 无法归因于检索**：RAG-Boost = 三路加权融合（Whisper decoder 26.67 / 原 LLM
   15.09 / RAG 路 16.06）。融合较其最好单路（15.09）降 3.42 点、较 RAG 路（16.06）降
   4.39 点。**论文没有「去掉 RAG 路的两路融合」对照臂**，也未给融合权重数值或标定协议
   （§2.3 只说 "the output based on RAG is given a higher weight"）——因此 11.67 相对
   13.83 的 −2.16（相对 −15.6%）**在「检索增益」与「系统组合（ROVER 式）增益」之间不可分**。

**评测面（严格限定）**：§3.1 L140——"We use the English (American) dataset of MLC-SLM to
**train and evaluate (Development Set)** the model."。即 (a) 多语挑战赛中**只用英文（美式）
子集**；(b) **训练与评测同用 dev set**，无测试集；(c) 融合权重亦无独立标定集，权重选择与
报数共面 → 有选择性拟合风险；(d) 标签本身有噪声底（L140）："The word error rate of the label
is lower than 2%"。剩余误差归因为人工检查（L184）："The remaining gap (around 12% WER) is
dominated by overlapped speech and overly rapid speech per manual inspection."

**表内可比性瑕疵（引用时须避开）**：同为 Whisper 的两行差 12.53 点——Challenge Baseline 的
"Vanilla Whisper-large-v3" 14.14 vs 本文自测 "large-v3-turbo" 26.67，文中无解释。故 26.67
这一路（也是被融进最终系统的三路之一）的口径与挑战赛 baseline 行不同源，**14.14 与 26.67
不可互相解释**。另：L187 由 15.09 vs 15.31（差 0.22 点、无 CI）得出 "Phi-4 outperforms Qwen…
highlight its superior adaptability"，属超出证据的断言，不得转引。

## 5. DFS 四问

**方法**：在 SLAM-ASR（Whisper-encoder + projector + Phi-4-mini）之上，训练一个 CLAP 式跨模态
双塔从语音直接检索候选关键词（FAISS），用 LoRA + 2,000 样本微调把 LLM 训成能消费这些关键词的
纠错器，最后把 Whisper 解码、原 LLM 解码、RAG 纠错三路输出加权融合成最终转写。

**局限**：(i) **反 training-free**——四处训练组件，且论文明写微调是 "essential"；(ii) **重度
白盒**（encoder 特征、可插 projector、LLM 当文本塔、LoRA+全参微调、另取 decoder 流），
API-only 冻结核上零可运行；(iii) **零门控**——检索结果无条件进入融合，唯一的"控制"是一个
固定的、数值未公开且未消融的融合权重；(iv) **归因不可分**——最终增益混入三路系统组合，缺
「无 RAG 路」的融合对照；(v) **摘要与方法节两处口径冲突**（库内容物、查询模态），流式主张
无机制、无延迟数字；(vi) **评测面极窄**——单语子集、train/eval 同用 dev、无测试集、无种子/
CI；(vii) 无代码/模型/词库公开物；(viii) 无任何检索侧指标（召回/命中率/误检率），故"检索
为何有害"的机理未被测量。

**改进空间**：本篇缺的正是 R2 的实验位——(a) **门控臂**：在同一表上补 `always-inject /
never-inject / gated-inject` 三臂，把"未训练检索是净负"从一行消融升为受控结论，并测出门控能
挽回 32.98→? 中的多少；(b) **拆系统组合**：报「两路融合（去 RAG）」与「三路融合」的差，才能
把 11.67 中属于检索的部分分离出来；(c) **准入门**：既然误检关键词能把 WER 打到 tiny 档，注入
前的相关性/置信筛选（而非 co-training）是显然的替代机制假设——本篇从未试过；(d) **检索侧
可观测量**：报命中率与误注入率，把"raw RAG 为何退化"从现象变成机制。

**可借鉴**：(a) **一个公开报告的、同骨干近似受控的「无条件注入 = 净负」数据点，且落在语音
ASR 本域**（15.09 → 32.98；跨系统 13.83 → 32.98），这是 R2 门控/准入动机在**本域**最直接的
一手证据——先前同类证据（如 MementoGUI Table 4）来自视觉/GUI 域；(b) **一个"训练是唯一解药"
的公开主张**，恰好构成 R2 命题的**对立面**，可直接作为 R2 要证伪的 H0（详 §7）；(c) 三路加权
融合的**反面教训**——R2 若采用多解码流组合，必须自带「去掉受测组件」的对照臂，否则复制本篇的
归因缺陷；(d) 语音侧跨模态检索关键词（不经文本假设）的接口形状，在 R2 需要"重听动作产出可
检索 key"时是一个已验证可训的 donor 结构（但**须训练**，不可作 training-free 先例）。

## 7. 2026 重审条款预置

提案 §8 的通用重审条款针对「2023 时代近邻」。本篇为 2025 件，故按篇预置**三条具名重审
对象**，Stage-2A 复现先行时逐条重审、结论回写本条目：

1. **RB-RA-1（负结果的可迁移性）**：本篇「未训练检索注入 → WER 恶化 2.19×」测于 3.8B
   Phi-4-mini + Whisper-large-v3-turbo 的 SLAM-ASR 栈、纯关键词库、无门控、英文 dev。
   **重审问句**：在**冻结 omni 核**（Qwen3-Omni-30B 口径）上，原生在上下文中消费候选词表时，
   无条件注入是否仍净负？**判定后果**：若仍净负 → R2 门控/准入动机获得本域最强单篇一手支撑；
   **若不再净负 → 本篇的动机价值失效，R2 不得继续引其作动机，须回落到自测 K-Gate 数据**。
   该分支必须显式写进 prior-difference 记账，不得只保留有利分支。
2. **RB-RA-2（"co-training is essential" 的证伪对象化）**：本篇的公开主张
   （L180）是**「训练是让外部知识可用的必要条件」**——这正是 R2 training-free plug-in 的
   零假设 H0。**重审设计**：R2 须给出同一注入面上的 `无门控 training-free` / `有门控
   training-free` / （引证）`co-trained` 三点对照，才能把 H0 从「未被检验」推到「被本工作
   证伪/受限证伪」。**若 R2 的门控 training-free 臂仍不及无检索基线，本篇的 essential 主张
   在 R2 设置下即被复现，须如实报告并触发 §8 MERGE 触发行复核。**
3. **RB-RA-3（归因协议不得继承）**：本篇最终数（11.67）出自三路加权融合且缺「去受测组件」
   对照。**重审约束**：R2 一旦采用任何多假设/多解码流组合，必须自带 `去掉检索路` 的融合臂；
   否则本条目判其复制了本篇的归因缺陷，该数字不得作为检索效应量上报。
