# D2 深读：Pi-Serini（2605.10848）

来源核对：本地 eprint LaTeX 源（`acl_latex.tex`，1712 行，单文件）+ `custom.bib`；
全部数字取自源码表格/pgfplots 坐标，非 PDF 版面读数。
作者 Tz-Huan Hsu / Jheng-Hong Yang / Jimmy Lin（Waterloo / Stencilzeit）。

## 1 方法本质

Pi-Serini 问一个纯对照性的问题：当 LLM 在 agentic loop 里越来越强时，词法检索器（BM25）还够不够。
它的答案方式不是造更好的检索器，而是把"BM25 弱"这个既有结论拆成三个可分离的因素——**参数配置、
检索深度、agent–检索器交互接口**——然后逐个复位。系统本体极简：一个 ReAct LLM + 一个
retrieval controller，controller 是唯一隔离点，向 agent 暴露三个工具（`search` 取回并缓存最多
1000 条排序、只回显 rank 1–5；`read_search_results` 翻页浏览缓存排序；`read_document` 按行分页读原文），
从而把"检索多深"和"什么进上下文"解耦。终止用**墙钟时间预算**（T=300s，0.7T 时注入提交 steer 并封锁三个工具）
而非固定迭代上限。结论是：在 BrowseComp-Plus 上，配好参数、深度足够、再配一个能管缓存排序的工具接口，
BM25 就能匹配甚至超过已发布的稠密检索 agent，且评测成本降 3.3–10 倍。
论文自己把瓶颈从"检索器能不能找到证据"改写成"agent 能不能认出并把上下文花在已经给它的证据上"。

## 2 三轴/key-value 定位（重点：BM25 调什么、检索深度多少时暴露什么）

**BM25 调的是什么（精确）**：只调 Anserini 的两个参数 `k1`（词频饱和）与 `b`（长度归一化）。
- Anserini 默认 = `(k1=0.9, b=0.4)`，论文明确说这套默认值是**为短文档/passage 检索调的**。
- 网格搜索（Fig 3，100 条 query 采样）最优点 ≈ `(k1=16, b=1.0)`；默认点落在低性能区。
- 主实验实际固定用 `(k1=25, b=1)`，全部 Pi-Serini run 不变；论文另测了网格最优 `(16,1)`，结果相近。
- **调优方向的物理依据是文档长度**：BrowseComp-Plus 文档中位数 ~2k tokens、90 分位 ~14k tokens
  （引 BrowseComp-Plus 原文 Fig 4）。长文档里证据被埋在噪声中，长度归一化与词频饱和的权重比
  passage 检索大得多。**这是"往大 k1、高 b 调"这一方向的唯一依据，不是普适方向。**

**检索深度调的是什么**：`search` 的返回条数 k（backend request limit），主实验 k=1000。
深度消融（Fig 2，gpt-5.4）给出三段行为：
- **Surfaced recall 单调随深度上升且不饱和**：evidence 70.48(k=5) → 86.22(k=100) → 94.16(k=500) → 95.78(k=1000)；
  gold 73.12 → 90.45 → 96.83 → 97.33。
- **Previewed recall 早饱和并回落**：evidence 峰值 74.67 在 **k=50**，到 k=1000 反降到 70.89；
  gold 峰值 79.82 在 k=100，k=1000 降到 74.78。
- 结论边界（论文原话意）：深度给了 BM25 足够的一阶召回容量把证据放进缓存排序，但**更大的缓存排序不会
  自动让 agent 去看更多相关证据**。

**三层召回读数的分层（这是本文最可复用的度量结构）**：轨迹日志记四个文档集——
`D_surfaced`（search 返回）、`D_previewed`（经 `read_search_results` 显示过摘录）、
`D_opened`（`read_document` 读过）、`D_cited`（最终答案引用）；对应 Surfaced / Previewed /
Behavior（= opened ∪ cited）三个 recall。**基线 agent 只有单一 top-k 检索工具（k=5），因此只有
`D_surfaced` 可比** —— 这条口径限制直接决定了主表大量"-"。

**key-value 定位**：Pi-Serini 全程 key = BM25 词法倒排索引项（稀疏、可调参、无学习），
value = 原文文档（按行分页进上下文）。它**没有做任何 key 侧组织升级**——不建图、不建层次、不多面。
它的全部增益来自 (a) 稀疏 key 的两个超参、(b) key→候选集的截断深度、(c) value 进上下文的选择性接口。
因此它在 R2 的组织轴上不是"一步演进"，而是**组织轴的对照零点（well-tuned flat sparse baseline）**。

## 3 主实验数字（LaTeX 源核对）

数据集：BrowseComp-Plus，830 query / 100,195 文档；每 query 平均 6.1 evidence 文档、2.9 gold 文档；
文档平均 5,179.2 词 / 32,296.2 字符。judge = `gpt-5.3-codex`（180s 超时）。

1. **Table 1 行 (m)**：Pi-Serini + `gpt-5.5` + BM25 = **Acc 83.1 / Calib 15.7 / Cost \$291.6；
   Surfaced 94.7(evi) 94.4(gold)；Previewed 73.6/72.9；Behavior 58.9/56.1**。全表最高 Acc。
   （正文另处写作 83.13%。）
2. **Table 1 同模型对照（本文最干净的一条）**：同为 `gpt-5` + BM25，已发布基线行 (c) = Acc 58.3 /
   Surfaced 61.7(evi)；Pi-Serini 行 (i) = **Acc 74.6 / Surfaced 90.5(evi) 93.8(gold)**，
   且成本从 \$400.4 降到 **\$94.9**。行 (i) 亦略高于稠密基线行 (d) `gpt-5`+`qwen3-embed-8b` 的 73.0。
3. **Table 1 反例（稠密不保证更好）**：`meng2026revisiting` 的 `gpt-5.2`+`qwen3-embed-8b` 行 (e) = Acc **45.1**、
   成本 \$1–2k、平均 **73.8** 次工具调用（Table 2）；Pi-Serini 同 LLM `gpt-5.2`+BM25 行 (j) = Acc **70.5**、
   \$122.2、17.2 次调用。AgentIR-4B 行 (f)（专为深研训的推理型检索器）= Acc 68.1 / Surfaced 79.2。
4. **Table 3（BM25 调优消融，gpt-5.4，100-query 子集，终止条件同为 300s）**：
   默认 `(0.9,0.4)` → 调优 `(25,1)`：Accuracy **64.0 → 82.0**（+18.0 **绝对百分点**）；
   Surfaced **84.6 → 95.7**（+11.1 点）；Previewed 50.7 → 70.4；Behavior 36.4 → 52.2；成本 \$24.1 → \$21.7。
   网格最优 `(16,1)` 给出 81.1 / 94.0，与 `(25,1)` 相近。
   **摘要里的 "improves answer accuracy by 18.0% and surfaced evidence recall by 11.1%" 是绝对百分点差，
   不是相对提升**——引用时不得写成"提升 18%"。
5. **Fig 2（深度消融，gpt-5.4）**：Surfaced(evi) **70.48 (k=5) → 95.78 (k=1000)**，差 **+25.3 绝对点**
   （即摘要 "25.3% over the shallow-retrieval setting"，同样是绝对点差，shallow = k=5）。
   Previewed(evi) 峰 74.67 @ k=50，k=1000 回落 70.89。
6. **Table 3 终止策略与前缀缓存**：MaxIter100（对齐基线口径）Acc 76.0 / \$24.9；3600s 超时 Acc 83.0 / \$26.3；
   300s 为 82.0 / \$21.7。所有档位 **82%–90% 的 total token 由缓存服务**，论文归因前缀缓存为成本效率主因。
   （注：Table 3 有一行 `Acc.†` = 66.7 / 83.7 / 92.7 / 83.0，**† 在 LaTeX 源中从未定义**，
   表注亦无；MaxIter100 档 Acc 76.0 而 Acc† 92.7 的巨大落差暗示它是"排除超时/未提交 query 后的准确率"，
   但这是推断，不可作为引用数字。）

## 4 DFS 四问

**方法**：把"BM25 弱"分解为参数/深度/交互三因素并逐个复位；用 retrieval controller 作单一隔离点，
把检索深度与上下文管理解耦（缓存排序 + 分页浏览 + 按需读原文）；用墙钟预算替代迭代上限；
用四层文档集日志（surfaced/previewed/opened/cited）把"系统给了什么"与"agent 用了什么"分开度量。

**局限**：单一 benchmark（BrowseComp-Plus，英文、固定语料、长文档），论文自己列为限制并明说
"the lesson is not that BM25 is enough everywhere"；调优参数与网格搜索都在同一分布上做，无独立 dev split
（100-query 采样既用于网格搜索、也用于消融报告）；主表跨系统对照混杂 LLM 代际（`o3`/`gpt-5` 基线
vs `gpt-5.5`/`deepseek-v4`），只有 `gpt-5`+BM25 与 `gpt-5.2` 两处是同模型对照；
成本数字依赖厂商定价表（Table 4）与前缀缓存命中率，跨时间不可复现；Previewed/Behavior recall 显著低于
Surfaced（gpt-5.5：94.7 / 73.6 / 58.9），论文承认这是其最小化浏览接口的直接后果。

**改进空间**：论文自己指出的方向是"帮 agent 导航缓存排序、把上下文花在对的证据上"，
即把增益从一阶召回转到证据消费判断；failure mode 分析给出一个可操作构念——**premature branch commitment**
（`claude-opus-4.7` 在弱假设分支上纵向深挖不回退，`gpt-5.5` 保持探针可逆、失败即回到原始线索），
这暗示"分支可逆性"本身是可被控制/奖励的量。

**可借鉴（对 R2）**：(a) **三层召回分层度量**（surfaced / previewed / behavior）是把"检回了"与"用上了"
分离的现成协议，与 R2 §7 的 K5-r（检索层读数）/ K5-t（任务层判死）两级判定结构同构，可直接作为
K5-r 的报告表头；(b) **"基线是否被调优"作为一等实验变量**的做法；(c) 墙钟预算 + 提交 steer 作为
终止策略，比硬迭代上限更贴近部署，且成本反而略降；(d) 四文档集轨迹日志的落盘 schema
可并入 R2 §3.4 第 1 项"可复放组织"的字段表。

## 5 R2 定位句核查

### 逐句判定

**句 1（§3.1 第 3 条，行 302–303）**：
> "**稀疏/稠密对照保持活跃**：Pi-Serini 2605.10848 显示调好的 BM25+足够检索深度即可暴露高证据召回
> ——组织升级的收益必须对着强稀疏基线验证，不能对着弱基线自证。"

**判定：CONFIRMED（表述精确）**。"调好的 BM25 + 足够检索深度"恰好对应论文的两个消融变量；
"暴露高证据召回"用词准确——论文的 94.7% 正是 **surfaced**（暴露层）recall，而非 previewed/behavior。
R2 用"暴露"而不用"利用"，无意间已经守住了论文最重要的边界。建议保留原词，勿在后续版本改写成
"高证据利用/高证据覆盖"。

**句 2（§3.4 第 3 项，行 368）**：
> "对照臂必须含调优的稀疏基线（Pi-Serini 教训）。"

**判定：CONFIRMED（纪律成立），但需补作用域限定 → 见新增事实 (1)(2)**。
论文确实提供了"未调优基线会掩盖真实对照"的直接证据（Table 3：64.0 → 82.0）。
但"调优稀疏基线"在 Pi-Serini 里是**三件事的合成**（参数 + 深度 + 工具接口），
R2 现行措辞只锁"调优"一词，未锁"调什么、深度多少、接口是否等强"，可被 sandbagging。

**句 3（§7 K5-t，行 721）**：
> "**K5-t（任务层，判死层）**：O2 相对 O1（含调优稀疏基线）无任务效用/answer-bearing coverage 增益 → …"

**判定：CORRECTED（作用域错位）**。Pi-Serini 的调优证据最强、最直接的层是**检索层（surfaced recall）**，
即 R2 的 **K5-r**；把"含调优稀疏基线"只挂在 K5-t（任务层）上，恰好挂错了层。
论文自身数据表明：调优稀疏基线在检索层的杀伤力远大于任务层
（Surfaced 84.6→95.7 已接近天花板，而 Behavior 只 36.4→52.2）。
建议把"含调优稀疏基线"同时写入 K5-r 的报告口径与 K5 的专属前置㈡。

### 深读后新增的、R2 应该知道的事实

**(1) "调优稀疏基线"的确切实验依据 = 只调两个参数，且调优方向由文档长度决定，不可跨语料照搬。**
依据是 Table 3 第 1↔2 列 + Fig 3 网格搜索：调的只有 Anserini BM25 的 `k1` 与 `b`；
默认 `(0.9,0.4)` → 主实验 `(25,1)`（网格最优 `(16,1)`）；网格在 **BrowseComp-Plus 采样 100 条 query** 上做。
**论文明确把"往大 k1、高 b"这一方向归因于长文档**（中位 ~2k tokens、90 分位 ~14k tokens），
并直说 Anserini 默认值是为短文档 regime 调的。
→ **对 R2 的直接后果**：R2 的 O 臂锚载体是 Spoken-SQuAD / SLUE-SQA-5 官方 passage 池，
其 value 是 SQuAD 式**短 passage**，正落在 Anserini 默认值本就适配的 regime。
**因此 R2 不得把 `(k1=25, b=1)` 当作"调优稀疏基线"的配置照搬**——照搬极可能反而把稀疏臂调坏，
制造一个新的弱基线，从而以另一种方式违反本条纪律。可移植的是**程序**（在自己的语料上对 `k1`×`b`
做网格搜索、并把检索深度作为独立变量扫），不是**数值**。这一条必须写进 authorization 预注册。

**(2) 深度是与参数并列的第二个必调变量，且"足够深度"在本文 = k 从 5 提到 1000。**
Fig 2：surfaced(evi) 70.48 → 95.78。R2 §3.4 现行措辞只说"调优的稀疏基线"，
未规定 O1 稀疏臂的检索深度必须与 O2 等强。若 O1 稀疏臂停在 top-5/top-10 而 O2 多面 key 查到更深，
则 K5-r 的"O2 能检回 O1 检不回的 value"会被深度差整体污染，读数无效。
**建议：把"检索深度对等"写成与"参数调优"并列的预注册项**。

**(3) 最关键的反向威胁：调优稀疏基线在检索层可能直接把 K5 的专属前置㈡打掉。**
R2 §7 K5 前置㈡ = "O1 单面 key 的检索层读数（R@k）距天花板有预注册余量（语义面已饱和则多面 key 无处发挥）"。
Pi-Serini 恰恰是"**调好的稀疏基线 + 足够深度可以把 surfaced evidence recall 顶到 94.7–95.8、gold 顶到 97.3**"
的实证。也就是说：一旦 R2 忠实执行"O1 含调优稀疏基线"这条纪律，**O1 的 R@k 很可能自己就饱和**，
前置㈡ 不过 → 按 K5 自身条款 K5 不触发任何判死、回 owner 重议载体（§5.4 梯④同型出口）。
→ 这不是 R2 的漏洞，而是 R2 应当**预先知道并预注册应对**的高概率分支：
"忠实执行本纪律与 K5 可判定性之间存在结构性张力"。
建议在 §3.4/§7 显式登记该分支，并预注册两条出路之一：
把 R@k 天花板判定改为**按面分层**（语义面允许饱和，非语义面看余量），或直接承认锚载体在检索层
无分辨力、把 O 臂读数下调为定性证据。**这是本次三篇深读中对 R2 最有实质影响的一条。**

**(4) Pi-Serini 的整体增益是三因素合成，R2 引用时不得把 58.3→74.6 归因于"调参"。**
已发布 `gpt-5`+BM25 基线（Acc 58.3）与 Pi-Serini `gpt-5`+BM25（74.6）之间同时变了三件事：
BM25 参数、检索深度（top-5 单工具 → 1000 条缓存 + 分页）、工具接口（1 个工具 → 3 个工具）。
**只有 Table 3 是在固定 harness 内隔离参数的**（64.0→82.0，gpt-5.4，100-query 子集）。
→ R2 若要量化引用"未调优基线掩盖多少"，唯一可引的是 Table 3 的 +18.0 点，且须标注
"gpt-5.4 / 100-query 子集 / 固定 Pi-Serini harness"。

**(5) 论文自己的结论支持 R2 的 K5-r ↔ K5-t 两级切分，且给出了转化率数字。**
gpt-5.5 行：Surfaced 94.7 → Previewed 73.6 → Behavior 58.9。论文结语明说问题已从
"检索器能否找到证据"转为"agent 能否认出并把上下文花在已给它的证据上"。
→ 这是**跨域独立证据**：检索层召回不会自动转化为使用层效用。R2 §3.4 把 K5-r 定为"报告层读数、
不携判死条款"、判死权只给 K5-t，与该证据一致，可作为该设计的外部支撑（而非仅内部谨慎）。
同时它也是 R2 §4（阶段三）主线论点的旁证。

**(6) 稠密检索器不保证更好，且"更贵"常与"更差"同现——可加强 R2 §3.1 第 3 条。**
Table 1 行 (e)：`gpt-5.2`+`qwen3-embed-8b` = Acc 45.1、\$1–2k、73.8 次工具调用；
同 LLM 的 BM25 版 = 70.5、\$122.2、17.2 次。行 (f) AgentIR-4B（专训推理型检索器）= 68.1。
→ R2 现行句只说"必须对着强稀疏基线验证"，可补一句更强的版本：
读集内已有**稠密/专训检索器输给调优稀疏基线**的实例，故"组织升级"的举证责任不止于"不弱于弱基线"。

**(7) 可直接复用的两个协议件（工程，非主张）。**
(a) 四文档集轨迹 schema（surfaced / previewed / opened / cited）+ 三层 recall 定义，
可并入 R2 §3.4 第 1 项"可复放组织"的落盘字段；
(b) 墙钟时间预算 + 0.7T 提交 steer + 工具封锁，作为终止策略的现成对照设计
（Table 3 显示它比 MaxIter100 成本更低 \$21.7 vs \$24.9 且 Acc 更高 82.0 vs 76.0）——
与 R2 §4.3 批评语音线"每个数量=硬编码常数"直接对位。

**(8) 引用格式提醒**：本文表号在源码中为 Table 1（主表）/ Table 2（工具调用）/ Table 3（BM25 调优+终止策略）
/ Table 4（附录定价），图为 Fig 1（成本-准确率）/ Fig 2（深度消融）/ Fig 3（BM25 网格）/ Fig 4（系统图）。
Table 3 的 `Acc.†` 一行**在源中无定义**，不可引用。
