## 1. 方法本质

MMSearch-Plus 是一个 **311 题的多模态浏览基准 + 一个 model-agnostic 搜索 agent 框架**。
造题方法叫 **Spatial–Temporal Extrapolation**：不问画面里直接可见的东西，而问"上下文蕴含但
物理上不在场"的事实——空间外推指画外实体（背对镜头的人、被遮挡的标识），时间外推指所描绘
瞬间之前/之后的事件（首发名单、下一个进球、下一段剧集）；解题必须先精确定位事件（时间/
比赛/剧集），再检索并整合更广的上下文（§ste）。素材取自公开视频平台与 arXiv PDF，人工标注者
挑关键帧或截图，**准入三条**：(i) 含模糊/嘈杂信息以挑战感知；(ii) 含不熟悉实体、必须外部检索；
(iii) **不能被 Google 图像搜索直接检出**（§数据采集）。再叠一层对抗过滤：标注者出自身知识
之外的题，并在**至少两个闭源 MLLM** 上验证不可解；关键视觉子区域模糊或遮挡；仍可轻易解出的
题直接丢弃。难度是**事后**标注的：若 o3 或 Gemini-2.5-Pro 无检索或仅凭图搜即可答对则记 Easy
（94 题，30.2%），否则 Hard（217 题，69.8%）。评测指标是 accuracy 对 acceptable-answer 集，
GPT-4o 做 LLM-as-judge，人工抽检报"与人判完全一致"。附带的 agent 框架交织 text search /
image search / zoom-in(SoM) 三类工具，并定义**五档 search mode** 阶梯（§experiment）。

## 2. 三轴定位

**搜索决策谁做。** **取决于档位**——这是本文最有价值的结构：五档从"框架全定"到"模型全定"：
(a) *Without Search*（不许检索）；(b) *Image Search*（框架强制：每张题图取 top-10 图搜结果，
由 Gemini 摘要并缓存后塞进上下文，模型无调度权）；(c) *Text Search*（只许文搜，top-5 网页，
每轮模型生成 3–5 条改写 query，上限 20 轮）；(d) *Full Rollout*（模型自主决定每步调哪个工具，
图搜每轮恰 1 条 query，text+image 合计上限 20 轮）；(e) *Full Rollout + SoM*（额外开放 zoom-in
与按 bbox 索引的子图检索，工具调用总上限 20）。**按模型分设预算**：Qwen 因 pilot 显示 >10 轮
无增益而封 10 轮。

**几轮 / 停止判据。** 上限 20 轮（Qwen 10）；停止 = 模型自发 emit ANSWER，否则触顶。**没有
置信度/收益/预算型停止判据**。实测行为（§analysis、Figure 4）：Gemini 恒在第 9 步或之前作答；
o3 可维持 10+ 轮、对 ~50+ 条检索项推理；而**错误轨迹的 search 调用数通常多于正确轨迹**
（Figure `fig:3x2-trajectory-stats`）——即调用数与正确性负相关。

**证据准入。** **无准入门**。SerpAPI 返回排序结果，框架把 top-k 转给模型；网页由一个 MLLM
（作者用 Gemini）摘成**两个字段**注入：`web_info`（以任务为条件的语义摘要）与 `related_info`
（把该结果的缩略图/首图与题图关联起来的证据，如相符的招牌、版式、微小文字）。URL/标题由
SerpAPI 侧携带。摘要的目的是压缩交互历史以适配上下文窗口，不是筛选。缓存纪律：**只缓存
image-search 的排序 URL/缩略图及其 MLLM 摘要（按题图缓存）**，理由是该设定下 top 图搜结果
跨时间相对稳定；text search 不缓存。

**provenance 机制细节（R2 委托的核心项）。** 本文"provenance-aware"有三个确切所指，**全部
在构造/工具设计层，无一在指标层**：

1. **标题级主张**：论文标题即 *Benchmarking Provenance-Aware Search for Multimodal Browsing
   Agents*；abstract 原文 "SoM enables provenance-aware zoom-and-retrieve and improves
   robustness in multi-step reasoning"。所以 R2 的标签不是外推，是照抄标题。
2. **SoM = 区域级出处锚定**（§agent-fw 原文 "To enable precise, provenance-aware inspection"）：
   SoM 在本文特指**每张题图一组人工核验的 bounding box**（不是模型产生的框）；第一轮同时给
   原图与带框+编号的叠加图（避免遮挡、允许交叉引用）；模型给一个 index，框架回裁剪子图；
   image search 亦可按 bbox index 检索。作者明说之所以人工标框，是因为受测 MLLM 自身 grounding
   能力不足、且题中实体长尾（自动化需极强的开放词表检测，如 SAM 2 也不够）。→ provenance 在
   此 = **把一次检索 query 锚定到图中一个可指认的区域**，从而"这条证据由图的哪个部位引出"
   可追溯。
3. **构造侧的交叉核验要求**：题目设计成必须 cross-validate（附录 `fig:real-teaser` 例：
   micro-text/歌词 → 歌手裁剪 → 音乐节/品牌招牌 → 交叉核验官方 schedule 得出确切演出时间）；
   conclusion 明说当前系统的两大不足之一是无法 "maintain verifiable chains of evidence
   across long-horizon tool use"。

**但**：没有 attribution precision / unsupported-claim 之类**指标**；答案不要求给出处；judge
只比答案与 acceptable 集；`related_info` 是给模型看的辅助字段，不是被评分的归因输出。
**且该机制基本没被模型采纳**：$P(\text{image search}\mid\text{zoom})$ = Gemini 25.37%
(34/134)、Qwen 10.56% (15/142)、**o3 仅 2.87% (18/627)**；scene-text 场景抽样中 o3 8/10、
Gemini 7/10 只用"内建 OCR + 文搜"而不对该子区域做图搜（§analysis）。

1. **Table 1（`tab:main-results`）平均 accuracy × 五档**：
   o3(2025-04-16) 15.1 / 19.3 / **37.0**(Text) / 36.0(Full) / **37.6**(Full+SoM)；
   GPT-5 10.3 / 16.4 / — / — / 35.4；Gemini-2.5-Pro 10.6 / 16.4 / — / 23.8 / 27.7；
   Qwen-2.5-VL-72B **0.0** / 13.5 / — / 6.1 / 7.1；Human(Chrome 浏览器) **22.8**。
   → 开源在 No Search 下为 0.0（论文据此称"MMSearch⁺ 抵抗参数捷径"）；人类 22.8 **低于**
   o3 的 37.6，但按类别互有胜负（论文命名为"人与 MLLM 的比较优势不同"：无工具时 o3 地理
   31.2 > 人类 20.3，而 Sports/Vlog 人类通常反超）。
2. **Table 1 难度分栏（Easy 掉分现象）**：o3 的 Easy 列 50.0 / **63.8** / 50.0 / **54.3** /

   Full Rollout 54.3（−9.5，论文另以"23 题 / 全 311 题上 7.4 个绝对点"表述）。论文抽 10 例

   结论明写：掉分**不是** over-retrieval 或干扰项暴露，而是 **image search 的 underuse**，
   属"是否调用"的**策略级**错误。
3. **SoM 增益（Table 1）**：o3 36.0→37.6 (+1.6)、Gemini 23.8→27.7 (**+3.9**)、
   Qwen 6.1→7.1 (+1.0)。abstract 口径为 "improvements up to +3.9 points"。
4. **Table 4（`tab:main-results-lite`，239 题去内部知识子集）**：全部模型 No Search 恒为 0.0

   Qwen 0.0 / 8.4 / 3.3 / 4.2；Human 18.8。类别级唯一明确受益于图搜的是 Sports（o3 相对

5. **工具行为与错误统计（§analysis 正文）**：Qwen 在 **45/311** 题上产生 **421 次非法

6. **规模与分布（Figure 3(b) `tab:summary` / Table 3 `tab:primary`）**：311 题（均含图）、

7. **模型横比里有无 omni/audio 相关模型：没有。** 受测 4 个模型 = o3 / GPT-5 /

   值得记的是：**素材源包含视频平台，但只取关键帧静图，音轨从未进入任务**——视觉搜索谱系
   在"有视频源"的条件下仍主动丢弃音频维度。

## 4. DFS 四问

**方法。** 三件耦合：①用空间-时间外推自然放大搜索空间，逼出 hypothesize→test→refine 的长
轨迹与跨源交叉核验；②五档 search-mode 阶梯把"内部知识 / 单跳检索 / 纯文搜 / 自主 rollout /
加区域锚定"分离成可对照的臂；③用人工核验 bbox 把 region-level grounding 从"模型能力"里
**外生化**，从而单独测量"给定完美区域锚定后的检索行为"。

**局限。** (a) SoM 框人工标注 → 该臂测的不是端到端可部署系统，作者自陈自动化需极强开放词表
检测；(b) **无 provenance / attribution 指标**，"provenance-aware"停在构造与工具层；
(c) live SerpAPI，仅图搜结果做缓存、text search 不冻结 → 跨时间不可严格复放；(d) 311/239 题、
单轮、无 CI、单 judge；(e) 开源侧结论不可靠——Qwen 在 No Search 得 0.0、Full Rollout 反而
从 13.5 掉到 6.1，同时有 421 次非法工具调用，说明该框架的 tool-format 对开源模型不友好，
论文自己在被注释掉的段落里承认应"在相同 search controller 下重跑 OSS 基线"；(f) 部分档位
缺格（GPT-5 无 Full Rollout 行、Qwen/Gemini 无 Text Search 行），跨档比较非完全交叉。

**改进空间。** 把人工 SoM 换成自动 grounding；补归因/出处指标（当前完全缺）；冻结 text-search
快照；把"何时该调 image search"做成显式策略（论文自陈这是 o3 的主导失效模式）；把 lite 去污
从"事后子集"升为"构造期硬约束"。

**可借鉴（对 R2，四项，全部是协议）。**
①**五档 search-mode 阶梯** = 天然的因果阶梯，与 R2 §6.1 的 A0–A6 同构；尤其它的
"**Text-Search-only**"臂正是 R2 需要的"关掉某一模态检索通路"的消融形状（对应 R2 §2 的模态
映射矩阵）。②**lite 去内部知识子集**：剔除"任何受测模型无检索即可答"的题得 239/311，并**同时
报 full 与 lite 两张表**、画 $y{=}x$ 散点（Figure 5）判断参数记忆的影响面——这比"构造期用两个
闭源模型验证"更强，因为它对**评测时**的新模型也有效。③**难度事后标注**：用模型可解性而非
人工主观定义 Easy/Hard。④**轨迹级统计面**：$P(\text{next tool}\mid\text{current tool})$ 马尔可夫
转移矩阵、first-zoom 步位分布、zoom 深度分布、"错误轨迹调用更多"的相关性——R2 §4.3 关于停止权
的论证可直接照搬这套统计。

### 5.2 深读后新增的、R2 应该知道的事实

**N1（该机制存在但模型基本不用——引用时须降格）。** SoM 的净增益仅 +1.0～+3.9 点，且
"zoom 后接图搜"这条通路模型极少走：$P(\text{image}\mid\text{zoom})$ o3 **2.87%** (18/627)、
Gemini 25.37% (34/134)、Qwen 10.56% (15/142)；scene-text 抽样中 o3 8/10、Gemini 7/10 只走
OCR+文搜。→ R2 §4.4 若把"区域级出处锚定"列为"跨域已成熟机制位"，须改为"**已被提出、效果
1–4 点、且当前模型基本不采纳**"。这条对 R2 是**双向**信息：机制位确实存在（可借形状），但
不能作为"视觉域已经解决、语音域落后"的论据。

**N2（lite 子集反转结论——对 R2 §2 是强证据）。** 去掉 72 题可凭内部知识答的题后，o3 的最佳
臂是 **Text-Search-only 31.4**，高于 Full Rollout 27.3 与 Full+SoM 30.1；仅 Sports 类图搜为
正收益（+6.6 / +10.0）。即"**加入跨模态（图像）检索通路在去污后整体为负收益，且收益强烈
分层**"。这与 R2 §4.3 记录的 Omni-DeepSearch 类别非均匀性（IMAGE 38.75→50.00、SPEECH
55.00→70.83 升；VIDEO 36.88→31.25、AMBIENT 36.67→20.83 降）**同形**。R2 可把它写成"跨域
同构的分层性证据"（借形状），但按 H5 withheld 不得外推效果量级。

**N3（视觉域的停止失效是 under-call，与语音域记录的 over-search 互补）。** Easy 分栏
63.8→54.3 的掉分被作者用 10 例人工查轨迹明确归因为 "**underuse of image search**"（9/10 全程
未调），并**显式排除** over-retrieval / 干扰项解释；同时"错误轨迹调用数多于正确轨迹"。
→ R2 §4.3 目前把停止权失效写成单向（AudioRAG 无限循环 type-D 增多、Omni-DeepSearch 预算
饱和 = over-search）。视觉域给出的是对称的另一半。**R2 应把停止/调度失效面写成双向
（over-call ∧ under-call）**，否则 §6 的 A3/A4 臂设计只覆盖一半失效模式，K1b 的差分识别力
会被系统性低估。

**N4（轮数/预算的可对标口径）。** Full Rollout 上限 **20 轮**（text+image 合计），每 text 轮
生成 3–5 条改写 query、每 image 轮恰 1 条 query；Image Search 档 top-10、Text Search 档
top-5；**Qwen 因 pilot 显示 >10 轮无增益而单独封 10 轮**（按模型分设预算）。这与 R2 §5.3
"固定档阶梯需向上扩档至实测成本不低于自适应臂"的要求相容，且给出更细的一条纪律：**预算上限
应按模型 pilot 结果分设并说明理由**，而不是全模型统一封顶（后者正是 R2 §4.3 批评
Omni-DeepSearch"最优档随任务分层剧变、论文却统一封顶"的同类问题）。人类基线口径：Chrome
浏览器、每题 ≥10 分钟、上限 20 分钟。

**N5（构造纪律：检索器级排除 + 事后去污两级，R2 可完整照搬）。** MMSearch-Plus 的准入判据里
有一条 R2 载体没有的**硬条件**：截图"**不能被 Google 图像搜索直接检出**"——这是对一跳捷径的
**检索器级**排除；再叠"至少两个闭源 MLLM 验证不可解"与"关键区域模糊/遮挡"；最后叠**事后**
`MMSearch⁺_lite`（剔除任何受测模型无检索可答的题）。→ R2 §5.1 记 Omni-DeepSearch-640 的
first-hop 实体泄漏过滤属**模型级**（用 GPT-5 判），弱于检索器级：模型级过滤只保证"该模型
猜不出"，检索器级过滤保证"该检索工具一步拿不到"。两级串联是 R2 可完整照搬的两步。

**N6（部分缓存 = 最低成本的快照折中）。** 只缓存 image-search 的排序 URL/缩略图与其 MLLM
摘要（按题图缓存），理由写在正文：该设定下 top 图搜结果跨时间相对稳定，故不损可复现性；
text search 不缓存。→ 对 R2 §5.2「Omni-DeepSearch-640 无检索快照」的缺口，这是比 MMSearch
的"全证据落盘"更轻的一档折中：**先冻结最不稳定/最贵的那一路工具输出**。
