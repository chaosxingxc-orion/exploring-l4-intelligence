## 2. 系统构造：一个有状态图 + 五个 Phase

### 2.1 论文自述的问题设定与三条设计目标（逐字）

Abstract（p.1）首句即给出本篇的问题重定位：

> "Audio agents extend large audio-language models (LALMs) by decomposing audio questions into tool calls, intermediate evidence, and iterative reasoning steps. However, as LALMs become stronger, **the key challenge shifts from enabling tool use to determining when agentic evidence acquisition genuinely benefits audio understanding.**"

> "We propose AUDIO-MIND, an auditable and pluggable framework for **conditional evidence acquisition** in audio understanding. AUDIO-MIND dynamically combines a strong frontend with planner-guided tool use, **preserving frontend judgment when initial evidence is sufficient while acquiring bounded external evidence for questions with unresolved evidence gaps.**"

§1（p.1）给出这一转向的理由（**加粗为论文自身加粗**）：

> "**Under such a strong frontend, the value of external tools depends less on their existence than on whether their outputs are more reliable, more precise, or more targeted than the model's own perception.**"

§4 开篇（p.4）三条设计目标逐字：

> "AUDIO-MIND operationalizes conditional evidence acquisition with three design goals. First, it should **preserve the frontend LALM when direct audio perception is already sufficient**. Second, it should **expose the unresolved evidence gap before invoking tools**. Third, it should **make each external operation bounded and inspectable**, so that tool outputs, transformed audio artifacts, and re-listening results can be traced back to the decision that requested them."

§4（p.4）系统形态逐字：

> "The system is organized as a **stateful graph** in which each module reads a shared evidence state, performs one bounded operation, and writes structured updates for later modules."

§4.1（p.4–5）角色分工逐字：

> "In our default instantiation, AUDIO-MIND separates audio perception from textual orchestration. **An audio-capable LALM serves as the frontend for initial perception, targeted re-listening, and final answer generation, while a text LLM serves as the planner for prompt construction, action selection, evidence summarization, and format checking.** The shared evidence state keeps these roles pluggable: frontends, planners, tool executors, and checkers can be replaced as long as they preserve the same evidence contracts."

### 2.2 五阶段流水线（Phase 编号只在 Figure 1 图形层，p.4）

正文只写 §4.2 / §4.3 / §4.4 三节；**Phase 编号与终止分支语义出自 `figures/architecture.pdf` 的可抽取文本层**（并与 PDF p.4 的渲染文本双通道核过）。
**引用纪律**：以下每个引号内的**标签串本身逐字**（本件已逐条核到图形文本层与 p.4 渲染层），
但**"Phase N ↔ 模型"的对应关系、以及用 `—` / `：` / `‖` 连接的成组关系，是本件依图中同列/同框对齐位置读出的重组**，
**不是图中一条连续字符串**。R2 引用时须照录这一区分。

> "(a) Question Lifecycle" — "Setup" → "Main Loop" → "Finalize"
> "Phase 1 Question-Oriented Prompt Generation **Text LLM**"
> "Phase 2 Initial Audio Perception **LALM**"
> "Phase 3 Initial Plan Construction **Text LLM**"
> "Phase 4 Decide → Execute → Fuse (**k iterative rounds**)"
> "Phase 5a Evidence Summary **Text LLM**" / "Phase 5b Final Answer Generation **LALM**" / "Phase 5c Format Check **Text LLM**"
> "5c → 5b on fail"
> "(b) Inner Loop — Zoom of Phase 4" — "**Planner Decision Node** / LLM call with **native function calling**"
> "**Terminal Actions**：Emit Final Answer (Exit Loop) — Evidence sufficient → Exit loop → Phase 5；Give Up (Exit Loop) — Information insufficient → Phase 5 with FAIL marker"
> "**Evidence Acquisition Path**：Tool Executor — parallel dispatch + resolve audio-ids；perception tools + transformation tools ‖ Frontend Re-listen — hand selected audio + focused prompt to the frontend for focused re-listen ‖ Evidence Fusion — Append new evidence to Evidence Log"
> "Agent State Update：append evidence item(s) / update planner state / continue next round"
> 状态四槽逐字："audio list"、"evidence log"、"tool call history"、"planner trace"

**三条须记入的结构判定**：

1. **即便零工具调用，也不是"直接问 LALM"**。最短路径仍为 Phase 1（planner 造感知提示）→ Phase 2（LALM 听）→ Phase 3（planner 造计划）→ Phase 4 一轮（planner 出 ANSWER）→ Phase 5a/5b/5c。
   即**至少 2 次 LALM 调用 + 至少 4 次 text-LLM 调用**。§B.1（p.12）证实这条路径占 **31.1%**。
   → **§6.4 的 0-call 桶（Δ = −0.6 pp）度量的正是"这套提示词重构本身"的净效应，而不是"什么都不做"。**
2. **最终答案始终由 LALM 在原音频上生成**，不是由文本轨迹推出。§4.4（p.6）逐字：
   > "The audio-capable frontend receives this summary together with **the original audio** and task context, so the final answer is **still grounded in direct listening** while being informed by accumulated evidence."
3. **失败是显式动作**。Give Up 分支写 `FAIL marker` 并仍进 Phase 5；§B.1（p.11–12，该句跨页）实测 **只有 1 个 run 走此支**，且原因是 API 内容安全拒绝，非证据不足。

## 3. 逐样本决策机制（**R2 审计问 1**）

### 3.1 决策发生在哪里、由谁做、读什么信号（§4.3，p.5，逐字全文）

> "The evidence acquisition loop is **the point where the agent decides whether additional evidence is worth obtaining**. At each iteration, **the planner observes the current evidence log, tool-call history, planner trace, available audio artifacts, and available tool inventory.** It then emits **exactly one action type**: call one or more independent tools, request frontend follow-up on selected audio, proceed to final answer generation, or stop with an explicit failure. **Each decision must include a short rationale, which is stored in the planner trace and shown back to the planner in later rounds.** This makes tool use accountable to a stated evidence gap rather than to tool availability alone."

**决策者 = text LLM planner**（MMAR 上为 `qwen3.5-plus`，MSU-Bench 上为 `Gemini 3.0 Flash`，Appendix D，p.13），
以 **native function calling** 发出动作（Figure 1 图形层，p.4）。

### 3.2 "保留前端判断 vs 获取外部证据"的判据来源：前端自报的不确定性

§4.2（p.5）逐字——**这是"证据缺口"这一构念的唯一生成机制**：

> "AUDIO-MIND instead asks the planner to generate a self-contained perception prompt that **restates the question, names task-specific listening targets, and asks the frontend to report uncertainty.** The frontend analyzes 𝒜 under this prompt and returns structured evidence: **a general description, relevant focus points, a preliminary answer when available, and uncertainty or verification needs.**"

> "The planner **treats the frontend caption as evidence rather than ground truth**. It converts the caption into a lightweight plan that records the clarified intent, expected answer format, focus points, and candidate evidence operations. **The plan does not execute tools; it only marks which claims appear answerable by direct perception and which may require verification.**"

§5.3（p.7）明确 planner 看不到什么：

> "**Since the planner has no access to ground-truth labels or baseline outcomes, and only observes the question, frontend-generated evidence, accumulated state, and available tool interfaces**, this alignment suggests that AUDIO-MIND captures a practical, question-level estimate of the frontend LALM's capability boundary through its evidence-gap formulation"

**案例研究给出唯一一次不确定性的数值形态**（Appendix C，p.13，逐字）：

> "under our prompt, the same frontend localizes the two pours at approximately 3–8s and 19–24s, but **marks the raw perceptual evidence as weak**, notes that no clear steam hiss or ice clink is audible, and **assigns only 0.3 confidence to its forced hypothesis**."

Figure 2 源（`figures/case_study_hot_water.tex`，p.13 渲染）逐字：
> "States: ``**acoustic evidence is insufficient**'' and ``**no audible steam hiss**''. Forced hypothesis confidence: **0.3**."

论文自己也把"外部"的含义限死在信号侧。§3 开篇（p.3）逐字：

> "Audio tools play a different role in audio agents than tools usually play in language-only agents. **Rather than only expanding the model's external action space, they often operate on the input signal itself: exposing a partial observation of the audio or reshaping the audio so that a later model or tool can inspect it more effectively.** Therefore, we treat audio tools as **evidence interfaces** rather than unconditional substitutes for the frontend LALM."

→ **本篇的 "external evidence" = 在同一段音频上跑的第三方感知/变换算子；不是外部世界知识，不是外部音频库，不是文档/网页检索。**

### 4.2 两类角色的官方定义（§3.1，p.3，逐字）

> "**Perception tools** extract observations from audio, such as transcripts, speaker turns, temporal boundaries, pitch, key, chords, or spectral measurements. These tools can support an answer when the question depends on a local, symbolic, or measurable cue. **Transformation tools** modify the audio source itself, for example by trimming, denoising, separating, filtering, resampling, or converting channels. **Their output is not usually evidence by itself; rather, it creates a better input for later perception by a tool or by the frontend model during targeted re-listening.**"

### 4.5 逐样本"重听 vs 外部检索"的同尺度比较？——**外源腿不存在，但音频侧有一条二选一**（R2 审计问 4 的直接回答）

**动作空间（§4.3, p.5 逐字，四选一）**：
`① call one or more independent tools` ‖ `② request frontend follow-up on selected audio` ‖ `③ proceed to final answer generation` ‖ `④ stop with an explicit failure`

**判定**：

- **不存在任何"外部检索"动作**（§4.1 的五项零计数）。因此**"重听 vs 外部检索"这条比较轴在本篇上不存在**。
- **但存在一条真实的、逐样本的二选一：`工具处理同一音频` vs `前端在选定/派生音频上重听`**——两者都在 OBS 侧。
- **重听不是通用兜底，且被论文明确限定**。§4.3（p.6）逐字：
  > "Frontend follow-up, or re-listening, is used when the unresolved question is better answered by direct perception on a better-selected input. This is especially useful **after tools create a materially improved artifact**, such as a trimmed segment containing the relevant event, or a separated speaker track that makes the target source easier to hear. … **The system does not use re-listening as a generic fallback; it is reserved for cases where selection or transformation changes what the frontend can perceive.**"
  → **重听在语义上被降级为工具的下游**（先变换、后重听），而非与工具并列的同尺度备选。
- **重听的经验频率极低**。§B.3（p.12）逐字：
  > "Targeted re-listening … is used sparingly: **only 50 out of 999 MMAR questions (5.0%)** trigger at least one re-listen, **for 64 re-listens in total**."
  **本件复算**：50 / 999 = **5.005%**（与论文 5.0% 一致）；64 / 50 = **1.28** 次/触发题；64 相对 1,675 次工具调用 = **3.82%**。
- **因此，可用的对照只有两级**：`现在答` vs `再取证据`（其中"再取证据"内部再分工具/重听两支）。
  **"同一条样本上把重听与外部检索放在同一决策尺度上比"这件事，本篇没有做，也不可能做——它没有外源腿。**

## 5. 证据准入与冲突处置（**R2 审计问 3**）

### 5.1 论文自述的立场：证据不被当作 ground truth——但这是**立场，不是门**

三处逐字：

> "The planner **treats the frontend caption as evidence rather than ground truth**."（§4.2, p.5）
> "we treat audio tools as **evidence interfaces rather than unconditional substitutes** for the frontend LALM."（§3, p.3）
> "**although tool outputs are treated as bounded evidence rather than ground truth, they may still be noisy, domain-limited, or convention-dependent**"（Limitations, p.9）

### 5.2 冲突处置：**显式地不裁决，原样传给前端**（本篇最承重的一句）

§4.4（p.6）逐字：

> "The system then prepares a **neutral evidence summary** that reports observations, **preserves apparent contradictions, and avoids deciding which source is correct**. The audio-capable frontend receives this summary together with the original audio and task context, so the final answer is still grounded in direct listening while being informed by accumulated evidence."

§5.4（p.8）再次确认冲突只被"保持可见"：

> "**it makes the answer path easier to audit because unsupported assumptions, conflicting evidence, and tool-dependent claims remain visible.**"

**判定**：**冲突被保留、被展示、被下传，但不被判定。**裁决权全部下沉到最终那一次前端 LALM 调用（一次不透明的隐式融合）。
**系统层没有任何 accept / reject / 降权 / 回退机制。**

### 5.3 校验器只管格式，明文不管内容（§4.4，p.6，逐字）

> "A separate format checker then validates **only whether the proposed answer follows the expected structure**. **It does not judge content correctness**; it simply returns structural feedback when the answer format is invalid. This prevents formatting errors from being conflated with evidence failures."

### 5.4 全篇唯一的"拒绝"是 schema 级的工具名拒绝（§B.2，p.12，逐字）

> "We also observed **6 invocations of a non-existent tool name (`content`) across 4 questions**; these are **planner hallucinations rejected by the executor** and represent a minor failure mode in tool selection."

**本件复算**：6 / 1,675 = **0.358%** 的调用；4 / 999 = **0.400%** 的题目。
→ **这是"工具名不存在"的执行器拒绝，不是"证据内容不可信"的准入拒绝。**

### 5.5 准入相关的全零清单（本件核定）

| 准入维度 | 本篇是否具备 | 依据 |
|---|---|---|
| 证据真伪判定（accept / reject） | **无**（`admiss*` 全文 0 次；无任何拒绝证据的机制） | §4.3 / §4.4 全文 |
| 与音频的回验（把工具结论拿回音频上验一遍） | **无**（重听是"在更好输入上再感知"，不是"验证已有证据") | §4.3, p.6 |
| 冲突裁决 | **明文不做**（"avoids deciding which source is correct"） | §4.4, p.6 |
| 置信度阈值 / 门控 | **无**（`gating` 词界 0 次；唯一 `threshold` 在工具描述里） | 全文 |

| true / swapped / stale 三态受控实验 | **无**（无注入错证据支、无过期证据支、无 oracle 臂；`oracle` 全文 0 次） | 全文 |
| 工具输出质量的量化报告（WER、DER、tempo 误差…） | **无**——全篇不报任何工具自身的准确度 | 全文 |

## 7. 可审计轨迹：暴露了什么、是决策输入还是仅日志（**R2 审计问 6**）

### 7.1 轨迹的内容（§4.1，p.4–5，逐字）

> "The agent is organized around an **explicit evidence state** that records **audio artifacts, frontend observations, planner decisions, tool outputs, evidence summaries, and format feedback**. Each graph node reads this state, performs one bounded operation, and writes structured updates for later stages."

Figure 1 图形层（p.4）给出状态四槽：> "**audio list** / **evidence log** / **tool call history** / **planner trace**"。

Abstract（p.1）给出对外声明的三样东西：
> "AUDIO-MIND produces higher-quality, auditable reasoning traces that **expose uncertainty, tool evidence, and answer rationales**"

派生物的溯源（§4.2, p.5，逐字）：
> "Each input audio file receives a stable identifier such as `audio_0`, and **any derived artifact created later is appended to the same audio list with its own identifier and provenance.** This lets later decisions refer to original or transformed audio consistently **while keeping the evidence path inspectable**."

### 7.2 **轨迹是决策输入，不只是日志**（明确回答）

§4.3（p.5）两句同时成立：

> "the planner **observes the current evidence log, tool-call history, planner trace, available audio artifacts, and available tool inventory**"
> "Each decision must include a short rationale, which is **stored in the planner trace and shown back to the planner in later rounds**."

→ **理由串（rationale）被写回状态并在后续轮次回喂给 planner** ⇒ 轨迹**同时是审计对象与下一轮的决策输入**。
这是本篇与"只落日志"的可解释性做法的实质差别。

**但须同时记入**：轨迹**不参与最终答案的裁决**——最终答案由前端 LALM 在**中性证据摘要 + 原音频**上生成（§4.4, p.6），
而该摘要**明文不裁决冲突**（§5.2）。→ **轨迹驱动"要不要再取证据"，不驱动"信哪条证据"。**

### 7.3 轨迹质量的量化（§5.4，p.8，逐字）

> "For reasoning-trace quality, we apply **MMAR-Rubrics**, the official instance-level protocol from the **Interspeech 2026 Audio Reasoning Challenge**. It **scores each correct-answer trace by averaging five instance-specific binary criteria and assigns zero to incorrect answers.** Under this protocol, AUDIO-MIND obtains an MMAR-Rubrics score of **66.5%**, compared with **59.6%** for Qwen3.5-Omni."

脚注 2（p.8）逐字：> "**Scores are not directly comparable to the challenge report because we use Qwen3.5 as the judge instead of GPT-4o.**"

**本件复算与三条判定**：

1. 绝对差 = 66.5 − 59.6 = **+6.9 pp**。
2. **该指标对错误答案置零 ⇒ 它是"准确率 × 条件轨迹分"的乘积**。
   剥离准确率后的**条件轨迹分**（本件推导）：Audio-Mind = 66.5/80.4 = **82.71%**；Qwen3.5-Omni = 59.6/78.9 = **75.54%**；
   **条件差 = +7.17 pp**。**标为本件派生值**（前提：两者的 rubrics 与 accuracy 用同一分母；论文未声明 rubrics 用 999 还是 1000，**登记为口径缺口**）。
3. **评审模型 = Qwen3.5**，与 MMAR 上的 **planner（`qwen3.5-plus`）同族、与前端（`qwen3.5-omni-plus`）同族**。
   → **同族自评风险**：论文只声明"与挑战赛报告不可比"，**未讨论评审与被评系统同族这一偏置**。**本件登记为承重威胁。**

## 8. 论文自述的局限与失败模式（**R2 审计问 7**）

### 8.1 Limitations 全文（p.9，逐字）

> "Our evaluation is limited to **MMAR and MSU-Bench**, which cover broad audio-QA and multi-speaker understanding **but do not fully represent real-world uses such as long-form meeting analysis, audio editing, forensic listening, or interactive inspection**. ### 8.2 正文/附录中另行自认的四条失败模式

## 11. DFS 四问

### 11.1 方法

**一句话**：在一个**冻结的 API 前端 LALM** 之上，用一个**同样冻结的文本 LLM 作 planner**，
按**有状态图**把"问题导向感知 → 计划 → 逐轮动作选择 → 证据融合 → 中性摘要 → 前端在原音频上出答案 → 格式校验"串起来；
planner 每轮读证据日志/工具历史/理由轨迹/音频清单/工具清单，**恰好发一个动作**（并行工具调用 / 前端重听 / 出答案 / 放弃），**每个动作必附理由**；
工具是 **38 件全部作用在同一条音频上**的感知/变换算子，按"该输出允许支持何种结论"的 boundary 描述暴露给 planner。

**核心科学主张有两句**：
> "**the key challenge shifts from enabling tool use to determining when agentic evidence acquisition genuinely benefits audio understanding**"（Abstract, p.1）
> "**agentic decomposition can become an orchestration bottleneck when the workflow does not preserve the frontend's holistic audio-grounded judgment**"（Abstract, p.1）

**方法本身的三条特征**：零训练、条件性（31.1% 零工具退出）、前端保留（最终答案永远由 LALM 在原音频上给出）。

### 11.2 局限

**论文自认**：基准覆盖窄（无长会议/取证/编辑/交互）、依赖工具质量（音乐与声学分析尤甚）、额外计算使直连在简单/低延迟场景更优；
另自认深链退化（>10 桶 16.7 vs 50.0，n=6）、planner 工具名幻觉、前端声学幻觉、agentic 分解可成瓶颈。

**本件补记八条**（§8.3）：零成本/延迟数字；零消融；零方差/种子/显著性；零工具质量报告；跨基准前端不同；MSU-Bench 无行为分析；三家 agent 基线跨骨干不可比；三处数字不一致（§6.6）。

**本件另记两条与 R2 直接相关的结构性局限**：

- **证据一旦取回即无条件采纳**：没有任何机制阻止一条错误的 ASR 转写或错误的 tempo 估计进入证据日志并影响最终答案；
  论文的应对是"把冲突留着让前端自己看"，**这把准入问题转成了前端的隐式融合问题，并未消除它**。
- **"boundary" 是提示词层的声明，不是可验证的合同**：`boundary instructions` 只存在于 planner 配置（未公开于正文），
  **无任何实验检验 planner 是否遵守了这些边界**（例如是否曾用转写去回答说话人身份问题）。→ **该设计的有效性在本篇内零实证。**

### 11.3 改进空间

按对 R2 的价值排序：

- **(a) 补上外源腿**。本篇的动作空间在 OBS 侧已经很密（38 件），**SUPPLY 侧完全为空**。
  在同一 planner 决策尺度上加入"取外部知识"分支，即可把"答 vs 再听"升级为"再听 vs 外求"的**双源逐样本选择**；
  本篇的 TABLE 4 分层协议**可以原样复用作对照方法**。
- **(b) 补上证据准入**。本篇把冲突"保留不裁决"。加入 accept/reject（相似度下限、来源可靠度、与音频的回验、top-1/top-2 间隔）
  即可回答"坏证据被挡住能挽回多少"——本篇**连这一档的实验位都是空的**。
- **(c) 构造 true / swapped / stale 三态受控证据**。本篇工具输出的真伪**从不受控**（自然发生、不标注、不分层报告），
  因此"证据质量→最终准确度"这条曲线在本篇内不可测。
- **(d) 补消融与成本**。+1.5 pp（15/999 题）目前无法归因；0 桶的 −0.6 pp 提示提示词重构一支可能为负。
  加上分部件消融 + token/延迟计量，"条件性"这一设计的性价比才可判。
- **(e) 用配对统计重报**。15/999 的配对差须给检验；本篇零显著性。
- **(f) 换非同族评审模型重测 MMAR-Rubrics**。当前评审 Qwen3.5 与前端/planner 同族。
- **(g) 把 boundary 的遵守率变成可测指标**。当前 boundary 只是提示词声明，无遵守率、无越界率。

### 11.4 可借鉴

1. **"按工具调用深度分层 + 同题配对基线"这套行为分析协议直接可搬**（TABLE 4, p.8）。
   它把"框架是不是真的条件性"从设计声明变成可测行为：0 桶 Δ ≈ 0 证明"保留前端"、深桶 Δ > 0 证明"增益集中"、
   **且基线在深桶单调下降本身就是"planner 的证据缺口判断与前端能力边界对齐"的间接证据**。
   R2 若要论证逐样本选择的有效性，**这是本读集内成本最低、说服力最高的一套现成协议**。
2. **"动作必附理由串 + 理由回喂"这一轻量可审计设计**（§4.3, p.5）。
   代价只有若干 token，收益是轨迹既可审计又参与决策；**且它使"为什么这一条要取证据"成为可检查对象**。
3. **"中性证据摘要：保留矛盾、不裁决来源"作为一种明确的设计选择被写清楚**（§4.4, p.6）。
   R2 若采相反做法（显式裁决/准入），**本篇正好是同期、同形态的对照点**，可直接引作"不裁决"一端。
4. **"工具边界"这一概念化**（§3.2, p.3：转写可验词汇内容但不可验说话人身份）。
   即使本篇未实证其有效性，**这套"某类输出允许支持何种结论"的表述本身，是准入机制的自然前置词汇**。
5. **"强前端下 agentic 分解可能是负收益"这一发现的论证形状**（matched-backbone 对照：70.50 vs 78.90）。
   **换强骨干后仍低于直连**是一个极强的反例形状，比"我们更高"更有信息量。

### 12.1 冻结黑盒 omni 核？

- **冻结**：**事实上是**——四个模型全为商用 API 服务模型，无权重/logits/KV 访问。

- **黑盒程度**：机制只写提示词、只读文本与 function-calling 结构化输出（§4.1–4.4, p.4–6）。
  唯一的接口面自证据是 §B（p.11）的 "**API content-safety rejection**"。
- **omni 核**：**是**——MMAR 上前端为 **Qwen3.5-Omni**（`qwen3.5-omni-plus`），MSU-Bench 上为 **Gemini 2.5 Pro (thinking)**；

**时间线相关的一条**：本篇被测的前端为 **2026 年发布的 omni 模型**（Qwen3.5-Omni, arXiv 2604.15804；Gemini 3 Pro 亦在 TABLE 2 出现）。

### 12.2 逐样本双源选择（重听 vs 外部检索）？

**本篇的实际配置**：**存在逐样本选择，但两个选项都在音频侧；外源腿不存在。**

- **决策点存在且是逐样本、逐轮的**：planner 每轮从四类动作中**恰好选一个**（§4.3, p.5）。
  这与"无条件注入"或"整臂开关"是不同的形态。
- **可选动作的实际内容**：
  ① `call one or more independent tools`（38 件，**全部作用于同一条音频或其派生片段**）；
  ② `request frontend follow-up on selected audio`（**在选定/派生音频上重听**）；
  ③ `proceed to final answer generation`；④ `stop with an explicit failure`。
- **不存在的动作**：**任何形式的外部检索**。`retriev*` / `knowledge base` / `external knowledge` / `Wikipedia` / `web ` 全文各 **0** 次；
  TABLE 8 的 38 件工具无一接受外部文档、外部音频或查询串作为输入。
- **①②之间是先后而非并列**：重听被明文限定为工具变换的下游——
  > "reserved for cases where **selection or transformation changes what the frontend can perceive**"（§4.3, p.6），
  且明文 > "**does not use re-listening as a generic fallback**"。
- **两支的经验配比**：工具 **1,675** 次（1.68 次/题）vs 重听 **64** 次（**50/999 题 = 5.0%** 触发）。
  本件复算：重听占两支合计的 **3.82%**。
- **因此，本篇在同一样本上做的比较是"现在答 vs 再取证据"，其中"再取证据"内部再分工具/重听；
  "同一样本上比较重听与外部检索"这一比较在本篇不存在。**

### 12.3 证据准入：true / swapped / stale 的处置？

**本篇的实际配置**：**三类条件均未构造，准入机制不存在。**

| 条件 | 本篇是否构造 | 一手依据 |
|---|---|---|
| **true（真证据）** | **不作为受控条件**。工具输出的真伪**自然发生、不标注、不分层报告**；论文自认工具"may still be **noisy, domain-limited, or convention-dependent**" | Limitations（p.9） |
| **swapped（错证据）** | **不作为受控条件构造**。最接近的读数是 >10 桶的退化（16.7 vs 50.0），论文猜测其一因为 "long tool chains **accumulating noisy intermediate evidence**"，但**不受控、不标注、n=6 且论文自称不下结论** | §B.4（p.12） |
| **stale（过期证据）** | **不存在**。全篇无知识源、无时效概念 | 全篇 |
| **absent（无可用证据）** | **有一个显式动作但几乎不触发**：`Give Up (Exit Loop) — Information insufficient → Phase 5 with FAIL marker`；实测 **999 个 run 中 1 个**走此支，且原因是 API 内容安全拒绝而非证据不足 | Figure 1（p.4）；§B.1（p.11–12） |

**准入机制**：**无**。取回即入库；**不判真伪、不拒绝、不降权、不回验**；
冲突**明文不裁决**（> "preserves apparent contradictions, and avoids deciding which source is correct"，§4.4, p.6），
原样下传给前端做一次不透明的隐式融合。格式校验器**明文不判内容**。
唯一"拒绝"是执行器对不存在工具名的 schema 级拒绝（6 次 / 4 题，§B.2, p.12）。

**须一并陈述的两条**：
- **"Tool boundaries"（§3.2, p.3）是面向 planner 的、声明式的范围约束**（"what kind of claim a tool output is **allowed to support**"），
  实现位置为 planner 配置（Appendix E, p.14），**不是运行期对某条具体证据的真伪判定**，且**其遵守率全篇未测**。
- 论文把"按可靠性分级组织工具"这一做法**明确归给他人**（Multi-Source Evidence Fusion, arXiv 2603.17822, 2026：
  > "combines independent LALM observations with acoustic tools **organized by reliability tiers**"，§2.2, p.3）。

## 14. 深读后新增的、R2 应该知道的事实

1. **本篇的 "external evidence" 与 R2 的 SUPPLY 不是同一件事**。
   38 / 38 件工具**全部只作用于同一条输入音频或其派生片段**；`retriev*` / `knowledge base` / `external knowledge` / `Wikipedia` / `web ` 全文各 **0** 次。
   论文自己把工具定义为 > "they often **operate on the input signal itself**"（§3, p.3）。
   → **本篇占据的是"逐样本决定要不要在同一音频上再取观测"这一格；R2 的双源腿（OBS vs SUPPLY）中的 SUPPLY 侧在本篇完全为空。**

2. **但"逐样本条件性决策"这一格，本篇占得相当满，且是训练自由的**。
   决策者是被提示的通用文本 LLM，每轮恰好一个动作、必附理由、理由回喂；
   信号是**前端在问题导向提示下自报的 uncertainty / verification needs**；
   planner 明确看不到 gold 与 baseline 结果（§5.3, p.7）。
   **实测条件性**：31.1% 零工具退出、平均 1.68 次调用、99.9% 以 ANSWER 退出。
   → **R2 在"逐样本 + 训练自由 + 冻结黑盒前端"这三条上，与本篇高度重叠；差别集中在动作面的构成与准入。**

3. **证据准入这一格是**完全**空的，且是论文的明确设计选择而非疏漏**。
   §4.4（p.6）逐字 > "**preserves apparent contradictions, and avoids deciding which source is correct**"。
   格式校验器明文不判内容。全篇唯一"拒绝"是对**不存在工具名**的 schema 级拒绝（6 次 / 4 题）。
   → **本篇是"取证据但不判证据"的一个明确、同期、可直接引用的对照端点。**

4. **MMAR 上的头条增益 = 999 题中的 15 题（+1.50 pp）**（本件由 TABLE 4 与 TABLE 5 两条独立通道整数重建，结果一致）。
   其中 **+18 题来自 3 与 4–5 两个工具桶**，而 **0 / 1 / >10 三桶合计 −6 题**。
   **报本篇效应时必须同时给出这一分解**，否则"agentic 有效"会被读成全局效应。

5. **底选谁决定了效应量**：以作者自测 Qwen3.5-Omni† 78.90 为底 = **+1.50 pp**；
   以**厂商自报** Qwen3.5-Omni 80.00 为底 = **+0.40 pp ≈ 4 题 / 1000**。
   作者自测比厂商自报低 **1.10 pp**，论文**未讨论这一落差**。
   → **任何"agent 抬升了 X"的跨篇比较都必须声明底是哪一个。**

6. **0 工具调用桶（311 题，31.1%）上，本篇是负的（−0.6 pp = −2 题）**。
   而该桶**并非"直连 LALM"**：它仍走 planner 造感知提示 → 前端感知 → 计划 → 证据摘要 → 前端二次生成 → 格式校验（≥2 次 LALM + ≥4 次 text-LLM 调用）。
   → **实测：这套提示词重构本身在不需要工具的三成样本上是净损的。** 这是本件读数，论文未如此表述，
   但它对任何"结构化提示流水线自带增益"的假设是直接反例。

7. **能力边界是题目相关的、且论文自认无普适最优分工**（Appendix A, p.11 逐字）：
   > "**there is no universally optimal division of labor between external tools and frontend LALMs. The capability boundary is question dependent** … **As both LALMs and specialized tools improve, this boundary may also shift across model generations and task settings.**"
   实测支撑：Music Theory **+15.87**、Anomaly Detection **+17.65**、Temporal Analysis **+14.29** vs
   Audio Difference Analysis **−25.00**、Spatial Analysis **−13.33**、Acoustic Quality **−11.11**。
   **但负向的五个子类里有四个 N ≤ 18**（逐格分辨率 ≥ 5.6 pp），**其上的差异都在 1–2 题量级、不承重。**

8. **重听在本篇被降级为工具的下游，且极稀疏（5.0% 触发、64 次）**。
   论文明文 > "does not use re-listening as a generic fallback"。
   → **"重听"在本篇不是与"外求"并列的一个源，而是"变换之后再感知"的收尾动作。**
   R2 若把重听设为与外部检索同尺度的一支，**本篇不构成该形态的先例**。

9. **本篇的可审计轨迹既是审计对象也是决策输入**（§4.3, p.5：理由串写回 planner trace 并"shown back to the planner in later rounds"）。

   **但评审模型是 Qwen3.5，与 MMAR 的前端与 planner 同族**——论文只声明"与挑战赛报告不可比"，**未讨论同族自评偏置**。
