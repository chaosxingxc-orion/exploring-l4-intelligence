## 1. 方法本质

DPR 用**两个权重不共享的 BERT-base(uncased) 编码器** `E_Q`、`E_P`（各取 `[CLS]` 输出，`d=768`）把 query 与
passage 分别映射进同一个 768 维空间，相似度定义为**点积** `sim(q,p)=E_Q(q)^T E_P(p)`；检索 = 对 21,015,324 段
预计算的 passage 向量做 FAISS（HNSW，CPU）近邻搜索。之所以必须用可分解的相似度（而非 cross-attention），
是为了让 passage 表示能**离线预计算**——这条约束就是"key 必须先于 query 存在"的原理来源。训练是**度量学习**：
对每个 `(q_i, p_i^+)` 最小化正 passage 的负对数似然 `−log[e^{sim(q,p+)} / (e^{sim(q,p+)} + Σ_j e^{sim(q,p_j^-)})]`。
**in-batch negatives 的精确机制**：批内 `B=128` 个 question 与其正 passage 构成 `Q`、`P`（各 `B×d`），
`S=QP^T` 是 `B×B` 相似度矩阵，`(q_i,p_j)` 当 `i=j` 为正、否则为负，于是**一批内复用出 B²=16384 个 (q,p) 对、
每 question 得 B−1 个负例**；最优配置在此之上再加 **1 条全批共享的 BM25 硬负例**（"高 BM25 分但不含答案"）。
下游 reader 是**另一个** BERT-base **cross-encoder**，对 top-k（最多 100）算 passage-selection 分并抽 span，
训练时每 question 采 `m̃=24` 段；retriever 与 reader **分离训练**（§6.2 报告：联合训练 NQ 只有 39.8 EM，
低于分离的 41.5）。

## 2. key-value 定位（本条为 R2 承重点）

| 维度 | 事实 |
|---|---|
| **检索单元（value 的粒度）** | 2018-12-20 英文 Wikipedia，DrQA 预处理去表格/信息框/列表/消歧页，切成**100 词不重叠**文本块，共 **21,015,324** 段（§4.1） |
| **value 的实际内容** | 该 100 词 passage 原文，**前缀 Wikipedia 文章标题 + `[SEP]`**（§4.1）。即 value 从一开始就携带一个**弱出处字段**（文章标题）；除此之外无版本、无 URL、无冲突标记、无引用支持、无 abstain 字段 |
| **key 的内容** | `E_P(title ⊕ [SEP] ⊕ passage)` 的 `[CLS]` 向量，768 维。**标题同时进 key 与 value** |
| **key 与 value 的关系** | **key = value 文本的确定性函数**；每个 value **恰好一个 key、单面**。key 与 value **没有独立的装载自由度**——不存在"把 A 面信息放 key、把 B 面信息放 value"的设计空间 |
| **key/value 的角色分离（R2 措辞的真实成立面）** | 成立：索引里存的是向量（检索头，供 MIPS），reader/上下文消费的是原文（内容头）。**分离的是表示与阶段角色，不是信息内容** |
| **key 空间是学出来的** | 立论前提就是"ORQA 之前稠密检索从未打赢 BM25"（§1）；DPR 的贡献即证明**只用 (q,p) 对微调双编码器**就够。样本效率（Figure 1）：**1,000 条**训练样本即超过 BM25，1k→59k 继续单调改善。→ 门槛低但**非零**，"未经检索目标训练的编码器空间可检索"在本文中**无证据** |
| **key 与 value 之间的第三段** | BERT cross-encoder reader/reranker（§6.1）。它是"**选**"不是"**拒**"：无 abstain、无冲突处理、无来源质量分级。R2 §1.3 意义上的**准入门在 DPR 中不存在** |
| **多面 key** | **无**。DPR 无"同一 value 多层/多粒度/多模态 key"的任何形态 |

## 4. DFS 四问

**方法**：用两个不共享权重的 BERT 编码器 + 点积 + in-batch NLL 度量学习，把 query 与 passage 训练进同一个可
MIPS 检索的 768 维空间；核心洞见是"稠密检索不需要额外预训练目标（ICT），只需要正确的负例构造"，最终配置
= 批内 gold 负例 + 1 条 BM25 硬负例。

**局限**：(a) key 单面且是 value 的确定性函数，没有任何"装什么进 key"的设计自由度；(b) key 空间的可检索性
**必须靠检索目标训练**，且负例构造是主导杠杆（Table 3），因此在"不许训练"的约束下这条杠杆完全不可用；
(c) 稠密检索有明确的失效域——问题与 passage 词面重叠高、语料域窄（SQuAD 全面输给调优 BM25）；(d) 无准入、
无 abstain、无冲突处理，reranker 只做排序不做拒绝。

**改进空间**：DPR 明确留下"同一 value 只能有一个 key"这一空位——2024 年后 GraphRAG 的社区摘要 key、层次索引、
视觉域的 element/scene 两级证据单元填的都是这个位。另一空位是 reranker 与准入门之间的落差：把
passage-selection 分从"排序信号"升级为"接纳/拒绝/标冲突"的判定量，是 R2 杠杆二的直接前身形态。

**可借鉴**：① in-batch negatives 与 hard negative 的效果分解（Table 3）作为"key 质量由负例构造决定"的量化
论据，用于论证 R2 红线下 key 侧杠杆的**先天缺失**；② 调优 BM25 的报告纪律（b=0.4、k1=0.9，dev 上调；混合
按 `BM25(q,p)+λ·sim(q,p)`、λ=1.1 重排 top-2000 并集）——R2 §3.4 的稀疏对照臂可直接照抄该协议；③ §5.4 的
"构建贵/查询便宜（稠密）vs 构建便宜/查询贵（稀疏）"两侧数据，作为 R2 §6.5 第九维 `index/snapshot amortized`
的口径先例。

### 5.2 深读后新增的、R2 应该知道的事实

1. **「未经检索目标训练的 embedding 空间不可检索」在文本域有对称证据，且这是对 O2 的硬约束**。R2 §2.2 已
   引 SpeechDPR 的负面读数（去掉蒸馏后检索率崩到 0.04%）；DPR 给出正面侧的下界（1,000 条 (q,p) 对即超 BM25，
   Figure 1）与立论前提（ICT 之前稠密从未赢过 BM25）。两侧合起来的结论：**key 空间的可检索性来自检索目标
   训练，不是编码器"有语义"就自动具备**。→ R2 §3.4 的 O2 计划用 emotion2vec / audio2vec 一类**冻结检查点**
   充当副语言面/场景面的 key，而这些检查点**不是以检索目标训练的**，其"近邻即检索"性质在本地读集内**零证据**。
   建议在 §3.4 的 O2 构建约束里**加一条前置检定**（与 K5 的两条专属前置并列）：每个候选面先在锚数据集上跑
   「该面 key 的可检索性」读数（该面 query 能否把目标 value 排进 top-k，对照同面随机基线），不过关则该面
   不入 O2。否则 K5-r 的负读数将无法区分"多面 key 无用"与"该面编码器根本不是检索空间"。
2. **key 质量的主导杠杆是负例构造，而 R2 拿不到它**（Table 3）：批内负例把 top-5 从 42.6 抬到 51.1，负例
   数 7→127 再抬到 55.8，**单条 BM25 硬负例再抬 +10 到 65.8**（第二条无用）。→ R2 红线禁训练 ⇒ 只能继承
   已发布检查点里固化的负例分布。这不是 R2 的缺陷，但**必须在 §3.4 诚实声明**：O1/O2 的对照是"两种冻结
   key 装载"的对照，**不是** key 表示质量上限的对照；文本域达到的 key 质量有相当一份来自 R2 结构上无法
   复现的训练杠杆。
3. **调优稀疏基线会赢，且失效条件恰好命中 R2 的 T2 锚**：DPR 把 BM25 调参（b=0.4、k1=0.9，dev 上调），
   **SQuAD 上 BM25 全面反赢**（top-20 68.8 vs DPR-multi 51.6；端到端 EM 38.1 vs 24.1）。作者归因两条：
   标注者**看着 passage 写问题**导致词面重叠高；语料仅来自 500+ 篇文章、分布极偏。→ **R2 §5.1/§6.1 的 T2
   锚 Spoken-SQuAD 正是 SQuAD 派生**，属 DPR 明确指出的稠密检索劣势域。这对 K5 的专属前置 ㈡（"O1 单面 key
   的 R@k 距天花板须有预注册余量"）是一条具体风险：**在 Spoken-SQuAD 上调优稀疏基线可能本就很强、稠密单面
   key 本就不占优**，于是 O2 的"多面稠密 key"要同时打赢一个在该域天然强势的稀疏基线。建议 R2 在 §3.4/§5.4
   就地记入，并优先考虑 SLUE-SQA-5（非 SQuAD 派生）作为 O 臂主锚。
4. **分离训练优于联合训练（与 RAG 方向相反）**：§6.2 报告 NQ 上联合训练 retriever+reader 得 **39.8 EM**，
   低于 DPR 的分离 pipeline **41.5**。而 RAG（2005.11401）的 Table 6 显示联合微调检索器**有**收益。
   → "端到端联合"并非普遍占优；R2 采用"全栈冻结 + 外显确定性控制面（不联合训练任何东西）"在 pre-2024
   有一个**正面先例**，可用于回应"为什么不端到端"的评审质询（附带 RAG 的反向读数以保持诚实）。
5. **组织成本的两侧口径先例**（§5.4）：稠密=构建贵（21M 段嵌入 8 GPU×8.8 h + FAISS 建索引 8.5 h）/查询便宜
   （995.0 q/s，CPU，top-100）；稀疏=构建便宜（Lucene 倒排 ~30 min）/查询贵（23.7 q/s/线程）。
   → R2 §6.5 第九维 `index/snapshot amortized` 与 §3.4「O2 的库构建成本按该维计入」的量级参照；且提示
   **O2 造 N 个面的 key，构建维成本按面数近线性放大而查询维几乎不变**——这条结构性事实应在 O 臂预算
   预注册里写明。
6. **口径瑕疵（非承重，但须挡住误引）**：§1 引言的头条数字 "**65.2% vs. 42.9% in Top-5 accuracy**" 在正文
   **无对应表**——论文所有检索表只报 top-20/top-100（Table 2）或 dev 的 top-5/20/100（Table 3）。eprint 里
