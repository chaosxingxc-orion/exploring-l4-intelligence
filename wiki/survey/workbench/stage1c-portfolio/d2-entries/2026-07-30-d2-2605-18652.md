## 1. 方法本质

MementoGUI 把长程 GUI 控制**从上下文长度问题重构为在线记忆控制问题**：给一个**冻结**的 GUI
动作骨干 π_B 外挂一个记忆控制器 MementoCore，控制器由**四个 task-specific LoRA adapter 挂在共享
冻结 Qwen3-VL 上**实现，对应 Step Processor / WM Compressor / Episodic Writer / Episodic Selector。
每步 Step Processor 一次前向输出四元组 `(o_t, s_t, b_t, γ_t) = f_step(g, x_t, a_{t-1}, W_{t-1})`：
`o_t∈[0,1]` 是写入显著度、`s_t` 事件摘要、`b_t` 任务相关 ROI 框、`γ_t` 是否需要 episodic 检索。
工作记忆**仅当 `o_t > τ` 时追加**（Eq. wm_update），超容量时由 WM Compressor 合并旧条目。
情景记忆在 t=1 初始化，**此后仅当 `γ_t = 1` 才刷新**，否则 `R_t = R_{t-1}`（Eq. em_update）——
检索上下文被**冻在原地**。检索本身两级：先用当前截图+目标做嵌入粗检 TopK，再由 Episodic Selector
做多模态相关性筛选后才注入。记忆以骨干原生 chat template 序列化为普通文本 + ROI 图像，
**无新增 token、无投影层、无架构改动、无动作骨干微调**。控制器训练 = 从 PSAI computer-use 轨迹
自动策划的 SFT 数据（四个算子各一套），再对 Step Processor 与 WM Compressor 追加 DPO。

## 2. 三轴定位

**门控信号是什么**：**两个来自同一次训练过控制器前向的学习标量**：
(a) 写入显著度 `o_t ∈ [0,1]`，门控工作记忆的写入；
(b) 二值 `γ_t`，门控"本步是否重新跑一次 episodic 检索"。
两者都条件于 `(g, x_t, a_{t-1}, W_{t-1})`——目标 + 当前截图 + 上一动作 + **已累积的工作记忆**。
论文原话点出这一闭环："allowing the accumulated working memory to gate when retrieval is
invoked."（累积的内部状态决定何时去外部取）。与 cotomi 的 LLM 自由裁量截然不同：这里是可读出的
标量/标志，且"episodic-retrieval activation tags"是**显式监督目标**。

**决策规则训练还是规则**：**训练**，而且训了两道——SFT（importance score 与 retrieval activation
tag 都是监督目标）+ DPO（只给 Step Processor 与 WM Compressor，理由是这两个算子"直接在信息量与
上下文预算之间取舍"；Episodic Writer/Selector 有直接监督目标故只 SFT）。写入门在学习标量之上再叠
一个**确定性阈值 τ**——即架构恰好是"学习标量 + 固定阈值"，正是 R2 控制器想要的形状；
但**它依赖标注监督，故不是 training-free**。

**作用在哪道门**：**两道门都有**，这是本篇最有价值的结构。
- `γ_t` = **采集门**：在付出检索代价之前决定要不要刷新。注意其被门控的对象不是"首次获取"，
  而是**对已持有上下文的刷新（refresh）**——这在 R2 的采集门定义里是一个尚未单列的子类。
- Episodic Selector `f_sel` = **准入门**：嵌入粗检出来的候选，先过一道学习的多模态相关性筛选
  **才注入**上下文。
- `o_t/τ` + WM Compressor = 第三类：对 **agent 自身观测流**的写入侧/保留侧闸门（对自产证据的
  准入，不是对外部证据的准入）。

## 4. DFS 四问

**方法**：在冻结动作策略之外，用训练出的**逐步标量门**（写入显著度 + 检索刷新标志）把交互历史
从被动上下文改造为主动管理的决策层，并对取回的情景记忆加一道学习的准入筛选；全部以原生多模态
prompt 接口注入，不动骨干。

**局限**：(i) **不是 training-free**——四个 LoRA + SFT + DPO，需要自动策划的监督，无法照搬到 R2
的 API-only 冻结核；(ii) **`γ_t` 与 `τ` 从未被单独消融**——全篇没有"always refresh / never refresh
/ γ-gated"三臂对照，所以**刷新门本身没有孤立的效果测量**（论文的证据是"怎么选"即 two-stage vs
single-stage vs random，不是"要不要刷"）；(iii) 轨迹成功率绝对值极小（1.29 → 3.57%），头条
"+32.71%" 相对增益建立在约 2 pp 绝对值上；(iv) 自家 bench 上的 VAM 回退（UI-Venus No History
最优）未被讨论；(v) 离线 reference-based + LLM-judge 评测，无在线环境执行；(vi) 主表不含控制器
自身推理的成本记账（只有 Table 2 / Table 5 报 token 与时延）。

**改进空间**：缺失的 γ 消融恰恰是 R2 能做且必须做的实验——固定 selector、只变刷新策略
（always / never / gated），报答案改变率。另一处：`o_t` 是**显著度**分数而非 value-of-information
分数，它从不问"写下这条会不会改变动作"；把门控信号从"这条重要吗"换成"这条会改变决策吗"是
reward-guided 估计量的空位。

**可借鉴**：(a) **三臂检索消融设计**（random context / single-stage / 学习 two-stage，全部对齐到
一个"不检索"的 WM-only 参照）是三篇里最干净可移植的协议——它把"无条件检索比不检索更差"变成
**被测量的陈述**而非断言，正是 R2 准入门需要的臂结构；(b) **把"刷新"与"首次获取"当作两种不同
动作**——R2 的 re-resolve 在结构上就是对**已持有观测的重呈现**（R2 §1.3 第②类信息作用），
MementoGUI 的 `γ_t` 因此比任何 tool-call 门（ToolGate/FOVEA）都更贴 R2 的重听动作机制位；
(c) plug-in-onto-frozen-backbone + 记忆以原生 chat template 序列化 = R2 在 API-only 约束下可用的
接口形状。

## 5. R2 定位句核查

**R2 §4.2 原句（L414-415）**：
> "MementoGUI 2605.18652 连'检索刷新'本身都被门控；"

**判定：CONFIRMED**（机制层），附两条加强与一条必须声明的限制。

- **机制字面确认**：Eq. `em_update` 即 `R_t = R̃_t if t=1 or γ_t=1, else R_{t-1}`，`γ_t` 由
  Step Processor 输出；论文原话："Unlike static retrieval, MementoGUI initializes episodic
  context at the first step and **refreshes it only when γ_t=1**"，以及"allowing the accumulated
  working memory to gate when retrieval is invoked."
- **加强 1（轴位）**：该门是**训练出来的标量/标志（SFT+DPO）**，不是 prompt 级裁量——它应落在
  R2"决策规则=训练"一侧，与 cotomi 的 LLM 裁量形成对照。R2 §4.2 现把两者放在同一 bullet 而不
  区分，建议内部分档。
- **加强 2（门位）**：MementoGUI 还有一道**真正的准入门**（Episodic Selector 在注入前筛掉嵌入
  检索的候选），所以它是**双门系统**。R2 §4.4 的 M1 行（"pre-call 准入门（证据进上下文前拒绝）|
  ToolGate"）可以补上第二个、独立的跨域实例，且这个实例带"不检索"参照臂。
- **限制（一旦升格到效果层必须声明）**：`γ_t` **从未被孤立消融**。可用的效果证据是 Table 4
  的**选择质量**（filtered > unfiltered > 部分情形下的 no-retrieval），不是"门控刷新胜过总是刷新"。
  R2 若把本引用从机制层升到效果层，只能引 Table 4，且必须改述为"检索**筛选**的质量决定检索是
  净正还是净负"。

### 深读后新增的、R2 应该知道的事实

1. **Table 4 是视觉域一个现成的"无条件检索 = 净负"数据点，而且带"不检索"反事实臂**：
   Random Episodic Context（64.46/2.22）与 Single-stage Retrieval（64.40/2.33）在 UI-Venus-1.5-8B
   上**双双低于 WM-Only（67.69/2.69）**；GUI-Owl-1.5-8B 上 Single-stage 的轨迹成功率（1.19）
   低于 WM-Only（1.40）。这比 ToolGate 的基率论证**更强也更干净**，因为反事实臂在场。
   R2 §4.1"无条件检索是默认失效模式"与 §4.4 的 M1 行都可引用。
2. **No History 在若干基准×骨干格子上直接胜出**（MM-Mind2Web + GUI-Owl-1.5-8B：17.78 优于全部
   记忆变体；MementoGUI-Bench VAM + UI-Venus-1.5-8B：No History 1.80 = 最优）。"历史/记忆不免费"
   在主张记忆有用的论文**内部**复现——这是 R2 §4.1"更相关 ≠ 更好"的又一独立证据。
3. **同一记忆上下文在两个 API 核上符号相反**（Table 2：GPT-5.5 VAM −16.41% vs Gemini-3.1-Pro
   VAM +18.81%）。直接支持 R2 的载体纪律（口径不得串用），也警告任何"注入策略跨核泛化"的主张。
4. **"刷新"≠"首次获取"——这是 R2 目前没有利用的机制位匹配**：R2 的 re-resolve 是对已持有观测的
   重呈现（§1.3 第②类），MementoGUI 的 `γ_t` 门控的正是这一结构类（刷新已持有的情景上下文）
   而非首次工具调用。建议 R2 §4.2/§4.4 显式记这一条：**跨域已有"刷新门"先例，且它是训练出来的；
   R2 的独立性主张应落在"训练无关地做同一件事 + 用感知不确定性信号驱动它"，而不是"首次提出刷新
   要被门控"。** 这同时收窄了 R2 可主张的新颖面，必须写进 prior-difference 记账。
5. **控制器规模非单调**（Table 5：WM-only AMS 67.69/67.82/67.38 对应 2B/4B/8B）="门更强 ≠ 结果
   更好"，是对 R2 估计量容量论证的警示。反面：8B 的 WM+EM 端到端**比** 8B 的 WM-only **更快**
   （56.20 s vs 72.47 s）——更好的门可以靠缩短轨迹自付成本，这个成本记账形状 R2 预算章可用。
6. **训练依赖对直接移植是否决性的**：四个 LoRA adapter、SFT（PSAI 自动策划）+ DPO。R2 只能把它
   引作**机制位/协议 donor**，不得引作 training-free 先例。
