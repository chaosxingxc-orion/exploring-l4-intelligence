## 1. 六字段方法卡（对齐 R2 §2.1/§2.2 口径）

| 字段 | 事实 |
|---|---|
| **组织** | **无持久知识组织**。不存在语料库、索引、key/value、快照、出处 schema、版本或冲突标记。所谓"工具库"是 6 个**对当前音频现算**的函数（Table 1）：T1 ASR=Whisper-large-v3；T2 情感识别=emotion2vec_plus_large；T3 和弦识别=madmom；T4 速度估计=librosa beat_track；T5 音高跟踪=librosa piptrack；T6 声音分类=AST。工具集大小 K=6 固定（§3.1）。工具输出为结构化 JSON（附录 B：ASR 纯文本串、情感单标签、和弦 `{timestamp,[value]}` 序列、tempo 单标量如 `"117.19"`、pitch `{timestamp, f0}` 序列、声音分类逗号分隔标签串）。**没有任何外部知识源**——无 web、无检索器、无文档、无 KB。 |
| **供给** | **单次单跳、无预算、无停止问题**。一个可训练的 Audio Tool Agent `π_θ(t\|s)` 接收 `(x_a, x_q)`，一次性输出工具索引子集 `z ⊆ {1..K}`（§3.1），执行后交冻结 Reasoner 作答一次。Algorithm 1 写成"抽单个工具"，§3.1 与 Table 4 的 `Avg. Tools`=1.30 表明实际是子集（**内部口径不一致，见 §5 严谨性备注**）。**无多轮循环、无 hop 计数、无停止判据、无预算维度、无 abstain**。决策由 **RL 学出**（GRPO），不是规则、不是阈值、不是价值估计。预算形态：唯一的量化成本是消融表里的 `Avg. Tools`（Table 4）。 |
| **使用** | **无条件拼接**。工具输出直接进 Reasoner 提示词（附录 A.3：`Extra information from the audio analysis: {chart-table-info here}`）。**无准入门、无冲突处理、无来源质量、无引用归因、无 abstain 分析、无候选区**。Reasoner 提示词强制 `<answer></answer>` 单标签输出。基线 Reasoner 提示词（附录 A.4）不含额外信息。 |
| **changed vs held-constant** | **changed（训练对象）= 且仅 = Agent 策略 `π_θ`**：以 Qwen2-Audio-7B-Instruct 初始化（§4.2），GRPO（shao2024deepseekmath），TRL 框架，8×A100，per-device batch 8，200 steps，lr 1e-6，temperature 1.0，group size **G=6**，AdamW。数据=AVQA 音轨（yang2022avqa），按 R1-AQA 协议把问题里的 "video" 改成 "audio"，**随机子采样 2,025 条**（R1-AQA 用全量约 38k）（§4.1）。奖励 = `r_i = I(ŷ_i=y*) − I(y_base=y*) ∈ {−1,0,1}`（式 1）；GRPO 组内标准化 `Â_i=(r_i−mean)/std`（式 2）+ PPO clip + 对 `π_ref` 的 KL（式 3）。**held-constant（冻结）**：Reasoner 全程冻结（§3 首段"the underlying reasoning backbone remains frozen throughout the process"），实例=Qwen2-Audio-7B-Instruct 或 GPT-4o Audio；六件工具全部为**已发布现成组件**，不训练；工具库组成、提示词模板固定。**UNVERIFIED**：未说明 `π_θ` 是全参微调还是 PEFT/LoRA（只给 TRL+lr 1e-6+200 steps）。 |
| **runtime-visible vs gold-only 信号** | **推理期可见信号极窄**：`π_θ` 的输入只有 `(x_a, x_q)`（附录 A.2 提示词）。**没有**不确定性信号、自一致性/众数计数、候选答案探针、重呈现一致性、检索反馈、冲突计数、来源质量——即比 R2 §6.2 的 `V̂` 族**更少**的运行时输入。**gold-only 信号全部在训练期被吃进权重**：奖励的两项都需要 `y*`（gold），且 `y_base` 需要一次额外的冻结 Reasoner 调用。**oracle 行显式为 gold-only 事后量**：Figure 2 的 "Theoretical Upper Bound"=`a post-hoc metric counting a sample as correct if any individual tool succeeds`（§2），论文诚实标注为单工具选择的天花板。→ **信息边界结论：AuTAgent 把 gold 依赖搬进训练期权重；部署期决策信号比 R2 更贫。这正是两条路线的分界线。** |
| **数据/基线/指标/成本** | 见下 §2 逐数还原。指标=MCQ accuracy（§4.3）。基准=MMAU test-mini（sakshi2024mmau）与 MMAR（ma2025mmar）。**成本记账仅一维**（`Avg. Tools`，Table 4）：**无** wall-clock、latency、token、API 花费、显存、推理调用数记账；训练成本只给硬件与步数，**未记 reward 生成开销**（每样本每步 = 1 次 baseline Reasoner 调用 + G=6 次 (工具执行 + Reasoner 调用) = 7 次 Reasoner 调用/样本/步；GPT-4o-Audio 监督变体意味着付费 API 参与 RL 奖励，论文零记账）。 |

## 3. DFS 四问

**方法**。AuTAgent 把"音频工具选择"形式化为一次单步动作选择，用 GRPO 训练一个**独立的**策略模型
`π_θ(t|s)`（Qwen2-Audio-7B-Instruct 初始化），Reasoner 全程冻结；奖励是**基线相减的差分奖励**
`r=I(ŷ=y*)−I(y_base=y*)∈{−1,0,1}`（式 1）——只有"基线错、用工具后对"才给 +1，"基线本来就对"给 0（哪怕用工具也对），
"基线对、用工具后错"给 −1。2,025 条 AVQA 样本、200 步即收敛。解耦设计带来 plug-and-play 迁移性
（Table 3）。它的定位在其自述 §6 里写得很清楚：音频域的 tool-augmented agent 此前"largely heuristic"
（AudioGPT/HuggingGPT/ReAct 一类 training-free 调度），而视觉域已有 VisTA 用 RL 优化工具使用策略——
**AuTAgent 是 VisTA 的音频移植**（与 R2 §4.3 读出的 "AudioRAG 即 WebThinker 的音频移植" 同构）。

**局限**。① **它自己的数据不支持"学会不调用"这一叙事**：差分奖励的 Reward=0 分支本应教会在简单题上弃用工具，
但 Figure 4 显示 No-tool 从 234 掉到 41（−82%），`Avg. Tools`=1.30>1.0——**训好的策略几乎总要调至少一件工具**；
论文把这解读为优点（"learned preference for verifiable acoustic details"），而它与"抑制冗余"的宣称在方向上相反。
它真正学到的是**选哪件**，不是**要不要**。② **完全没有停止/预算/多轮问题**：Algorithm 1 单次采样-执行-作答，
不存在 hop、停止判据、预算分配，因此没有 over-search 轴，也无法验证任何"何时停"的机制。③ **使用端零机制**：
工具输出无条件拼接（附录 A.3），无准入、无冲突、无归因、无 abstain；All-Tools −9.1 pt 这个失效面它是靠
**换掉供给**（少选工具）绕开的，而非在使用端处理。④ **成本记账只有一维**，训练期奖励生成开销（含 GPT-4o
监督变体的付费 API 调用）零记账。⑤ **对照臂的信息量不对等**（严谨性问题，见下）。⑥ 载体窄：只有 MMAU
test-mini（n=1000）与 MMAR，无 CI、无多 seed、无 split 说明、无统计检验。

**严谨性备注（本件在 LaTeX 源里发现的四处，供 R2 引用时避坑）**：
- **A. 对照臂提示词信息不对等（最重要）**：`Tools w/ Desc.` 提示词（附录 A.1）给出六件工具的**完整功能描述**；
  而 `AuTAgent Prompt`（附录 A.2）的工具位被写成 `0: type1 (A) … 5: type6 (F)`——**无任何语义描述**。若这是
  论文的删节，属排版问题；若这是真实训练提示词，则"trained vs prompted"的对比**同时**变动了训练与提示词
  可见信息量，不是干净的单因素消融。论文未做任何说明。→ 标 **UNVERIFIED**，两种读法都要在引用时声明。
- **B. Algorithm 1 与 §3.1/Table 4 口径不一致**：Algorithm 1 写 `Sample tool: z^(g) ~ π_θ` / `o^(g) ← t_{z^(g)}(x_a)`
  （单个工具），§3.1 写 `a discrete combination of selected tool indices z ⊆ {1,…,K}`（子集），Table 4 的
  `Avg. Tools`=1.30 支持子集读法。算法框是简化写法。
- **C. Algorithm 1 的 advantage 与式 2 冲突**：算法框写 `Compute Advantage: A^(g)_i ← r^(g)_i`（原始奖励直接当
  advantage），式 2 写组内标准化 `(r_i−mean)/std`。二者不等价。
- **D. 正文数字与表格不一致**：§5.1 正文称 GPT-4o 上 "improved to 66.80% and 63.00%"，但 Table 2 的
  `AuTAgent (Ours)` 行是 **67.20 / 63.00**，66.80 是 Table 3 的 **Plugin** 数；§1 引言又称 "achieve 66.80% on
  MMAU Test-mini and 62.80% on MMAR"（=Plugin，与 Table 3 一致）。→ **引用时必须区分 Self（67.20/63.00，需用
  GPT-4o 反馈做 RL，成本高）与 Plugin（66.80/62.80，Qwen2 反馈训练后直接插）**，不得混用。
- （另：源文件含一张被注释掉的 `tab:policy_robustness` 草表，其 GPT-4o 分项与 Table 2 不完全对齐且含
  `±0.XX` 占位符——**草稿残留，不可作为证据**，本件不引用其数。）

**改进空间**。① 最大的空位是**把差分奖励从训练信号改成推理期决策量**：净增益 `Δ=I(用工具对)−I(基线对)` 的
**离线**版本可以在 dev 上按 (工具, 题型/音频类别) 逐格测出边际效用，再用确定性优先序在部署期选工具——
论文的 Figure 2（逐工具边际）+ Figure 4（提示词分布与边际效用错配）已经把这个 training-free 方案的两块料
都摆出来了，却从未测试它。**Table 4 的分解（训练本身只买 0.20 pt，2.80 pt 来自净增益目标）恰恰说明这条路
大概率可行。** ② 缺 abstain/准入：All-Tools 的 −9.1 pt 完全没在使用端被处理。③ 缺多轮与停止：单步框架下
"该不该再看一次"无法表达。④ 缺成本-效果面：`Avg. Tools` 一维不足以支持任何效率主张。⑤ 缺统计基建（CI、
多 seed、multiplicity）。

**可借鉴**。① **六件冻结工具栈 + 其 JSON 输出 schema（Table 1 + 附录 B）**：全部现成已发布组件，直接落在 R2
§1.4 许可的"工具级冻结组件"内，可原样搬（尤其 emotion2vec_plus_large——R2 §3.4 的多面 key 提案里点名要用的
正是这一类，此处有已发表的用法与输出格式先例）。② **差分/净增益量的形式**：`r=I(ŷ=y*)−I(y_base=y*)` 与 R2
§6.5 的 `delta_E = U(M(x,q,E),y) − U(M(x,q),y)` **是同一个量**——R2 应把它作为音频域先例引证（谱系 credit），
差别在于 AuTAgent 用它做训练奖励、R2 用它做评价指标与离线标定目标。③ **对照臂设计**：`Vanilla / Random
Selection / All-Tools / Tools w/ Desc. / Ours` 五行结构，与 R2 §5.3 的 `always/never 角点 + random-matched-cost
+ 最强固定档` 同构，可作已发表的对照结构先例。④ **oracle 行的写法**：Figure 2 的 Upper 是"已执行动作池上的事后
最优"，与 R2 §6.1 **A6 臂**定义完全同型——A6 有了音频域的已发表先例。⑤ **Binary-vs-Differential 消融范式**：
把"目标函数"单独消融出来，是 R2 论证"决策目标 > 是否训练"的现成方法论模板。

## 4. R2 相关性判定

### (a) 红线关系

**它训练了什么**：训练对象 = 一个**独立的 Audio Tool Agent 策略 `π_θ`**（Qwen2-Audio-7B-Instruct 初始化），
算法 = GRPO + 基线相减差分奖励，数据 = AVQA 子采样 2,025 条，8×A100 / 200 steps / G=6（§4.1、§4.2、Algorithm 1）。
Reasoner **不训练**（§3 首段明写冻结）。

**对 R2 三条红线（§1.4）的逐条判定**：

| R2 红线 | AuTAgent | 判定 |
|---|---|---|
| ① 不修改冻结核参数 | Reasoner 参数全程不动 | **满足**（就 Reasoner 而言） |
| ② 不为本任务新训练任何模型 | 为本任务 GRPO 训练了 `π_θ` | **违反** |
| ③ 不新增 LLM 代答 | `π_θ` 只输出工具索引，最终作答权在冻结 Reasoner | **满足** |

→ **按检索线（SpeechDPR/SpeechRAG/WavRAG）先例处置：方法论基线、组件不可搬。** 不可搬的具体对象 =
**`π_θ` 策略检查点**（其决策能力由 gold-驱动的 RL 训练产生，搬进 R2 即违反红线②）。

**可作冻结工具的已发布产物**：

- **可搬（高价值）**：**六件工具栈全部是第三方已发布的冻结组件**——Whisper-large-v3、emotion2vec_plus_large、
  madmom、librosa(beat_track / piptrack)、AST（Table 1），加上附录 B 的六套输出 JSON schema、附录 A 的四套
  提示词模板。这些**本来就在 R2 §1.4 的许可清单内**，AuTAgent 提供的是"已发表的组合用法 + 输出格式 + 逐工具
  边际效用读数"。
- **不可搬**：`π_θ`（RL 训练产物）。
- **无新 benchmark**：只用既有 MMAU test-mini / MMAR / AVQA，未发布新数据集。
- **检查点/代码发布状态 = UNVERIFIED**：作者列表里给了项目页 `tongsiqian.github.io/AuTAgent`；论文正文
  **没有任何** code/checkpoint/data release 声明（ICML 模板的 "Software and Data" 节被注释掉了）。**本任务零网络
  请求，无法核实**；发布状态核查应并入 R2 §9 的"三篇检索线检查点发布状态核查"同一条 authorization 义务。
  即便发布，`π_θ` 也不可用（红线②：它是"为任务训练的策略"，不是通用工具）。

### (b) 对 R2 独立性的威胁面

**b1. 调度决策是学出来的还是规则的？** **纯 RL 学出**（GRPO，§3.2）。推理期没有任何阈值、价值估计、
不确定性信号——`π_θ` 就是一个吃 `(x_a,x_q)` 吐工具索引的黑盒策略网络。→ **它不占据 training-free 控制面这个
方法位**，一次都没试过确定性/阈值/校准型的 training-free 调度（它的 training-free 对照臂只有"给描述让 LLM
自由选"这一种最弱形态）。

**b2. 它是否已经占据"audio 工具调度"的方法位？** **部分占据，边界清晰**：

| 方法位 | AuTAgent | R2 |
|---|---|---|
| 选哪个动作（工具身份） | **占据**（trained，单步） | A4 臂族的一个维度 |
| 要不要获取（skip/abstain） | **未占据**——Figure 4 显示 No-tool 234→41，`Avg. Tools`=1.30，策略几乎总调用 | R2 §6.2 `max V̂ ≤ τ → ANSWER/STOP` |
| 何时停（多轮） | **不存在该问题**（单步框架） | K2 over-search 判据 |
| 预算分配 | **不存在**（无预算维度） | 分维预算 `b_t` |
| 感知/知识双源分配 | **不存在**（无知识源，只有感知工具） | **R2 主杠杆、A4b−A4a 差分的定义所在** |
| 证据准入/冲突/abstain | **未占据**（无条件拼接） | 杠杆二 + K4 |
| 外部知识获取 | **完全不存在** | R2 的研究对象本体 |

**b3. 最关键的边界：它根本不在 R2 的研究对象域内。** 按 R2 §1.3 的四类信息作用，AuTAgent 的六件工具**全部**
产出**对同一段音频的重表达**（第②类：ASR 转写、情感标签、和弦序列、BPM、f0、事件标签），**没有一件引入外部
新信息**（第①类）；MMAU/MMAR 的答案由音频本身决定，不需要任何外部知识。→ **AuTAgent 占据的是 R2 里
`RE_RESOLVE_AUDIO` 那一侧的感知动作选择，不是外部知识获取调度。** R2 §1.3 明确把重表达列为"R2 预算的竞争
对手"而非研究对象——AuTAgent 是这个竞争对手的**已发表最强实现**，这既是边界证明，也是 R2 感知侧信号设计的
参考。

**b4. 真实威胁（不淡化，三条）**：

1. **叙事威胁（最强）**：AuTAgent 的中心论证与 R2 的纲领**表面直接对立**——"prompt-based selection fails to
   assess context-dependent utility"（摘要）、"Only through specialized training to internalize a policy of
   'when to use which tool' can we achieve precise noise filtering"（§1）。一位读过此文的评审会直接问 R2：
   音频工具调度上 training-free 已被实证不够，你凭什么。**R2 必须在 §4.5 或 §8 正面回应，不能只在
   bibliography 里挂着。**
2. **实用性威胁**：Table 3 的 weak-to-strong 迁移（用 Qwen2 反馈训出的策略插到 GPT-4o 上只掉 0.40/0.20）说明
   "训一个小策略"成本低、可移植——削弱"训练不可行所以要 training-free"这类**可行性**理由。R2 的理由必须落在
   红线与科学问题（部署期只有 runtime-visible 信号、黑盒 API 无法训练、gold 不可用），**不能落在"训练太贵"**。
3. **口径威胁（须做 scope 修补，MINOR 级）**：R2 §4.3 现写"读集内**没有任何一处** scalar reward 充当推理期
   控制器"——**字面成立**（AuTAgent 的 scalar reward 是训练期奖励，推理期不计算任何 reward）。但同节"**没有人
   测量**'这次采集是否改变了答案'"这句在 AuTAgent 面前需要限定作用域：**AuTAgent 的奖励定义就是这个反事实
   测量**（式 1），Figure 2 的逐工具边际也是。→ 建议 R2 把这两句都改成"**在外部知识获取线（AudioRAG/
   Omni-DeepSearch）上**……；感知工具线的 AuTAgent 已在**训练期**做了该测量，但它没有外部知识源、没有停止/
   预算/准入"。

**b5. R2 的 training-free 调度相对它的对照价值（天然对照臂）**：

- **它是同任务族上 trained-RL vs training-free 控制面的天然对照臂**，且**已把双方的读数都摆在同一张表里**：
  `Tools w/ Desc.`（training-free）vs `AuTAgent`（trained）。R2 因此拿到一个**已发表的量化靶子**：
  训练相对 training-free 的净残差只有 **+3.00 / +3.80**（Qwen2 骨干）与 **+4.30 / +3.00**（GPT-4o 骨干）。
- **两条对 R2 有利的、可核验的读数**（我方算术，源数在 Table 2/Table 4）：
  - **强骨干上 training-free 已吃下过半增益**：GPT-4o 上 `Tools w/ Desc.` 占总增益 **56%**（MMAU）/
    **62.5%**（MMAR）；弱骨干 Qwen2 上只有 29%/39%。**骨干越强，training-free 越接近 trained**——R2 核为
    Qwen3-Omni-30B（强于 Qwen2-Audio-7B）。**须诚实附条件**：该趋势是两点外推，且 R2 主载体上本核仅 6.56
    （近地板，R2 §5.4），"骨干更强"在不同载体上不可直接串用。
  - **训练本身几乎不产生增益，决策目标才产生增益**：MMAU 上 `Tools w/ Desc.` 51.20 → `Binary Reward` RL
    **51.40**（**+0.20**）→ 差分奖励 **54.20**（+2.80）。**AuTAgent 自己的消融证明：3.00 pt 的 93% 来自
    "以相对基线的净增益为决策目标"，不是来自训练。** 而"以净增益为决策目标"在 R2 里正是 `V̂` + 离线标定
    的 training-free 实现。**这是把 b4-1 的叙事威胁整条反转的核心论据。**
- **可用的反驳论证（建议写进 R2 §4.5/§8）**：AuTAgent 判死的是"**给工具描述让 LLM 自由选**"这一种最弱的
  training-free 形态——无不确定性信号、无逐实例价值估计、无阈值、无离线标定、无准入门、无成本记账
  （附录 A.1 提示词可查）；且该对照臂与 trained 臂的**提示词信息量本身不对等**（严谨性备注 A，UNVERIFIED）。
  **"自由 prompt 失效" ≠ "结构化确定性控制失效"** ——这正是 R2 §6.2 与自由生成 controller 的可识别差异
  （决策量/阈值/记账全部外显可审计）所在。

### (e) 三轴定位（R2 组织/供给/使用 + "文本域 2025 agentic → 2026 定价校准"谱系）

| 轴 | AuTAgent 段位 | 相对 R2 谱系的位置 |
|---|---|---|
| **组织** | **比语音检索线更空**：无库、无索引、无 key/value、无快照、无出处、无版本、无冲突标记。工具是对当前音频的现算函数。 | 不在组织谱系上。R2 §3.3 的"语音域组织轴全面空位"结论**不变、且被加强**（连"平铺向量库"这一级都没有）。 |
| **供给** | **learned single-shot action selection**：决策由 RL 学出，但只决定"选哪件"，且单步无循环、无预算、无停止。 | **不在"2025 agentic → 2026 定价校准"这条主轴上**，它落在一条**正交分支**：文本/视觉域的 **trained tool router / retrieval gate**（自述最近邻=视觉域 VisTA，§6），而不是 agentic 深搜（Search-o1/Search-R1）或定价获取（CTA/VOI-search/PRA/AdaCompute）。按 R2 §4.3 的段位语言：它比 AudioRAG/Omni-DeepSearch **更不 agentic**（无多轮）但**更"学习化"**（非 prompt）。**R2 §4.3 的"语音域供给轴停在 pre-pricing"结论不变**——AuTAgent 同样零定价、零预算、零校准，它只是把 pre-pricing 的动作选择从 prompt 换成了权重。 |
| **使用** | **无条件接纳**（附录 A.3 直接拼接），无准入/冲突/归因/abstain。 | 与 AudioRAG/Omni-DeepSearch **同段位**。R2 §4.3 的"使用轴停在无条件接纳"结论**不变、被第四篇独立证据加强**；且它的 All-Tools −9.1 pt 是该段位**代价**的最干净量化。 |

**跨谱系净结论**：AuTAgent 不填 R2 §4.4 表里的任何一个机制空位（M1–M8 无一被它占据：M1 准入门无、M2 预算无、

M8 无预算再分配）。**唯一需要按事实更新的两行是 M7（从"唯一 oracle 行=Omni-DeepSearch 实体分解"改为"两条，
第二条为 AuTAgent 的单动作事后 oracle，属感知工具轴"）与 M6/M1（音频域已有 harmful 基率量化，但只作用于
供给侧、未在使用端设门）。**
