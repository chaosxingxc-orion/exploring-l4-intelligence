## 1 方法本质

EchoSight 是 KVQA 的 **retrieve-then-rerank** 框架，四件套：KB（百万级"维基文章+配图"对）、
retriever、reranker、answer generator。第一阶段**纯视觉检索**：用冻结 Eva-CLIP-8B 把查询图与
KB 里每篇文章的**配图**都编码，余弦相似度 + Faiss 取 top-$k$ 篇。第二阶段**多模态重排**：把候选
文章切成 section（每 section 前缀文章标题），用 BLIP-2 Q-Former 从 (查询图, 问题) 抽 32 个 query
token，与 section 的 `[CLS]` 文本嵌入取**最大成对相似度**得 $S_r$，再与第一阶段视觉分 $S_v$ 做
**加权和** $\alpha S_v+(1-\alpha)S_r$（$\alpha=0.5$）选出唯一 top-1 section。该 section 单独作为
RAG 上下文喂给一个**现成冻结 LLM**（E-VQA 用 Mistral-7B-Instruct-v0.2，InfoSeek 用 LLaMA3-8B-Instruct）。
生成端全程零训练；**reranker 需要训练**（Q-Former 除视觉塔外全参微调，hard-negative 对比学习，
E-VQA 900K 样本 / 150K steps / 单卡 A100-80G 40 小时，lr 1e-4，bs 6，N=24 负样本），
并**零样本迁移**到 InfoSeek（只在 E-VQA 上训过）。

## 2 key-value 与三轴定位

| 维度 | 事实（LaTeX 源核） |
|---|---|
| **key 用什么构建** | **两层 key，且第一层不是文本。** 第一层 key = **每篇维基文章配图的 Eva-CLIP-8B 视觉嵌入**（pooled last-layer），query = 查询图，即 **image→image**；`CLIP I-T`（图像→标题+摘要文本，即 Wiki-LLaVA 那条路）在本文是**被击败的对照组**（E-VQA R@1 3.3 vs EchoSight 无重排 13.3）。第二层 key = **section 文本的 Q-Former `[CLS]` 嵌入**（section 前缀文章标题），query = **(图像, 问题) 联合的 32 个 Q-Former query token**，打分取 32 个 token 上的 **max** 成对相似度。 |
| **多面 key（关键）** | 每个候选 section 同时挂**两个不同"面"的分数**：实体页首图给的**视觉面** $S_v$（继承自该 entry 的最佳匹配图）与 (图像+问题) 给的**多模态面** $S_r$，靠**单一权重 $\alpha=0.5$ 线性融合**。这是本地读集里最接近"同一 value 多面 key + 融合规则"的现成先例。 |
| **检索几跳** | **1 跳硬检索 + 1 跳重排，全固定。** rerank scope（送进重排的候选数）是硬编码常数，主结果用 **Top-20**；没有停止决策、没有 query 改写、没有迭代。 |
| **证据怎么进上下文** | **唯一 1 个 top-1 section 原文**（$\arg\max$ 单选）进 prompt，配合问题给冻结 LLM。无摘要、无多证据合并、无引用标注、无冲突处理、无 abstain。 |
| **有无准入** | **完全没有。** $\arg\max$ 永远输出一个 section，不管分数多低；没有阈值、没有"不检索/不采纳"分支。 |

**三轴读数**：组织轴 = 图像 key + section value + 双面打分融合（2024 年就有面级融合，但只在
**打分层**，索引仍是单向量）；供给轴 = 固定单跳 + 固定 scope；使用轴 = 无条件接纳 top-1。

## 3 主实验数字（LaTeX 源核对）

## 4 DFS 四问

**方法（做了什么）**：把 KVQA 的第一跳从"图像→实体名文本"改成"图像→实体配图"（同模态检索，
避开 CLIP 跨模态 gap），再补一个**训练过的多模态重排器**把 (图像+问题) 与 section 文本对齐，
最后只喂 1 个 section 给冻结 LLM。相对 Wiki-LLaVA 的核心增量就是**把"问题"提前接入检索决策**
（Wiki-LLaVA 的问题只在第二跳的纯文本 Contriever 里出现，第一跳完全不看问题）。

**局限**：(a) 重排上限被 retriever 池子锁死（R@20 恒 48.8，Tab.1）；(b) rerank scope 是**手工**
在 recall 与 17× 吞吐代价之间折的，没有 per-query 自适应；(c) 只取 top-1 section，无多证据、
无冲突、无准入，$\arg\max$ 强制输出；(d) 需要训练 reranker（40 A100-h），且只有 E-VQA 有
evidence-section 标注，InfoSeek 是零样本迁移；(e) InfoSeek 的 100K KB 是作者**自己从 E-VQA 过滤
重建的**（原库未公开），所以它与 Wiki-LLaVA 的 InfoSeek 数字（28.9 vs 31.3）**不同库、不可直比**；
(f) E-VQA 只用 single-hop，无多跳。

**改进空间**：(i) $\alpha$ 是**固定 0.5 的全局常数**——两个面的权重不随 query 变，天然的
per-query 面权重自适应空位；(ii) scope 应由前瞻价值决定而非常数（Tab.5/6 已把成本曲线量好，
只缺决策器）；(iii) top-1 单证据 → 多证据 + 准入 + 归因；(iv) 48.1 点的 gold headroom 说明
retrieval 而非 reasoning 是瓶颈（gold section 下 LLM 已达 89.9–90.7）。

**可借鉴（形状，H5 withheld）**：**(1) 双面打分融合 $\alpha S_v+(1-\alpha)S_r$ 是 R2 §3.4
"多面 key 的 query 面路由/融合规则"的现成最简先例**——同一 value（section）挂视觉面与多模态面
两个分数、线性融合、单一超参，可直接作为 R2 O 臂融合规则的 baseline 形态（并把"$\alpha$ 固定
不自适应"作为要改进的点）。**(2) 三级 gold 粒度阶梯（Title / Article / Section）** 把 oracle
headroom 拆成"key 定位收益"与"value 精度收益"两段，是 R2 M7/A1′ 的直接模板。
**(3) Tab.5+Tab.6 的"recall 增益 vs 吞吐代价"配对表**是"组织/检索代价曲线"的现成报告格式。
**(4) Tab.8 的跨生成器稳定性行**是"机制增益不依赖某个特定 LLM"的最小论证形状，R2 §6 若要主张
控制面而非模型带来增益，应照抄这一行。

### 深读后新增的、R2 应该知道的事实

1. **R2 §3.4 的"多面 key 融合规则"已有 2024 年的可比 baseline，且带一个明确的可改进点。**
   $\alpha S_v+(1-\alpha)S_r$、$\alpha=0.5$ 全局固定。R2 的 O 臂若做"语义面 + 副语言面"融合，
   应把"固定 α 线性融合"设为对照臂，把"per-query 面权重自适应"设为处理臂——这样贡献边界从
   "有多面 key"（已被占）收窄为"**面权重由部署可见信号自适应**"（未被占）。这直接影响 R2 §4.4
   空位表与 §6 的 O1/O2 归因设计。
2. **gold 收益的 key/value 分解有跨论文一致的量级。** EchoSight：只给实体标题 29.4 vs vanilla
   21.0 = **+8.4 点**；给 gold section 89.9 = 再 **+60.5 点**。M3-VQA 2604.25122 独立测出
   Entity-Name 相对 Original **+10.2 点**、Sentence 相对 Entity-Name 再 **+15.2 点**。两篇一致
   显示"**给对名字（key）的收益远小于给对内容（value）**"。R2 的 A1′ 如果只做"gold 语义假设"
   一臂，据此形状预期收益偏小、可能功效不足；应像这两篇一样**至少两级**（gold key 臂 + gold
   value 臂）才能把 headroom 归因清楚。（H5：这是形状借用，效果不跨模态外推。）
3. **"检索但排序差 → 比不检索更糟"在 EchoSight 里也复现了。** Tab.3：w/o rerank + KB Article
   = 19.4 < vanilla Mistral-7B 21.0。连同 Wiki-LLaVA 的 26.4 < 28.5，视觉域**两篇 2024 论文
   各自独立给出"无条件接纳检索结果导致净负增益"的实测**。R2 §4.3 第 2 条（语音域"检索结果无条件
   进上下文、没有人测量这次采集是否改变了答案"）现在有两个同域邻居的反例做对照，批评强度显著上升。
4. **重排的天花板 = retriever 召回池**：Tab.1 R@20 在 w/o 与 w/ rerank 下**同为 48.8**。对 R2
   的含义：控制面（重排/门控/调度）永远无法超过供给面召回上限，所以 R2 的 A 阶梯必须**分开报**
   "召回上限行"与"控制面收益行"，否则控制面的增益会被误读为可无限外推。
5. **成本自适应的空位是 2024 就量好数据、只差决策器。** Tab.5/6 已经把 scope→(recall, QPS)
   的整条曲线量出来了，作者的处置是**人工选一个常数**。这正是 R2 M2/M8"预算不该统一封顶"论点在
   视觉域最干净的出处（比 R2 现在依赖的 VOI-search / AdaCompute 更早、且同为知识检索场景）。
6. **它是"生成端全冻结、只训检索侧"的混合形态，红线读数需分列。** 生成端用现成 Mistral-7B /
   LLaMA3-8B，零训练、零 prompt 调优声明；但 reranker 全参微调 40 A100-h，且依赖 E-VQA 的
   **evidence-section 人工标注**才能构造正样本（InfoSeek 无此标注 → 零样本迁移）。R2 若引它作
   "training-free 邻居"会失准：正确表述是"**生成端 training-free、检索侧需标注监督训练**"。
   附带含义：R2 若考虑训练自己的多面编码器/融合器，就落进这一形态并触碰 §1.4 红线，必须走
   **冻结现成编码器 + 无训练融合**（与 R2 §9 "多面 key 冻结编码器选型"待办一致）。
7. **跨论文数字不可直比的两个具体陷阱**（R2 若在 §3.2/§5 并排列表时会踩）：(a) InfoSeek KB：
   EchoSight 用**自建**的 100K（从 E-VQA 过滤，原库未公开），Wiki-LLaVA 用 InfoSeek 官方 6M 的
   **随机 100k 子集**（并保证 6,741 个相关实体在内）——库不同；(b) E-VQA 指标：EchoSight 明写
   BEM，Wiki-LLaVA 写"官方评测脚本"，且 EchoSight 主表把 Wiki-LLaVA 的 21.8（single-hop, $k{=}1,n{=}1$）
   与自己的 41.8 并列。两篇都只做 single-hop。
