## §1 方法本质

Agent-Omni 用一个 master agent 在**推理期编排一池现成基础模型**，从而在不做任何 omni 级
联合训练的前提下接受文本/图像/音频/视频的任意组合并输出文本。master agent（Claude 3.7
Sonnet）走四段内部流程：**Perception**（把各模态输入摘要成一份 JSON 语义描述）→
**Reasoning**（推出 `user_intent`，为每个需进一步处理的模态生成子问题，产出结构化 JSON
执行计划）→ **Execution**（按计划调用模型池中指定的专家模型，把每个子问题与其答案配对
收集）→ **Decision**（整合全部输出构造 `final_answer`，评估完备性，输出 `is_final` 标志与
`suggestions`）。若 `is_final=false`，下一轮 Reasoning 读上一轮 `suggestions` 生成针对
"缺失或不确定信息"的追问，循环直至 `is_final=true` 或触达硬上限 $L$（默认 3）。模型池按
模态分工：Deepseek R1（文本）、Claude 3.7 Sonnet（图像与视频）、Qwen2.5-Omni（音频）。
一个关键设计约束：**下游专家只看得到自己模态的输入，看不到用户原始 query 与任何上下文**，
因此 Reasoning 必须把全部必要上下文显式写进每个子问题（prompt 明写此点，并鼓励每轮每
专家问三个以上不同问题）。全系统零训练（"the model pool ... operates without any
additional training"），但**最终答案由 Claude 3.7 Sonnet 的 Decision 模块合成**，
omni 模型（Qwen2.5-Omni）被降格为一个音频子专家。**全篇没有任何外部知识检索**——
"获取"的对象始终是用户已提供的那批输入，只是换不同模型、换不同子问题再问一遍。

## §2 六字段方法卡（对齐 R2 §2.1 格式）

| 字段 | 内容 |
|---|---|
| **组织** | **无任何持久知识组织**。既无语料库、索引、快照，也无跨实例记忆。唯一的持久物是回合内那份不断追加的 JSON（`input_summaries` + 历轮 `historical_message` + 各专家问答对 + `suggestions`），跨题即弃。"知识源"实际上是**模型池本身**（模型参数里的先验），不是可组织、可版本化、可审计的外部库。无出处字段、无冲突标记、无引用支持、无 abstain 支持——**逐字段为零**，与 R2 §3.3 对语音 agentic 线的判定同型。 |
| **供给** | 每轮由 master agent **prompt 自由生成**：选哪些专家、问几个问题、问什么，全部由 Reasoning 模块在结构化 prompt 下产出（prompt 鼓励"每轮每专家 >3 个问题"）。停止由 Decision 模块自由生成的布尔 `is_final` + **硬编码全局上限 $L=3$** 共同决定。Decision prompt 里唯一的"停止判据"是自然语言启发式：*If you are not 100% confident in the completeness or correctness of the answer, initiate a next round*。**无预算变量、无价值估计、无成本感知、无按数据集/类别的预算再分配**——$L$ 是一个跨全部 15 个基准共用的常数。 |
| **使用** | 无准入门。Decision 模块把**全部**专家输出无条件读入并"蒸馏整合"成 `final_answer`（prompt 要求"Never repeat agent responses verbatim. Always distill and integrate"）。有一条弱一致性检查：*Actively scan for logical inconsistencies, incorrect assumptions, or misaligned interpretations*，以及格式合规检查——但均为自由生成，无 admit/reject 判定、无冲突计数、无来源质量分级、无归因、无 abstain。跨专家冲突的处理完全隐式。 |
| **changed vs held-constant** | **零训练**（held-constant 一切模型参数）：Claude 3.7 Sonnet 与 Deepseek R1 走 AWS Bedrock API，其余（Phi4、Qwen2.5-Omni、Qwen2-Audio、Llava-Video）用 vLLM 本地部署，均无微调。changed 的只有 prompt、JSON schema 与编排拓扑。**但作答权被整体转移**：Qwen2.5-Omni 只回答关于音频的子问题，`final_answer` 由 Claude 3.7 Sonnet 合成。 |
| **runtime-visible vs gold-only** | runtime-visible：各专家的文本回答、`input_summaries`、历轮 `historical_message`、Decision 自评的完备性/一致性叙述、`is_final` 布尔、当前轮号 `cur_round_num`。gold-only：accuracy（每个基准的官方口径）。**gold 完全不回流决策**（合规）。但同时**没有任何标量 runtime 信号进入停止决策**——`is_final` 是自由生成的布尔，不是可标定量；论文报告的 exit rate 是**事后统计**，不是控制量。 |
| **数据/基线/指标/成本** | 数据：15 个基准 × 5 类。文本 MMLU（4 域）/MMLU-Pro/AQUA-RAT；图像 MathVision/MMMU/MMMU-Pro；视频 VideoMathQA/STI-Bench/VSI-Bench；音频 **MMAU / MELD-Emotion / VoxCeleb-Gender**；omni **Daily-Omni / OmniBench / OmniInstruct**。基线两类：(1) 各模态基础模型直答；(2) **DSPy-CoT**（同一模型内的结构化 CoT 提示，代表"单模型内提升推理"对照"跨模型编排"）。指标：accuracy（统一 prompt 模板，多选题"The answer is <X>"）。成本：**只有 wall-clock latency 一个维度**（表 `tbl:latency_table`），无 token 数、无调用计数、无 API 费用、无等成本对照。无 CI、无多 seed、无显著性检验。 |

**主实验表结构还原**（8 个表源逐一核过）：

- `tbl:agent-setup`：模态 × 模型 × 角色，配置表。
- `tbl:acc_text_modality` / `tbl:acc_image_modality` / `tbl:acc_video_modality` /

## §3 主实验数字（LaTeX 源逐格核对）

1. **音频表 `tbl:acc_audio_modality`**：Agent-Omni **MMAU 73.20% / MELD-Emotion 51.97% /
   VoxCeleb-Gender 98.60%**；Foundation Qwen2.5-Omni **70.90 / 38.35 / 97.85**；
   Phi4 Multimodal Instruct 59.70 / 33.37 / 35.41；Qwen2-Audio-7B 54.70 / 22.15 / 50.14。
   即音频三项的增益分别为 **+2.30 / +13.62 / +0.75**——增益几乎全部集中在 MELD-Emotion。
2. **DSPy-CoT 在音频上是灾难**：DSPy-CoT + Phi4 的 MMAU **25.40%**（vs Foundation Phi4
   的 59.70，掉 34.3 点）、MELD 15.03（vs 33.37）、VoxCeleb 31.95（vs 35.41）。
   DSPy-CoT + Qwen2.5-Omni 的 MMAU 与 Foundation 完全相同（70.90 / 70.90），MELD
   37.32 < 38.35、VoxCeleb 88.02 < 97.85。**即"在单模型内加结构化 CoT"在音频域普遍
   为负收益**——这是一条独立于 R2 现有读集的、指向"prompt 级增强不够"的音频域证据。
3. **omni 表 `tbl:acc_omni_modality`**：Agent-Omni Daily-Omni **60.03** / OmniBench
   **49.56** / OmniInstruct **77.50**；Foundation Qwen2.5-Omni 53.72 / 45.18 /
   **81.06**。**OmniInstruct 上裸 Qwen2.5-Omni（81.06）打败整套 agentic 框架（77.50）
   3.56 点，且论文自己把 81.06 加粗**。即三个 omni 基准里有一个编排是净负收益。
4. **迭代消融 `tbl:ablation_iteration` 的 accuracy 行（1/2/3 轮）**：
   MMAU 72.20 → 72.70 → **73.20**（单调，总 +1.00）；
   **MELD-Emotion 51.97 → 51.97 → 51.97（三轮完全不变，总 +0.00）**；
   VoxCeleb 98.24 → 98.74 → **98.60**（**非单调，第 3 轮低于第 2 轮 0.14**）；
   Daily-Omni 58.06 → 58.56 → 58.73；OmniBench 43.17 → 45.27 → 46.23；
   OmniInstruct 74.57 → **74.46** → 74.88（**非单调，第 2 轮低于第 1 轮**）。
5. **迭代消融的 exit rate（1/2/3/4+）——本批最有用的一组数**：
   MMAU **71.80 / 23.10 / 4.60 / 0.50**（≈28% 的题多跑至少一轮，换来 +1.00 点）；
   **MELD-Emotion 59.38 / 31.02 / 7.03 / 2.58**（**≈40.6% 的题多跑至少一轮，
   accuracy 变化恰好 0.00**）；VoxCeleb 93.50 / 5.50 / 1.00 / 0.00；
   文本类 >92% 首轮退出（MMLU 94.39、MMLU-Pro 94.19、AQUA-RAT 92.91）；
   **STI-Bench 首轮退出仅 22.05%、次轮 75.98%**。即"该迭代几轮"在数据集之间从 22% 到
   94% 剧烈变化，而 $L$ 是一个跨全部基准的常数 3——与 R2 §4.3 对 Omni-DeepSearch
   "最优档位随任务分层剧烈变化、论文却统一封顶"的批评完全同型，且本篇给出了**退出率
   这一更细的证据形式**。
6. **latency `tbl:latency_table`**：Agent-Omni MMAU **4.23s** vs Qwen2.5-Omni 0.24s
   （≈17.6×）；MELD 5.09 vs 0.09（≈57×）；VoxCeleb 7.5 vs 0.09（≈83×）；
   Daily-Omni 16.7 vs 0.27（≈62×）；OmniBench 7.47 vs 0.28；OmniInstruct 5.14 vs 0.18；
   视频最贵 VideoMathQA 20.53s、VSI-Bench 16.47s。对照 DSPy-CoT 大致把基线 latency
   翻倍（Claude MMLU 0.88 → 1.72）。**即 MELD 上那 40.6% 的额外轮次以约 57× 的
   latency 代价换来 0.00 点增益**——这是音频域"花费与效果不单调"最干净的一处实测。
7. **内部不一致（须如实标注）**：默认配置 $L=3$，但 `tbl:ablation_iteration` 第 3 轮的
   omni 三列（Daily-Omni **58.73** / OmniBench **46.23** / OmniInstruct **74.88**）与
   主表 `tbl:omni_comparison` / `tbl:acc_omni_modality` 的 headline 值
   （**60.03 / 49.56 / 77.50**）**不相符，差 +1.30 / +3.33 / +2.62**。同表的
   文本/图像/视频/音频四块第 3 轮值与 headline **逐格相符**（如 MMLU 89.23、
   MMLU-Pro 83.21、MathVision 44.71、MMMU-Pro 60.23、VideoMathQA 30.71、STI-Bench
   40.00、MMAU 73.20、VoxCeleb 98.60 均一致）。故不一致仅限 omni 三列，来源不明；
   **引用 Daily-Omni/OmniBench/OmniInstruct 数字时必须标注该冲突并给出所引表号**。
8. **模型池消融（附录 `tbl:diff_agent_audio_acc`）**：把音频专家换成 Phi4 得 MMAU
   **75.00%**（高于所选配置的 73.20，且为该表加粗最优），但 MELD 只有 41.13、VoxCeleb
   44.12；Qwen2-Audio 得 VoxCeleb **99.50%**（最优），但 MMAU 70.80、MELD 40.39；
   所选 Qwen2.5-Omni 为 73.20 / 51.97 / 98.60。**即 headline 的 MMAU 73.20 不是该论文
   手上最好的 MMAU 配置**——所选配置是跨三基准的折中，论文未把这一点在正文写明
   （正文只说 "Phi-4 Multimodal Instruct performs best on MMAU"）。图像侧同理：
   Claude 3.7 Sonnet 60.23 vs Qwen2.5-Omni 52.95 vs Phi4 36.07（MMMU-Pro，差 24.16 点）。

## §4 DFS 四问

**方法**：文本 LLM 作 master、按模态派发子问题给一池冻结专家模型、把回答整合成答案，
并用自由生成的 `is_final` 布尔 + 硬上限 $L=3$ 控制迭代。零训练、纯推理期编排。

**局限**：(a) **无外部知识**——"获取"只是对同一批输入换模型、换子问题再问，属 R2 §1.3
第②类信息作用（对已有观测的重表达），不引入实例级外部新信息；(b) 停止判据是自由生成的
布尔 + 全局常数，退出率数据自证需求跨数据集差 4 倍以上而封顶统一；(c) MELD 上 40.6% 额外
轮次换 0.00 点、VoxCeleb 与 OmniInstruct 非单调——迭代自校正在部分任务上是纯成本；
(d) `final_answer` 由 master LLM 合成，"增益来自编排还是来自把 Claude 3.7 Sonnet 与
Deepseek R1 拉进环"无法归因，作者自己在消融里承认"gains come not only from
orchestration but also from leveraging high-quality specialized models"；
(e) 下游专家不见原 query 的设计把上下文完整性责任全压在 Reasoning 的 prompt 上，是一条
未被消融的单点脆弱面；(f) 成本只报 latency，无 token/调用/费用；无 CI、单次运行、无显著性；
(g) omni 三列 headline 与迭代表第 3 轮不符（§3.7）；(h) 作者自陈的局限：依赖外部 API
稳定性、单模型误差会在编排中传播放大、仅在 curated 基准上评测、只能输出文本。

**改进空间**：把 `is_final` 从自由生成布尔换成可标定的标量停止判据（本篇的 exit-rate ×
accuracy 表已经把"该停没停"的诊断面铺好了，只差一个控制量）；按数据集/类别再分配迭代
预算（AdaCompute 形态）；给跨专家冲突加显式仲裁与来源质量分级；把作答权还给单一
承重模型以恢复归因；补 token/费用记账与等成本对照；修 omni 列的表间不一致。

**可借鉴**：**exit rate × accuracy × 迭代档的联表**是一个极便宜且信息量很高的
continue-stop 诊断工具，R2 §6.5 合理性层的 `continue-stop 混淆矩阵` 可以直接采用这一
表形式（并补上"多跑的那部分题的 paired delta"这一本篇缺失的关键列）；模型池替换消融的
表形状（固定 master、换单个专家）可作 R2 O 臂/工具级冻结组件选型的报告模板；
"下游专家只见本模态输入"的隔离约定可作 R2 A5 扰动臂里"证据脱离原 query 语境"的一种
确定性构造方式。

## §5 R2 威胁面判定

### (a) 是否已做"部署可见信号估计外部证据动作边际价值"或"感知 vs 知识不确定性的动作分配"

**否，两项皆无。** 该系统没有外部知识动作（无搜索、无检索、无知识库），"获取"的全部内容是
向模态专家重复询问同一批输入；因此不存在"外部证据动作的边际价值"，也不存在"感知 vs 知识"
两侧可分配。停止决策是 LLM 自由生成的布尔 + 硬编码 $L=3$，**没有任何标量估计量**。
本篇是 R2 §4.3 第 1 点（"每个采集决策=LLM 自由生成，每个数量=硬编码常数"）在音频/omni
域的**第三个独立实例**，且比 AudioRAG/Omni-DeepSearch 更极端：连"预算档"这个概念都没有，
只有一个跨 15 个基准共用的循环上限。

**需要更新的 R2 空位断言（读集内量词）**：

1. **§0 / §4.3 的"本地读集内全部三篇 agentic 系统"必须改为二分线量词**（与 EChO 条目
   §5a 第 1 点同一处修复，此处不重复论证）。Agent-Omni 归**感知/模型编排线**，不是 R2
   对象的 incumbent。
2. **§4.3 第 1 点"读集内没有任何一处 scalar reward 充当推理期控制器（37 行音频/omni
   语料场级事实）"** → 就本篇而言**成立且被加强**（`is_final` 是布尔，非标量）。
   但该量词的真正压力来自 NAP 的自报置信度阈值，见 NAP 条目 §5a。
3. **§4.3 第 3 点"停止权是被它们自己的数据实证的失效面"** → **本篇给出第三组、也是最
   干净的一组自证数据**，建议直接纳入：MELD-Emotion 上 40.6% 的题多跑至少一轮而
   accuracy 变化恰为 0.00（且 latency 约 57× 于裸模型）；VoxCeleb 第 3 轮低于第 2 轮；
   OmniInstruct 第 2 轮低于第 1 轮；首轮退出率跨数据集从 22.05%（STI-Bench）到 94.39%
   （MMLU）而 $L$ 统一为 3。这组数字比 Omni-DeepSearch 的三档预算消融更细（带退出率），
   且**是纯感知/编排线的**——因此 R2 引用时必须标注它证明的是"轮内自校正在部分任务上
   零收益/负收益"，**不能**改写为"外部检索过度"的证据（信息角色不同）。
4. **§4.4 M8（按类别/实例再分配固定总预算）"语音域状态：自证最优预算随类别异而统一封顶"**
   → 本篇提供第二个实例，量词从"Omni-DeepSearch 一处"扩到"两处"，并新增退出率这一
   更强的证据形式。
5. **§3.3 语音域组织轴全面空位** → 成立且覆盖面扩大。本篇连"库"都没有（模型池不是可
   组织、可版本化、可审计的知识库），出处/冲突/引用/abstain 逐字段为零。建议 §3.3 的
   "agentic 线：AudioRAG 与 Omni-DeepSearch 干脆没有持久知识组织"扩写为覆盖
   感知/编排线三篇。

### (b) 调度/编排决策是训练的、prompt 自由生成的、还是确定性规则的

**几乎全部 prompt 自由生成 + 一个硬编码常数**：
- **prompt 自由生成**：`user_intent` 抽取、选哪些专家、每专家问几个/什么问题
  （prompt 鼓励 >3 个）、答案整合、完备性自评、`suggestions`、`is_final` 布尔。
- **确定性规则**：仅 $L=3$ 的循环上限，以及"专家→模态"的静态绑定（表 `tbl:agent-setup`）。
- **训练**：零。
- 停止启发式的原文即"若不是 100% 确信完备与正确就再来一轮"——这正是 R2 §4.2 引用的
  ToolGate 结论（prompt 级"自我怀疑"提示对采集门控无效）所指的形态，而本篇的退出率
  数据（MELD 40.6% 额外轮次 → 0.00 增益）**就是该无效性的一次实测**。建议 R2 §4.2 在
  引用 ToolGate 时并列此实例，把"跨域借来的形状"升级为"音频/omni 域已有同向实测"。

### (c) 与 R2 的 RE_RESOLVE 动作的关系

**弱、隐式的部分占据，不构成对 A4b 的实质威胁。**
master loop 的后续轮次会用新的子问题**再次询问同一个音频专家同一段音频**，功能上是一次
"重询问音频"。但：(i) 没有独立的重听动作类型——它与"再问文本专家"在动作空间里不可区分；
(ii) 触发信号不是任何感知不确定性度量，而是 Decision 模块自由生成的"不够完备/不够确信"
叙述；(iii) 没有重呈现一致性度量（R2 的 `audCons`）、没有假设集离散度（`disp(H_t)`）、
没有多假设并行；(iv) 与外部检索之间不存在竞争关系（无外部动作），所以**"感知 vs 知识
的预算分配"这一 R2 核心决策问题在本篇完全不存在**。
**对 A4b 独立性论证的影响**：可忽略。但 R2 应把它列入"重询问音频已被隐式实践"的
如实清单，避免"重听动作在语音/omni agentic 线完全没有出现过"这类过强表述——正确的
表述是"重询问音频作为 loop 副产品出现过（Agent-Omni），作为一等动作原语出现过
（NAP），但**在与外部知识动作竞争同一预算的分配问题中从未出现**"。

### (d) 红线关系与可搬组件

**红线三条逐条**：
1. **不修改冻结核参数** → **合规**（全部 API / vLLM 直调，零微调）。
2. **不为本任务新训练任何模型** → **合规**。
3. **不新增 LLM 代答** → **违反，且比 EChO 更彻底**。`final_answer` 由 master
   （Claude 3.7 Sonnet）合成；omni 模型被降格为音频子专家，只回答子问题。作者自己的
   消融也确认增益部分来自"拉进了更强的专家模型"而非编排本身。因此 Agent-Omni 的
   73.20 / 51.97 / 98.60 **不可作为 R2 的可达目标或臂**，只能作方法论对照。
   它同时是 R2 §1.4 归因批评的**第三个干净实例**（AudioRAG 的 Qwen3-8B controller、
   EChO 的 DeepSeek-V3 verifier、本篇的 Claude master）——建议 R2 §1.4 把"AudioRAG 一例"
   扩为三例，该论点的证据基础从此不依赖单篇。

**可搬组件（红线内）**：
- **exit rate × accuracy × 迭代档联表**：直接搬为 R2 §6.5 合理性层 `continue-stop`
  诊断的报告表形式，并补本篇缺的关键列——"多跑轮次那部分题的 paired delta 与
  correct→wrong 计数"。这一补充恰好把本篇的最大弱点变成 R2 的一个具体贡献点。
- **模型池替换消融表形状**（固定 master、逐一替换单专家）：R2 工具级冻结组件（音频向量
  模型、DSP 算子）选型报告的模板。
- **latency-per-benchmark 对照口径**：R2 九维成本记账里 wall-clock 维的一个已发表参照
  （agentic 编排相对裸模型 17–83× 的量级），可用于 §7 `COST_DISPARATE` 倍数的预注册
  取值讨论。
- **"下游专家只见本模态输入"的隔离约定**：可作 A5 扰动臂中"证据脱离原 query 语境"的
  确定性构造方式之一。

**不可搬**：master agent 合成 `final_answer`（作答权转移）；`is_final` 自由生成布尔
（不可标定，与 R2 §6.2 的确定性阈值规则冲突）；把 omni 核降为子专家的整体拓扑。

### (e) 是否提供新载体/基线数字

**提供 6 个载体与一组基线数字，但没有一个可作 R2 载体；其中 MELD 是一条重要的负面结论。**

- **音频三载体**：MMAU、**MELD-Emotion**、VoxCeleb-Gender。**全部不可作 R2 载体**：
  答案完全由音频本身决定，外部知识对实例级答案无边际价值，落在 R2 §1.3 信息角色边界
  之外（第③类"潜在知识激发"或干脆是纯感知任务）。
  **MELD-Emotion 尤其重要**：R2 §9 的调研待办是"寻找情感/韵律假设作为 query 钥匙、
  答案需要外部知识的成型基准"。**MELD-Emotion 不满足该条件**——它的答案就是情绪标签
  本身（R2 §1.3 明确举的反例："说话人是什么情绪"本身就是答案）。因此本次深读为该待办
  提供了一个**明确的排除结论**：情感识别类基准（MELD 及同族）不能充当 R2 的情感槽载体；
  合格载体必须形如"先判情绪 → 再检索针对该情绪的外部应对知识 → 答案依赖该知识"，
  读集内仍为零。建议把这条排除结论写进 §9，避免后续会话误把 MELD 当载体。
- **omni 三载体**：Daily-Omni、OmniBench、OmniInstruct——同样无外部知识需求，不可作
  R2 载体；仅可作"冻结 omni 核在多模态整合任务上的能力参照"。
- **基线数字（可引，须标注表号与冲突）**：Qwen2.5-Omni（7B 级）MMAU **70.90** /
  MELD **38.35** / VoxCeleb **97.85** / Daily-Omni **53.72** / OmniBench **45.18** /
  OmniInstruct **81.06**（`tbl:acc_audio_modality`、`tbl:acc_omni_modality`、
  `tbl:omni_comparison` 三表一致）。注意：这是 **Qwen2.5-Omni**，按 memory 记录
  「Qwen2.5-Omni 口径全过期」，故只能作跨代参照，**不得**与项目核 Qwen3-Omni-30B
  数字串用。
- **一条独立的方法论证据（对 R2 有利）**：**DSPy-CoT 在音频三载体上普遍为负收益**
  （Phi4 上 MMAU 59.70→25.40、MELD 33.37→15.03；Qwen2.5-Omni 上 MELD 38.35→37.32、
  VoxCeleb 97.85→88.02，MMAU 完全不变）。这说明"在单模型内加结构化 CoT 提示"这条最
  便宜的路在音频域不奏效——为 R2"需要外显控制面而非 prompt 级增强"的立场提供了一个
  音频域的、独立于 R2 现有读集的对照点。建议纳入 §4.3 或 §5.3 的基线讨论（作为
  "prompt 级增强基线不足"的实证，不作效果外推）。
- **一条反向证据（须如实纳入最强反方）**：OmniInstruct 上裸 Qwen2.5-Omni 81.06 打败
  整套 agentic 编排 77.50。即"加一层 agentic 控制面"在某些任务上是净负收益，且是论文
  自己加粗承认的。R2 §7 的 K1a 判死机制已经覆盖这种可能，但 §9 的最强反方栏建议补一条：
  读集内已有 agentic 控制面在 omni 任务上净负收益的自证实例。
