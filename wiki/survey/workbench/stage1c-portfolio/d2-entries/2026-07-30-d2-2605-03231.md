## 1. 方法本质

cotomi Act 是浏览器扩展形态的 computer-using agent（CUA），由两件互补部件加一个共享层构成：
一个 ReAct 式 **agent scaffold**（管浏览器状态、拼 prompt、路由动作），和一个把用户日常浏览
被动蒸馏为组织知识的 **behavior-to-knowledge pipeline**，二者通过人与 agent 都可读可写的
**shared knowledge workspace**（activity timeline / task board / wiki）桥接。scaffold 的核心
被作者定义为对抗 **context bloat**：每步喂全量 accessibility tree、或逐字保留全部历史观测，
会把上下文塞满过期信息并劣化后期决策。为此有四个机制：adaptive（lazy）observation、
verbal-diff 历史压缩、粗粒度动作、任务分解。**lazy observation** 是本篇与 R2 相关的机制位：
默认只送视口内可见元素，让 agent **按需索要全树**，对视觉复杂页面再行 enrich。组织知识则由
推理模型**自行决定**是否调用 `search_workspace` 工具取回（"避免每轮注入无关上下文"）。
测试期扩展（+TTS）= 每步采样 N≤5 个候选动作取多数票（执行前共识，无事后 verifier）+ 模型
自己吐出多子目标计划时派生并行子 agent。

## 2. 三轴定位

**门控信号是什么**：两道门，**信号都在 LLM 内部、都不可观测、都无标量**。
(a) 观测层：由推理模型自己决定"这一步要不要索要全树"，触发条件只有定性描述（"视觉复杂页面"），
无分数、无阈值、无外部估计量、无预算记账。
(b) 知识层：由推理模型自己决定是否调 `search_workspace`，触发条件同样是定性列举（指令欠定、
出现组织内行话、要求续做未完工作）。全篇**没有任何 scalar reward、校准先验或价值估计**参与获取
决策；唯一被量化钉住的旋钮是 best-of-N 的 N≤5，而它是**静态配置**而非逐实例决策。

**决策规则训练还是规则**：**两者皆非**——是 prompt 级/scaffold 级的 **LLM 自由裁量**。
没有训练出来的门控模块，也没有显式的可审计规则（阈值/预算/停止条件）。这一点值得 R2 单独记账：
本篇与 MementoGUI（trained gate）在同一 §4.2 bullet 里，但落在轴的相反端。

**作用在哪道门**：两处都是 **采集门（pre-call acquisition gate）**——决策发生在额外观测/工作区
证据尚未存在之时。**完全没有准入门**：全树请求或 `search_workspace` 返回的东西无条件进上下文，
无佐证检验、无冲突处理、无引用归因、无 abstain。workspace 的双向人工 curation loop 是**离线
人在环的写入侧质量闸**（用户审批 artifact 修改），不是运行期准入门，不可混记。

## 3. 主实验数字（LaTeX 源核对）

**⚠ 两套口径不可串用**：头条分数（Table 1）用未披露的推理模型跑 WebArena；机制消融（Fig. 2）
用 Gemma-4-31B-IT 跑 WebArena-**Verified** 82 任务子集。80.4 无法用消融 delta 分解。

1. **Table 1（`tab:webarena`）WebArena 任务成功率（%）**：cotomi Act (base, 仅 fmt 提示)
   **74.4** 全量 / **76.5** 179 任务人类子集；+TTS **75.7 / 80.4**。对照：人类 78.2；
   OpAgent 71.6 / 74.9†；CUGA 61.7 / 64.3†；OpenAI Operator 58.1；SteP 33.5 / 40.8†
   （†=作者据公开结果重算）。**+TTS 在人类子集上 = +3.9 pp**。协议注：作者发现 WebArena 自动
   评分器有非平凡比例的假阳/假阴，**三名标注者人工复核了每一条自动判决**；且 cotomi 只用
   answer-format 澄清（fmt），不用其他系统用的 site-specific UI/导航提示。
2. **Fig. 2（`fig:trajectory`）消融口径**：WebArena-Verified，Gemma-4-31B-IT，**39 个配置**，
   **82 任务 × 3 轮**。基线（全量 accessibility tree、无变化信息）**40.6% SR**。
3. **当前观测轴**：加规则生成的 **verbal diff**（DOM 变化的自然语言描述）= **+12.7 pp → 53.3%**，
   是单项最大增益；只加位置型变化标记 = **+7.3 pp**。
4. **lazy observation**：只送视口可见元素 + 按需索全树 → 端到端响应时间 **471 s → 184 s/任务
   （≈2.6×）**。**准确率只有定性表述 "comparable"，全篇没有任何 lazy observation 的准确率数字。**
   （这是本篇最重要的数字完整性事实，见 §5。）
5. **执行历史轴**：逐字保留全部历史观测到第 20 步已达 **~57K** input tokens；用同样的 verbal diff
   替换过期观测 = 准确率 **+1.1 pp**、每步 token 成本 **23.9K → 6.3K（3.8×）**。
6. **不可加性（本篇被 R2 引用的真实出处）**：两轴合并增益 **+13.8 pp** < 单项之和 **+22.1 pp**。
   作者给出的机制原因原文："both encode 'what changed' through different channels, so their
   combined gain is less than the sum of individual effects"——**部分替代**。
7. **行为知识（Fig. 4 `fig:behavior-coverage`）**：WorkArena-L1 六类目子集（dashboard/form/
   knowledge/list-filter/list-sort/service-catalog，每模板 20 seed，6 种随机类目顺序取均值），
   零覆盖基线 **≈51%**，满覆盖（277 件 artifact）最高 **+10 pp**。**raw trajectory 格式在低覆盖
   处反而降分 −2 pp（17% 覆盖）**，高覆盖才成为最强格式；script / insight 全程稳定。
8. **Table 2（`tab:sc-jump`，附录）service catalog**：拿到 48 条自身脚本前 **75.0%** → 后
   **99.2%** → 满覆盖（100%）**97.5%**。即**加入其他类目的知识后，本类目又略降**（6 个顺序中
   5 个在拿到脚本时立刻满分，order_01/04 在满覆盖时回落到 95%）。

## 4. DFS 四问

**方法**：在一个以"保持上下文窗口聚焦"为总纲的工程化 scaffold 里，把"看更多"和"知道更多"都
做成 LLM 自主触发的按需逃生阀（on-demand reveal），并用 verbal diff 把"变化"这一信息压到
两条通道上；测试期扩展靠执行前多数票共识降低单步方差。

**局限**：(i) lazy observation **无准确率数字**，"comparable" 未量化、未消融，无法承载任何效果
主张；(ii) 头条与消融是不同模型/不同基准子集，80.4 不可分解到机制；(iii) demo 论文，无 seed、
无置信区间、无显著性，行为知识实验的"用户行为"实为 agent 成功轨迹（作者自承真实用户轨迹还含
失败/中断/探索绕路，鲁棒性"remains to be validated"）；(iv) **门控完全无成本-收益记账**——
没人测全树请求率、`search_workspace` 调用率，更没人测"这次获取是否改变了答案"；
(v) 无任何准入侧控制；(vi) "on-demand design avoids injecting irrelevant context on every turn"
是**未经测量的设计理由**，没有 on-demand vs always-inject 的对照臂。

**改进空间**：不可加性结论恰好是 value-of-information 控制器想要的形状（同质通道替代 ⇒ 第二条
"变化"通道的边际价值递减），但本篇只观察到它、随后把默认值硬编码。把"索要全树"做成有定价的
动作、给一个标量估计量、并报告请求率与答案改变率，整块空着。行为知识侧同理：raw trajectory
在低覆盖有害、满覆盖最强，明显需要按覆盖度自适应选格式，论文只做静态格式对比。

**可借鉴**：(a) **替代性/不可加性的测量设计**——单独测轴 A、单独测轴 B、测 A+B，报告缺口
（+12.7 / +1.1 vs 合并 +13.8 vs 求和 +22.1）——可直接移植到 R2 的"重听 vs 搜索"这对动作，
用来判定两个信息通道是否同质替代；(b) 时延作为一等成本，且**效果主张与成本主张分开报告**
（本篇因此没有把 2.6× 包装成"又快又准"）；(c) raw trajectory 低覆盖 −2 pp 与 Table 2 的
99.2 → 97.5 回落，是与 ToolGate 不同机制族（知识积累而非工具调用）的两个独立"更多上下文非
单调有益"数据点。

## 5. R2 定位句核查

**R2 §4.2 原句（`2026-07-29-r2-coreview-draft.md` L415-416）**：
> "cotomi 2605.03231 的 lazy observation 表明预取与轮内获取不可加。"

**判定：CORRECTED**（机制归属错 + 概念词非论文口径）。

- **错误 1（归属）**：不可加性的证据**不在 lazy observation 上**。论文的不可加性是
  **当前观测轴**（轮内 verbal diff，+12.7 pp）与 **执行历史轴**（用 verbal diff 替换过期观测，
  +1.1 pp / 3.8× 省 token）之间的部分替代：合并 +13.8 pp < 求和 +22.1 pp，原因是"两者用不同
  通道编码同一件事（what changed）"。lazy observation 是另一件事，其唯一量化结果是时延
  471 s → 184 s（≈2.6×），准确率只有 "comparable" 的定性说法、**无数字**。
- **错误 2（口径）**："预取 / 轮内获取"是 R2 的词汇，不是论文的。存在一个可辩护的映射
  （历史 diff = 已在上下文中携带的信息 ≈ 预取；当前观测 diff = 本轮呈现的信息），但该映射必须
  明写为 **R2 的读法**，且引用锚点必须改到 verbal-diff 消融（Fig. 2 / §3.1 "Execution history"），
  不能挂在 lazy observation 上。

**建议改写**：
> "cotomi 2605.03231 的两条 'what changed' 通道（轮内观测增强 vs 历史表示）**部分替代**——
> 单独 +12.7 pp 与 +1.1 pp，合并只 +13.8 pp 而非 +22.1 pp（Gemma-4-31B-IT / WebArena-Verified
> 82 任务 × 3 轮口径）；R2 把这读作'已携带上下文与轮内获取不可加'。其 lazy observation 是另一
> 机制：默认只送视口元素、按需索要全树，只报了 471 s → 184 s（≈2.6×）的时延收益，准确率仅以
> 'comparable' 定性表述、无数字。"

### 深读后新增的、R2 应该知道的事实

1. **数字完整性**：lazy observation **没有准确率数字**。若 R2 想要"被门控的按需获取不损准确率"
   这一效果论据，本篇**不能**量化提供。本篇在 R2 §9 证据底座中原属"登记未深读层（只作机制定位、
   不引数字）"；D2 之后**引用仍必须停在机制层**，只是理由从"未深读"变成"论文自己没给数字"。
2. **两道门都是采集门、都是 LLM 自由裁量**（无标量、无阈值、无预算）。这使 cotomi 成为 R2 §4.3
   失效模式 #1（"每个采集决策 = LLM 自由生成"）在**浏览器域**的又一实例。这**加强** R2"pre-pricing
   不是语音域特有、而是各域默认态"的判断，但同时**削弱**把 §4.2 轴结论读成"视觉域已成熟"的写法：
   §4.2 现有措辞把 cotomi 与 ToolGate/FOVEA 并列在"被门控的获取"下，会让读者误以为它也做了定价。
   建议 §4.2 内部再分两档：**有标量/阈值的门**（ToolGate、FOVEA、MementoGUI）与**LLM 裁量的门**
   （cotomi）。
3. **新增非单调数据点**：Table 2 的 service catalog 75.0 → 99.2（拿到自身脚本）→ **97.5**（满覆盖）。
   加入**其他**领域的积累知识后，已有脚本的领域又略降。配合 Fig. 4 的 raw trajectory 低覆盖
   −2 pp，本篇为 R2 §4.1"更相关 ≠ 更好 / 多花不一定多得"贡献两个来自**知识积累机制族**（非工具
   调用族）的独立数据点。
4. **口径串用风险（必须在 R2 中显式隔离）**：80.4 / 76.5 / 75.7（Table 1，WebArena，推理模型未
   披露，三人人工复核）与 40.6 / 53.3 / +13.8 / +22.1（Fig. 2，Gemma-4-31B-IT，WebArena-Verified
   82 任务 × 3 轮）是两套口径。R2 不得把消融 delta 表述为对 80.4 的分解。
5. **设计理由 ≠ 效果论据**："on-demand design avoids injecting irrelevant context on every turn"
   全无对照臂支撑。R2 §4.2"被门控的获取"bullet 只能把 cotomi 记作**设计位置**论据，不能记作
   门控有效的**效果**论据。
6. R2 §4.4 机制表可新增一行观察：cotomi 有 **best-of-N（N≤5）执行前共识**这一测试期扩展，且它
   在人类子集上值 +3.9 pp——这是"训练无关的推理期算力"在**动作选择**（而非获取）上的收益，
   与 R2 的 V̂ 控制面不同层，不应与获取预算混记。
