## 1. 方法本质

**这不是基准，是一套训练配方**（与 R2 §4.2 演进链里的前两项不同类）。目标是把"多模态深搜
agent"的训练全链路开源：底座为三个 Qwen3-VL 变体（8B-Instruct / 30B-A3B-Instruct /
32B-Instruct），先做 agentic SFT（36,592 条多轮工具轨迹），再做多轮 **fatal-aware GRPO**
（8K prompts）。三个组件：
（1）**数据构造**（§3.1）：在 English Wikipedia（**2025-05-01 快照**）超链接图上做受约束随机
游走，长度 $h\in\{2,3,4\}$，跳过消歧/列表页、环、以及入度 > $\tau_{hub}{=}10{,}000$ 的枢纽节点
（约剔除入度最高的 0.03% 节点）；路径节点被赋**功能角色**——$v_0$=anchor（视觉入口）、
$v_1..v_{h-1}$=bridge、$v_h$=answer；GPT-4o 生成 canonical question，再**逐个实体**从最远 bridge
向 $v_0$ 做 fuzzy rewriting，每次替换须同时满足三不变式：**答案不变 / 唯一性（$|\mathcal{R}(q_f)|=1$）
/ 别名非泄漏**；最后把 anchor 换成视觉指代表达（"图中这个人"），配 Wikimedia Commons 或
infobox 图并用 CLIP 相似度筛（阈值 0.28）。**关键差异**：视觉锚点放在路径**源头**而非答案实体
（对比 WebWatcher / Skywork-R1V4），以压制单跳捷径。
（2）**工具环境**（Table 1，7 个）：检索类 `TextSearch`（Serper 取 top-k URL → JINA Reader 转
Markdown → Qwen3-32B 出每文档 2–4 句 query-focused 摘要，输出结构为
`[Passage i] (title, url, summary)`）、`ImageSearch`（反向图搜/视觉实体检索）；图像增强类
`Sharpen` / `SuperResolution`(EDSR) / `PerspectiveCorrect`；注意与解析类 `Crop` / `OCR`。
（3）**训练算法**（§4.2）：复合奖励 $r=r_{fmt}\cdot[\alpha r_{acc}+(1-\alpha)r_{query}]$，
$\alpha{=}0.8$；$r_{fmt}$ 是逐步结构门（`<think>` 后须紧跟 `<tool_call>` 或末步 `<response>`，
工具执行错误亦记 0）作为**乘性闸**；$r_{acc}\in\{0,1\}$ 由 GPT-4o judge 判语义等价；
$r_{query}\in[0,1]$ 由 GPT-5.4 按四维 rubric 给稠密过程分。**fatal-aware masking**：fatal step
$f_i$ = 首次出现 **$K{=}3$ 连续工具执行错误**处，之后所有生成 token 掩掉，且过程奖励只在
valid prefix（$l<f_i$）上计算；再对 fatal 轨迹做**单边 advantage clamp** $\hat A_i=\max(\tilde r_i,0)$，
使失效前缀"要么被强化、要么零梯度"，绝不被惩罚。

## 2. 三轴定位

**搜索决策谁做。** 模型自己（ReAct think-then-act，OpenAI 风格 function calling，
`<think>`/`<tool_call>`/`<response>`）。但**决策能力被训练进权重**——这正是与 R2 定位
（冻结黑盒 omni + training-free 检索调度）相反的一面：这里没有任何推理期可调的控制器，
调度策略是 SFT+RL 的产物。

**几轮。** **无显式轮数上限**。约束只有两个：token 预算（Table 5：Max Response Length
**70,000 tokens**/prompt，Max Prompt Length 4,096）与 fatal abort（$K{=}3$ 连续工具错误）。
参考量级：SFT 轨迹平均 **6.3** 个工具调用轮；RL rollout 组大小 $G$=8（8B）/16（30B-A3B），
温度 train/val 0.7/0.7。

**停止判据。** 主动停止 = 模型自发 emit `<response>`；论文对此只有定性描述（附录 case study：
"the rollout terminates as soon as cross-modal evidence converges"），**没有任何显式收敛判据、
置信阈值或预算判据**。被动停止 = fatal abort，此时按约定强制 $r_{acc}=0$（作者明说这是结构性
保证而非评价判断：无终答时正确性"严格未定义"，保守归零以保持组相对优势估计良定）。对"检索
该不该继续"施压的唯一机制是 $r_{query}$ 的第 (ii) 维（跨轮逻辑推进与迭代改写）与第 (iii) 维
（检索载荷信噪比）——但它是**训练期奖励，不是推理期控制器**。

**证据准入。** **无推理期准入门**。`TextSearch` 的输出在工具内部就被 Qwen3-32B 压成结构化
摘要列表，**URL 字段被保留在载荷结构里**（三篇中唯一在证据载荷里显式保留 url 的），但答案不
要求引用、judge 不核出处、无冲突处理、无 abstain。$r_{query}$ 的信噪比维度是**轨迹级事后打分**，
不是逐条准入。图像观测直接注入视觉骨干，天然绕过 token 级损失（§2 token-level generation mask）；
视觉上下文 $\mathcal{I}_l$ **单调增长**，历史视觉观测严格保留以便交叉引用（如 Crop 结果与其
SuperResolution 版本对读）。

**出处与快照。** 训练数据侧冻结（Wikipedia 2025-05-01 快照 + 明示的枢纽阈值/CLIP 阈值/重试
上限），**评测侧不冻结**（live Serper）。judge 侧有一条罕见的可比性纪律：benchmark judge
prompt **刻意与 Vision-DeepResearch 已公开的评测协议对齐**，并与 RL 训练用的 $r_{acc}$ judge
**分离**（字段名不同、后者用于训练信号、前者事后施加于最终轨迹），理由写在图注里
（附录 `apdxfig:bench-judge`）。

## 4. DFS 四问

**方法。** 把"多模态深搜"当**训练问题**解：造反捷径的多跳图文 QA → 用前沿闭源模型（Claude
Opus 4.6）在真工具环境里蒸出专家轨迹 → 双级 rejection → agentic SFT → 多轮 GRPO；并针对
agentic rollout 特有的"级联工具失败"提出 fatal mask + 单边 advantage clamp，把"整条丢弃"与
"整条照训"之间的第三条路（保留 valid prefix）做成算法。

**局限。** (a) 全程需训练（256/64 卡 × 天量级），与冻结黑盒/training-free 路线不可换算；
(b) "fully open recipe"的**上游依赖闭源**：专家蒸馏自 Claude Opus 4.6、判官为 GPT-4o 与
GPT-5.4，配方本身不自给；(c) **无推理期显式停止/预算控制**，只有 70k token 预算与 fatal abort，
因此"检索该不该做/做几次"仍没有可调旋钮；(d) 评测走 live Serper、无快照、Pass@1 单样本、
无 CI；(e) Table 2 多处缺格（DeepMMSearch-R1 仅 2 列、DeepEyes-v2 与 WebWatcher 各缺 2–4 列，
Avg 列写 `--`），跨行 Avg 比较的可比性受损；(f) 源码级瑕疵：消融表两个 `\label` 落在同一
`table` 环境（见"编号约定"）；(g) fatal 只覆盖"$K{=}3$ 连续**执行错误**"，不覆盖"调用成功但
零信息增益"这一更常见的浪费形态。

**改进空间。** ①把 $r_{query}$ 的过程信号从**训练期奖励**搬到**推理期控制器**——这正是 R2 的
位置，也是本文留下的最直接台阶；②给显式预算/停止策略（当前 SOTA 里也没有，见 §5-N5）；
③冻结检索快照做可复放评测；④把 fatal-aware 记账从"执行错误"推广到"无增益调用"；
⑤把专家/判官换成开源模型以真正闭合"open recipe"。

**可借鉴（对 R2，四项，全部可在零训练前提下用于评测/诊断侧）。**
①**fatal-aware 记账**：把轨迹切成 valid prefix + 失效后缀，过程指标只在 prefix 上算。R2 §6
在 API-only 条件下必然遇到工具级失败，这是现成的记账法；对 AudioRAG 的 type-D 无效答案/
无限循环（R2 §4.3）尤其对症——现行 R2 把它记为"停止权失效"，用本法可把"失效后缀"与"有效
前缀"分开记账，避免整条轨迹被判废而丢掉可用信号。
②**$r_{query}$ 四维 rubric** 可原样降级为 R2 的**离线轨迹质量诊断量表**（不入 controller，
避免 gold 入环）：(i) 已发出 query 与初始 prompt 的语义相关性；(ii) 跨轮的逻辑推进与迭代改写；
(iii) 检索载荷内部的信噪比；(iv) 图/文（在 R2 = 音/文）检索工具的**跨模态互补使用**。第 (iv) 维
正对 R2 §2 的模态映射矩阵。
③**judge 可比性纪律**：评测 judge prompt 与被对标工作的公开协议对齐并落盘，且与训练用 judge
分离。
④**构造纪律**：anchor 放路径源头而非答案实体 + 三不变式（答案不变/唯一性/别名非泄漏）+
两级难度过滤且**过滤器是冻结的第三方模型**（不是被评模型、不见 gold）。

### 5.2 深读后新增的、R2 应该知道的事实

**N1（该方向的竞争面已经是训练型 agent——直接影响 R2 §8 独立性论证）。** 视觉域的训练路线
已把 MMSearch 推到 **72.3**（OpenSearch-VL-32B，GPT-4o judge 口径），同底座 Qwen3-VL-32B
agentic 基线仅 53.9；连 8B 训练后的 64.5 都已远超 Gemini-2.5-Pro 的 direct 39.8。
→ **推论**：视觉域的 training-free 推理期控制面是**被跳过的路径**（社区直接走了训练），不是
"尚未被发现的空位"。因此 R2 **不能**用"视觉域也没做门控/停止"来支持"音频域 training-free 有
空间"；独立性论证必须落在音频域自身的约束上（无可用训练数据、闭源/冻结 omni、API-only、
成本），这与 R2 §1.4 红线与 §8 管辖界线是一致的，但目前 §4.2 的叙述方式容易滑向前者。

**N2（反捷径构造的效果被逐件量化——可作 R2 §5.1 的跨域量级参照）。** Table 3(a)：
source-anchor grounding −11.5、fuzzy entity rewriting −10.3、staged filtering −8.2，
而图像修复增强子集仅 −1.3。这三件正好对应 Omni-DeepSearch-640 的"视觉必要性过滤 / first-hop
实体泄漏过滤 / 纯问题推理过滤"三道（R2 §5.1）。→ 说明这类过滤**不是形式主义，量级在 8–12 点**；
R2 评价载体构造纪律时可引此作为"过滤缺失的代价下界"（按 H5 withheld，只借形状与量级参照，
不外推到音频域效果）。

**N3（过滤器纪律：不见 gold、与被评模型解耦）。** 两级难度过滤用**冻结的 Qwen3-VL-32B**
（先剔无工具可答、再剔单次 `ImageSearch` 可答），VQA 四道准入检查（masking / uniqueness /
visual relevance / non-triviality）中的 uniqueness 用只看 $q$ 的 GPT-4o judge、visual relevance
用 CLIP 阈值 0.28。→ 与 R2 §5.1 对 AudioRAG-500 的批评（"过滤器与错误判官**都见 gold audio
attribute**"）正面呼应：存在一个**不见 gold、且与被评模型解耦**的过滤器设计范式。R2 可把
"过滤器必须冻结、第三方、不见 gold"写成构造纪律标杆条款。

**N4（judge 可比性纪律，优于"多 judge 投票"）。** 本文把 benchmark judge prompt **刻意对齐
Vision-DeepResearch 的公开协议**，并把训练用 $r_{acc}$ judge 与评测 judge 分离（字段名不同、
一为训练信号一为事后评判），理由写在图注。→ 这解决的是**跨论文可比性**；R2 载体
Omni-DeepSearch-640 的"三 LLM judge 多数投票"解决的是**内部一致性**，两者不互替。建议
R2 §6.5（四层评价）增一条："judge prompt 与被对标工作对齐并落盘；若无可对齐协议，则公开
prompt 并单列 judge 敏感性"。

**N5（停止/预算在训练型 SOTA 里同样缺席——对 R2 §4.4 是加强但须改措辞）。** 全文无推理期
轮数上限，只有 70,000 token 响应预算与 $K{=}3$ 连续工具错误的 fatal abort；"evidence
converges"仅为定性描述。→ 因此 R2 §4.4 表里 M2（value-per-budget + 双硬预算）/ M7
（oracle/headroom 报告行）**在这条视觉搜索线上同样为空**——它们的跨域出处是 donor lane
（ToolGate / VOI-search / FOVEA / M3-VQA），不是这条搜索 agent 线。R2 §4.2 轴结论现写
"视觉域把'获取要定价、证据要审计、oracle/gold-evidence 臂是标准报告行'变成共同实践"——
按本篇证据，这个"共同实践"**不含**视觉搜索 agent 主线（MMSearch / MMSearch-Plus /

oracle-TTC 且未标注）。建议把该轴结论限定为"视觉域的**donor lane**（工具门控/实验设计/协议化
四臂）已成共同实践；视觉搜索 agent **主线**尚未采纳"。这对 R2 是净加强（补的是**共同空白**
而非"落后补课"），但必须先把过度概括的措辞收回。
