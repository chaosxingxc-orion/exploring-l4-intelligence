## §1 方法本质

EChO-Agent 把复杂音频问答重写为一条四段固定流水线 **Tool → Evidence → Reason →
Verify**：一个文本 LLM 编排器（DeepSeek-V3）先按问题类型静态派发一组现成音频分析工具、
把它们的原始输出蒸馏成一份紧凑的"证据链"，再由冻结 LALM（Qwen3-Omni-Instruct 30B）
在**原始音频 + 问题 + 选项 + 该证据链**上作答，最后由同一个文本 LLM 做格式修复、
证据-答案一致性检查与双候选仲裁。工具池只有四类**感知**工具——YAMNet（音频事件检测）、
Whisper（ASR）、SpeechBrain wav2vec2（语音情感识别）、Essentia MIR（tempo/key/beat）——
**全篇没有任何外部知识检索动作**（无搜索引擎、无知识库、无 web），所谓"证据"完全是对同一段
音频的重表达。工具派发是 *question-type-conditioned static dispatch*：编排器判定问题类型后
查一张预定义映射表取固定工具组合，论文明写这样做是为了"消除随机工具选择带来的方差"；工具
失败最多重试 2 次，不可恢复则记 `[UNAVAILABLE]` 以防幻觉。作答阶段用两种配置（不同温度 +
证据顺序重排）跑两遍得到两个候选，仲裁阶段由编排器比较两条推理链的"证据对齐强度与内部
一致性"选出最终答案。全系统零训练、全部组件为已发布冻结检查点，但**最终答案由
DeepSeek-V3 发出**（$y^{*}=\mathcal{M}_{\text{L}}(\pi_{\text{ver}},q,\mathcal{E},
\hat y^{(1)},\hat y^{(2)})$），作答权不在冻结 omni 核。论文自身的定位语是：既有音频
agent（AuTAgent / AudioRouter / CoFi-Agent / AudioRAG）"主要处理获取了什么信息，而不是
信息如何被使用"——把创新点押在使用端。

## §2 六字段方法卡（对齐 R2 §2.1 格式）

| 字段 | 内容 |
|---|---|
| **组织** | **无任何持久知识组织**。不存在语料库、索引、快照、文档 ID、版本或出处 schema。唯一的"知识"是每题现场生成的观测集 $\mathcal{O}$ 与蒸馏后的证据集 $\mathcal{E}$，回合内易失、跨题不复用。证据条目带隐式来源标签（哪个工具）与工具自报置信度，但无落盘规范、无可复放合同。 |
| **供给** | 感知侧固定：问题类型 → 预定义工具组合（确定性查表），编排器把 $q$ 改写为每个工具的 directive $p_j$，$o_j=t_j(\mathbf a,p_j)$；每工具调用一次，失败重试 ≤2 次。作答侧固定：reasoning 恰好跑 2 遍（变温度 + 证据重排）。**无预算变量、无停止规则、无价值估计、无外部检索动作**。所有"多少"都是硬编码常数。 |
| **使用** | 这是全篇承重处，也是唯一接近 R2 准入门的机制。DeepSeek-V3 在结构化指令 prompt 下执行三操作：**relevance filtering**（丢弃与 $q$ 无关内容）、**cross-observation synthesis**（多工具重叠信息合并，按自报置信度或具体性解冲突）、**evidence structuring**（按使用顺序重排为证据链）。作答 prompt 强制 (i) 问题分解为子决策、(ii) 每个中间结论引用 $\mathcal{E}$ 中对应条目、(iii) 结构化输出。验证三查：格式合规（规则化修复）、推理-答案一致性（不一致触发答案更正或带定向反馈 $f^{(r-1)}$ 重生成）、双候选仲裁。**全部为 LLM prompt 级自由生成，无标量阈值、无 admit/reject 混淆矩阵、无 abstain。** |
| **changed vs held-constant** | **零训练**（held-constant 一切）：YAMNet、Whisper、SpeechBrain wav2vec2 SER、Essentia、Qwen3-Omni-Instruct-30B、DeepSeek-V3 全为现成冻结检查点，无微调、无 adapter、无 LoRA、无 RL。changed 的只有 prompt 与流水线拓扑。**但新增了一个深度介入作答环的文本 LLM**：DeepSeek-V3 既构造证据也发出最终答案 $y^{*}$。 |
| **runtime-visible vs gold-only** | runtime-visible：工具自报置信度（YAMNet 帧级置信、SER 置信）、工具可用性/失败码、两候选是否一致、格式合规性、CoT 与答案的自洽性。gold-only：accuracy（parsed option vs GT）与官方 MMAR rubric 分（instance-level rubric 保真度）——两者都只在离线评测出现，**未回流进任何决策**。**无任何 runtime 信号被用来决定"要不要多取一次证据"**：工具集与轮数都是常数。 |
| **数据/基线/指标/成本** | 数据：MMAR（多选题），按单类型/复合类型音频分层报告（Sound / Music / Speech / Sound-Music / Sound-Speech / Music-Speech / Sound-Music-Speech）。基线：端到端 Qwen3-Omni-Instruct（同 backbone、同 prompt、同解码配置）为主基线，另横比 7 个 OLM。指标：accuracy + 官方 MMAR evaluator 的 rubric 分（过程质量）。成本：**完全无记账**——无 latency、无 token 数、无调用计数、无 API 费用、无 GPU 时。四工具 + 两遍 reasoning + 仲裁的开销一个字未报。无 CI、无多 seed、无显著性检验、无样本量声明。 |

## §4 DFS 四问

**方法**：以文本 LLM 为编排器 + 四类冻结感知工具 + 冻结 LALM 作答 + 同一文本 LLM 做
证据蒸馏与仲裁的四段流水线；决策结构 = 确定性静态派发（供给）+ prompt 级自由生成
（使用/验证）+ 硬编码常数（轮数）。全程零训练。

**局限**：(a) 供给侧完全无自适应——工具集、调用次数、reasoning 遍数全为常数，没有任何
"这次取证值不值得"的判断，也没有停止规则；(b) 证据蒸馏与仲裁由 DeepSeek-V3 自由生成，
决策量不外显、不可审计、不可标定，且**最终答案由该文本 LLM 发出**，"增益来自外部证据
还是来自多了一个强文本 LLM"无法归因（与 R2 §1.4 对 AudioRAG 的同型批评完全一致）；
(c) 工具不确定性与跨工具冲突被作者列为**未来工作**——现有解冲突只是 prompt 里"比较自报
置信度或具体性"，无校准；(d) 零成本记账、零 CI、单 seed、n 未报，71.0 vs 68.7 的 2.3 点
差在无 CI 下不可判显著；(e) 纯 Sound 列负收益、两列并列，"复合音频增益最大"的叙事被自表
部分反驳；(f) 承认 sound 粒度被 YAMNet 的粗事件标签封顶。

**改进空间**：把工具派发从静态查表升级为按部署可见信号定价的自适应获取；把证据蒸馏从
自由生成改成外显标量准入门（可标定、可审计、不转移作答权）；给工具输出做置信度校准与
跨工具冲突的显式仲裁统计；补成本记账与 CI；把 rubric 分从终点指标改成过程诊断信号。
最直接的空位：**该论文自己指出的"工具不确定性 + 跨工具冲突"正是 R2 准入门的 $\gamma$
分量要处理的东西，而它明确不做**。

**可借鉴**：四类冻结感知工具的选型（YAMNet / Whisper / SpeechBrain-SER / Essentia）恰是
R2 `RE_RESOLVE_AUDIO` 的现成确定性实现候选，且与 R2 的假设槽型泛化一一对应（声音事件槽 /
言语实体槽 / 情感槽 / 音乐属性槽）；`重试 ≤2 次 → [UNAVAILABLE]` 的工具失败协议可直接
搬为 R2 的工程护栏；question-type static dispatch 可作 R2 A4a 臂"re-resolve 固定档"的
一个具体档位定义；MMAR 官方 rubric evaluator 可作 R2 §6.5 合理性层的过程保真工具（不进
主 leaderboard）。

## §5 R2 威胁面判定

### (a) 是否已做"部署可见信号估计外部证据动作边际价值"或"感知 vs 知识不确定性的动作分配"

**否，两项皆无，且缺得很干净。** 该系统**根本没有外部知识动作**——工具池四类全是对同一段
音频的感知重表达（R2 §1.3 的第②类信息作用），不引入任何实例级外部新信息。因此"外部证据
动作的边际价值"在其框架里无定义，"感知 vs 知识"的分配问题也不存在（只有感知一侧）。
供给侧的每一个"多少"都是硬编码常数；没有任何 runtime 信号回流进获取决策。

**需要更新的 R2 空位断言（读集内量词）**：

1. **§0 与 §4.3 的"本地读集内全部三篇 agentic 系统"必须改写——这是本批最硬的量词修复。**
   读集内的音频/omni agentic 工作在本批后至少 6–7 篇。且它们不是同质的一堆，必须**二分**：
   - **外部知识 agentic 线**（R2 的直接 incumbent）：AudioRAG 2602.10656、
     Omni-DeepSearch 2605.08762、VoiceAgentRAG 2603.02206；
   - **感知工具 / 模型编排 agentic 线**（**无任何外部知识获取**，因此不是 R2 对象的
     incumbent，但占据感知动作道）：EChO-Agent 2606.15141、Agent-Omni 2511.02834、
     NAP/OmniAgent 2606.19341、AuTAgent 2602.13685（另有代理深读）。
   现行 §0 的句子（"停在 LLM 自由决定+硬编码预算常数+检索结果无条件进上下文"）对第二线
   在**检索语义上不成立**（它们不检索），照抄会被评审判为量词失真。
2. **§4.3 第 2 点"检索结果无条件进上下文：无准入门"需加范围限定。** 该断言在外部知识线上
   仍成立，但读集内**已存在**一个作用在感知工具输出上的过滤/解冲突/重结构环节
   （EChO 的 Evidence Integration），且**其价值被量化了**。R2 不能再笼统说"使用轴停在
   无条件接纳"，须改为："外部知识线使用轴停在无条件接纳；感知工具线已有 prompt 级
   证据过滤（EChO），但为自由生成、无标量阈值、无 admit/reject 统计，且由新增文本 LLM
   执行并发出最终答案（红线不合规）"。
3. **§4.4 机制位表两行需修**：
   - **M1（pre-call 准入门）"三篇皆无"** → 仍成立（EChO 的过滤是 *post-observation*，
     不是 pre-call；它从不决定"这次调用值不值得买"）。但表头"三篇"要改为分线量词。
   - **M6（负信息增益 / 更相关≠更好）"语音域状态：无；无人检查检索页是否含答案"** →
     **必须更新**。EChO 提供了语音域第一处**聚合级**负增益读数：证据未结构化时
     65.4 < tool-free 68.7。仍无**实例级**检查（没人测单条证据是否含答案、是否翻转答案），
     所以准确写法是"已有聚合级负增益读数（EChO 65.4 vs 68.7），仍无实例级证据审计"。
     这条改动对 R2 **有利**：它是杠杆二（证据准入门）在音频域的直接效果论据，且不再需要
     完全依赖 Decocted 的跨域外推。
4. **§4.4 M7（oracle/headroom 报告行）"唯一 oracle 行=Omni-DeepSearch 实体分解"** →
   仍成立，EChO 无 oracle 臂、无 gold-evidence 行。

### (b) 调度/编排决策是训练的、prompt 自由生成的、还是确定性规则的

**三类混合，且分工清楚**：
- **确定性规则**：工具派发（question-type → 预定义工具组合的查表）、工具重试上限 2 次、
  reasoning 恰好 2 遍、格式修复（rule-based post-processing）。论文明确把确定性当卖点
  （"eliminating variance from stochastic tool selection"）。
- **prompt 自由生成**：证据蒸馏三操作、解冲突（比自报置信度/具体性）、一致性检查、
  双候选仲裁——全部由 DeepSeek-V3 在结构化指令 prompt 下自由产出，无外显标量、无阈值、
  无标定。
- **训练**：零。

**对 R2 的含义**：EChO 是"确定性派发 + 自由生成使用端"的组合，恰好与 R2 反过来
（R2 要的是**确定性使用端 + 自适应供给端**）。因此 R2 §6.2 "与自由生成 controller 的
可识别差异"这一段现在有了一个比 AudioRAG 更贴的对照物，且 EChO 的静态派发可直接充当
R2 §5.3 "固定档阶梯"的一个已发表档位。

### (c) 与 R2 的 RE_RESOLVE 动作的关系

**EChO 本身不占据 RE_RESOLVE**，但它的参考文献指出了一个占据者，这是本篇最重要的
新事实之一。

- **它自己不占**：工具在第一段一次性跑完，之后不再回看音频；reasoning 阶段虽然重跑两遍
  且每轮注入诊断反馈 $f^{(r-1)}$，但**每轮吃的是同一份 $\mathcal{E}$ 与同一段原始音频，
  没有新的感知动作**——没有"按不确定性触发的重听"，没有重呈现一致性度量。R2 的
  `audCons`/`disp(H_t)` 在其中无对应物。
- **它的 intro 与 related work 明写这是 LALM 的结构缺陷**：*once subtle cues are missed,
  the model cannot revisit raw audio to verify hypotheses or recover evidence*——
  与 R2 §1.2 的问题陈述同构，可作为"重听机制真实存在"的第三方论据（R2 目前只靠
  Omni-DeepSearch 的 oracle 分解与 A.6 轨迹）。
- **新发现的占位者（重要）**：其 bib 收录四篇 Interspeech 2026 ARC 同批系统，其中
  **`cofiagent2026` = "CoFi-Agent: Coarse-to-Fine Uncertainty-Triggered Re-Analysis for
  Audio Reasoning"**，正文描述为 *adds coarse-to-fine uncertainty-triggered
  re-analysis*——**按标题即占据"不确定性触发的音频重分析"这一方法位**，正是 R2
  `RE_RESOLVE` 的触发机制。另三篇：`autagent2026`（RL 学工具选择策略，=已在读的
  2602.13685）、`audiorouter2026`（工具路由与推理模型解耦）、`audiorag2026`（检索增强
  多跳音频推理，描述与 R2 主载体 AudioRAG 2602.10656 吻合但**不可假定同一篇**）。
- **如实声明其证据强度**：这四条 bib 条目**全部是占位式**——作者字段写作
  `{CoFi-Agent Team}` 一类、无 arXiv id、无 DOI、无页码，仅 `note = {Audio Reasoning
  Challenge submission}`。因此它们是**线索，不是证据**；不得据此改写 R2 任何承重断言。
- **对 A4b 独立性论证的影响**：EChO 本身不构成威胁（不占 RE_RESOLVE、不做外部知识）。
  真正的威胁来自 NAP（见该篇 D2 §5c）与这条 CoFi-Agent 线索。**处置建议**：把
  "CoFi-Agent 全文获取与 D2 深读"升为 R2 §9 authorization 前义务清单的**一等条目**，
  与"三篇检索线检查点发布状态核查"同级——它是读集内按标题最接近 R2 `RE_RESOLVE` 触发
  机制的具名工作，在拿到全文前，R2 不得声称"不确定性触发的音频重听在语音域缺席"。

### (d) 红线关系与可搬组件

**红线三条逐条**：
1. **不修改冻结核参数** → **合规**。Qwen3-Omni-Instruct 全程冻结，无微调。
2. **不为本任务新训练任何模型** → **合规**。四工具与两个 LLM 全为已发布检查点。
3. **不新增 LLM 代答** → **违反，且是硬违反**。最终答案 $y^{*}$ 由 DeepSeek-V3 在
   $\pi_{\text{ver}}$ 下发出；不一致时"answer correction"也由它执行。冻结 omni 核只
   产出候选 $\hat y^{(1,2)}$。故 EChO 的 71.0 **不可作为 R2 的可达目标或臂**，只能作
   方法论对照——且它是 R2 §1.4 "增益无法归因到外部知识还是多了一个模型"这条批评的
   第二个干净实例（第一个是 AudioRAG 的 Qwen3-8B controller）。

**可搬组件（红线内）**：
- **四类冻结感知工具**作为 `RE_RESOLVE_AUDIO` 的确定性实现：YAMNet→声音事件槽、
  Whisper→言语实体/事件槽、SpeechBrain wav2vec2 SER→情感槽、Essentia MIR→音乐属性槽。
  这直接支撑 R2 §6.2 的 `audCons`（音频重呈现中首选假设被复现的比例）在**四个槽型上
  都有现成算子**，并给 §9 的"多面 key 冻结编码器选型"提供一组已在音频 agentic 论文里
  用过的候选（需另核检查点许可与版本）。
- **工具失败协议**：重试上限 + `[UNAVAILABLE]` 占位（防幻觉）→ R2 工程护栏。
- **question-type static dispatch**：作 A4a 的 re-resolve 固定档定义（R2 §6.1 现写
  "从 {0, 每题至多 1 次前置重听} 中按 dev 最优选定"——可扩展为"按槽型标签查表派发固定
  工具组合"这一已发表档位）。
- **MMAR rubric evaluator**：R2 §6.5 合理性层的过程保真度工具（离线诊断，不进主榜）。

**不可搬**：DeepSeek-V3 证据构造器与仲裁器（作答权转移）；双候选仲裁作为终局裁决
（同因）；prompt 级解冲突（不可标定，与 R2 要求的确定性 `confl` 相冲）。

### (e) 是否提供新载体/基线数字

**提供，但不是 R2 主载体；提供两个高价值基线事实。**

- **新载体：MMAR**（多选题 + 官方 rubric evaluator + 单/复合音频七层分层）。
  **不能作 R2 载体**：无外部知识需求，全部答案由音频本身决定（R2 §1.3 的第②/③类作用），
  按 R2 的信息角色边界落在主张分布之外。**可用处**：(i) §6.5 合理性层的过程保真指标来源；
  (ii) 讨论 §5.4 近地板风险时的对照口径（见下）。
- **基线数字（对 R2 §5.4 直接有用）**：**Qwen3-Omni-Instruct 30B 在 MMAR 上 68.70%
  accuracy / 58.7 rubric，Qwen3-Omni-Thinking 30B 69.00%**。对比 R2 主载体
  Omni-DeepSearch-640 上本核 Thinking 仅 6.56。**这说明本核的近地板不是"音频推理能力
  地板"，而是"音频驱动外部知识搜索这一任务形态上的地板"**——两个口径同核、同规模、
  差一个数量级。这条对比对 R2 是双刃的：一方面它支持"缺的是知识获取的控制面，不是感知
  能力"这一叙事（有利）；另一方面它加重 §5.4 的担忧——6.56 可能反映的是**任务形态级
  能力缺失**而非可被 training-free 控制面修复的调度缺陷。建议 R2 §5.4 明写这组对比并
  给出处置：灵敏度前置检定不通过就走回退梯，不得把"感知能力尚可"当成"搜索调度可抬升"的
  证据。
- **第三个可引数字**：Gemini 2.0 Flash MMAR 65.60 低于 Qwen3-Omni-instruct 68.70——
  与 Omni-DeepSearch 表上 Gemini-3-Pro 43.44 远超本核 6.56 的排序**相反**。即"闭源
  模型在音频推理上未必强于本核，但在音频驱动搜索上强一个数量级"，进一步定位落差在
  **agentic 搜索控制面**而非音频感知。这是 R2 §0"这段落差就是 R2 的台阶"的一个新的、
  独立于主载体的支撑点，建议纳入 §1 或 §5.4（标注为跨载体跨核对比，不得合成为单一读数）。
