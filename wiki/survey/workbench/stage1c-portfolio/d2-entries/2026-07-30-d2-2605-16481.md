## 1. 方法本质

把无界视频流变成**可搜索、可复检、可引用**的记忆底座，全流程 **training-free**。三层耦合：
(1) **Online Indexing**：拉普拉斯方差模糊门（`τ_blur`=20）+ 预嵌入冗余门（SSIM `τ_ssim`=0.92 等）
先做廉价前置级联，通过的帧才进嵌入模型；再以余弦距离对参考帧做**自适应去重**——维护滑动距离直方图
`H_d`，用 **Otsu 分割**导出 `τ_dedup`（样本不足时退回固定 0.88），`d_c > τ_dedup` 时提交一个 **moment**
（保留原帧+嵌入+相对/绝对时间戳）并重置参考；同一套 Otsu 峰值分析在 moment 距离序列上切 **event** 边界
（最大事件时长 300 s 兜底）。严格在线、不访问未来帧。
(2) **Hierarchical Memory**：event 内维护四件——保留的 moments、帧嵌入、**MLLM 写的 event summary `C_i`**、
时间元数据 `(t, T)`；并按年龄分 recent/mid/long 三层做**保真度递减**保留（Table 5）。
(3) **Agentic Retrieval**：MLLM 作为规划器，在 `{search, inspect, summarize, answer}` 上跑有界多轮循环，
搜到的候选一律先 `inspect`（直接看原帧）再答，答案必须挂一个 `best_ref = (turn_idx, result_idx)` 指针。
索引与检索由异步编排解耦。

## 2. key-value 定位 ⚠ **本节含改变 R2 空位断言的发现**

### 2.1 value 是什么

同一份底层证据：**保留的原始帧（moment）+ 其所属 event 的时间区间**。原帧被显式声明为 "first-class
evidence"，query 时可回看（这是本文相对"压缩记忆"范式的立论点）。

### 2.2 key 有几层、几面

**三个可寻址的检索结构 + 一套结构化时间键，全部指向同一份 event/moment 证据**：

| key | 模态 | 表示 | 构建时机 | 打分式 |
|---|---|---|---|---|
| `frame` | **视觉** | 帧嵌入 `e_t`（Gemini Embedding 2；论文写"具体实例化是实验选择"，引 CLIP / Frozen-in-Time） | 在线索引期，逐帧 | `S_VIS(F_t) = cos(q_k, e_t)` |
| `event` | **文本** | MLLM 写的 event document `C_i = MLLM(E_i)` 的嵌入 `v_{d_i}` | 在线索引期，event 封口时 | `S_TEMP(d_i) = cos(q_k, v_{d_i})` |
| `summary` | **文本** | 跨 event 聚合的 summary document（按时间窗口物化） | **query 期按需物化**并持久化回记忆 | 同 `S_TEMP` |
| 时间键 | 结构化（非嵌入） | `time_range`：`relative/absolute/auto` 三模式；单锚点或双锚点区间；锚点前后各至多 7 天（604800 s） | 索引期写入 `(t, T)` | 精确/区间过滤，不打分 |
| `visual_ref` | 视觉 | 以图检索（appearance-based retrieval） | query 期给定 | 附加检索算子 |

层级关系：`frame ⊂ event ⊂ summary`（粒度递粗），**且三层共享同一套时间元数据锚点**，
论文明确写"the two pathways share metadata, so retrieval can move from event-level temporal hypotheses
to frame-level spatial evidence without alignment loss"。这就是它称的 **Parallel Representation**。

### 2.3 ⚠ **本篇已具备"同一 value 的多面（且跨模态）key"** —— 直接触及 R2 §3.2 的空位断言

- `event`/`summary` 键是**文本模态**的 key（MLLM 对同一段视频写的描述的嵌入），
  `frame` 键是**视觉模态**的 key（同一段视频的帧嵌入本身）。二者**并置、指向同一份 value**，
  并在同一次 `search` 里被**同时**打分（论文原话："`search` consults two pathways within a hybrid
  retrieval step"），分工写明：`S_TEMP` "prioritising situational context"（语义/情境面），
  `S_VIS` "pinpointing object-level details"（外观/对象面）。
- 因此 R2 draft 第 321–323 行"读集内 …… **未见跨模态多面 key**（语义面与副语言/场景面并置指向同一
  value）"**在"语义面 + 外观/场景面"的读法下已被本篇占据**。仍然成立的只有更窄的版本：
  **无副语言面 key、无音频模态 key**。见 §5 判定 C/D。
- 论文自己在 Appendix A（Limitations）第一条 "Modality asymmetry" 把这个缺口点名了：
  "it does not yet preserve original audio at the same granularity or maintain an equally rich substrate
  for speech, ambient sound, or other non-visual cues. Many real-world queries depend on such evidence,
  including **speaker identity, verbal commitments, and alarms**." —— 这是**论文亲口留给 R2 的空位**，
  比 R2 现有的措辞更有力，且可直接引用。

### 2.4 query 如何路由到层/面 —— **R2 O2"query 按槽型路由"的现成机制在此**

三级路由，全部由**冻结 MLLM 在严格 schema 下自报**，无训练：

1. **顶层路由**（Table 7 第 1 行，`light` 路由，T=0.0、max_tokens=300）：把用户请求归为
   `final` / `retrieve` / `summarize` 三选一，只允许一个 JSON 对象。
2. **面选择（关键）**：planner 的 `search` 动作带一个 **`sources` 字段 = `{frame, event, summary}` 的任意子集**
   （Table 6 明确写 "Allows the planner to explicitly target different memory structures"），
   外加 `summary_filter`（按 structure 标签/粒度过滤）、`visual_ref`（以图检索）、`joint_inspection`。
   系统提示词还写了 intent parsing："decomposes user intent into executable sub-queries with explicit
   temporal constraints, target entities, **operator selection, and source prioritisation**"。
   **这正是 R2 §3.4 O2 里列的"冻结核在固定 prompt schema 下自报槽型标签选面"那一支，已有现成实现。**
3. **预算/宽度参数也由规划器自报**：`top_k ∈ [1,200]`、`inspect_k ∈ [0,50]`（clip 到 top_k）、
   `threshold ≥ 0`（schema 默认 0.65）、`inspect.max_frames ∈ [1,16]`。
4. **执行纪律**：所有动作载荷过 **Pydantic 严格 schema（`extra="forbid"`）**；首轮 JSON 非法则追加一次
   "ONLY one valid JSON object" 修复重询，仍失败则回落到一个宽松 `search`，不终止循环。
   这套"结构化控制面 + 一次修复 + 确定性回落"是 R2 O2 路由**可直接照搬的工程规约**。
5. **R2 提到的另一支（"不路由、查全部面后按预注册权重融合"）在本篇只做到一半**：`search` 确实同时打两条
   路径的分，但**论文没有给出 `S_TEMP` 与 `S_VIS` 的融合公式或权重**——只写了两个分数式，
   如何合并候选、如何跨路径排序**在正文与附录中均缺失**。这是本篇的一处方法空洞，也是 R2 可以补的点。

## 4. DFS 四问

**方法**：训练自由的三层视觉记忆——Otsu 自适应边界的在线索引（保留原帧为一等证据）+ 事件级层次记忆
（帧嵌入 / MLLM 事件文档 / 按需物化的摘要文档三条平行检索路径 + 共享时间锚点）+ 冻结 MLLM 在
Pydantic 严格 schema 下跑 `search/inspect/summarize/answer` 有界循环，答案挂具体证据指针。

**局限**：(a) **净增益极小且指标是自选的复合**——RT+BT +0.95，而 Overall −2.07、Fwd −8.14；
(b) **零消融**，"多面 key + agentic 检索"三件套的贡献无法分离，甚至无法确认平行表示是否有用；
(c) 两条路径的分数**没有融合规则**，`S_TEMP`/`S_VIS` 如何合并排序在正文与附录均缺失；
(d) MM-Lifelong 上 n=266、无 CI、无种子，前三名差距在 1 个 SE 内；
(e) **代价只量了存储帧数，未量延迟/token/费用**，而作者自承成本"substantial"；
(f) 全部数字绑定在闭源 Gemini 3 Flash + Gemini Embedding 2 的 API 上，无开源复现路径；
(g) 论文自承 Fwd 模式差是设计后果（"evidence-seeking and citation-oriented" 的控制器会过早提交），
即**证据优先的检索取向与"等待未来决定性证据"的校准目标冲突**——一个真实的机制级取舍；
(h) 长程扩展的自承缺陷：索引期漏掉的边界"cannot be recovered downstream"，即写入决策不可逆。

**改进空间**：(1) 补最小消融：`sources ∈ {frame} / {event} / {frame,event,summary}` 三臂
——这正好是 R2 O1 vs O2 在视觉域的对照，**本篇留了空位**；(2) 给出 `S_TEMP`/`S_VIS` 的显式融合
（预注册权重或 RRF），本篇的空洞恰是 R2 可以定义清楚的地方；(3) 对 Table 5 的三层保真度做扫描，
把"保真度 vs 存储"从默认配置变成真正的曲线；(4) 补音频面 key（作者自己点名 speaker identity /
verbal commitments / alarms）。

**可借鉴（对 R2，价值最高的一篇）**：
① **`sources` 子集选择 = query→面路由的现成实现**，且是 R2 §3.4 明确列出的两支路由之一
（"冻结核在固定 prompt schema 下自报槽型标签选面"），已被证明可在冻结核上跑通；
② **Pydantic 严格 schema（`extra="forbid"`）+ 一次修复重询 + 确定性回落**——R2 的"确定性两选一、
authorization 预注册"可直接采用这套控制面纪律，附录给了完整提示词与约束清单（Table 6/7）；
③ **`best_ref = (turn_idx, result_idx)` 指针 + 缺失时回落到最高分候选**——一套可复放的引用/归因机制；
④ **`inspect_k` 前瞻 + `joint_inspection` + anchor adjudicator（严格 JSON：`match/confidence/
observed_event/reason`）**——"检回来的东西信不信"这一 R2 核心决策的一个具体算子集合；
⑤ **Otsu 自适应阈值替代固定阈值**（滑动统计上导出门限，统计不足时回落）——R2 若需在部署时可观测信号上
定门限，这是一条免训练、无 gold 依赖的做法；
⑥ **一条负面教训**：三层记忆 + agentic 检索堆上去，在同一底座上只换来 +0.95 的自选复合指标、
Overall 反降 2.07。R2 的 O 臂必须预注册主指标，并同时报"未被选进复合指标的那些维度"。

### 深读后新增、R2 应该知道的事实

1. **R2 的空位断言必须收窄（最重要）**：详见判定 D。当前措辞会被评审直接以本篇击穿。
   建议的替代措辞已在 D 中给出，且**收窄后 R2 的 O2 仍然站得住**——本篇的面是"视频语义 vs 视频外观"，
   不含副语言/说话人/声学场景，且没有融合规则、没有对照实验。
2. **R2 O2 的"query 按槽型路由"可以借，而且借到的是完整实现**：`sources ⊆ {frame,event,summary}`
   + `summary_filter` + `visual_ref` + `joint_inspection`，全部由冻结 MLLM 在 Pydantic
   `extra="forbid"` schema 下自报，附录给了逐字提示词与全部数值约束（Table 6/7）。
   R2 §3.4 写的"两选一"其实**在本篇是同一个动作里的两件事**（选 sources 子集 = 路由；子集取全 = 查全部面），
   这比 R2 现在的"或"关系表述更干净，建议吸收。
3. **本篇没有跨面融合规则**——`S_TEMP` 与 `S_VIS` 两式并列，如何合并候选、如何跨路径排序全文缺失。
   R2 的 O2 若给出"预注册权重取最大相似度融合"的确定性规则，这是**相对本篇的真实增量**，
   而且是可以在 authorization 里预注册、可审计的那种增量。
4. **训练环节：零**。R2 引用时可放心地把本篇归为 training-free 组织的正面先例（与 TFRL 北极星相容），
   无需像 15019 那样区分 SFT 支线。
5. **"组织不是免费的"这句话，本篇提供的是间接但更锋利的证据**：同一底座 Gemini 3 Flash，
   加上三层记忆+agentic 检索后 **RT +6.50 / BT −4.58 / Fwd −8.14 / Overall −2.07**，
   净收益只出现在一个把 Fwd 排除的复合指标上（+0.95）。这是"组织带来重分配而非纯增益"的直接读数，
   比 R2 现在挂在 2605.14906 上的说法更适合支撑"组织有代价"。作者自己也把 Fwd 的退化归因于设计取向
   （evidence-seeking 控制器会过早提交），是机制级而非噪声级的解释。
6. **本篇的"代价"只有存储维度**（Table 2：0.06% 帧），**没有延迟/token/费用**；作者在 Limitations
   自承成本 substantial。R2 若要引"保真度/成本权衡"，本篇**不能作为成本轴的量化来源**。
7. **零消融**：R2 若把本篇当作"多面 key 已被证明有用"的证据会出错——本篇从未隔离测量过平行表示的贡献。
   反过来说，**O1 vs O2 的隔离对照在视觉域也还是空的**，这对 R2 的 O 臂是有利的空位。
8. **一条可引的规模事实**：MM-Lifelong month-scale 上人机差距 82.5% vs ≤17.62%（>65 pp），
   作者称该基准"explicitly exposing the working-memory bottleneck of end-to-end MLLMs and
   global localisation collapse in agentic baselines"——可作 R2 §3.2 演进段"组织问题远未解决"的收束句。
