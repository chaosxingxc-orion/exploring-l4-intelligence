### 2510.11454 — Audio-Maestro: Enhancing Large Audio-Language Models with Tool-Augmented Reasoning (Lee, Lin, Lee; NTU + ASUS; arXiv 2510.11454v1, 13 Oct 2025)

**方法面（method surface）**：MECHANISM: a two-phase, fully prompted (zero-shot, no fine-tuning) tool wrapper around a frozen LALM. Phase 1 (Sec 3.2) is a single binary decision a_decision = M_LALM(x_audio, q, T) in {Ans, C} - answer directly, or emit one-or-more Python-style tool calls. Phase 2 (Sec 3.3) executes every selected tool on the SAME audio, y_k = t_k(x_audio), serializes each into timestamped JSON, and concatenates: c_aug = Concat(x_audio, q, y_1..y_|Tsel|); the LALM then answers from c_aug. Note the core keeps the raw audio in Phase 2 - the tool evidence is additive, not a replacement (this is what the 'Text Only + Tool' ablation isolates). SIGNALS USED: none beyond the LALM's own prior over tool descriptions. No score, no confidence, no reward, no execution feedback - the decision is made BEFORE any tool output is seen and is never revised. DECISION RIGHTS HELD: (a) call-or-not, (b) which subset of 13 tools. DECISION RIGHTS ABSENT: no stop, no abstain, no repair/re-call after seeing tool output, no budget or cost term, no arbitration between the direct answer and the tool-augmented answer (Phase 2 output is committed unconditionally), no cross-instance memory. CORE: frozen; gradient use: zero. ### 2407.09886 — Speech-Copilot: Leveraging Large Language Models for Speech Processing via Task Decomposition, Modularization, and Program Generation (Kuan, Yang, Huang, Lu, Lee; NTU; arXiv 2407.09886v2, 23 Sep 2024; IEEE SLT 2024 pp.1060-1067)

**方法面（method surface）**：MECHANISM: two offline-then-online phases. PHASE A - toolset construction (Sec 3.1). A.1 Task decomposition: given N diverse task instructions {I_i} (>50, GPT-3.5-synthesized), an LLM maps each instruction to its task via chain-of-thought, then - crucially - considers ALL instructions SIMULTANEOUSLY (not instance-by-instance) to induce a compact sub-task set {T_j}^M such that every task T_i = h_i({T_j | j in J}) for some combination function h_i (Eq. 1); self-reflection is then applied to de-duplicate near-identical sub-tasks. A.2 Task modularization: the LLM converts each sub-task into a documented code module with a fixed 5-field spec - (1) module name, (2) objective/task info, (3) input with data type and format, (4) output with data type and format, (5) example usages showing solo AND compositional use. Humans then bind each module to a concrete speech model under two stated selection principles: 'Scientific support' (only models with public papers/tech reports) and 'Clear guidelines' (documented setup/run commands). PHASE B - program generation (Sec 3.2). The agent pi produces z = pi(q | {f_i}) via four steps: identify task T from query q; determine combination h and sub-task set T_q; select the relevant modules f_q; emit a Python program that calls f_q and composes results with h. The program is then executed by a Python interpreter on the audio. SIGNALS USED: none - selection is entirely the LLM's prior over module documentation; no reward, no execution feedback, no retry. DECISION RIGHTS: which modules, how to compose them (including conditionals/iteration - Table 4 shows 3.9 reasoning steps vs 1.6 modules on average, so real control flow, not just a call list), and implicitly how much to spend. ABSENT: no stop/abstain, no repair on program exception or empty module output, no re-plan after execution, no credit assignment to modules, no cross-instance memory, no skill induction from execution traces (the module set is frozen after Phase A). CORE: everything frozen; no gradients anywhere; the controller LLM is GPT-4o (2024-05-13) for construction/generation/evaluation and GPT-3.5-turbo-0125 inside modules. IMPORTANT ARCHITECTURAL NOTE: the controller never hears the audio - it programs over text module outputs only. 16 modules (Table 3): ASR, language ID, speech detection, SER, SNR, reverberation detection, accent classification, stress position, spoofing detection, chord classification, synthetic-speech detection, speaker verification, diarization, sound classification, Query-LLM, speaker distance. BENCHMARK: Dynamic-SUPERB, 55 tasks over six aspects (AUD/CNT/DEG/PRL/SEM/SPK), MCQ, GPT-4o-as-judge + human verification.

**自述与显见局限**：STATED (Sec 6 Conclusion and Future Work, phrased as future work rather than a Limitations section - the paper has none): (1) 'Our future work could explore using multiple modules or foundation models for each function' - i.e. the current one-model-per-module binding is a hard-coded allocation, admitted as suboptimal; (2) 'and applying reinforcement learning from human feedback [55] to optimally select the best module for a given task' - the authors themselves name module-selection credit assignment as the missing piece; (3) 'to address the evolving and diverse nature of speech-processing tasks, we could expand the coverage of modules to tasks challenging for current speech foundation models' - module coverage is a static, offline-fixed ceiling. EVIDENT (not owned): (4) The controller is text-only; every acoustic fact must survive a module's textual serialization. Audio-Maestro's Text-Only+Tool ablation later quantifies this loss on the same family of toolkits (DeSTA Test 52.61 text+tool vs 63.06 with audio). At inference both paths are still producible from a frozen core; only the gold indicator is missing. Substituting a label-free arbiter for that indicator - consensus margin between resampled tool and no-tool answers, with an evaluator tested as a margin arbiter on top of consensus - is the one step that converts the field's best credit signal into a runtime decision rule, and no paper in the trio runs the comparison at inference. Speech-Copilot names the same gap in its own words ('applying reinforcement learning from human feedback [55] to optimally select the best module for a given task', Sec 6 verbatim).【复核更正 wf_5f1f5801】 (b) DECISION IS PRE-OBSERVATION AND SINGLE-SHOT EVERYWHERE. All three commit to a tool set before any tool output exists and never revise. Post-observation rights - discard the evidence and fall back to the direct answer, call one more tool, stop, abstain - are unoccupied across all three: stop/abstain unoccupied in the tool/skill dimension read set (and only weakly occupied elsewhere in audio-omni per D2)【复核更正 wf_5f1f5801】. Audio-Maestro's Improved/Degraded table makes the first of those rights immediately quantifiable: of tool calls that change the answer, 41.6-43.5% change it the WRONG way (Gemini 10.75 improved vs 7.65 degraded; DeSTA 15.53 vs 11.71; GPT-4o 11.13 vs 8.57), and it is Audio-Maestro's EVALUATION (via a separate no-tool run), not its deployed pipeline, that computes both candidates -- a deployed arbiter would cost one extra frozen-core pass per item. A 2-candidate best-of-N arbiter over {direct, tool-augmented} is the degenerate TFRL case, is run by nobody in this trio's read set, and is not free.【复核更正 wf_5f1f5801】 (c) TOOL-OUTPUT RELIABILITY IS UNMODELLED WHILE BEING THE DOMINANT FAILURE MASS. Audio-Maestro's error taxonomy attributes 73.3-90.0% of post-tool failures to Tool Output Error versus only 6.7-16.7% to Incorrect Tool Selection (Table 4). AuTAgent - the newest paper - does not address, measure, or cite this. Cross-tool consistency, tool self-consistency under perturbation, and output-shape sanity are all gradient-free and all absent. (d) NO SKILL INDUCTION FROM EXPERIENCE. Speech-Copilot mines sub-tasks from INSTRUCTIONS offline and freezes the module set; none of the three papers read mines recurring successful programs or tool sequences from execution traces into new named skills.【复核更正 wf_eefb24e7】 Combined with the absence of cross-instance memory in all three, the 'induction' half of the charter question is empty. (e) NO CONFLICT RESOLUTION. When two tools disagree about the same span, no paper has a rule; evidence is concatenated and the frozen core arbitrates implicitly. (f) NO COST TERM. AuTAgent's parsimony (1.30 vs 1.62 avg tools) is an emergent side-effect of its zero-reward rule, not an allocation objective; Audio-Maestro states latency as a limitation and measures nothing; Speech-Copilot argues cost qualitatively. Explicit budget/risk allocation is not run in this dimension's read set (3 papers, D3 read surface, 2026-07-26).【复核更正 wf_5f1f5801】 (g) EVIDENCE-LEVEL RATHER THAN TOOL-LEVEL SELECTION is untried: run several tools cheaply, then admit only evidence that survives an arbiter - this decouples acquisition cost from context pollution and directly targets the All-Tools collapse.

GATES AND RISKS. (1) THE TRAINED BOUNDARY IS +3.0 TO +4.3 over prompted routing (AuTAgent Table 2: Qwen2-Audio 51.20->54.20 MMAU / 37.50->41.30 MMAR; GPT-4o Audio 62.90->67.20 / 60.00->63.00). Any gradient-free credit mechanism we build is judged against that band ON THE SAME tool library and frozen core, and the honest comparison also carries AuTAgent's cost (8xA100, 200 GRPO steps, ~2,025 gold-labelled items, 1 baseline + 6 rollout = 7 reasoner forward passes per training item) as the thing we avoid paying.【复核更正 wf_5f1f5801】 (2) BASELINES ARE NOT PORTABLE BETWEEN PAPERS - Audio-Maestro reports a closed-source GPT-4o MMAU test-mini vanilla at 62.50 while AuTAgent reports GPT-4o Audio at 57.40 on the same split, and neither paper pins an API snapshot or a consistent model identifier.【复核更正 wf_5f1f5801】 Any comparison table we publish must re-run its own vanilla, prompted-routing, all-tools and random arms; citing cross-paper vanillas would be a fabricated comparison. (3) THE ROUTING CEILING IS BOUNDED ON A GOOD LIBRARY. The charter's premise that signal-driven allocation has measured headroom is supported by the ARC waste statistics and by AuTAgent's All-Tools collapse, but Audio-Maestro's own attribution puts selection errors at only 6.7-16.7% of failures on a well-documented tool kit (13 tools claimed in text; 12 enumerated in Table 1 and Table 5). That 6.7-16.7% figure is a share of a hand-labelled sample of POST-TOOL ERRORS ONLY (n=30 per model, 3 annotators, no inter-annotator agreement reported) and does not bound allocation headroom -- AuTAgent's ~11.9-point post-RL single-tool oracle gap points the other way. Expect allocation alone to have a modest ceiling and expect verification/arbitration on tool OUTPUTS to carry more of the gain -- restate this as a hypothesis to be measured on our own stack, not a preregistered prediction, until the two readings are reconciled.【复核更正 wf_5f1f5801】 (4) ORACLE HEADROOM SURVIVES RL: AuTAgent's single-tool oracle is 66.1 vs its achieved 54.2 on the same backbone (Fig. 2, Table 2) - ~11.9 points still unclaimed after training; the combination oracle is not lower than 66.1 (single-tool oracles are a subset) and is unmeasured, and 66.1 itself excludes the no-tool action so it is not a strict upper bound on AuTAgent's action space.【复核更正 wf_5f1f5801】 This is the strongest published argument that the decision problem is not solved by better weights. (5) BLACK-BOX COMPATIBILITY IS FINE. AuTAgent's frozen-reasoner decoupling exposes only (audio, question) -> tool indices -> text answer; no weights, gradients, hidden states, attention or logprobs cross the boundary. Its selector, however, is trained, so we adopt its MEASUREMENTS and PROMPTS, never its mechanism. (6) METRIC RISK: all three are MCQ-accuracy-only on MMAU / MMAR / Dynamic-SUPERB, consistent with the standing caution that token-level metrics under-report wrapper gains; Audio-Maestro's Improved/Degraded 2x2 is the better instrument and should be our primary report alongside accuracy. (7) REPRODUCIBILITY: Speech-Copilot is pinned to gpt-4o-2024-05-13 and gpt-3.5-turbo-0125 (legacy snapshots) so its numbers are historical, not comparable; AuTAgent's 2,025-item training split has no released ID list or seed; AuTAgent states no code release in-text.

BASELINE IMPLICATIONS FOR OUR PROGRAM. Adopt AuTAgent Sec 2 / Fig. 2 as the mandatory preliminary-analysis design - No-Tool, Single-Tool Isolation per tool, All-Tools, and a post-hoc any-tool-succeeds oracle - before any controller is written; it establishes both the floor and the ceiling of the action space on our own stack. Adopt AuTAgent App A.1 verbatim as the prompted-routing incumbent; App A.2's name-blinded variant is AuTAgent's own treatment-arm prompt, not a control the paper ran, so using it to separate prior-driven from signal-driven routing requires us to run our own 2x2 (blinded/described x trained/prompted). Adopt Audio-Maestro Table 3's Improved/Degraded/Both-Correct/Both-Wrong protocol and App A.5's TOE/ICT/RME annotation packet as the failure-attribution instruments -- these, plus AuTAgent's any-tool-succeeds oracle, all consume gold labels and are licensed for offline evaluation and one-time calibration only; no runtime controller may read their output.【复核更正 wf_5f1f5801】 Adopt Speech-Copilot Sec 3.1.2's 5-field module schema as our tool-registry contract (it is the only one carrying compositional usage examples) and its Table 4 steps-vs-modules statistic plus AuTAgent Table 4's accuracy-x-avg-tools pairing as the dual-axis report card. Standardize on a common {tool, output} envelope with a per-tool payload type: timestamped spans are the shared choice only for span-valued tools (chord, and Audio-Maestro's stated general design) -- four of AuTAgent's six App B payloads are scalar/label/string, not timestamped spans -- and on the six-to-thirteen open tool implementations both list.【复核更正 wf_5f1f5801】 The single most concrete open composition this dimension leaves us: a training-free, label-free counterfactual arbiter that decides post-observation whether tool evidence is admitted, exercising discard/stop/abstain rights on a frozen omni core - measured against the +3.0-to-+4.3 trained-gate band on accuracy AND on average calls, with the Improved/Degraded 2x2 as the diagnostic that shows where the gain came from.
