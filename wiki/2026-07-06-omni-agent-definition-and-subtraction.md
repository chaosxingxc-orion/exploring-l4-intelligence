An omni agentic system is a **frozen** speech/omni multimodal LLM embedded in an inference-time agent scaffold — controller, tools/skills, memory, knowledge/RAG, and verifier — steered only by **reward-guided, training-free** means (no weight or structure change) to activate the model's pretrained knowledge.

## Organizational-form subtraction — the method

For each capability we **subtract** the modality-agnostic reasoning layer (what a text LLM supplies once a percept is serialized to text) from the full capability. The remainder is the **multimodal organizational form**: the part that (a) is triggered by a *non-lexical* signal (a property of the waveform that survives when the words are held constant), and (b) instantiates a *signal-in / structured-cross-modal-out* I/O contract a text-in/text-out model cannot express. We classify each capability's remainder as a distinct research object *from its own evidence* — we do **not** apply a blanket "commodity" verdict (an earlier internal pass did exactly that by over-generalizing a cascade test; this deliverable corrects it with the three-column cut below).

The governing constraint is the machine-checked **InfoBoundary** result: selection/orchestration over a *fixed* element set is bounded by the frozen model's own **oracle@N**; a capability crosses that ceiling only through a **new-info element** or an **in-contract decoding edit**, never through best-of-N/reward-guided selection alone. This is a constraint on *which lever* can work, not a verdict on which capabilities are commodity.

## Per-capability detail (with tier tags, IDs, and folded-in corrections)

### Perception — the single genuinely distinct form (distinct = YES; front-end only)

Perception's *extraction front-end* is the one capability where the frozen omni supplies decision-relevant information a text LLM structurally cannot recover from any transcript: for pure sound/music items the transcript is empty, so `omni(audio) > omni(own-transcript)` is information-theoretic, not stylistic. The field treats front-end acoustic extraction as its own object — **LISTEN (arXiv 2510.10444)** finds frozen audio LLMs "transcribe rather than listen" and under-use acoustics; **MMAU (2410.19168)** spans 27 sound/music/speech skills; **ParaS2S (2511.08723) / S2S-Arena (2503.05085)** and **MMAR (2505.13032)** probe paralinguistic-triggered response. The distinctness is **front-end-only**: reasoning over the extracted percept is commodity, so the research object is "extract percept + decide when it is decision-relevant + admit it," not the reasoning.

Internal evidence: the deployable perception-delta harness (`p6_perception_delta.py`, uses only test-time info, no gold) gave **SQuAD-zh +0.283 (SIG)** — but this is a Chinese-ASR round-trip artifact (the transcript *is* the answer content), an ASR-quality confound, **not** paralinguistics; the clean sound/music delta **mmau-mini +0.117 is directional-only, n.s. at n=60**; vocalbench-zh delta 0.0. `dec_synthesis.json` confirms no deployable in-fence *selector* clears the +10% bar, which is why the lever is admission-routing, not best-of-N.

- **T1 (on-disk, runnable):** **mmau-mini** (parquet `data/test_mini-*.parquet`; MCQ over sound/music/speech incl. emotion-shift/speaker-role/temporal-event; needs n scale-up beyond the n=60 directional run). **crema-d** — 7,442 clips / 91 acted speakers; because the 12 sentences are fixed and neutral it is a *transcript-invariant minimal-pairs* set (refutes the inventory "no minimal-pairs set" gap) AND the project's only gold speaker labels. **CORRECTION (load-bearing): the 6-way emotion gold MUST be read from the FILENAME code `{actor}_{sentence}_{EMOTION}_{intensity}` (ANG/DIS/FEA/HAP/NEU/SAD), NOT the csv `classname`** — the csv agrees with the acted code only ~46% and is ~55% neutral-skewed (a crowd-perceived rating, usable offline only, never as reward). Also on-disk: **meld** (natural TV emotion, context-heavier), **vocalbench-zh** (weak perception probe — reward is lexical QA).
- **T2 (public, citable):** RAVDESS / IEMOCAP / TESS / SAVEE (the other minimal-pair emotion corpora used in LISTEN 2510.10444); **VoxCeleb1/2** (large real speaker-verification corpus — *was removed from our 28*, so any at-scale voiceprint test requires re-acquiring it); **AudioBench (arXiv 2406.16020)** and, as a *separate* entry, **Dynamic-SUPERB (arXiv 2309.09510; Phase-2 2411.05361)** — **CORRECTION: these are two distinct benchmarks; 2406.16020 is AudioBench only.**
- **T3 (must-build, no on-disk seed):** a multi-turn task where a paralinguistic/speaker cue is the *decisive* variable, and cross-session voiceprint-keyed recall → park to W4.

### Memory — promising but narrow, gated on a T3 build (distinct = PARTLY)

The multimodal form is distinct only at PERCEPTION+KEY: capturing a non-text acoustic fact and keying/retrieving by voiceprint or acoustic event. **audiomc (2512.14865)** and **MTalk-Bench (2508.18240)** exist because transcription destroys the decisive recalled variable; **AFA (2604.25022)** implements voiceprint-keyed multi-user memory to prevent persona confusion. **CORRECTION: X-Talk (2512.18706) is dropped as evidence for the voiceprint-keyed-memory mechanism** — it is a general modular S2S framework; the specific "separate SID module + EMA per-user profile" mechanism is AFA's alone, so the speaker-keyed-memory sub-claim now rests on AFA only (it does not collapse). Everything downstream is commodity text-memory machinery — **LoCoMo (2402.17753)**, **LongMemEval (2410.10813)**, **PERMA (2603.23231, a benchmark — CORRECTION: moved out of the "systems" list)**; implemented by systems Mem0 / MemGPT / A-MEM / **Memoria (2512.12686)**. Our T6 (`t6_compression_feasibility.json`) confirms empirically: unified index task-purity 1.0, precision@k 0.62 vs 0.10 random floor — but the key is a *lexical* content summary. M5 (`m5_*`) shows best-of-N over a fixed recalled set nets **zero** significant WER gain on speaker/entity-keyed ASR memory (B6 CI [−0.0019, 0.0160], B7 CI [−0.0040, 0.0123] both cross 0; selector gain_sel = +0.00000; speaker ICC(1) on WER only 0.066 — the voiceprint key has little to grab on our data).

- **T1 for form-classification only (not a clean reward surface):** **audiomc** — on-disk/runnable (audio embedded in a 5.3 GB parquet), directly instantiates Audio-Cue Inference Memory, BUT single-session (state resets per item) and **rubric-judged** (no exact-match reward, not oracle@N-measurable). **eva-bench** — the only multi-turn voice surface with deterministic SHA-256 DB-state gold, but it is DB-state-update, single-session, NOT acoustic-keyed.
- **T2 (public):** MTalk-Bench (2508.18240), AFA (2604.25022); text commodity refs LoCoMo (2402.17753), LongMemEval (2410.10813).
- **T3 (must-build; the sharpest distinct object AND the deterministic-reward surface the lever needs):** a cross-session, voiceprint-keyed recall task built from **crema-d** (91 gold acted speakers → inject per-speaker facts across synthesized sessions, retrieve keyed by voice, exact-match reward). This is a named inventory HARD GAP (no cross-session corpus, no voiceprint-keyed recall task).

### Knowledge / RAG — the cleanest boundary-crosser, but modality-agnostic (distinct = PARTLY, conditioned)

RAG is the cleanest Axis-① new-info element — it genuinely fills the read-out-impassable knowledge gap InfoBoundary proves selection cannot cross (M3-style new-info injection **cleared the bar: +22% rel on vocalbench-zh**). But the crossing is *modality-agnostic*: the retrieved fact helps a text LLM equally. The multimodal form (audio-native retrieval) is distinct only **conditionally**: it beats ASR→text under lossy ASR — **SpeechDPR (2401.13463)** is "significantly better when UASR was poor"; error propagation quantified in **2209.12944** and Korean cascade **2605.17443**; **SQuTR (2602.12783)** is a noise-robustness bench — or when the KB holds non-lexical audio (**WavRAG (2502.14727)** audio+text +2.74×). On clean-ASR it merely **ties** ASR→text (WavRAG R@10; the M3 lesson). Mainstream audio-RAG (Google S2R; WavRAG) casts the query as *lexical-semantic intent, explicitly not acoustic*; the non-lexical-keyed branch (**Emotional-RAG 2410.23041**, **VoxRAG 2505.17326**) is thin/text-simulated.

- **T1: none** — no dataset in the 28 ships a retrieval-corpus + relevance-judgment structure; all are reader/MCQ with context already given.
- **On-disk seeds (audio present, but no relevance labels):** spoken-squad (spoken passages + own question + answer), heysquad (spoken questions), SQuAD-zh / vocalbench-zh (knowledge-QA surfaces with NO retrieval corpus on disk).
- **T2 (public, native relevance judgments):** **SLUE-SQA-5 (2212.10525)**, **NMSQA / openSQA (via SpeechDPR 2401.13463)**, **SVQ / MSEB (Google S2R)**, **SQuTR (2602.12783)**.
- **T3 build recipe — CORRECTION (disk cannot support the original join):** build the retrieval bench **from spoken-squad ALONE** — each item ships passage-audio + its own question + answer, so use the item's question as query and its passage as gold, mining distractor passages from *other items* (no cross-dataset join). **Drop the heysquad↔spoken-squad SQuAD-id linkage**: parquet schemas share no key (spoken-squad has no id/title/text passage; heysquad has SQuAD id+text), and joining would require ASR-transcribing the passages — reintroducing the very ASR step audio-native retrieval avoids. Fallback: public SLUE-SQA-5 / NMSQA (T2). Pre-registered win-condition must be the ASR-lossy / non-lexical-corpus regime.

### Skills / Tools — reject the broad framing (distinct = PARTLY → WEAK)

Skill declaration/registration is text-native and ported unchanged (no audio-native tool-call message format exists — MCP/OpenAI-function-calling/SKILL.md carry text only); post-trigger routing/argument-fill/orchestration is modality-agnostic IF-THEN a text controller supplies. A distinct form exists ONLY at the *activation interface* — firing/gating on a non-lexical decisive cue (**Audio2Tool 2604.22821**, **OmniACBench 2603.23938**, **ParaBridge 2606.10581** argue ASR discards it) — but it **collapses into PERCEPTION**, is oracle@N-bounded for any read-out selector, and every fielded signal→behavior solution is *fine-tuned* (ParaBridge; **ParaS2SBench 2511.08723**; **2603.15981**). Deployed voice-agent stacks (**AURA 2506.23049**, **Speech-Copilot 2407.09886**, **VoiceAgentBench 2510.07978**, **LTS-VoiceAgent 2601.19952**) all route on lexical intent. **CORRECTIONS:** Audio2Tool's stressors are **acoustic/noise-robustness cues (not paralinguistic)** — its trigger is lexical intent under acoustic stress; OmniACBench is **context-grounded output/TTS control (reading a script aloud with appropriate tone), not input-signal-triggered skill activation** — its "signal→behavior" billing is overstated.

- **T1 (but saturated):** minds14 / slurp / speech-massive (SLU intent+slot, exact-match) — the *commodity* lexical form; `dec_synthesis` shows **minds14 saturated (greedy 0.94, oracle_delta 0.0067)** → zero lever headroom.
- **Lever:** element-gating / admission of the skill *library* — **SkillsBench (2602.12670)**: curated-through-a-gate **+16.6pp (33.9% → 50.5%; CORRECTION from +16.2pp)** vs self-generated ≈ 0. Governs the library, not the per-item acoustic trigger.
- **Out of scope:** soulx-duplug turn-taking is full-duplex (frozen half-duplex contract-forbidden); tau2-Bench (2506.07982) / tau-Voice (2603.13686) have no audio on disk / full-duplex voice arm.
- **T3 (must-build):** a transcript-invariant, signal-decisive activation task (seed **crema-d**). **Recommendation: reject "signal-triggered skill activation" as its own branch** (commodity machinery + a perception problem the perception-delta lane already owns); fold the only defensible remnant — verifiable-reward gating of an audio-keyed skill library — into the perception + audio-keyed-memory frontier.

### Verifier / Reward — pursue the *decorrelated* verifier (distinct = PARTLY)

The capability splits by verification SIGNAL. **(1) Lexical/content verification is commodity:** E10b (n=40, paired-bootstrap CIs) shows a context-differentiated two-system omni verifier does NOT beat plain self-consistency majority on any lexical surface (ver_minus_maj CI straddles 0 on SQuAD/big-bench, **NEGATIVE −0.075 on mmau**), with generator/verifier error ρ≈0.5 — read-out bounded by oracle@N. It collapses to text GenRM/self-consistency (**2408.15240**; survey **2508.16665**; **2504.01005**). **(2) Signal-grounded verification is a genuine distinct object:** the field builds dedicated *frozen-LALM-as-judge* benches — **AudioJudge (2507.12705)** (training-free audio-concat+ICL; ~0.91 Spearman w/ humans — decimal unconfirmed, see caveats), **ParaPairAudioBench (2606.24648)**, **SpeechJudge (2511.07931)**, **EmergentTTS-Eval (2505.23009)**, **WavReward (2505.09558)**. The perception-delta confirms the necessary non-text signal exists. **Constraint:** the same-weights verifier is oracle@N-bounded, so the research value is specifically the **decorrelated** verifier (δ_corr>0) — verifier-AS-TOOL (external acoustic/embedding feature) over verifier-AS-ROLE, the W4 omni-embedding bridge (parked #37). **Soft-SVeRL (2605.28561)** and **FUSE (2604.18547)** corroborate that correlated self-verifiers fail and decorrelated ensembling is the fix; **One-Token-to-Fool (2507.08794)** shows naive LLM-judge reward fragility. ASR N-best rescoring (**2406.18972**) is a borderline signal-in/lexical-target case.

- **T2 (clean, deployable, non-leaking preference targets):** ParaPairAudioBench (2606.24648), AudioJudge (2507.12705), SpeechJudge (2511.07931), WavReward (2505.09558), EmergentTTS-Eval (2505.23009).
- **NOT T1:** the 28 have no task where a paralinguistic/speaker signal is the *decisive selection* variable (HARD GAP: "SER is never a decision variable"); the T1 lexical surfaces only confirm the commodity side (E10/E10b, done).
- **T3 build-seed:** paired-candidate acoustic-verification items from on-disk **crema-d** (emotion/speaker gold used *offline only* to score the verifier, never as reward) + **vocalbench-zh** (whisper/quality obedience). Deployability guard: rewards MUST be self-consistency/confidence/rule/tool-success — WER-vs-gold, gold-emotion, rubric-gold are **leakage**, offline measurement only.

## Our contribution surface

Three organizational forms are **genuinely distinct** and constitute the contribution surface, in descending order of how cleanly the distinctness holds:

1. **Perception (front-end extraction) — the flagship distinct object.** It is the *only* capability where the frozen omni supplies decision-relevant information a text LLM provably cannot recover from any transcript (information-theoretic on empty-transcript sound/music items; corroborated by LISTEN 2510.10444 and MMAU 2410.19168). The research object is *extract percept + decide when it is decision-relevant + admit it* — not the commodity reasoning that consumes it. Under InfoBoundary the correct frozen lever is **element-gating/admission (the perception-delta as router) + new-info injection of the percept**, not best-of-N. Testable at **T1 today** (mmau-mini live; crema-d minimal-pairs with filename gold).

2. **The decorrelated signal-grounded verifier.** Verification of quality/prosody/emotion/speaker/paralinguistic-obedience is a real signal-in object with a training-free frozen-LALM-as-judge instantiation (AudioJudge 2507.12705 et al.), but its Stage-1 payoff is confined to the **decorrelated** case (δ_corr>0 via an external acoustic/embedding feature — the W4 bridge), because the same-weights verifier is oracle@N-bounded (E10b, in-house). **T2** on public preference benches.

3. **Audio-keyed memory + audio-native retrieval — distinct only at the key/percept.** Both cross the boundary as new-info elements, but the crossing is *modality-agnostic* (the fact/passage helps a text LLM equally); the genuinely multimodal sliver is narrow — a non-text write-and-key for memory, and the lossy-ASR / non-lexical-KB regime for retrieval. Both are **T3 builds** (cross-session voiceprint recall from crema-d; a spoken-squad-only retrieval harness).

**Skills/Tools is not a standalone branch** — its distinct remnant is a perception problem the perception lane already owns, wrapped in commodity registration/orchestration; fold it in.
