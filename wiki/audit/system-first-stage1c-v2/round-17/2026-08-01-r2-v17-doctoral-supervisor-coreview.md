# R2 v17 整改核验复审：round-16 阻断项实质关闭，但同批 D2 的三处同载体反向读数未回流到它们所威胁的设计与判据

## 一、裁决摘要

**裁决：`MAJOR_REVISION_REQUIRED_BEFORE_FORMAL_OPENING`；1 项 MAJOR、8 项 MINOR、5 项
观察。非零 MAJOR 轮——续77② 的零 MAJOR 生效条件本轮不成就。**

先说本轮核验的正面结论，因为它决定了 MAJOR 的性质与代价：

1. **round-16 的唯一 MAJOR 已实质关闭**。六点整改中五点闭合、一点部分闭合；§六 复审验收
   清单八项全部有定位证据；MINOR-1..5 四闭一部分。载体数据包、dev/test 隔离合同、知识
   时态与污染协议、同载体基线阶梯四项均从"待定"变为可复现的协议文本。
2. **本批的数字源核纪律是本战役迄今最强的一次**。我逐项复核了 v17 新增数字对 D2 条目的
   落点：ConEC 的 10.41/10.29/9.69 与稀有词 24.84→18.72、Whisper large 7.98（6.94/17.43）
   与"实体面 oracle 仍胜 6/8"、规模差 21.7×、Fox 的 1013/1782 与 13.6M/673,366、Huang24f
   的 10.40 vs 10.29 与 3.7–6.7%/30 epochs、RECOVER 的 23.81→15.85/15.90 与 0.05/99.4%、
   Xiao 的 10.92→28.97/19.11→42.48/13.37/24.21pp——**全数在对应 D2 条目内可定位、方向
   一致、无跨表拼接**。八张表的列宽全部自洽（1063 行内零结构性断裂）。
3. **两处对自己不利的刻画被主动更正**，这是诚实的加分项：round-16 把 Huang 2024 描述为
   "trained upper bound"，v17 按一手核验反向更正为**非上界**（其自表总 WER 10.40 不敌零
   训练 shallow fusion 10.29，真上界=ConEC oracle 9.69，L464/L764）；Fox 词表被标注为
   **oracle 派生自测试参考**并钉入 test-gold 禁令（L464）。
4. **正文工作记录标记为零**。L12–L848（§0–§8 全部正文）无任何 `round-xx`／`MAJOR-x`／
   `MINOR-x`／`(owner…裁定)` 标记，全部佐证集中在 frontmatter（L2–L10）与 §9 治理节
   （L938 起）。该纪律本轮首次完全达标。

阻断本轮签字的不是方向、不是框架、也不是 round-16 的遗留问题，而是**同一天完成的 D2 批
在回流上出现了方向性不对称**：对本方案有利的读数（RECOVER 占据前三分量、Xiao 的注入
灾难佐证"噪声耐受属核训练分布"、ConEC 的 oracle headroom）被逐处写进 §0/§1.2/§2.3/§5.1/
§8 并驱动了判据修订；而**同一批 D2 里指向本方案自身机制的三处反向读数，一处也没有进入
它们所威胁的章节与判据**。其中最重的一处（Xiao 在主载体上实测的"查询质量天花板"）连
数字都已写进 §9 的数字纪律声明（L1049），却在正文 §0–§8 中一次也没出现。

这不是"再补一篇论文"的问题——证据全部已在本地在案，闭合是机械性的。但在**正式开题
签字**这一门禁上，一份把有利证据写满、把不利证据留在 D2 里的证据底座，不能被判为闭合。

## 四、C 部分：本轮新发现

### MAJOR-1：同批 D2 的三处同载体反向读数未回流；§0「反向先验具名（两条）」量词因此为假

#### 4.1 缺陷形态

v17 的双轨自检批产出了五件新 D2。对**支持**本方案的读数，回流是彻底的：RECOVER 的三分量
占据改写了 §0/§1.2/§2.3/§8 五处并新设组⑤ 子档与强制对照臂；Xiao 的注入灾难被写入双侧
证据合同并升格"噪声耐受属核训练分布"为必要项候选；ConEC 的 oracle headroom 进了 §5.1 并
成为第零步 gate 的动机。对**指向本方案自身机制**的读数，回流是零。

**实例①（最重）：Xiao 在主载体上实测的"查询质量天花板"完全缺席。**
其 D2 条目（`2026-08-01-d2-icassp2025-xiao-rag.md`）L301–302 记载：在 Earnings21+ConEC
context files（即本方案主载体数据包）上，把检索 query 从 Whisper 假设（WER 10.92）换成
**oracle 转写（WER 0）**，检索命中率只涨 **+1.28pp**（44.22→45.50 @500）／**+0.29pp**
（@1000）；反向地，把 query 换成 WER 19.11 的更差假设，命中率仅降 1.24pp（L304）。同条目
L540 逐字写道：「检索损失比查询质量损失大约 20 倍（26.94 pp vs 1.28 pp）。**这是对 R2
「用重听改善检索 key」分量的反向先验**」，并在 L449–452 明确建议把 R2 §7 判别力条款的
"先算 oracle headroom"扩写为两级链条：**上下文覆盖上界（69.02）→ 检索命中率（42.08）→
效果**。

核验结果：`69.02`／`42.08`／`54.12`／`1.28pp` 四个数字在提案 **§0–§8 正文中零出现**
（全文仅 L1049 的 §9 数字纪律声明含之）；`命中率`／`覆盖上界`／`查询质量` 三个检索词在
正文的命中全部属于发音库同音候选命中率（L221/L254）与 ConEC 实体覆盖率（L761），与本读数
无关。§7 灵敏度前置④（L647–648）仍只有单级 oracle 残余余量，未按其 D2 建议扩为两级。

这一读数直接压在两处承重结构上：(a) §1.2 的音频特有因果链「误听实体 → 错 query → 相关但
全错的证据链」（L103–107）——在主载体上，query 质量对检索的价格标签已被同载体一手实测钉
在 1.28pp；(b) **收窄后唯一的新颖性承重腿**「双源动作选择＝门控选择性重解析＋按样本调度」
（L42–44/L775–779）——重解析的下游价值正是"改善假设→改善查询/裁决"。

我如实记录其边界，以免评审自身外推：Xiao 测的是 ConEC 逐场文档 chunk（320 字符、小闭合
文档集）的召回命中率，不是发音库同音候选检索，也不是任务效果；小语料冗余会使命中率提前
饱和。因此它**不是判死**，而是一条必须具名登记、并进入第零步余量检定设计的同载体反向
先验。提案自己的双侧证据合同（L790–791「引用任一侧必须成对出现」）与效应量预注册纪律
（L496–497「不得先注册后找载体」）正是为此类读数设的。

**实例②：RECOVER"多假设近乎净零"未与本方案的多假设设计对接。**
