# Stage-1 Deliverable — Testable-Now Probes + Data-Construction Spec

**Stage:** 1 (problem definition). **Grade:** all in-house numbers below are hypothesis-grade (small-n, directional-only; re-establish at Stage-2). **Object of study:** a frozen omni (speech/audio) MLLM embedded in an agent scaffold (controller, tools/skills, memory, knowledge/RAG, verifier) — inference-time, reward-guided, no weight/structure change.

**Framing (three-column cut, not a blanket "commodity" verdict).** For each capability we separate three things: (1) a genuinely **distinct multimodal front-end** (signal-in → structured percept/key, triggered by a non-lexical acoustic/prosodic/speaker/temporal property the transcript discards); (2) the **commodity layer** — modality-agnostic logic a text LLM supplies once the percept is serialized; (3) the **deployable frozen lever** and its **data tier**. The machine-checked **InfoBoundary** result governs the lever, not the classification: selection/orchestration over a *fixed* element set is read-out, bounded by the model's own **oracle@N**; a capability crosses that ceiling only via a **new-info element** or an **in-contract decoding edit**. `dec_synthesis.json` (Stage-1) confirms no deployable read-out selector clears the +10% relative-gain bar on our live surfaces, and the read-out levers already tried (E7 few-shot, E8 prompt-opt, E10/E10b two-system verifier) all failed it.

### Capability map (three-column cut)

| Capability | Distinct multimodal front-end (research object) | Commodity layer (text LLM handles) | Deployable frozen lever | Tier of the distinct form |
|---|---|---|---|---|
| **Perception** | signal-in → structured percept (emotion/speaker/event/prosody); acoustically triggered | reasoning over an already-extracted, text-encoded percept | element-gating/admission (perception-delta router) + new-info percept injection | **T1** (mmau-mini, crema-d) |
| **Memory** | capture a non-text acoustic fact into an entry; voiceprint/event **keying** | admission logic, indexing, NN retrieval, update, temporal reasoning, abstention | admission/**write** policy that stores the omni's *own* audio-cue descriptions (new-info) | **T3** (deterministic-reward cross-session voiceprint recall = hard gap) |
| **Knowledge/RAG** | audio-native retrieval (bypass ASR); indexing non-lexical audio | when-to-retrieve, query rewrite, multi-hop, fusion, synthesis; the injected fact itself | element-gating/admission + reward-guided reranking over retrieved evidence | **T3** (build from spoken-squad; distinct only under lossy-ASR / non-lexical KB) |
| **Skills/Tools** | fire/gate a skill on a non-lexical decisive signal (**activation/perception interface only**) | declaration/registration (MCP, SKILL.md, JSON schemas), routing, arg-fill, orchestration | verifiable-reward skill-admission **gate** (library-level) | **T3** (no on-disk signal-decisive activation task) |
| **Verifier/Reward** | signal-grounded verification (quality/prosody/emotion-match/speaker-match/paralinguistic-obedience) | rank-by-correctness: self-consistency, CoT critique, weighted voting (GenRM, 2408.15240) | best-of-N + reward-guided selection; **decorrelated verifier-as-tool** | **T2** public (T3 build-seed crema-d/vocalbench-zh) |

**Single genuinely distinct object:** PERCEPTION's front-end extraction — the one place the frozen omni supplies decision-relevant information a text LLM *cannot* recover from any transcript (perception-delta is information-theoretic; corroborated by LISTEN arXiv 2510.10444 and MMAU arXiv 2410.19168). Its distinctness is **front-end-only** — reasoning over the percept is commodity — so the research object is "extract percept + decide when it is decision-relevant + admit it into the scaffold," not the reasoning.

## Part A — Probes runnable NOW on T1 data

Ranked by how cleanly they run today. **P3, P4, P2 are fully runnable now with a deterministic reward and zero new data or construction.** P1 leads because it is the single highest-value **lever needing no new data** and the one untested InfoBoundary crossing-path — but it is **harness-blocked, not data-blocked**. P5 is partial (needs construction). P6 is out-of-contract (blocked).

### P1 — In-contract decoding edit: Audio-Aware Decoding *(lead — the lever needing no new data)*

- **Capability tested:** decoding-edit read-out — does per-token contrastive decode that up-weights tokens whose logit rises *when the audio is present* (Audio-Aware Decoding, arXiv 2506.07233) harvest any of the measured oracle@N headroom? This is the **only untested member** of the two InfoBoundary crossing-paths (a decoding-edit; the selection/read-out levers E7/E8/E10 already failed the bar).
- **Datasets:** mmau-mini **[T1]**, SQuAD-zh **[T1]** — both non-saturated with real headroom (`dec_synthesis.json`: mmau `oracle_delta` +0.147, SQuAD-zh +0.14). Both wired in `scripts/p2_baselines.py` with on-disk audio.
- **Verifiable reward:** yes — reuses `p2.reward` verbatim: MCQ option-letter match (mmau-mini), normalized substring match (SQuAD-zh). Deterministic, no judge.
- **needs_new_data:** **no** — but needs a new **harness**: faithful AAD needs per-step logits from an audio vs no-audio (or noised-audio) forward pass, which the resident llama.cpp OpenAI chat endpoint (`input_audio`, server-side full generation) does **not** expose. Requires a custom `llama-cpp-python` logit-access decode loop; the HF/int4 transformers path OOMs on the Blackwell 5090.
- **Caveat:** MUST be judged against a **hardened baseline** = greedy (temp 0) + a temperature sweep + a CoT prompt, paired-bootstrap CI on the delta, against the +10% relative-gain bar. The Mirage result (arXiv 2504.10020, NeurIPS 2025) shows reported contrastive-decoding gains are often artifacts of the adaptive-plausibility constraint silently converting sampling→greedy — without the hardened baseline any gain is untrustworthy. Prior (from verdict 2.2 + `dec_synthesis`): read-out levers do not clear the bar → a Mirage-survived gain would be a notable positive; a null is the likely and still-informative outcome.

### P3 — Non-speech (sound + music) perception-delta on mmau-mini *(sharpest "omni ≠ ASR→LLM" evidence)*

- **Capability tested:** cleanest test that the omni is a genuine new-info (perception) element — on audio with **no speech**, the model's own transcript is empty / `[no speech]`, so any omni(audio) advantage over omni(own-transcript) is **unambiguously acoustic** (no lexical channel can leak the answer).
- **Datasets:** mmau-mini **[T1]** — restrict to on-disk `task=='sound'` (333) + `task=='music'` (334) = 667 non-speech items (the parquet carries a `task` field, verified on disk).
- **Verifiable reward:** yes — MCQ option match (`p2.reward`), deterministic, gold on disk.
- **needs_new_data:** no. Two-arm perception-delta harness already built (`p6_perception_delta.py`: A = omni(audio); B = omni(own model-produced transcript, text-only) — boundary-clean, deployable, no golden reference).
- **Caveat:** mmau items are "ask-ABOUT-the-audio" MCQ (no timestamps, no event-detection labels) → measures perception-*as-answer*, not detection; 25% chance floor. p6 ran mmau POOLED at n=60 (+0.117, n.s.); the speech third dilutes the signal, so run the full 667 (or a powered slice) and check power.

### P4 — Paralinguistic-as-decision-variable with reward already on disk: mmau-mini speech-emotion/prosody MCQ

- **Capability tested:** the framing question for perception directly — is a paralinguistic signal a decision variable the frozen omni can act on? Score greedy accuracy AND oracle-over-N on the paralinguistic subset.
- **Datasets:** mmau-mini **[T1]** — on-disk speech sub-categories: Dissonant Emotion Interpretation (20), Emotion State (20), Emotion Flip Detection (20), Phonemic Stress Pattern Analysis (153).
- **Verifiable reward:** yes — MCQ option-letter match (`p2.reward`), deterministic, gold on disk.
- **needs_new_data:** no (zero construction).
- **Caveat:** small per-sub-category n (20 each for emotion cuts) → underpowered alone; **pool the ~80 emotion items** or use the 153 stress items for power. 25% floor; reasoning ABOUT speech, not detection. This is the honest "verifiable-now" counterpart to the **mmsu-BLOCKED** path (mmsu labels missing on disk). Pairs naturally with P3 (run the perception-delta on the *same* subset to prove the decision needs acoustics).

### P2 — Transcript-invariant perception-delta on CREMA-D acted emotion *(clean paralinguistic control)*

- **Capability tested:** is the omni's audio channel a genuine new-info element for **paralinguistics specifically** — does omni(audio) beat omni(own-ASR-transcript) on emotion when the lexical content is held constant, so the transcript carries **zero** emotion cue? This is the clean control the run p6 lacks: p6's only SIG live delta (SQuAD-zh +0.283) is lexical and conflates the ASR-bottleneck with perception.
- **Datasets:** crema-d **[T1]** — on-disk verified (7,442 clips, 91 acted actors, 12 fixed *neutral* sentences). Because the 12 sentences are fixed, arm B's transcript is identical across emotions → delta is attributable purely to acoustic perception (mirrors the lexical–acoustic minimal-pair design of **LISTEN (arXiv 2510.10444) / VoxParadox (arXiv 2605.27772)**).
- **Verifiable reward:** yes — deterministic 6-way match to the **FILENAME-encoded acted emotion code** `{actor}_{sentence}_{EMOTION}_{intensity}` ∈ {ANG, DIS, FEA, HAP, NEU, SAD}. **CORRECTION (load-bearing, folded in):** key off the **filename code, NOT the shipped `test.csv`/`train.csv` `classname` column** — `classname` agrees with the acted filename code only **46%** and is ~55% neutral-skewed (812/1489 test rows labeled "neutral"); it is a crowd-*perceived* rating, not the acted label. Keying the reward off `classname` would corrupt ~54% of labels. Use `classname` only as a separate offline signal, never as the reward.
- **needs_new_data:** no — data + labels on disk; needs only a loader + emotion-MCQ prompt; reuses the p6 two-arm design.
- **Caveat:** emotion is ACTED/portrayed on fixed English sentences → external-validity limit. Audio-LLM SER is a known weak spot (**VoxEmo arXiv 2603.08936**; paralinguistic-reasoning gap arXiv 2509.16589 — treat the specific "~22% recall" figure as **unverified**, keep only the qualitative weakness claim). A near-chance delta is a plausible outcome and is itself informative: it would say the frozen omni cannot turn acoustic emotion into a decision → SER is not a usable decision variable in the frozen contract.

### P5 — Speaker identity as a decision variable: CREMA-D same/different-speaker discrimination *(PARTIAL — needs construction)*

- **Capability tested:** can the frozen omni use **voiceprint** (not lexical content) as a decision variable — a same-speaker / different-speaker binary judgment?
- **Datasets:** crema-d **[T1]** — the **only** on-disk asset with gold speaker labels (91 filename-encoded actor IDs; librispeech/meld/audiomc speaker metadata is unlabeled).
- **Verifiable reward:** yes — binary same/diff, deterministic from filename speaker IDs; balanced positives/negatives.
- **needs_new_data:** **partial.** Two blockers: (1) the task needs **two clips per item**, but the chat endpoint's `input_audio` is one-audio-per-turn and multi-audio on this llama.cpp omni build is **unverified** → likely requires concatenating two clips into one wav with a separator tone (construction over on-disk assets, no new corpus); (2) design control — pair **same-speaker clips with *different* sentences** and **different-speaker clips with the *same* sentence**, forcing the model onto voiceprint and blocking a lexical/sentence-identity shortcut (the 12 sentences are shared across all speakers).
- **Caveat:** crema-d is ACTED, 91 speakers, same 12 sentences → a minimal controlled probe, **not** a speaker-verification benchmark; no large SV corpus exists in T1 (VoxCeleb was removed), so a null here **cannot** be generalized. This is the sole T1 seed for the speaker-decision-variable question.

### P6 — soulx-duplug turn-taking *(OUT-OF-CONTRACT — reported blocked, not a valid T1 probe)*

- **Capability:** full-duplex turn-taking / backchanneling / pause-handling as signal-triggered behavior (Full-Duplex-Bench, arXiv 2503.04721; soulx-duplug ships Full-Duplex-Bench-zh + Easy-Turn-Testset-en).
- **Why blocked:** the reward is the **timing/latency** of when the model yields or takes the turn — requiring a streaming model that listens and speaks simultaneously. The frozen omni is served single-turn request→full-response (`input_audio`), i.e. architecturally **half-duplex**; it cannot produce the real-time overlapping behavior the metric scores. A degenerate single-turn reduction ("take the turn now? yes/no") would not measure the actual capability. Data also ships as unextracted zips, but extraction does not fix the architectural mismatch.
- **needs_new_data:** yes (and out of the frozen contract). Flag for a future streaming-serving track, not WS-3.

## Part B — Data-construction spec for the T3 research objects

For each: the seed/corpus, the task, the verifiable reward, and the **dataset-level isolation design** — the observable surface (available at inference) vs the held-out golden (offline scoring only), with the discipline that **scaffold elements draw only from the observable surface**. This is the InfoBoundary discipline made concrete at the dataset level.

### B1 — Cross-session, voiceprint-keyed recall (MEMORY) — the sharpest distinct object

- **Why T3:** inventory hard gap is explicit — no cross-session/multi-session corpus; no voiceprint-keyed recall task. audiomc **[T1, on-disk/runnable]** instantiates the audio-cue *content* form but is **single-session** and **rubric-judged** (no deterministic reward, not oracle@N-measurable) → it can classify the *form* but gives the verifiable-reward lever no clean surface. eva-bench **[T1]** is multi-turn with deterministic gold (SHA-256 DB-state) but is tool/DB-state, **not acoustic-keyed**.
- **Seed:** crema-d **[T1 seed]** — 91 gold acted speakers (filename-encoded actor IDs), on disk.
- **Task:** inject per-speaker facts across synthesized sessions (a "session" = a sequence of utterances from one actor, each carrying a fact bound to that voice); at query time, present a probe utterance from one actor and require retrieval of the fact previously bound to **that voice** — retrieval keyed by voice identity, not by the probe's lexical content.
- **Verifiable reward:** EXACT-MATCH on the recalled fact (facts drawn from a closed symbol set), deterministic and oracle@N-measurable.
- **Isolation design:**
  - *Observable surface (inference):* the audio waveforms only (session utterances + query utterance). The memory store is **written from the omni's own outputs** over that audio (its own voiceprint embedding / audio-cue description) — the InfoBoundary-permitted **new-info element** (same pattern as W4 omni-embedding-as-element).
  - *Held-out golden (offline only, never on the tape):* the filename actor-ID → session mapping and the fact↔actor binding key. Used only to score exact-match recall.
  - *Elements draw only from observable:* candidate memory entries and retrieval keys are produced by the frozen omni over observable audio; the correct-answer key is not an element.
- **Prior/caveat:** M5 evidence (`m5_memo_censuses.json` / `m5_selector_confirmatory.json`) — best-of-N/reward-guided selection over a *fixed* recalled set gave **no significant** WER gain on speaker/entity-keyed ASR memory (B6 CI [-0.0019, 0.0160], B7 CI [-0.0040, 0.0123], both cross 0; selector `gain_sel=+0.00000`; speaker ICC(1) on WER only 0.066 → the speaker signal barely explains variance). So the defensible lever is the **write/admission policy** (reward = downstream recall accuracy), not selection. External validity: crema-d is acted, 91 speakers, 12 fixed sentences → synthetic sessions; a null cannot generalize to real multi-session dialogue. **Correction folded:** the voiceprint-keyed-memory field precedent rests on **AFA (arXiv 2604.25022)** alone — X-Talk (2512.18706) is dropped here (it is a general modular S2S framework, not a voiceprint-keyed-memory + EMA mechanism). Field forms that motivate this build: audiomc (2512.14865), MTalk-Bench (2508.18240). Commodity orchestration reference: LoCoMo (2402.17753), LongMemEval (2410.10813), PERMA (benchmark, 2603.23231); our T6 (`t6_compression_feasibility.json`) shows the index empirically reduces to a **lexical** text-embedding retrieval structure (task-purity 1.0, precision@k 0.62 vs 0.10 floor).

### B2 — Audio-native retrieval harness (KNOWLEDGE/RAG)

- **Why T3:** none of the 28 ships a retrieval-corpus + relevance-judgment structure — all are reader/MCQ tasks with the context already given, so the distinct **retrieval** form is not runnable as-is.
- **Seed (CORRECTION folded):** build from **spoken-squad ALONE [T1 seed]**. On-disk parquet = `{context (passage audio bytes), instruction (question), answer}`. Each item already ships passage-audio + its own question + answer → use the item's question as the query and its own passage as the gold, mining distractor passages from **other** items (no cross-dataset join needed). **Do NOT** attempt the heysquad↔spoken-squad SQuAD-id join: spoken-squad has no `id`/`title`/text passage and heysquad has SQuAD `id` + text `context` — there is no shared key; linking would require ASR-transcribing the spoken passages and fuzzy-matching, re-introducing the exact ASR step audio-native retrieval is meant to avoid. **Fallback (T2):** public SLUE-SQA-5 (arXiv 2212.10525) / NMSQA-openSQA (SpeechDPR, arXiv 2401.13463), which ship native retrieval relevance judgments.
- **Task:** audio-query → retrieve top-k passages from the audio corpus → grounded answer; compare audio-native dual-encoder retrieval vs ASR→text retrieval.
- **Verifiable reward:** retrieval R@k (gold = the item's own passage) AND downstream exact-match answer (normalized substring match on the SQuAD gold answer). Deterministic.
- **Isolation design:**
  - *Observable surface:* the query audio + the corpus of passage-audio. Query vectors and retrieval keys are produced by the frozen omni / retriever over observable audio only.
  - *Held-out golden (offline):* the query→gold-passage identity (item index) and the SQuAD gold answer string — used to score R@k and answer EM; never fed to the retriever as a label.
  - *Elements draw only from observable:* retrieved candidates come from the audio corpus; the gold-passage index and answer string are not elements.
- **Pre-registered honest win-condition:** audio-native beats ASR→text **only** in the ASR-lossy regime (noise/accent/low-resource/code-switch — SpeechDPR 2401.13463 "significantly better when UASR was poor"; SQuTR 2602.12783) or when the KB holds **non-lexical** audio (WavRAG 2502.14727 audio+text +2.74×). On clean-ASR text-knowledge QA it merely **ties** ASR→text (WavRAG R@10) — the M3 lesson bites and the omni adds no >transcript delta to the *retrieved knowledge*. Deployable lever = element-gating/admission + reward-guided reranking over retrieved evidence (W1 machinery), **not** a novel trained retriever (all audio-native retrievers in the field are trained). The knowledge injection is a genuine Axis-① boundary-crosser, but the injected fact is modality-agnostic (helps a text LLM equally).

### B3 — Transcript-invariant, signal-decisive activation/perception minimal-pair set (PERCEPTION + SKILLS)

- **Why T3:** inventory hard gap — no on-disk task where a paralinguistic/speaker signal is the **decisive** activation variable. The SKILLS verdict recommends **not** treating "signal-triggered skill activation" as its own branch: its declaration/registration (MCP, SKILL.md, JSON schemas — no audio-native tool-call message exists) and post-trigger routing/arg-fill are commodity; the distinct part **collapses into perception**. So this build is a perception/activation minimal-pair set, folded into the perception-delta frontier.
- **Seed:** crema-d **[T1 seed]** — 6-way emotion + 91 speakers, filename gold, on disk. Because the 12 sentences are fixed and neutral, this is natively a **transcript-invariant minimal-pairs set** (same words, varied emotion/actor) — refuting the inventory's "no transcript-invariant minimal-pairs perception set" gap.
- **Task:** synthesize a signal-DECISIVE activation task where the correct skill/label flips **only** with the non-lexical cue and the transcript is held constant — e.g. emotion-gated escalation-skill fire, or speaker-voiceprint-gated tool admission; alternatively re-cut minds14/slurp with a paralinguistic overlay that changes the correct skill.
- **Verifiable reward:** exact-match on the cue-determined correct skill/label, deterministic from the **filename** emotion/actor code (NOT the csv `classname` — same correction as P2).
- **Isolation design:**
  - *Observable surface:* the audio + a text skill-library declaration. The activation decision is produced by the frozen omni over observable audio.
  - *Held-out golden (offline):* the filename cue-code → correct-skill mapping. Never on the tape.
  - *Elements draw only from observable:* candidate activations are the omni's own outputs; the cue→skill key is not an element.
- **Constraint/caveat:** InfoBoundary caps any read-out selector over a fixed skill set at oracle@N — a training-free selector cannot make the omni perceive a cue it does not already surface. On the one T1 surface the *lexical-intent* (commodity) form applies to, minds14 **[T1]** is SATURATED (`dec_synthesis`: greedy 0.94, oracle_delta 0.0067) → zero lever headroom. Every fielded signal→behavior solution is **fine-tuned** (ParaBridge 2606.10581, ParaS2S 2511.08723) — the training-free slice is empty. The only clean in-fence levers are the perception-delta **admission router** and **new-info percept injection**; the library-level skill-admission **gate** (SkillsBench arXiv 2602.12670: curated-through-a-gate **+16.6pp**, 33.9%→50.5%, vs self-generated ≈0) governs the *library*, not the per-item acoustic trigger. **Corrections folded:** SkillsBench = +16.6pp (not +16.2); Audio2Tool (2604.22821) trigger is **lexical intent under acoustic/noise stress** (not paralinguistic); OmniACBench (2603.23938) is **context-grounded output/TTS acoustic control**, not input-signal-triggered activation.

### B4 — Signal-grounded, decorrelated omni-verifier paired-candidate set (VERIFIER/REWARD)

- **Why T2, not T1:** the lexical/content verification form is **commodity** — E10/E10b (n=40, paired-bootstrap CIs) show the context-differentiated two-system omni verifier does **not** beat plain self-consistency majority on any lexical surface (SQuAD-zh, big-bench-audio, mmau-mini, vocalbench-zh), NEGATIVE −0.075 on mmau, generator/verifier error correlation ρ~0.5 → read-out, bounded by oracle@N. Our 28 have **no** task where a paralinguistic/speaker signal is the decisive **selection** variable (hard gap: "SER is never a decision variable"); crema-d/mmsu gold-as-reward would be **leakage**.
- **T2 public (deployable, non-leaking preference targets):** ParaPairAudioBench (arXiv 2606.24648), AudioJudge suite (arXiv 2507.12705; frozen LALM-as-judge, audio-concat+ICL, **training-free** — squarely our regime), SpeechJudge-Eval (arXiv 2511.07931; speech-naturalness pairwise), EmergentTTS-Eval (arXiv 2505.23009; prosody/expressiveness), WavReward (arXiv 2505.09558; spoken-dialogue IQ+EQ). All public.
- **T3 build-seed (to test the distinct form *deployably* on our modality mix):** construct paired-candidate acoustic-verification items where the distinguishing dimension is paralinguistic and the reward is **deployable**.
  - *Seeds on disk:* crema-d **[T1 seed]** (91 acted speakers, 6 filename emotions + speaker-ID → emotion-match / speaker-match candidate pairs) and vocalbench-zh **[T1 seed]** ("answer in a whisper" / acoustic-quality/empathy → "did the response obey the paralinguistic instruction" verification; requires the frozen omni to emit speech).
  - *Task:* pairwise "which candidate matches the acoustic evidence" (emotion-match / speaker-match / paralinguistic-obedience).
  - *Deployable reward:* whether a frozen omni verifier separates the pairs via **deployable** confidence/self-consistency (across verifier prompts) **better** than a transcript-only judge — i.e. the measured error-decorrelation δ_corr.
- **Isolation design:**
  - *Observable surface:* the candidate audio (and, for pairwise, the reference audio) + the verifier prompt. The verifier score is the frozen omni's own deployable signal (self-consistency across prompts, confidence, rule/format, tool-success).
  - *Held-out golden (offline ONLY — using it as reward = leakage):* gold emotion (filename code), gold speaker-ID, rubric-gold, WER-vs-gold. Used only to *measure* the verifier (δ_corr / separation), never as the training-free reward.
  - *Elements draw only from observable:* the verifier consumes candidate/reference audio and its own outputs; golden labels are not elements.
- **Constraint (machine-checked InfoBoundary):** a same-weights omni-as-verifier re-reading the same input is READ-OUT, bounded by oracle@N; gains require **δ_corr > 0**, which only drops when the verification signal is INDEPENDENT of what the generator used — (a) a paralinguistic/acoustic RE-READ the generator's lexical pass discarded (perception-delta shows this signal exists: p6 +0.283 SIG SQuAD-zh, +0.117 mmau), or (b) the **W4 omni-embedding** as an M-independent verification feature (parked task #37 — the concrete bridge to the flagship). So **verifier-AS-TOOL** (external acoustic/embedding feature) is theoretically preferred over **verifier-AS-ROLE** (same weights, differentiated context). Corroboration: Soft-SVeRL (2605.28561) / FUSE (2604.18547) — correlated self-verifiers unreliable, decorrelated ensembling is the fix; One-Token-to-Fool (2507.08794) — naive LLM-judge rewards fragile; GenRM (2408.15240) — the commodity baseline the omni verifier collapses to on lexical signals.
