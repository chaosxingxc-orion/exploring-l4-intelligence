## 1. 背景与动机（Background & Motivation）

### 1.1 部署现实：核心冻结、能力外挂

语音 / omni 多模态 LLM 已进入"核心冻结、能力外挂"的部署形态。最强的 omni 核心——本地冻结检查点（Qwen3-Omni-30B，arXiv:2509.17765）或闭源 API（GPT-4o-Audio、Gemini 一类）——使用方既不能改权重、也不能改结构；闭源 API 更只暴露**音频/文本进、文本出、多次采样**这单一接口契约，连 logprob / logit_bias / 语法约束都不保证可达。这不是缺陷假设，而是**部署现实**。

在这一现实下，真实业务价值**不在**把某个核心的裸能力刷到极致（那是模型厂的事），而在把一个既有核心搭成**可验证、可闭环**的系统，针对性提升其**外挂能力**。三类外挂按粒度区分——知识（通用事实）、记忆（特定实例召回）、技能（任务模板注册）；本提案聚焦**知识子系统**，记忆 / 技能为同级外挂、暂缓。核心价值在于：无需触碰核心权重即可在知识依赖型语音任务上兑现效果，且**接口最小化设计**天然向闭源 API 迁移。本地冻结核心是**科学载具**（严格可复现），闭源可迁移性是**价值主张**（跨核心冒烟作证）。

**"知识依赖型语音任务"的范围界定**：指任务的正确输出依赖于**音频本身未携带、须由外部证据补足**的信息——语音知识问答（heysquad / SQuAD-zh / squtr，答案在语料而非音频）、口语意图/槽位理解（SLURP，域知识约束槽值）、以及实体/专名密集的转写（is21_deep_bias / AISHELL-NER，稀词与命名实体须由偏置库补足）。这类任务是外挂知识子系统能真正兑现效果的场景；纯声学任务（如说话人识别、情感）不在本提案范围。

### 1.2 为什么是前端知识校正，而非后端融合

training-free 的主战场在**前端**——组织与校正输入侧的多模态知识体系。**后端**（重排序 / 验证器）不立为独立研究方向，只作**数据集无关的标准 reward 信号供给**（详见 §10、附录 B）。三条理由：

1. 后融合（生成式纠错 / rescoring）在强、低-WER 的冻结核心上普遍**中性到有害**：自由改写在强首遍上灾难劣化（LIR-ASR arXiv:2509.15095，2025-09——在 Whisper-large-v3（CER/WER 2.89/5.23）上去掉规则约束、令 LLM 自由改写使 CER/WER 恶化到 6.62/9.27，约 2.3× 劣化；arXiv:2501.15310，2025-01——强核心经 LLM 纠错后 WER 不降反升；旧证据 Apple arXiv:2405.15216 **[已弃用]**报 3–12% 幻觉率）。
2. 前端注入受核心生成能力封顶但**不破坏**它，且闭源 API 原生可达（prompt 注入）。
3. 后端唯一可移植的 training-free 原语（受约束选择 + 误差去相关信号）保留为**发现段触发器**与**使用段信任标定器**——换数据集不换信号定义。

**基线哲学反转**：不要求先把核心调到极致再测知识系统。基线 = **裸核心标准用法**；long-context 全塞入、own-ASR 朴素级联从"基线"改编入**系统复杂度阶梯**（外挂系统的最低阶形态）——主主张比对裸基线，阶梯主张比对**平凡知识供给**，检验"组织智慧"的净增益。

### 1.3 组织框架：检索–发现–使用（RDU）

全部证据与未决问题以 RDU 三段透镜组织：

- **检索 Retrieve**：给定语音输入，如何在异构键空间中找到候选证据——核心难点是**匹配几何**（§5）；
- **发现 Discover**：**何时**需要知识、需**哪类**、检回候选里**哪些真相关**——一个可被测量的触发/门控子系统（§6）；
- **使用 Use**：知识以**何形态**进入模型、模型**采纳多少**——版本化标准知识卡 + 信任标定（§7）。

### 1.4 Stage-1 先验证据（全部 directional 假设级，带账本 ID）

- **使用段最强杠杆（已验、valid）**：结构化知识卡递送 **+24.6pp（相对 +34.6%，5/5 过 Holm；C-MINDS-V2）**——全项目最大已验效应，指向"递送形态"是主导杠杆。
- **纯指令有害（已验、valid）**：真 zero-shot 纯元指令（不给内容）在 MInDS-14 上 **−0.245，CI [−.286, −.201]（C-MINDS-V2）**——发现段必须供给**内容**，只给元指令反而破坏行为。
- **采纳固执（directional）**：冲突时模型仅约 **24% 采纳外部知识（SQuAD keep-参数 0.70；C-KEEP，directional，工件溯源后 mint）**——使用段信任标定的靶点。
- **召回优先（历史指征）**：精度门控在一次探针中给出 gate−inject **−0.134，CI [−.23, −.05]（C-T7）**，方向性提示"约束是召回而非精度、宁可多送不可漏送"。**诚实标注**：该探针测于已判 invalid 的信息泄漏语境，证据地位受损，故仅作**方向性 motivator**，其操作化约束将由发现段（§6）在清白管线上**重新独立建立**，不作已证规律引用。
- **reward 标定线（directional）**：存量池离线选择器电池中，logprob@8 在 clean/snr5 两条件下 corpus-WER 方向一致（clean +0.0094 [.0034,.0165]、snr5 +0.0081 [.0005,.0161]；C-ASR-V2），但在真实发现网格（16 比较）全家族 Holm 校正后**两条件均不存活**——directional，非独立复现。此信号依赖逐 token logprob，**已退出系统设计**（闭源 API 不保证可达），仅留 ledger 作工程诊断，发现段触发一律改用输出侧信号（§6、§10）。

## 2. 相关工作与定位（Related Work & Positioning）

**引用新鲜度规则**：每条方向影响型主张（方法有效性裁决、替代形态论证、效应量先验、测试床选型）由 **≥1 篇 ≥2025-01 一手来源**锚定；较早著作仅在带显式角色标签时引用——**[谱系]** = 历史谱系、**[标准]** = 方法学/统计标准（不过期）、**[已弃用]** = 引以宣告其死亡/被证伪。

### 2.1 上下文偏置：解码器访问分水岭 → 检索式注入

六族传统偏置技术在 chat-API omni 下**无一原样存活**，分水岭是**解码器内部访问**而非训练与否（活体锚点 = trie 研究 arXiv:2508.17796 + 当代 llama.cpp 工具事实）：shallow fusion（Zhao IS2019 **[谱系]**）、CLAS/深度上下文（arXiv:1808.02480 **[谱系]**）、trie 约束解码（arXiv:2508.17796）、TCPGen（arXiv:2109.00627 **[已弃用]**）、contextual adapters（arXiv:2205.13660 **[已弃用]**）、CTC beam boosting——均需帧级 log-prob 或训练。连"免再训练"的 CTC-WS（arXiv:2406.07096 **[已弃用]**）也失效——它需 CTC 帧 log-prob，而 chat API 不暴露任何帧 logit。

**检索式注入（retrieve-then-inject）是文献收敛出的替代形态**：大偏置库 → 语音键检索小候选子集 → prompt 注入。证据在与 Qwen3-Omni 同族基座上很强：BR-ASR（Qwen-Audio，arXiv:2505.19179，HB-16）、RECAST（Phi-4/GPT-4o-mini，EMNLP2025 findings.203，HB-23）、Hotword-RL（Qwen2.5-7B，arXiv:2512.21828，HB-15）、Locate-and-Focus（Qwen2-Audio，arXiv:2507.18263，ACL2025，HB-25）、Phoneme-RAG（Apple，arXiv:2409.15353 **[谱系]**，HB-24）。两条一致读数：(1) **top-2 甜点**——候选越多单调越差（HB-15 KER 11.99@top-2 vs 15.21@top-10），整表塞 prompt 在 N≥100 灾难幻觉、"list-vomiting"（LOGIC，arXiv:2601.15397，HB-17）；(2) **所有赢家检索器都是专门训练的对比检索器**（BR-ASR CLAP 命中 93/91%、GLCLAP 89/74%，HB-26），**off-the-shelf CLAP 词汇键已死（R@1≈0.1，HB-26）**。

**定位**：我方差异**不在偏置机制新颖**，而在把这条被专训检索器统治的能力做成**零训练、闭源 API 兼容**的系统——对外故事 = "零训练前端追平/超越需专训检索器的 pipeline"。这个赌注的可行性正是 §5 匹配几何的核心问题。

### 2.2 LLM 重排序 / 生成式纠错：收编为 reward 基础设施

后融合的最 load-bearing 裁定是**约束选择安全、自由改写陷阱**：N-best 受约束 closest-mapping 受 oracle 硬封顶、永不幻觉、training-free 可用（SEAL arXiv:2501.08421，2025-01——把受约束解码立为安全可部署原语；剑桥 arXiv:2307.04172 **[谱系]**）；而自由改写在强低-WER 基线上灾难劣化（LIR-ASR arXiv:2509.15095，2025-09）。**适用性限定**：该原语是 **regime-conditional 而非普适**——当 LLM 足够强时无约束解码在部分集上可超 N-best oracle（剑桥 arXiv:2409.09554，2024），约束选择的安全优势在"ASR 核心已强、头空小、幻觉风险高"（即本研究的 regime）时最大。因此后端被**收编为 reward 基础设施**——只保留受约束选择 / 误差去相关信号，不立后融合研究线；误差去相关的谱系借用 ROVER（Fiscus 1997 **[谱系]**）"互补错误"框架，**作借用基础设施认账、不作理论贡献主张**。

### 2.3 主动检索：FLARE / Self-RAG 谱系与"迁移问题"

发现段的**触发式两遍管线**（第一遍生成取不确定度 → 决定检索 → 第二遍生成）**不是新方法**，其谱系是文本 LLM 的主动/自适应 RAG——**FLARE**（Jiang et al. 2023，arXiv:2305.06983 **[谱系]**）与 **Self-RAG**（Asai et al. 2023，arXiv:2310.11511 **[谱系]**）。我方定位发现段 = **"主动检索能否迁移到冻结 omni"**，非机制新颖（§6）。

### 2.4 语音 / 多模态 RAG 与再听

音频键 / 跨模态检索是最佳拟合（BR-ASR、GLAP、Locate-and-Focus），避开"转写-bootstrap 失效"；但 BR-ASR 自身的赢家实为**文本键**（更 OOV-鲁棒、更少同音命中）。**再听（re-listening）**是当前前沿——把源音频喂回纠错器（AVGER arXiv:2501.04038，2025-01，audio-visual GER，LRS3 相对 WER −24%；SEAL 走 speaker-error 轴）；Qwen3-Omni 天然可再听，但令 reward 音频接地时 **Information-Boundary Guard 适用**（验证器不得见 golden 转写）。**同音/近音干扰污染**是音频相似检索的 #1 已证失效（BR-ASR DCL、RECAST 硬负挖掘，HB-21）——任何 retrieve-then-bias selector 须含**显式 precision / 去相关项**。

### 2.5 定位总述

**我方不主张任一段的机制新颖，而主张在一个零训练、闭源 API 兼容的 omni agentic system 上，把 RDU 三段精心组织后取得业务效果**——对裸核心基线错误率相对下降 ≥10%、全家族校正后可靠、边界清白，并在系统复杂度阶梯上相对平凡知识供给有可靠净增益。与先行工作的关系：偏置线——我方**零训练** vs 其**专训检索器**（§5 是这条赌注能否成立的关键）；后融合线——**收编为 reward 基础设施**；主动检索——**迁移问题**；语音 RAG——**键模态答案已分化**。**效果是唯一最终裁判**，成败以业务效果判定，不以"负结果也是贡献"自我安慰。

## 3. 问题陈述与假设（Problem Statement & Hypotheses）

### 3.1 主问题（唯一，效果口径）

> 以冻结 Qwen3-Omni-30B 为核心（科学载具；接口按闭源 API 兼容层约束）的 omni agentic system，加装前端多模态知识子系统（RDU 三段，组件异构、全部冻结使用），能否在知识依赖型语音任务上，对**裸核心标准用法基线**取得 **≥10% 错误率相对下降**、全家族校正后统计可靠、边界清白的业务效果提升？并在**系统复杂度阶梯**上，精心组织的 RDU 配置相对平凡知识供给（long-context 塞入、own-ASR 朴素级联）是否有可靠净增益（"组织智慧"的次级主张）？

**双主张结构**：(a) **头号主张** = 最优 RDU 配置 vs 裸核心基线，错误率相对下降 ≥10%（口径见 §8.3）；(b) **阶梯主张** = 最优 RDU vs 平凡供给臂的较优者的可靠净增益，裁定"增益是否归因于 RDU 组织智慧、而非仅来自任何知识供给"。

- **成功语义**：达标 → 系统主张成立，对外故事 = "零训练前端追平/超越需专训检索器的 pipeline"。
- **失败语义**：不达标 → 进入**系统设计迭代循环**（§11，Stage-2 内 ≤5 轮、每轮 owner 批准），耗尽迭代预算仍不达标才由 owner 决定是否转向边界性结论。**"负结果也是贡献"禁用于主问题**——主问题按去赢设计；该表述仅保留给次级科学点。
- **合规口径**：组件"冻结使用" = 我方不训练任何参数（零 LoRA、零投影、零 adapter）。上游预训练组件（含 trained-frozen 检索器）照 **LLMLingua-2 先例**（Pan et al. 2024，arXiv:2403.12968 **[标准]**）如实披露为"用法 training-free、非 training-free-by-construction"。若任一环节须训练一个薄投影才能达标，则如实报告为 training-free 检索的**负结果**，绝不静默替换。

### 3.2 主效果假设 H-sys

- **Estimand**：最优 RDU 配置相对基线的**错误率相对下降**（单尺度）；主聚合口径 = 跨集固定效应（DerSimonian-Laird 随机效应仅作参考，k=3–4）。
- **决策规则**：错误率相对下降尺度单门；**per-dataset SESOI 数值表**预注册（§8.3）；主判定 = 错误率相对下降 ≥10% 且家族校正后 CI 下界越过该集 SESOI。
- **交互模型预注册**：`y ~ key + delivery + key×delivery + (1|group)`；H-sys 赢家按**格级估计**选择（非边际），主效应解读受交互-CI 宽度门控（防边际平均把键模态主效应稀释成 null）。
- **双主张裁定**：**go = H-sys-a**（vs 裸基线达标）于确证层成立；**H-sys-b（阶梯净增益）单独裁定**——若最优 RDU 对两条平凡供给臂的净增益家族校正 CI 下界均 >0 → "组织智慧"叙事挣得；若仅 H-sys-a 达标而阶梯净增益为 null → 系统有效但增益归因于"知识供给本身"，如实降级叙事，不 kill H-sys-a。

### 3.3 五个次级科学点（S1a / S1b / S2 / S3 / S4）

- **S1a（同分布冻结匹配）**。**问题**：给定冻结嵌入器，把检索键从"文档内容形态"（q2a）改造为"问题形态"（q2q，建库离线伪问题合成）能否显著提升同分布匹配质量？——即**零训练的匹配几何重塑**是否有效（详见 §5）。**Estimand**：q2q 伪问题合成键 vs q2a 直接内容键的检索质量（R@k / nDCG）与端到端贡献，同一冻结嵌入器。
- **S1b（生成桥接 vs 专训检索器——系统核心反制）**。**问题**：最优生成桥接配置（建库 q2q + 查询时 a2a/HyDE）能否**在零训练下**追平/超越专训冻结检索器（GLAP / nemotron）？——这是"零训练前端 vs 专训检索器"整个赌注的核心检验。**Estimand**：生成桥接几何 vs trained-frozen 检索器的检索质量与端到端贡献。**预注册承诺**：若须训练一个薄投影才达标，如实报告为 training-free 的**负结果**。
- **S2（递送主效应，收敛为标准）**。**动机**：递送形态是全项目最大已验杠杆（结构化卡 +24.6pp / 相对 +34.6%，C-MINDS-V2）。**Estimand**：**版本化标准知识卡 vs flat 注入**（单一预注册对比，详见 §7）。
- **S3（发现段·被测量子系统）**。**动机**：何时检索——全项目证据最薄段；定位 = active-retrieval（FLARE / Self-RAG **[谱系]**）向冻结 omni 迁移。**Estimand**：触发式 two-pass 相对恒检索的**效果-成本 Pareto 位置**——增益差 **TOST**（等价，margin 预注册）+ 调用降幅 **≥30% superiority**（Pareto 支配），**两门皆须过**（详见 §6）。第一遍不确定度信号 = 输出侧 **m=5 采样自一致性一致率**（温度 T=0.7）。
- **S4（实体粒度实例；热词/上下文偏置）**。**动机**：热词偏置 = RDU 三段在实体粒度的具象，retrieve-then-inject 被 ≥5 篇同族基座论文强证据支持为替代形态（附录 A）。**匹配几何在实体粒度的具象** = **合成 carrier-sentence 键**（§5.4）。**Estimand**：可部署列表 = eval 前冻结的热词库经音频键检索的产出（outcome）；"真词保证入列"降为 oracle 上界臂、永久不可部署；B-WER 主指标（相对 ≥15% 靶，比 H-sys 更严）**reference-anchored 计分**（§8.5）。

## 4. 系统架构（System Architecture）

### 4.1 RDU 三段管线

```
语音输入 audio-in
  └─▶ [发现 Discover：何时/需何类知识 — 触发式两遍管线（可被测量的子系统，§6）]
        └─▶ [检索 Retrieve：匹配几何（q2q/q2a/a2a 三态 × 生成桥接，§5）]
              └─▶ [使用 Use：标准知识卡（content/source-tag/relevance-signal/usage-directive）+ 信任标定（§7）]
                    └─▶ 冻结 omni 核心生成 core generation ─▶ 业务效果 business effect
```

### 4.2 系统接口契约（硬约束，唯一，无 tier 划分）

只用任何闭源 API 都保证暴露的接口：**音频/文本输入、文本输出、多次采样**。发现段触发用**输出侧信号**：采样自一致性（m=5，一致率颗粒度 {0,.2,.4,.6,.8,1}，首遍温度 T=0.7、与第二遍 greedy 明确区分）、验证器一致度、答案级置信引出。

logprob 触发、`logit_bias` 加性偏置、语法硬约束**不是系统组件**——三者均依赖解码器内部访问，闭源 API 不保证可达，已从系统臂族移除。唯一相关的已验信号 logprob@8（C-ASR-V2，directional）的 Stage-1 标定记录保留于 ledger、仅供工程诊断，与系统组件严格分离。本地冻结核心亦**仅经黑盒接口使用**（接口对等性 = 设计属性），llama.cpp 白盒能力仅限工程诊断。

### 4.3 知识子系统候选组件（全冻结使用；选型由 dev 效果决定并如实报告）

| 组件 | 角色 | 键/来源 | 冻结使用标注 | 一手锚 |
|---|---|---|---|---|
| **qwen3-omni-own** | 键=查询嵌入（旗舰）+ 生成桥接的伪问题/HyDE 生成器 | 2048d 隐态音频嵌入；黑盒生成 | 零训练/零投影；核心为上游预训练（LLMLingua-2 先例 **[标准]** 披露） | LCO-Embedding arXiv:2510.11693（2025-10，冻结 MLLM 无音频训练即 MAEB #1）+ MAEB arXiv:2602.16008（2026-02，均分 ~50–52%，远未饱和） |

### 4.4 科学载具 vs 可迁移性

**科学载具**：Qwen3-Omni-30B Q8_0 GGUF via llama.cpp（`-ngl 28`，resident `llama-server`），数据/代码/种子全 pin，**确证层结果在此复现**。选用本地冻结核心作代理的正当性在于：本系统**只经黑盒接口消费核心**（音频/文本进、文本出、多采样），本地核心的白盒能力在系统设计中被主动封锁、仅供工程诊断——因而在本地核心上成立的每一条系统级结论，其依赖的输入面与闭源 API 完全一致，不含任何闭源不可得的特权。**可迁移性主张**：接口最小化设计 + **跨核心迁移冒烟**（同一系统接口契约在第二核心 MERaLiON-2 或一闭源 API 上 1–2 集轻验，作可迁移性证据，非门控项）。科学结论落在冻结本地核心（严格可复现），可迁移性作为价值证据由跨核心冒烟支撑，**不以单核心成立冒称通用**。

## 5. 检索段：匹配几何（Retrieve — Matching Geometry）

### 5.1 核心难点：匹配对象与递送对象分离

检索段的深层难点不是"用哪个向量模型"，而是**匹配几何**。一条语音查询 q（问题分布）与一段被存储的证据文档 d（答案/内容分布）**天然处在不同分布**。用冻结的 off-the-shelf 嵌入器把 q 直接对 d 的内容匹配（**q2a**）是**跨分布弱关联**——这正是 off-the-shelf CLAP 词汇键已死（R@1≈0.1，HB-26）、而文献里每个赢家检索器都是**专门训练的对比检索器**（BR-ASR CLAP 93/91%、GLAP 93.8/98.5，HB-26）的根因：**训练检索器的全部作用就是桥接这条 q/a 分布沟**。

关键设计裁定：**匹配对象与递送对象分离**。

- **递送对象（value）= 证据内容，恒定不变**——不管键是什么形态，命中后递送给模型的永远是证据内容本身。
- **匹配对象（key）= 最大化匹配信号的任意形态，含问题形态**——键不必等于被递送的文档，可以是为该文档合成的伪问题、可以是内容本身、可以是查询的假想答案。

### 5.2 三态匹配几何：q2q / q2a / a2a

| 匹配regime | 键形态 | 匹配强度 | 实现（黑盒契约合法） |
|---|---|---|---|
| **q2a**（直接内容键） | 键=文档内容 | 跨分布**弱**关联（基线） | 冻结嵌入器直接编码文档内容；off-the-shelf 词汇键此处已死 |
| **q2q**（建库伪问题合成键） | 键=为文档合成的伪问题 | 同分布**强**信号 | **建库离线**：冻结核心为每篇证据合成若干伪问题（doc2query 式，Nogueira et al. 2019 **[谱系]**），键落在问题空间；语音查询本身即问题 → q2q 同分布匹配。仅调用黑盒 `generate`，**契约合法** |
| **a2a**（查询时 HyDE 桥） | 键=查询的假想答案 | 同分布**强**信号 | **查询时**：冻结核心为查询生成假想答案/证据（HyDE，Gao et al. 2022，arXiv:2212.10496 **[谱系]**），再以答案空间对文档内容匹配，把查询桥入证据空间 |

### 5.3 零训练路线：生成桥接匹配几何

文献用**训练**桥接 q/a 沟；本系统的零训练反制是**用生成桥接匹配几何**——两条路线都只调用黑盒生成接口，**无任何权重训练**：

- **建库侧 q2q**（doc2query 式伪问题合成，离线一次性，成本摊薄）：把键从内容空间搬到问题空间，让同分布匹配替代跨分布匹配。
- **查询侧 a2a**（HyDE，每查询一次生成，按两遍计价）：把查询从问题空间桥到答案空间。

**契约合法性与成本结构**：两条桥接路线都**只调用黑盒 `generate`**，不触碰任何权重、不访问解码器内部——因而对闭源 API 同样成立。成本分摊不同：建库侧 q2q 是**离线一次性**（伪问题合成随语料构建摊薄，查询时零额外遍数）；查询侧 a2a/HyDE 是**每查询一次生成**（按两遍计价，§6.2）。设计上二者可组合——建库 q2q 提供强同分布召回底座，查询 a2a 在难例上补桥；组合与单用的边际由 dev 效果决定并如实报告（家族表 #4–#6）。

**S1 分解**由此而来：**S1a** = 同分布冻结匹配（q2q vs q2a，同一冻结嵌入器，检验生成重塑几何是否有效）；**S1b** = 生成桥接几何（q2q/a2a 较优者）vs 专训冻结检索器（GLAP/nemotron），**系统的零训练核心反制**——能否在不训练任何参数的前提下，追平文献用训练买到的匹配质量。这是整个"零训练前端 vs 专训检索器"叙事成败的关键格：若生成桥接追平/超越 trained-frozen，则零训练路线自证；若不能、且须训练一个薄投影才达标，如实报为 training-free 负结果（§3.3），绝不静默替换为训练组件。

### 5.4 实体粒度：合成 carrier-sentence 键（S4）

匹配几何在实体粒度的具象：不用裸实体字符串作键（表面形式脆弱、同音易混），而是**合成一句承载该实体的 carrier-sentence 作键**——键因而落在与语音 utterance 同分布的可匹配形态（同 q2q 逻辑）。同音精度由 §8.5 的 H5a（检索召回 + 同音精度）单独诊断，界定同音误注入率。

## 6. 发现段：被测量子系统（Discover — Measured Subsystem）

发现段从"一个门"升格为**可被完整测量的子系统**。不再问二元的"要不要触发"，而是**测量整条效果-成本前沿**并把性能缺口归因到可定位的失效源。

### 6.1 算法空间（显式定义）

触发/门控算法空间显式枚举：**恒检索（always）**、**触发式两遍（triggered，第一遍取不确定度→决定→第二遍）**、**从不检索（none）**，及触发信号的变体（自一致性 / 验证器一致度 / 置信引出）。触发式两遍管线机制：第一遍以 **m=5** 采样、温度 **T=0.7** 取自一致性一致率（颗粒度 {0,.2,.4,.6,.8,1}），低一致率 → 触发检索 → 第二遍 greedy 生成。**逐 K-型答案等价定义**（预注册）：MCQ/闭式 = exact-match，抽取式 QA = normalized token-F1 ≥0.8，ASR = 样本间 normalized WER ≤0.1。

### 6.2 效率 = 效果-成本 Pareto 前沿

**恒检索 / 触发式 / 从不检索是同一条曲线上的三个点**，报告**曲线而非单一赢家**。横轴 = 成本（生成遍数：触发 item = m+1 = 6 遍，未触发 = m = 5 遍，恒检索 = 2 遍/item，从不检索 = 1 遍）；纵轴 = 效果（错误率相对下降）。S3 的确证判定 = 触发式点是否 Pareto 支配恒检索（增益差 TOST 等价 + 调用降幅 ≥30%，两门须过，§3.3）。

### 6.3 三层指标栈（核心新构件：需求标签）

| 层 | 指标 | 定义 |
|---|---|---|
| **L1 需求标签（need labels）** | 该 item 是否**需要检索** | **oracle 注入改变该 item 结果 ⟺ 需要检索**（ground-truth 需求，由 oracle-retrieval 臂 vs 裸核心逐 item 差分产生） |
| **L2 触发混淆矩阵** | 触发器决策 vs 需求标签 | 触发器的 retrieve/¬retrieve 对 L1 需求标签 → 真 TP/FP/FN/TN 混淆矩阵（触发器质量的真评估，不再是二元硬币） |
| **L3 端到端归因恒等式** | 总缺口三项分解 | **漏检损失（miss，需要但未触发）+ 失配损失（mismatch，触发但检回错证据）+ 未采纳损失（non-adoption，递送对证据但模型未采纳）≈ 总缺口** |

归因恒等式把"最优 RDU 距 oracle 上界的总缺口"分解为三段可定位、可归因的损失，直接指向迭代循环该修哪一段（§11.2 back-edge）——**漏检损失大** → 修发现段触发（放宽门控/换触发信号）；**失配损失大** → 修检索段匹配几何（§5，q2q/a2a 强化或换键）；**未采纳损失大** → 修使用段知识卡与信任标定（§7，调 usage-directive/α）。这把"系统不达标"从一个笼统结论变成一张可执行的修订清单，也令阶梯主张（H-sys-b）的解读有据：若净增益 null 的同时未采纳损失主导，则瓶颈在采纳而非组织。L1/L2/L3 为**描述性诊断**（非门控，不设 pass/fail 阈值），驱动 Pareto 前沿解读与迭代归因；确证判定仍由 §6.2 两门承载。

## 7. 使用段：标准知识卡（Use — Standard Knowledge Card）

使用段收敛为**一个规范**：版本化标准知识卡 schema。

### 7.1 版本化知识卡 schema

| 字段 | 内容 | 作用 |
|---|---|---|
| **content** | 检索到的证据内容（递送对象本身） | 模型据以作答的知识 |
| **source-tag** | 来源/出处标签 | 可溯源、可信任分层 |
| **relevance-signal** | 检索相关度信号（分数/置信） | 供模型加权、供信任标定 |
| **usage-directive** | 使用指令（如"仅当与语音中的实体相关时采用"） | 引导采纳，抑制盲抄 |

schema 版本化（写入 content_hash），跨集不变——换数据集不换 schema，只换 content。

### 7.2 S2：标准卡 vs flat

**S2 收敛为单一预注册对比 = 版本化标准知识卡 vs flat 注入**。动机是全项目最大已验杠杆（结构化卡 +24.6pp / 相对 +34.6%，5/5 过 Holm，C-MINDS-V2，valid（Stage-1 假设级））。这把 v-early 版本里"递送主效应 − 键模态主效应"的复合估计**简化为一条清晰对比**，裁定"标准卡组织"是否显著优于平铺注入。

### 7.3 信任标定

使用段核心约束是**采纳固执**（冲突时仅约 24% 采纳外部知识，C-KEEP，directional）——模型倾向相信自身参数而非外部证据，这既保护它免于低质检索的污染，也让高质证据的价值打折。信任标定的目标是**按证据质量条件化采纳**：证据可信时压制固执、提高采纳；证据可疑时保留固执、避免被误检索带偏。操作上用输出侧信号（自一致性、验证器一致度、置信引出）估计证据可信度，映射到知识卡的 **relevance-signal 字段**与 **usage-directive 措辞**，间接调节采纳权重 α（系统不改权重，只改递送形态与指令强度）。这把"采纳多少"从一个固定常数变成一个随证据质量变化的函数——**采纳固执 = 信任校准的靶点，而非要一律推高的旋钮**。reward 信号供给见 §10。

### 8.2 基线与系统复杂度阶梯

**基线 = 裸核心（frozen Qwen3-Omni-30B，无任何外挂知识子系统）标准用法**，可操作化定义（dev 轻调后冻结、写入 hash）：(a) 固定任务模板（音频进 + 固定任务定义文本；绝不含 golden 转写/答案/intent）；(b) greedy 采样（temperature 0.0，locked `sampling_params`）；(c) dev 轻调自由度仅限模板措辞与解析正则；(d) 基线只用系统接口契约。第三方可对照冻结模板/采样参数客观核验"基线是否被刻意压低"。

**系统复杂度阶梯**（臂族内自低向高）：①**long-context 全塞入**（平凡知识供给，无检索；预期在大列表下崩溃，HB-25 全注入 TSR 28.20% ≪ 检索 65.53%）；②**own-ASR 朴素级联**（ASR→文本键检索→注入，ASR WER 作协变量）；③**RDU 完整配置**。头号主张比对裸基线；阶梯主张比对 ①②。

### 8.3 单尺度与 SESOI

主判定尺度统一为**错误率相对下降**——准确率类按 error = 1 − acc 换算后取相对下降；主判定 = 错误率相对下降 ≥10%（H-sys）/ ≥15%（S4 B-WER，更严）。此统一口径避免**高基线天花板悖论**（例如 SQuAD-zh acc=0.925 按"acc 相对提升 10%"需 acc→1.0175 超天花板；改按错误率 error 0.075→0.0675 落在天花板内、可判定）。**不设"绝对且相对"双门**。per-dataset SESOI 数值表预注册：把 10% 错误率相对下降换算为各集绝对当量（heysquad 基线 error 0.775 → −0.0775 error；SLURP-intent 0.3548 → −0.03548 error；余待首格回填）。

### 8.4 预注册参考系资格规则

- **判定切分**：资格判定使用**第三个独立切分（eligibility-split）**——与探索层 exploration-dev、确证层 confirmatory 三方两两 group-disjoint，同一套 group-aware 抽取机器产出，预注册 n=40/集。这堵住"dev 噪声既抬头空侥幸达标、又在退场时收缩校正分母"的结构性双重得利。
- **判定条件**：进入主参考系（家族表）须在 eligibility-split 上同时满足：①**闭卷基线 < 0.85**；②**知识头空（oracle-retrieval − bare-core）的 CI 下界 ≥ 2×SESOI**（headroom 与 SESOI 同为 error-reduction 尺度）。判定用 **CI 下界**而非点估计。
- **单向性**：只出不进——数据集一旦退场为诊断状态，本迭代周期内不回补；重新入表须待下一迭代轮在新一轮 eligibility-split 上重判。
- **固定 MAX 家族规模**：家族表 15 项即预注册 MAX 家族规模，签署后固定不变；任一集经资格规则退场，**Holm/max-T 分母不收缩**——退场行记为"结构性不适用（N/A）"、不产出统计量，但仍占预注册分母位，校正**始终按 MAX=15 计算**。

**诚实预告**（基于早期 dev 信号，非正式判定）：SQuAD-zh（0.925）大概率因条件①退场为诊断状态；最终名单以 eligibility-split 正式判定为准。

### 8.5 S4 实体偏置协议

- **度量**：主指标 = 相对 B-WER/B-CER 下降（B-WER/U-WER 约定 = Le et al. arXiv:2104.02194，IS2021 **[标准]**）；U-WER/插入错误并列报告以惩罚盲抄。
- **热词库冻结**：每测试床热词库在 eval 之前冻结（is21 ~209.2K 稀词池 HB-28；AISHELL-NER 891 实体 HB-29 ICASSP2022；SLURP 逐域 slot 值库 HB-30 arXiv:2011.13205 EMNLP2020），快照写入 content_hash。
- **可部署列表 = 音频键检索产出**（含 carrier-sentence 合成键，§5.4），非注入 golden；真实体不保证入列。
- **B-WER 计分——reference-anchored**：计分对象（分母）= 该 utt 的全部参考偏置词（来自热词库 ground-truth，与检索是否命中无关）；检索产出**只**决定"哪些词进入 deployable 列表"，**绝不**决定计分范围。真实体被检索**漏检**时在 B-WER 中**计为错误**，绝不从计分对象剔除——deployable 臂的 B-WER 天然内含"召回不足"的惩罚，杜绝"只对检索到的词打分"的自我打分泄漏。命中与否**额外**作 H5a（检索召回 + 同音精度）单独报告，不替代主计分。
- **oracle 上界臂**：真词保证入列的列表降为**永久标注"不可部署、只作上界 headroom"**，与 gold-transcript 臂同级，绝不作主指标。
- **列表长度扫描 {2,5,10,50}**：先验甜点 top-2（HB-15）；另设 oracle-list 距扰词 N∈{100,500,1000,2000} 上界参考曲线（仅对文献 apples-to-apples）。
- **H5 目标与回退（adopted）**：H5 相对 B-WER 靶 15%；**若 M1 首格 dev smoke 测得检索短列表 prompt 相对 B-WER 降幅 <12%，目标自动下调至 10%**（与 H-sys 同尺度对齐），实测值与是否触发回退在 M2 如实记录。

### 8.7 cluster bootstrap 与功效诚实

paired cluster bootstrap，group_key = 来源篇章 id（heysquad/SQuAD：Wikipedia passage）/ 说话人或场景（SLURP）；跨集以固定效应为主，DL τ²（k=3–4）仅参考。**无组键的集**：或补真组键、或不入确证层；不得以 item-level bootstrap 冒充组无泄漏。**功效诚实**：dev n≈40、heysquad ci95 宽（有效 cluster 数 20–45），Holm 校正 15 项后排除 0 的功效低——**故探索层不触发任何 kill**（输出 = 配置排序 + Phase-B 协议草案）；kill 仅在确证层以加大 n 的锁定 test 判定。

### 8.8 采样 custody 与程序性防火墙

**custodian = 提交先于选择的确定性脚本 + 固定种子**：确证抽取由一个**在 arm 选择之前即提交到版本库**的确定性抽样脚本（固定 seed）执行——任何第三方可**逐字节复现**同一抽取。**程序性防火墙**：arm 冻结之前不发生任何确证 test 读取（探索/确证 split group-disjoint，探索层 dev-only 输出仅配置排序）。确证工件必须非空 provenance：`git_sha`（`git_dirty=false`）、`engine_build_id`、`dataset_revision`、`manifest_hash`、`sample_manifest` hash、`seed`、`env_versions`、KB `content_hash` + `embedder_token`；度量定义（corpus vs macro、B-WER vs WER）显式标注。确证 re-run 从干净 checkout 执行，记 re-runner 身份 + 日期 + run ID，落在预注册容差带内方过。

## 9. 边界纪律、custody 与完整性装置（Integrity Apparatus）

**Information-Boundary Guard（STANDING RULE）**：任何杠杆若靠部署没有的信息抬指标即 **invalid，无论统计多显著**；四问全 YES 方可跑（部署可得性、模态尊重、无 test-item 泄漏、真能力非喂答案）。

**逐臂 IB-Guard**：

| 臂类型 | 部署可得性 | 无 test-item 泄漏 | 裁定 |
|---|---|---|---|
| 检索键嵌入（omni-own/GLAP/nemotron，含 q2q/a2a 生成桥） | query = 音频；伪问题/HyDE 由核心自身生成 ✅ | value = 库 eval 前冻结的外部语料证据，绝不含 test-item ✅ | 部署 |
| own-ASR 级联 | query = omni 自身 ASR 输出（非 golden）✅ | 不注入 golden 转写；ASR WER 作协变量 ✅ | 部署（阶梯②） |
| 标准知识卡递送 | 文本任务定义 + 检索到的 KB 值 ✅ | 无 test-item 答案 ✅ | 部署 |
| S4 deployable 偏置列表 | = 音频键检索产出 ✅ | 真实体不保证入列、只在命中时出现 ✅ | 部署 |
| oracle-retrieval / gold-transcript / 保证入列列表 | ❌ 部署无此输入 | 用了 reference/golden | **永久非部署，只作上界 headroom** |

**KB custody**：`content_hash` 扩展覆盖**嵌入器 SHA + revision + 量化 + 归一化配置**（键侧/查询侧各一）与**索引构建参数**；**fail-closed 键==查询断言**——查询时须以 manifest 的 `embedder_token` 重嵌入到与持久化键同一空间，键侧 token ≠ 查询侧 token 时**抛错，绝不回退到默认嵌入器**（堵静默换空间 bug）。伪问题合成键与 carrier-sentence 键的生成 prompt/温度/seed 亦纳入 content_hash。

**五类常驻失败模式（结构性预防）**——从既有 invalid 谱系提炼：
- **P1 信息边界泄漏**（喂 golden 转写/答案→假增益；C-M3 假 +22.4%、C-T7 假 +51.7pp = invalid）→ 递送列表 = 检索产出（非注入）；oracle/gold 臂永久标不可部署；每杠杆过 IB-Guard。
- **P2 对象错配**（KB 值 = 查询自身文本而非检索语料文档；C-PHASEA = invalid）→ 语料侧 KB 重建；值必为**证据内容**；content_hash 扩展至嵌入器+索引。
- **P3 transductive/非零样本混淆**（support 建自 eval 行；C-MINDS-POLICY = invalid）→ 卡池与 eval 不相交；确证池组不相交于 union(dev + 旧 test + 65 曝光（指 65 个曾用于探索的 locked-dev 清单，已永久降级为非保密开发集）)；选择仅在 dev。
- **P4 依赖运行冒充重复 / winner's-curse**→ 独立组 cluster bootstrap；H-sys 赢家按 dev 格级估计选定、确证层单通道重立；S2 单一预注册对比。
- **P5 家族误计 / 事后收窄**→ 15 项家族全枚举预注册（固定 MAX，资格判定标注 N/A 不收缩分母）、全进 Holm/max-T；"显著"必注家族；交互模型预注册。

**伦理/许可/dual-use**：逐集 license + permitted-use；生物特征/声纹（AISHELL 说话人、SLURP）与情感数据按 PII/敏感属性处理；上下文偏置的预期用途界定为**无障碍/知识辅助**（防监听式关键词 spotting 误用）。

## 10. reward 信号层与理论轨（Reward-Infra & Theory Track）

### 10.1 reward 信号层（数据集无关的借用基础设施，非理论贡献）

reward 信号层**不是研究方向**，而是一组数据集无关的标准信号供给——换数据集不换信号定义。它只服务两处前端决策：(a) 发现段触发（§6），(b) 使用段信任标定（采纳率 α，§7.3）。**明确不用于输出重排序作为研究主张**。误差去相关信号 δ_corr 引 ROVER（Fiscus 1997 **[谱系]**）作跨源误差互补的借用基础设施认账，**移出定理约束清单、不作理论贡献**。

| 信号 | 所需接口 | 触发用途 | 标定用途 | 状态 |
|---|---|---|---|---|
| 小样本自一致性（m=5 采样一致率 / ROVER 词对齐投票 / MBR 互评 WER） | 多次采样、文本出 | 一致率低→触发 | 一致度→信任权重 | MBR@8 中性（ns），C-ASR-V2 directional |
| 验证器一致度（δ_corr：第二个 context-differentiated 冻结 omni 打分，同权重异 system-prompt） | 二遍推理、文本出 | 验证器质疑→触发 | 跨源一致→采纳 | 借用基础设施（ROVER/Fiscus） |
| 答案级置信引出（追问模型自评可答性/置信） | 追加一轮、文本出 | 低置信→触发 | 自评置信→α 校准 | 未验，探索层标定 |

logprob 类白盒信号退出系统设计（闭源不保证可达），仅留 ledger 作工程诊断。**成本纪律**：自一致性触发的多采样成本入 §6.2 按遍计价（触发 item m+1=6 遍）。**离线标定**用冻结存量池 CPU near-free（选择/验证器**永不见 golden 转写**）。

### 10.2 理论轨（形式化对象 = 系统算子，与工程实现同指一物）

对象 = **系统算子**（两遍管线触发规则与检索-递送复合算子），非"模型本体纯度"。门类匹配：触发是**有限一次性选择器** → 出**良定性说明 + 相关界**，不强证"收敛"（收敛在此未定义）；多轮迭代化推广才需收敛论证。

1. **两遍触发算子** g：signal s ↦ {retrieve, ¬retrieve}（阈 τ）。正确性 = 有界信号上确定阈值良定。**无约束反例（过严门控）**：precision 最大化的门在信号无信息（ρ_s≈0）时把 recall→0，端到端增益 G(g)=recall·Δ_deliver−(1−precision)·c_distractor 可 →0 或负——由 gate−inject 的方向性历史指征（C-T7，仅作构造 motivator，不作定理前提）激励。**recall 下限约束下的保证**：加显式约束 recall(g)≥r₀，则在冻结 omni 对干扰 passage 鲁棒（c_distractor 有界）下、Δ_deliver>0 时 RHS≥0——两段结构（无约束过严门失败 + recall 下限恢复下界），recall-floor 是发现段算子的显式约束项。
2. **检索-递送复合算子** D∘R：检索返回 ∅ 时 = 冻结基策略的恒等（no-retrieval 无头空）——系统只靠**送入真新证据**买头空、而非"多挂检索机器"帮忙，机器可验证。
3. **Coverage 引理作 i.i.d. 前置（非 operator-linked）**：复用 i.i.d.-Bernoulli 覆盖引理描述 top-k 覆盖概率 1−(1−p)^k；明确 NOT operator-linked（形式化的是抽样步、非选择规则），operator-linked 定理计数 = 0 为权威。
4. **可执行一致性**：Python↔Lean 逐例一致性测试令实现的触发/复合算子与定理假设逐例吻合；闭合前不作"Lean 证明我方触发收敛"的任何论文句。
5. **约束项 + 假设账（每假设量给测量槽）**：已有约束——τ→oracle（DONE）、β 信赖域、N* 预算；新增 recall-floor（发现段专属）。待验假设各有测量槽：per-item 检索召回 p、干扰代价界 c_distractor、信号-增益相关 ρ_s（§10.1 标定表）。

## 11. 风险、迭代/停止规则与里程碑门控 DAG

### 11.1 风险与缓解

| 风险 | 似然×影响 | 消解 gate |
|---|---|---|
| 跨模态路由缺口（audio-query→text-keyed-corpus 未实现） | 高×高（M1 门槛项） | M1 门内先交 own-ASR 文本-文本臂；路由并行建+验证；audio-key 臂门控于路由验证；cascade WER 作协变量 |
| 匹配几何失效（生成桥接不足以追平专训检索器） | 中×高 | S1a/S1b 分层判定；若须训练薄投影如实报 training-free 负结果；trained-frozen 对照臂界定头空 |
| 同音/近音污染（HB-21） | 高×中 | 音频键+文本键双持（BR-ASR TextualBias OOV-鲁棒）；recall-floor 算子含显式 precision 项；carrier-sentence 键；H5a 单独报同音精度 |
| 闭源 API 信号成本（自一致性/置信引出需额外采样；δ_corr 需 GPU） | 中×中 | 按生成遍计价（含 m=5 的 m+1=6 遍）；离线标定用存量池 CPU；δ_corr = 对存量池一遍打分非重生成 |
| 小簇退化（有效 N=cluster 20–45；k=3–4 DL τ² 不可靠） | 中×中 | group_key cluster bootstrap；固定效应为主；无组集不入确证或补组键；kill 确证层专属 |
| GPU 预算（多遍臂） | 中×中 | 按遍计价；开跑前实测 1 真格；两批切分（text-key 先）；GPU 会话 lock 协调 |

五类常驻失败模式 P1–P5 见 §9。

### 11.2 迭代 / 停止规则（效果优先；确证层专属 kill）

1. **确证层 H-sys 达标** → 系统主张成立，进入 Stage-3 评估。
2. **确证层不达标** → **系统迭代循环**：用 §6.3 归因恒等式分解瓶颈段（漏检/失配/未采纳）→ 修订组件/协议 → **重新探索**（DAG 上 M5→M2 back-edge）。**归因分析仅限探索 dev**——已消费的确证 test 绝不重读（防对已用尽 holdout 的适应性过拟合）。每次回退须：**全新 custodian 抽取**（新提交的确定性脚本 + 新固定种子）+ **append-only 预注册修正** + **owner 对该轮重新签字**；受 **alpha-spending**（每轮 α=0.01，总预算 0.05）与**预注册 holdout 供给表**（每集 max_rounds_supported = floor(未曝光组/round_size)，支持轮数<5 者如实封顶）双重约束。**预算 cap = Stage-2 内 ≤5 轮**（每轮 owner 批准）。
3. **oracle-retrieval 无增益的集** → 退出主场（仅适用于已通过资格规则、已进 confirmatory 但 headroom 反转/消失的情形，与 §8.4 资格规则时序/对象不重叠）。
4. **确证层专属 kill**：探索层不触发任何 kill，一切 TOST/CI 判定只在 owner 签 Phase-B 后的确证层发生。
5. **负结果纪律**："负结果也是贡献"禁用于主问题；次级科学点 S1a–S4 各自如实报告，正负皆入 claim_ledger，不影响 H-sys 判定路径。

### 11.3 里程碑门控 DAG（无日历周；按门 entry criteria 全绿推进）

```
M1 工程就绪 ──▶ M2 探索完成 ──▶ M3 Phase-B 签署（owner） ──▶ M4 确证完成 ──▶ M5 迭代或 Stage-3 裁决
              ▲                                                                          │
              └────────────── M5→M2 back-edge（不达标迭代，≤5 轮 cap，见 §11.2）◀───────────┘
```

**M1 工程就绪（立即开工，entry criteria）**：clean-checkout 重建绿；**跨模态路由**（audio-query→text-keyed-corpus）实现验证；**两遍管线 harness**；**伪问题建库路径**（doc2query 式离线合成 + carrier-sentence 键）；**确定性抽样脚本 + 固定种子**（提交入库）；**知识卡 schema**；**S4 资产**（is21_deep_bias + AISHELL-NER 标签 + B-WER 打分器 + 检索→列表对齐）；1 真格成本标定（含 m=5 自一致性 wall-clock）；**H5 fallback 门槛判定**（首格 dev smoke <12% → H5 目标降至 10%）。附带：own-ASR 级联臂、标准卡递送臂、探索分批（text-key 先）。退出 = 以上全绿。

**M2 探索完成（entry criteria）**：全臂族 dev 跑完（匹配几何 × 递送 × 阶梯 × S1a/S1b/S2/S3/S4）；发现段三层指标栈（需求标签 + 混淆矩阵 + 归因恒等式，描述性非门控）；§10.1 离线信号标定表；**预注册 holdout 供给表**；**资格判定**（独立 eligibility-split，CI 下界 ≥2×SESOI）；家族表资格标注（分母固定 MAX=15）；曝光重叠 winner 复选检查（分歧须 flag 供 owner）；S1/S2/S3/S4 探索排序 + 交互-CI 宽度检查。退出 = Phase-B 协议草案成文（预命名赢家 ≤3 + 基线族 + 对照臂 + 确定性抽样脚本 + 候选 ID 全集 hash + 资格标注家族表）。

**M3 Phase-B 签署（owner）**：审阅 M2 产出并签署，进入确证层。探索层本身不触发任何 kill。

**M4 确证完成（entry criteria）**：custodian 确定性脚本抽取（提交先于选择、固定种子、可逐字节复现）；单通道评分；H-sys 判定 vs 预注册 SESOI 家族（分母固定 MAX=15，本轮 α 按 alpha-spending）；**跨核心迁移冒烟**（第二核心 1–2 集轻验，非门控项）。

**M5 迭代或 Stage-3 裁决**：达标 → Stage-3；不达标 → 迭代循环（≤5 轮 cap）或 owner 复盘转向边界性结论。收尾：Decision-Log 追加 + Per-Work-Status 更新 + wiki-sync。

**汇报口径**：按门状态（各 entry criteria 绿/未绿）汇报，不按日历百分比。**预算超支中断**：任一门内实测成本超首格实测推算值 1.5× 时中断回报 owner（继续/削格/退场），不得静默吸收。
