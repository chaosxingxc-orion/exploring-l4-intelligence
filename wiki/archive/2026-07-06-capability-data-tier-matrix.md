# Capability × Data-Tier Matrix + Field-Dataset Survey

**Stage:** 1 (problem definition) · **Grade:** hypothesis-grade (Stage-1; in-house numbers are `directional-only` unless re-established at Stage 2) · **Date:** 2026-07-06 · **Object of study:** a frozen omni (speech/audio) MLLM inside an agent scaffold (controller · tools/skills · memory · knowledge/RAG · verifier), optimized training-free at inference (no weight/structure change).

This deliverable classifies five capabilities on the **three-column cut** — for each capability we separate (1) a *genuinely distinct multimodal organizational form* (non-text-signal input, structured cross-modal output), (2) the *commodity modality-agnostic layer* a text LLM supplies once audio is serialized, and (3) the *deployable training-free lever* that is admissible under the machine-checked **InfoBoundary** constraint. We do **not** issue a blanket "commodity" verdict — each capability is judged on its own evidence.

**InfoBoundary constraint (machine-checked, governs every lever):** selection / orchestration over a *fixed* element set (best-of-N, reward-guided reranking, verifier-as-role over the same weights) is a *read-out* lever bounded by the frozen model's own oracle@N. A capability crosses that ceiling only via (a) a **new-info element** (a genuinely independent signal admitted into the scaffold) or (b) an **in-contract decoding edit**. This is a constraint on *which lever can work*, not a verdict on which capability is commodity.

**Tier legend.** **T1** = in our frozen 28-dataset inventory AND on-disk runnable with a deterministic/verifiable reward (oracle@N-measurable). **T2** = not in our 28 but publicly acquirable with a real citable source. **T3** = must-build (no on-disk seed for the *distinct* form, or the only seed lacks the reward surface the lever needs). Every dataset claim below is tier-tagged; every number is traceable to a finding artifact or an arXiv ID; residual uncertainty is flagged in the final section.

**Verification corrections folded in (see final section for the full list):** crema-d emotion gold is keyed off the **filename** code, not the csv `classname` (csv agrees only 46%); the knowledge T3 build is rebuilt from **spoken-squad alone** (the heysquad↔spoken-squad SQuAD-id join is not constructible on disk); X-Talk (2512.18706) dropped as evidence for voiceprint-keyed memory (that mechanism is AFA's, 2604.25022); SkillsBench gain corrected to **+16.6pp** (33.9%→50.5%); Audio2Tool re-characterized as noise/acoustic-stress (not paralinguistic); OmniACBench re-characterized as *output* acoustic control (not input-signal-triggered behavior); PERMA (2603.23231) reclassified as a benchmark, not a system; Dynamic-SUPERB given its own ID (2309.09510).

## Per-capability detail (three-column cut)

### 1. Perception — the one genuinely distinct multimodal object
- **Distinct form.** Signal-in → structured percept, triggered by a waveform property (emotional tone, voiceprint, event onset, prosody, sound/music class) that is absent from or orthogonal to the transcript. A text LLM operating on the transcript *cannot instantiate this contract at all* — the input channel it needs (the waveform) has been discarded. For pure sound/music items the transcript is empty, so omni(audio) > omni(own-transcript) is **information-theoretic, not stylistic**.
- **Commodity layer.** The downstream reasoning over an already-extracted, text-encoded percept ("given emotion=angry, reply empathetically"; "given speaker=A, attribute this turn") — the text-LLM tail of an ASR+SER+diarization+AED cascade.
- **Evidence.** The only *significant* live perception delta was SQuAD-zh **+0.283**, but it is a **Chinese-ASR round-trip artifact** (the transcript *is* the answer content, so a lossy own-ASR transcript drops the answer) — an ASR-quality confound, **not** paralinguistics. The clean sound/music delta (mmau-mini **+0.117**) is directional-only, n.s. at n=60. The field's own finding (2510.10444) is that frozen audio LLMs largely fall back on the transcript and under-use the acoustic channel.
- **Correction (HIGH, folded in).** crema-d's 6-way emotion gold **must** be derived from the filename code `{actor}_{sentence}_{EMOTION}_{intensity}` (ANG/DIS/FEA/HAP/NEU/SAD), **not** the csv `classname` column, which agrees with the acted code only **46.0%** (test) / **45.4%** (train) and is 55% neutral-skewed. `classname` is a crowd-perceived rating usable only as a separate offline signal, never as the acted-emotion reward.

### 2. Memory — real but narrow, gated on a build
- **Distinct form.** (i) capturing a non-text acoustic fact (ambient sound / whisper / emotion) into a memory entry, and (ii) keying/retrieving by voiceprint or acoustic event. audiomc (2512.14865) and MTalk-Bench (2508.18240) exist because transcription destroys the decisive recalled variable; AFA (2604.25022) exists because a shared text memory confuses personas when it cannot key on *who* spoke.
- **Commodity layer.** Admission/write policy, index construction, NN/RAG retrieval, knowledge-update, temporal reasoning, abstention — modality-agnostic once audio→entry (LoCoMo 2402.17753; LongMemEval 2410.10813; PERMA benchmark 2603.23231; systems Mem0 / MemGPT / A-MEM / Memoria 2512.12686). Our own **T6** confirms it empirically for our stack: a unified index over the omni's own content-summaries retrieves task-relevantly (task-purity 1.0, precision@k 0.62 vs 0.10 random) but the key is a **lexical** content summary.
- **Correction (folded in).** The voiceprint-keyed-memory sub-claim rests on **AFA (2604.25022) alone**; X-Talk (2512.18706) is a general modular S2S framework and does **not** implement voiceprint-keyed memory-bank retrieval — dropped as evidence for this form.

### 3. Knowledge/RAG — cleanest boundary-crosser, but modality-agnostic
- **Distinct form.** Audio-native retrieval beats ASR→text precisely when WER is high — SpeechDPR is "significantly better when UASR was poor" (2401.13463); SQuTR (2602.12783) probes the noisy-ASR regime; a hybrid audio+text KB retrieves over non-lexical audio with no transcript (WavRAG +2.74× on the audio+text task).
- **Commodity collapse (the M3 lesson).** On clean-ASR text-knowledge QA the audio-native retriever only **ties** ASR→text — WavRAG R@10 tied on HotpotQA (0.8898 vs 0.8895) and SLUE-SQA-5 (0.7221 vs 0.7196); it wins meaningfully only on Spoken-SQuAD (+0.05). The retrieved fact is modality-agnostic — a text LLM given the same passage gets identical grounding. RAG genuinely crosses the oracle@N ceiling (Axis-① new-info element, `M(·|audio, retrieved-text)`), but that crossing is not omni-specific.
- **Correction (MEDIUM, folded in).** The T3 build recipe is rebuilt from **spoken-squad alone** — on-disk parquet schemas do not support a heysquad↔spoken-squad join (spoken-squad ships `{context-audio, instruction, answer}` with no id/title/text; heysquad ships SQuAD `id`+text). Use each spoken-squad item's own question as query and its passage as gold, mining distractors from other items; or fall back to public SLUE-SQA-5 / NMSQA (T2).

### 4. Skills/Tools — commodity machinery + a perception problem
- **Distinct form.** Firing/gating a skill on a non-lexical decisive signal (prosody/emotion, speaker-voiceprint, sound-event, turn-taking). The field argues the ASR step discards the decisive cue (Audio2Tool, ParaBridge, OmniACBench).
- **Commodity layer.** Declaration/registration is text-native and ported unchanged (no audio-native tool-call message exists — MCP/function-calling/SKILL.md carry text only); post-trigger routing/argument-filling/orchestration is modality-agnostic IF-THEN. The distinctness lives **entirely** in the perception/detection step, and once the cue is a symbol, "IF emotion==angry THEN fire de-escalation" is commodity routing.
- **Corrections (folded in).** Audio2Tool (2604.22821) stresses **acoustic noise/complexity**, not paralinguistics — its trigger is lexical intent under acoustic stress. OmniACBench (2603.23938) is context-grounded **output** acoustic control (read a script aloud with appropriate tone), *not* input-signal-triggered behavior — closer to controllable/context-grounded TTS. SkillsBench (2602.12670) net benefit is **+16.6pp** (33.9%→50.5%), self-generated skills ≈ 0.

### 5. Verifier/Reward — split by the verification signal
- **Lexical/content verification = COMMODITY (proven in-house).** E10b (n=40, paired-bootstrap CIs): the context-differentiated two-system omni verifier does **not** beat plain self-consistency majority on any lexical surface (ver_minus_maj CI straddles 0; **negative −0.075 on mmau**), ρ≈0.5 generator/verifier error correlation → read-out bounded by oracle@N (GenRM 2408.15240 is the baseline it collapses to).
- **Signal-grounded verification = GENUINE distinct object.** The field builds dedicated frozen-LALM-as-judge benchmarks for quality/naturalness/prosody/emotion-match/speaker-match/paralinguistic-obedience (AudioJudge 2507.12705; ParaPairAudioBench 2606.24648; SpeechJudge 2511.07931; WavReward 2505.09558; EmergentTTS-Eval 2505.23009), the I/O contract is truly signal-in, and the leading instantiation is **training-free prompt engineering** — squarely our regime. Our perception-delta (p6) confirms the necessary non-text signal exists.
- **Critical constraint.** The in-fence same-weights verifier is oracle@N-bounded; the research value is in the **decorrelated** verifier (δ_corr>0), which needs a signal *independent* of the generator: verifier-AS-TOOL (external acoustic/embedding feature) over verifier-AS-ROLE — the W4 omni-embedding-as-verifier bridge (parked #37). Corroborated by Soft-SVeRL (2605.28561), FUSE (2604.18547), One-Token-to-Fool (2507.08794). **Deployability guard:** rewards must be deployable (self-consistency, confidence, rule/format, tool-success); WER-vs-gold / gold-emotion / rubric-gold are **leakage**, usable only as offline measurement.

## Bottom line

Reading down the matrix, exactly one capability — **PERCEPTION** — is a genuinely distinct multimodal organizational form, and only at its **front-end extraction** (the omni supplies decision-relevant information a text LLM structurally cannot recover from any transcript). **MEMORY, KNOWLEDGE/RAG, SKILLS/TOOLS, and VERIFIER/REWARD are each *partly* distinct** — real non-text-signal input at a narrow interface (acoustic-fact capture + voiceprint key / lossy-ASR-or-non-lexical retrieval / non-lexical activation trigger / signal-grounded judging), wrapped around a **commodity modality-agnostic layer** a text LLM supplies once audio is serialized. Under InfoBoundary the admissible frozen lever is almost always **element-gating/admission or new-info injection**, never best-of-N over a fixed set (confirmed null in-house: E10b, M5). **Testable at T1 today:** only PERCEPTION (mmau-mini now, needs n scale-up; crema-d filename-keyed — the cleanest control). The sharpest distinct objects for the other four (cross-session voiceprint-keyed recall; audio-native retrieval bench; signal-decisive skill activation; deployable paralinguistic-decisive verification) are **T3 builds** — several seeded from the same on-disk crema-d asset, the rest deferred to W4 or tested first on public T2 benchmarks.
