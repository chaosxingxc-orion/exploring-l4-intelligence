## 1 方法本质

Wiki-LLaVA 给冻结架构的 LLaVA-1.5（CLIP ViT-L/14@336 + MLP adapter + Vicuna-7B）挂一个
**两级（hierarchical）检索管道**，把维基文档的原始文本块直接拼进 prompt 的 context 位。
第一级用**输入图像的 CLIP 视觉嵌入**去检**维基文章标题的 CLIP 文本嵌入**（跨模态内积，
Faiss HNSW，32 links/vertex），取 top-$k$ 篇文档；第二级把每篇文档切成 600 字符 chunk，
用 **Contriever** 以**用户问题**为 query 检出每篇 top-$n$ 段，共 $k\cdot n$ 段。
段落以**原文形式**（`Given the following context:\n<R1>\n<R2>\n<R3>\n<QUESTION>`）无条件
注入，没有任何相关性/冲突/准入判定。方法本身声称可 zero-shot 运行，但**论文的全部主结果都是
LoRA 微调后的**（Enc-VQA / InfoSeek 训练集 + LLaVA-Instruct 混批，batch 512）。
论文自陈两条局限：缺一个"图像+问题共同可检索"的嵌入空间；缺"从多篇文档中挑选"的机制。

## 2 key-value 与三轴定位

| 维度 | 事实（LaTeX 源核） |
|---|---|
| **key 用什么构建** | **两层 key，两种模态的 query。** 文档级 key = 维基文章**标题文本**经 CLIP 文本编码器 $E_t(t_i)$ 得到的向量，query = 图像 $E_v(I)$，打分 $\mathrm{sim}(I,t_i)=E_v(I)\cdot E_t(t_i)^T$。段落级 key = 600 字符 chunk 的 Contriever 嵌入，query = **问题文本**。**没有独立的实体识别/实体检索头**：复用同一个喂给 MLLM 的冻结 CLIP ViT-L/14@336 视觉塔（论文明说"for streamlined efficiency, the process involves utilizing a single visual encoder"）。 |
| **检索几跳** | **固定 2 跳、无自适应、无停止决策。** 跳数是管道结构常数，不是决策变量。$k\in\{1,2,3\}$、$n\in\{1,2,3\}$ 全部是**硬编码超参**，靠网格试出来；上限由 Vicuna 2,048 token 上下文窗口决定（论文明说 $k>1$ 时只能 $n=1$）。 |
| **证据怎么进上下文** | **raw chunk 原文直拼**，位置在 image tokens 之后、system prompt / question 之前（式 (1) 把 external memory tokens $e_0..e_\tau$ 记为独立段）。无摘要、无重写、无引用标注、无出处字段、无冲突标记、无 abstain 通道。 |
| **有无准入** | **完全没有。** 检索结果 100% 进上下文。论文在 Limitations 里把"让 MLLM 能判断检索项是否恰当"列为**未来工作**，并预判这可能需要超出"纯粹把检索项塞进 context"的新架构设计。 |

**三轴读数**：组织轴 = 层次两级 key（2024 年已有，比 R2 §3.2 归给 2605.15019 的"多粒度"更早，
只是粒度是**索引层级**而非**证据单元语义层级**）；供给轴 = 固定 2 跳无门控；使用轴 = 无条件接纳。

## 3 主实验数字（LaTeX 源核对）

| Wiki-LLaVA $k{=}1,n{=}1$ | 21.8 | 26.4 | 25.5 |

**(3) oracle 实体臂（Tab.2 灰底行，直接给 ground-truth 实体，跳过第一跳）**：

| 配置 | Enc-VQA Single-Hop | Enc-VQA All | InfoSeek All |
|---|---|---|---|

论文自算 headroom：Enc-VQA **+13.8 点**（40.2 − 26.4），InfoSeek **+22.6 点**（51.5 − 28.9）。

**(4) 微调对通用能力的破坏（Tab.4 `tab:llava_eval`）**——原 LLaVA-1.5 vs 微调版：

|---|---|---|---|---|---|---|
| 无（原模型） | 355.7 | 1513.3 | 35.1 | 71.6 | 86.9 | 85.8 |
| Enc-VQA | 200.7 | **802.8** | 36.6 | 67.7 | 72.9 | 63.4 |
| Enc-VQA + LLaVA-Instruct | 290.0 | 1170.1 | 36.6 | 70.4 | 87.2 | 86.6 |

**(5) 微调消融（Tab.3 `tab:ablation`，均不带检索）**：无微调 16.9 / 9.5 → 微调 29.0 / 16.0 →
微调+LLaVA-Instruct 28.5 / 17.9（InfoSeek +1.9 点，Enc-VQA −0.5 点）。

## 4 DFS 四问

**方法（做了什么）**：把文本域 RAG 的"两级 coarse-to-fine 检索"照搬到 MLLM：跨模态第一跳
（图像→标题）定位实体文档，同模态第二跳（问题→chunk）定位段落，段落 raw 拼进 prompt，
再靠 LoRA 微调教模型用这些段落。它是"图像多模态知识组织"这条线最早的可引骨架之一。

**局限**：(a) 第一跳是**方法的单点故障**——2M 库上 R@1=3.3%，导致带检索的 Enc-VQA All
（26.4）**低于**不带检索的同款微调基线（28.5），即**检索净负增益**；(b) 增加证据量在 Enc-VQA
上**单调变差**（26.4 → 23.2 → 20.3，n=1→3），论文自己归因为"噪声段落"，这是"更多≠更好"的
直接实测；(c) 无任何准入/冲突/归因机制，作者自陈为未来工作；(d) 需要微调，且微调把 MME
感知分打掉近一半（Tab.4）；(e) two-hop 问题被**从测试集里过滤掉**（4,750 条 single-hop 留存），
所以它没测多跳。

**改进空间**：论文亲自点名两条——(i) 让"图像+问题"落在同一个可检索嵌入空间（EchoSight 2407.12735
下一步就做了这件事，用 Q-Former 多模态 rerank）；(ii) "从一或多篇文档中选择"的高效范式，即
**证据选择/准入**。第二条正是 R2 §4.4 M1（pre-call 准入门）与 M6（负信息增益）在视觉域 2024
年就被作者点名却未做的空位。

**可借鉴（形状，H5 withheld，不跨模态外推效果）**：(1) **oracle 实体臂的构造法**——把"第一跳
检索"整段替换为 ground-truth 实体、保持第二跳与生成端不变，得到一条干净的 headroom 行，正是
R2 M7/A1′ 需要的"gold-key 臂"形状；(2) **$k\times n$ 网格**把"检几篇 × 每篇取几段"分解为两个
独立预算轴，且实测两轴对不同数据集**方向相反**（InfoSeek 增 n 有益、Enc-VQA 增 n 有害），
支撑 R2"最优预算随任务分层剧烈变化、不能统一封顶"（M8 形状）；(3) **Tab.4 那种"通用能力保全
报告行"**——凡涉及参数改动的方案都该附一张"原能力退化表"，这条正是 R2 训练无关（training-free）
纲领最有力的跨域论据。

### 深读后新增的、R2 应该知道的事实

1. **视觉域 2024 年就有"检索净负增益"的公开实测，且出自 R2 已引的这篇。** Tab.2：Enc-VQA All
   带检索 26.4 < 同款微调无检索基线 28.5；且 n=1→3 单调劣化 26.4→23.2→20.3。R2 §4.4 M6
   （"更相关≠更好"/负信息增益）现在可以在**视觉域 2024** 就落一个出处，不必只靠 Decocted
   2604.04373；R2 §4.3 批评语音域"没有人测量这次采集是否改变了答案"也因此更有对照力度。
2. **"无准入门"在视觉域是作者自陈的公开缺口，不是我们的外部指摘。** Limitations 原文把
   "increase the capability of the MLLM of distinguishing the appropriateness of retrieved items"
   列为未来工作，并预判需要新架构。R2 §4.4 M1 可以据此把"准入门"定位成"2024 年被点名、跨域
   至今未闭合"的机制位，而不是只在 ToolGate 2606.03054 才出现的新概念。
3. **Wiki-LLaVA 不是 training-free，且其 Tab.4 是"为什么必须 training-free"的现成跨域证据。**
   全部主结果依赖 LoRA 微调；MME-Perception 1513.3→802.8（−47%），混入 instruction 数据仅
   回到 1170.1。R2 §1.4 红线（冻结黑盒、API-only）此前主要靠成本/可得性论证，现在可以再加一条
   **能力保全**论证，并且是本域邻居自己量出来的。引用时须注明该表是同族基线的**参数改动代价**，
   不是我们的实验。
4. **oracle 臂的最小构造法（可直接抄形状给 A1′）**：只替换检索管道的**第一跳输出**为
   ground-truth 实体，第二跳（问题→chunk）与生成端完全不变，$n$ 保持同一网格扫描。这样得到的
   gold 臂与实测臂**只差一个受控变量**，headroom 可归因到"key 定位"这一环。R2 的 A1′ 若要做
   "gold 语义假设"臂，应照此只替换假设产出环节，而不要顺手把知识内容也换成 gold（否则 key 与
   value 两个变量同时变，headroom 不可归因）。
5. **上下文窗口是隐藏的预算约束、且被论文当成设计理由。** $k>1$ 时被迫 $n=1$，原因是 Vicuna
   2,048 token 上限。R2 §6 的预算轴设计需要把"上下文窗口"显式记为约束项而非自由参数，否则
   $k\times n$ 网格的可比性会被窗口截断污染。
6. **一条 R2 可用的 KB-规模敏感性事实**：同一 CLIP、同一方法，KB 从 100k 涨到 2M，R@1 从
   36.9 掉到 3.3（Tab.1）。任何"组织升级带来增益"的声明必须报 KB 规模；R2 §3.2 的"组织代价
   曲线"轴可以把"KB 规模 → 第一跳召回 → 端到端准确率"这条链当成最早的代价曲线实例
   （早于 R2 现在归给 2605.14906 的"组织不是免费的"）。
7. **它没测多跳**：two-hop 问题被从 Enc-VQA test 过滤掉（保留 4,750 条 single-hop）。R2 若在
   §3.2 用它论证"多跳知识组织"，须避让——多跳证据应改引 M3-VQA 2604.25122。
