## 2. 方法本质

### 2.1 五段管线（一句话：多 ASR 假设作证据 → 实体检索 → 约束 LLM 纠错 → 确定性验证）

本篇是**黑盒后处理**：冻结 Whisper-small 先解码，之后全部动作发生在**文本侧**。

**段一：Multi-Hypothesis Generation（§2.1，第 257–260 行）**。同一段音频用
`faster-whisper` 的 Whisper-small 在**五个温度** `T ∈ {0.0, 0.2, 0.4, 0.6, 0.8}` 各解码一次，
得 N=5 条假设。作者明说这一步**与框架解耦**：

> "The framework accepts $N$ ASR hypotheses for each audio segment. The hypotheses can be obtained
> using any method, such as temperature sampling from a single ASR model, beam search with diverse
> decoding, or an ensemble of different ASR systems."（第 260 行）

关键性质：**五次解码是无条件的、一次性的、全部发生在 agent 启动之前**。不存在"先看一眼结果
再决定要不要多解码"的分支。

**段二：Dynamic Entity Candidate Retrieval（§2.2，第 264–276 行）**。给定该域的实体短语表
（规模 446–6,198 条），对**每个短语 b** 算一个三信号打分（第 269–274 行 Eq. 1）：

```
score(b) = n_exact · w_e  +  f_best · w_f  +  p_hit · w_p
```

- `n_exact`：b 的词有多少个作为**精确 token** 出现在**全部假设并集**里（"the variants are
  concatenated to build a unified token set"）；
- `f_best ∈ [0,1]`：b 的任一词与任一假设的任一 token 的**最佳归一化 Levenshtein 相似度**
  （限制在字符数差 ±3 之内）；
- `p_hit ∈ {0,1}`：b 的**音形 key**与任一 token 的音形 key 共享 5 字符前缀则为 1。

权重 `w_e=1.0, w_f=1.2, w_p=0.6`，作者自述 "set empirically"，并给了理由：精确匹配最可信，
但模糊相似度**单位权重更高**因为它才是"恢复被打坏实体的主要机制"（`sitiva → cytiva`），音形
是辅助信号。取 **top-K=200** 送入 LLM prompt。动机是显式的成本/质量论证：

> "Entity phrase lists can be large (up to 6,198 phrases in our experiments). Sending all phrases
> in the LLM prompt is wasteful and may degrade quality."（第 267 行）

关键性质：**逐段无条件执行、无 no-retrieval 分支、无分数阈值**。K=200 是全局常数。这是读集内
"无条件检索"的又一实例（对接 R2 §8 双侧证据合同）。

**段三：Tool 1 — Fuse Hypotheses**（四策略，见 §2.2 逐一刻画）。
**段四：Tool 2 — Propose Corrections**（约束 LLM 编辑）。
**段五：Tool 3 — Verify & Apply**（确定性护栏）。

**Tool 2（第 305 行）**：LLM 只被允许提 **entity-only find/replace**，prompt 硬规则三条：
(a) 替换词**必须恰好是实体表里的某一条**；(b) **禁止任何通用改写**（语法、标点、填充词、
大小写）；(c) 鼓励 near-miss 纠正（`citeva → cytiva`）。输出为 JSON，字段含**字符偏移、原
span、替换 span、实体类型、confidence、简短 reason**。

**Tool 3（第 308 行）——五条确定性检查**（本篇最可移植的工程件）：

1. 替换词必须存在于实体短语表中；
2. **纯大小写变更一律丢弃**；
3. LLM 给的字符偏移若错，**系统重新定位 find span 并重算偏移**（不因 LLM 定位失败而丢弃）；
4. 原 span 与替换词的**归一化 Levenshtein 相似度须足够高**——`citeva→cytiva` 过，
   `star→cytiva` 被拒；
5. **从左到右应用，跳过与已应用编辑重叠的任何一条**。

**该门的位置很重要**：它不是"证据进上下文前的准入门"，而是**"动作离开 LLM 后的出口验证门"**。
R2 §0 的结构是「候选区 → 准入门 → 核裁决」，门在**证据侧**；RECOVER 的门在**动作侧**。两者
不是同一个机制位，但**互补**——见 §7「可借鉴」。

### 2.2 四种假设选择策略——逐一刻画（第 288–302 行）

四策略共享"实体命中计数"这个前置量：Tool 1 先用 top-K 候选去数**每条假设**里各出现了多少个
候选作为精确子串（作者称 "entity scoring" 步）。四策略在此之上分叉：

| 策略 | 决策规则 | 决策者 | 输出是否为某条真实解码 | 在 R2 轴上的定位 |
|---|---|---|---|---|
| **1-Best** | N=1，直接透传贪心（T=0）假设 | 无 | 是 | **退化臂**（证据轴的零点），非选择 |
| **Entity-Aware Select** | argmax 实体命中计数；**并列时用转写长度弱破平**（作者理由："longer transcripts correlate with fewer deletions"） | 确定性规则 | 是 | 单一读出量的贪心 argmax；**零学习、零标定、零音频** |
| **ROVER Ensemble** | 用同一启发式选 pivot → 其余假设用 **Needleman-Wunsch 全局对齐**贴到 pivot → **多数票 token 合并**；**并列偏向 pivot**；**插入须 ≥3/5 支持**才接受 | 确定性规则 | **否**（合成出一条无任何单次解码产生过的 token 串） | 证据**合并**而非选择；引入了单解码不存在的错误面 |
| **LLM-Select** | 把**全部 N 条假设 + top-K 候选**交给 GPT-4o，"The LLM chooses the best base variant **and can propose entity-only corrections in the same call**"（第 299–301 行） | **GPT-4o（黑盒）** | 是（base 变体） | **LLM-as-judge 型 best-of-N**；选择准则**隐式、参数化、不可读出、不可标定** |

**逐条对 R2 的读法**：

- **1-Best** 是本篇真正的对照臂，而不是弱基线——见 §4.3，在 R2 主载体上它拿走 99.4% 的增益。
- **Entity-Aware Select** 是"把一个读出量直接当动作价值"的教科书案例，其代价在 §4.4 被本篇
  自己测出来了（ATCO2 上 E-WER 降 9.1%、总 WER 涨 34.8%）。R2 的控制器若用"实体命中数"当
  重听/重解码的价值代理，会复现同一失效。
- **ROVER Ensemble** 的 `≥3/5` 插入门是一个**外显、可标定的标量门**——但它门的是 *token 是否
  进合并串*，不是 *要不要执行某个动作*。属"输出侧结构门"，与 R2 的动作门不同位。
- **LLM-Select** 是四者里唯一"由模型自己裁量"的，也是**总体最好**的（§4.1）。这一点对 R2 是
  **反向证据**：在本篇的设定里，**LLM 内隐裁量打败了三种外显确定性规则**。R2 主张"模型外可
  标定标量门优于核内口头仲裁"时，必须正面处理这个读数（见 §9 重审条款）。

**四策略的共同结构性缺陷（对 R2 承重）**：**策略是逐实验固定的全局配置，不是按样本选的**。
论文自己在 Future Work 把这件事列为未做：

> "Future work will explore **adaptive per-segment strategy selection** based on inter-hypothesis
> agreement, integration with word-level ASR confidence scores, comparison with more LLMs, and
> extension to multi-agent architectures."（第 598–601 行）

同一句还确认：**逐词 ASR 置信度也没用**——本篇连解码器给的置信量都没读，遑论音频。

### 2.3 "agentic" 的实际含义（须收窄）

标题/摘要/关键词三处用 "agentic"，正文引 ReAct（`yao2022react`）。**但管线里没有任何策略、
分支或状态依赖的动作选择**。逐字证据：

- 图 1 caption（第 119 行）："The agentic orchestrates three tools **in sequence**: Tool 1 …
  Tool 2 … Tool 3 …"
- §2.3（第 284 行）："it (i) analyses and fuses hypotheses into a single transcript, (ii) queries
  the LLM to propose entity-only find/replace edits, and (iii) verifies and applies only the edits
  that pass deterministic guardrails."
- 管线图 PDF 的文本标签（pdftotext 抽取）：`Tool 1: Fuse Hypotheses → fused text → Tool 2:
  Propose Corrections → proposals → Tool 3: Verify & Apply → Corrected Transcript`，
  外框标 `Agentic Orchestration`。**全图无回边、无条件分支**。

**判定：本篇的 "agentic" = 一个三段固定流水线 + agent 框架外壳（Agno）**。它在 R2 §4 的门控
查询-裁决环坐标系里是 **"always" 固定臂**，不是控制器。这一点**必须写进矩阵行**，否则 R2 会
被读成"又一个 agentic 方案已占据门控位"。

## 3. 训练态与信息访问边界

### 3.1 训练件逐项点名 → `training-free` = **CONFIRMED 满足**

| 组件 | 训练态 | 出处 |
|---|---|---|
| ASR：Whisper-small | **现成检查点**，经 `faster-whisper` 推理；无微调、无适配器 | 第 327 行 |

> **与 Fox 线的对照**：Fox & Delworth 的 ASP 是 13.6M 从零训练件、且训练对由**该 ASR 自身
> 训练音频解码挖错**产生（核绑定，API-only 下结构性不可得）。RECOVER 把 Fox 想解决的同一个
> 问题（"模型根本不会拼这个词"）改用**闭表 + LLM 语境裁决**绕过去，**不需要任何训练件**。
> 这正是 R2 §8 Fox 行里写的"外显世界知识 rescore（其作者已把 context-based rescoring 列为
> 未来工作——该分量空位为实现层）"——**该空位已被本篇填上**。

### 3.2 信息访问 → `API-only` = **CONFIRMED 满足**（且有作者自述）

- **ASR 侧需要什么**：只需要一个能**按温度采样**返回转写的接口。不读 logits、不读 beam、不读
  隐状态、不改解码图、不注入分数。主流黑盒 ASR API 普遍暴露 `temperature` 参数。**且**方法
  在 N=1 时完全成立（1-Best 策略），此时连温度接口都不需要。
- **LLM 侧需要什么**：一次文本 chat completion，输出 JSON。纯 API。
- **作者自述（第 527 行，逐字）**：

  > "…although this is not directly comparable (different ASR model and a decode-time
  > contextualization setting), **our black-box post-ASR pipeline** attains a similar recall on
  > Earnings-21 (70.07→80.69, +10.62 pp) while keeping overall WER essentially unchanged
  > (13.59→13.55)."

  ——**作者自己把本篇定位为"黑盒后处理管线"，并显式与 Huang 的 decode-time contextualization
  对比**。这是读集内第一处"同一载体上、黑盒 vs 白盒 biasing"的作者自述对照。

**判定：`API-only` = CONFIRMED**，且**强于** Siskos（Siskos 需要识别器的 CB/context-list
接口，属"模块解耦而非部署可得"）——RECOVER **连 CB 接口都不需要**，因为它完全在解码之后
工作。这是读集内**信息边界离 R2 最近的一件**。

| 129 | 贡献一："generating multiple hypotheses from an ASR **using the same audio**" | 描述多假设同源，非回访 |
| 260 | §2.1："The framework accepts $N$ ASR hypotheses **for each audio segment**" | 音频只是分段单位；框架的**输入是假设文本** |

**管线图独立佐证**（pdftotext 抽 `paper_pipeline_new.drawio.pdf` 的全部文本标签）：

### 3.4 是否新增 LLM 代答 → **触 R2 红线三（CONFIRMED）**

R2 红线三逐字（提案 §0）：「**不新增 LLM 代答（最终作答权在冻结 omni 核）**」。

RECOVER 的最终转写是**两个模型共同决定的函数**：

1. **基串**来自 Whisper-small（1-Best/EAS 为某条真实解码；ROVER 为合成串；**LLM-Select 下由
   GPT-4o 选择哪一条成为基串**）；
2. **实体 span 的改写**由 GPT-4o 提出（find/replace + 偏移 + 类型 + confidence + reason）；
3. **落地**由 Tool 3 确定性验证后应用。

**判定：新增 LLM 代答 = 是，但为"受限代答"**，须精确刻画，不得笼统扣帽：

- **受限之处**：GPT-4o **不能自由生成转写文本**。它只能 (a) 在 N 条既有假设中选一条，
  (b) 提出替换，且替换词**必须是闭表成员**、**必须与原 span 编辑距离足够近**、**不得只改
  大小写**、**不得动非实体区**。Tool 3 把不合规的提议全部否决。
- **仍然代答之处**：在 LLM-Select 下，**"最终输出的骨架是哪一条"这个决定权在 GPT-4o 手里**；
  且实体位置的最终用词由 GPT-4o 选定。**作答权是被切分的、并且切给了一个新增的第二模型**。

按 R2 §8 「作答权」列的既有取值（AudioGenie=新增 LLM 代答；NAP/AuTAgent=冻结核；
AudioRAG/Omni-DeepSearch=代答/冻结核），RECOVER 应记为
**「新增 LLM 代答（受限：变体选择 + 闭表实体替换；自由文本生成被确定性验证否决）」**。

> **反向须承认的一点（不得回避）**：RECOVER 的"受限代答"在**工程可靠性**上是一个**强于 R2
> 现有设计的点**——它对代答模型的输出施加了五条可审计的确定性验证。R2 的"作答权在冻结核"
> 是一条**体系约束**（保证系统身份与归因清晰），**不是自动的效果优势**。见 §5 的合取裁决。

### 3.5 Earnings-21 实体表的出身：**是否即 Fox oracle 派生表？**

**论文给的全部信息（第 319 行，逐字）**：

> "Earnings-21 [6] comprises 44 real earnings conference calls. Since each call is about 1 hour

**本读者的交叉核验**（旁证件：d2-entries/2026-08-01-d2-2209-01250.md §2.4，一手源核结论）：

  comprised of words and phrases **contained in the Earnings21 references**. These words and
  phrases were **manually curated from the list of PERSON and ORG entities automatically tagged
  by spaCy**." ——即 **从 test 的 gold reference 抽出**，作者自称 "best case scenario"。

**数值指纹一致：1013 = 1013。** 这是 Earnings-21 上**唯一公开的 1013 条实体表**。

**反向证据（必须同时登记，不得只报支持面）**：类型覆盖描述**不一致**。

  **"Persons, Orgs, Products"（三类）**——**与正文的四类描述内部就不一致**（第 343 行 vs
  第 319 行）。

**判定（分档记）**：

| 命题 | 判定 | 强度 |
|---|---|---|
| 其 Earnings-21 表**就是** Fox 发布的 1013 条 oracle 表 | **PROBABLE，未证实** | 数值指纹一致 + 该载体上唯一公开的同规模表 + 论文引了 Fox；但类型描述不符、论文未标出处 |

**存在于其 gold reference 标注层**（官方 24 类实体标注随参考转写发布）。任何一张"覆盖

test-gold 派生**。不存在第三个分支：Earnings-21 不提供任何与参考解耦的外部上下文层

判定不依赖于"是不是 Fox 那张表"。**

**其余四个载体的同项判定**（一并记，因为头条数字出自其中）：

| 载体 | 实体表出处（逐字） | 信息边界判定 |

1. **"多假设/best-of-N 作证据"这条路，在 R2 主载体上被本篇实测为近乎无效。** R2 若把
   "多解码/重听产生的多假设"当作核心供给机制，必须解释为什么它在 Earnings-21 上会比
   RECOVER 的温度采样多假设更有效——**唯一站得住的差异化理由是"条件化/定向"**（听哪段、
   以什么假设去听、何时不听），而不是"多几条假设"。这恰好收窄并强化了 R2 的 delta 定义。
2. **同时它抬高了 incumbent 的门槛**：R2 要赢的不是"Whisper 裸核"，而是
   **"Whisper 裸核 + 一次约束闭表 GPT-4o 编辑"**——后者在 Earnings-21 上已把 E-WER 从 23.81
   打到 15.90，且**零训练、纯 API、单次调用**。

### 4.4 负向格与过宽陈述（逐条核，全部由表体反证）

**(a) F1 净负四格——直接反证正文的 "in every case"。** 正文第 521 行逐字：

> "…but **in every case** the recall gains outweigh the precision loss, yielding **net F1
> improvements of +0.3 to +10.7 pp**."

按 `tab:main` 逐格算 ΔF1（系统 − baseline），**ContextASR-Bench 一列有四个负格**：

| 系统 @ ContextASR-Bench | F1 | ΔF1 |
|---|---|---|
| baseline | 94.89 | — |
| 1-Best | 94.82 | **−0.07** |
| Entity-Aware Select | 94.33 | **−0.56** |
| ROVER Ensemble | 94.81 | **−0.08** |
| GPT-4o-mini LLM-Select | 94.65 | **−0.24** |
| LLM-Select | 95.17 | +0.28 |

**"+0.3 to +10.7 pp" 这个区间只在 LLM-Select 一行成立**（LLM-Select 五载体 ΔF1 =
+5.58 / +7.35 / +3.65 / **+10.73** / **+0.28**——正是区间两端）。**"in every case" 的量词
在其自己的表里被证伪：25 个 GPT-4o/mini 系统×载体格中有 4 格 F1 净负。**
转引本篇 F1 结论时**必须限定到 LLM-Select**。

**(b) 精度损失被低报。** 正文同句称精度"trades off modestly (**7–9 pp** on Earnings-21 and
Common Voice)"。逐格算 ΔP：

| 载体 | baseline P | 1-Best | EAS | ROVER | LLM-Select |
|---|---|---|---|---|---|
| Earnings-21 | 93.25 | −4.51 | −7.08 | −5.68 | −2.10 |
| Common Voice | 96.39 | −13.76 | **−15.96** | −14.73 | −8.65 |

**Common Voice 上的最大精度损失是 15.96 pp，不是 9 pp。** "7–9 pp" 只对应
{Earnings-21 EAS = −7.08, Common Voice LLM-Select = −8.65} 这一对挑选，**对合并/选择类策略
低报约一倍**。

**(c) 总 WER 退化在四个载体上出现（不止"noisy domains"）。** ΔWER（系统 − baseline）：

| 载体 | EAS | ROVER |
|---|---|---|
| Earnings-21 | +0.75 | +0.29 |
| **ATCO2** | **+16.90**（48.63→65.53，相对 **+34.75%**） | +15.80（→64.43） |
| Eka-Medical | +2.08 | +2.16 |
| Common Voice | +3.70 | +3.15 |
| ContextASR-Bench | +1.14 | +0.37 |

正文把这归因于"multi-hypothesis fusion introduces insertion noise"（第 512 行）与
"merge-based fusion can increase overall WER…due to an increase in insertions"（第 587 行）。

> **本读者的机制反驳（推断，基于其架构约束，非论文陈述）**：**该归因对 Entity-Aware Select
> 不成立。** EAS **不做任何 token 合并**——它输出的是一条**完整未改的 Whisper 假设**，其后
> Tool 2/3 只被允许改实体 span（Tool 2 prompt 禁通用改写，Tool 3 要求替换词属闭表且编辑距离
> 相近）。因此 **EAS 输出的非实体区逐字来自被选中的那条解码**。ATCO2 上 +16.90 pp 的 WER
> 爆炸**只能来自变体选择本身**：以"实体命中计数（长度破平）"为准则，系统地选中了
> **高温度、更长、更易幻觉重复**的解码。
>
> **这是 R2 能拿到的最干净的一条教训**：把一个**读出量**（实体命中数）直接当**动作价值**，
> 会在总体质量上付出可测的、量级远超实体收益的代价——**E-WER −9.1%（相对）换 WER +34.8%
> （相对）**。R2 的控制器若用"检索命中/实体命中"当重听或重解码的价值代理，会复现同一失效。
> 且注意：**本篇的长度破平规则（"longer transcripts correlate with fewer deletions"）本身
> 就是把幻觉重复误读成"删除更少"**——这是价值代理设计错误的具体形态。

**(d) 弱 LLM 消融的读数。** GPT-4o-mini（仅 LLM-Select）RWERR 降到 2.2–15.7%，
且**在 Common Voice 上 F1 76.96 仍高于 baseline 73.40，但精度 91.48 明显高于 GPT-4o 的 87.74
而召回 66.43 远低于 80.79**——即弱核**更保守、改得更少**。作者结论"stronger LLM reasoning has
improved entity recovery under strict constraints"（第 512 行）成立，但须补一句：
**约束闭表编辑的收益强依赖裁决模型能力**，这条对 R2 的"冻结核裁决"路线是**同向支持证据**
（裁决能力越强、闭表纠错收益越大），同时也是**能力门（R2 §6.1）的必要性证据**。

## 5. 合取判定（**签字级承重**）

R2 的增量主张形式（§8 组合格结论）：**API-only + training-free + 双源动作「选择」+ 外显世界
知识 rescore** 四分量合取，在读集内无单件同时满足。逐分量对 RECOVER 裁决：

### 分量一：API-only —— ✓ **满足（占据）**

**证据**：只需按温度采样的转写接口 + 文本 LLM API；不读 logits/beam/隐状态，不改解码图，
不需要 CB/context-list 接口；N=1 时连温度参数都不需要。作者自述 "our black-box post-ASR
pipeline"（第 527 行）。**判定强度：CONFIRMED，且是读集内最干净的一件**（Siskos 需识别器
CB 接口，本篇连解码期接口都不需要）。

### 分量二：training-free —— ✓ **满足（占据）**

**证据**：§3.1 逐件表，零梯度、零任务特定参数件；唯一涉及的学习件（BERT NER）用于**数据
准备**、且是现成模型。**判定强度：CONFIRMED**。

### 分量三：外显世界知识 rescore —— ✓ **满足（占据；须精确刻画）**

这是四分量里最需要小心裁决的一格。逐层核：

| R2 分量的要件 | RECOVER 对应件 | 判定 |
|---|---|---|
| 知识**外显**（可枚举、可版本化、与核参数分离） | 1,013–6,198 条实体短语表，逐段检索 top-K=200 送进 prompt | **满足** |
| 检索/定位**外显** | 三信号打分 Eq. 1（exact/fuzzy/phonetic），权重与 K 为外显常数 | **满足，且比 R2 现设计更外显**（R2 的 key 表示走冻结编码器联邦，本篇是完全可读的词法+音形规则） |
| **rescore/裁决与解码分离** | 裁决发生在**解码之后**、由独立模型在文本上做；输出 JSON 含**实体类型/confidence/reason** | **满足**（对照 Zhang 线：其候选作 prompt 让 Whisper 重跑、裁决**隐在解码里**——本篇不是） |
| 裁决用到**世界知识** | GPT-4o 在语境中判断哪条闭表实体该填进来（`chronic holes→chronicles`、`max black institute→max planck institute`、`left hansa→lufthansa`）——**参数化世界知识 + 语境**联合裁决 | **满足** |
| 裁决结果**受外显门约束** | Tool 3 五条确定性验证（闭表成员/去 case-only/偏移重定位/编辑距离下限/非重叠） | **满足，且是动作侧的显式门** |

**判定：✓ OCCUPIED。** 且必须记两条加重情节：

1. **本篇恰好填上了 R2 §8 Fox 行里标为"空位"的那一格。** Fox 行的 R2 delta 写的是
   "外显世界知识 rescore（其作者已把 context-based rescoring 列为未来工作——**该分量空位为
   实现层**）"。RECOVER 把这个 future work **实现了，training-free、API-only、在同一主载体上**。
   **该分量在 R2 主载体上的空位已消失。**
2. **结构上与 R2 的裁决环同构**：RECOVER 的「top-K 候选区 → LLM 语境裁决 → 确定性验证门」
   与 R2 §0 的「候选区 → 准入门 → omni 核裁决」是同一形状，差别在**裁决者身份**（新增
   GPT-4o vs 冻结 omni 核）与**门的位置**（动作出口 vs 证据入口）。

### 分量四：双源动作「选择」—— ✗ **不满足（两个子分量双空）**

| 子分量 | RECOVER | 逐字证据 |
|---|---|---|
| **音频侧动作**（重听/定向重解析） | **完全缺席** | §3.3 六处逐字排查；管线图 `Audio` 节点单出边；三个工具输入输出全为文本；Future work 连"word-level ASR confidence"都还没接 |
| **按样本的动作选择** | **完全缺席** | 四策略是**逐实验固定的全局配置**；"Future work will explore **adaptive per-segment strategy selection** based on inter-hypothesis agreement"（第 598–601 行）——**作者自认未做** |
| （附）动作是否被门控 | **无门** | 5× 解码无条件；top-K 检索逐段无条件、无阈值、无 no-retrieval 臂；三工具固定串行、无分支 |

**判定：✗ 空缺，且是双重空缺。** 本篇在 R2 的动作轴上是**"always" 固定臂**，不是控制器。

### 合取裁决

> **RECOVER 在 R2 的四分量合取上占据 3/4（API-only ✓、training-free ✓、外显世界知识
> rescore ✓），仅在「双源动作选择」一分量空缺。这是读集内（现十六件）与 R2 合取重叠度
> 最高的一件，也是唯一同时占据前三项的一件。**
>
> **合取仍然成立（不空），但存活的腿只剩一条**：**双源动作选择**——且该腿的两个子分量
> （音频侧重解析动作 / 按样本门控选择）在本篇内**同时**空缺，两者都有作者自述或架构级
> 逐字证据支撑。

### 红线三与"第二条边界"的诚实记账

RECOVER **触 R2 红线三**（§3.4：GPT-4o 为新增代答 LLM，受限但确实持有基串选择权与实体用词
决定权）。因此 RECOVER 与 R2 的边界差异共**两条**：

1. **双源动作（含定向重听）+ 按样本门控选择** —— **这是合取存活的腿，是新颖性主张的承重面**；
2. **作答权在冻结核** —— **这是 R2 的自设体系约束，不是自动的新颖性来源。**

> **第 2 条必须如实降级，否则外审会击穿。** "我不用第二个 LLM"是一个**限制**而非**贡献**：
> 除非 R2 能证明单核作答在**效果**或**可归因性**上带来可测差分，它只能作为**系统身份/管辖
> 界线**条款（R2 §1.4 反还原不变量③的同族），不能作为 prior-difference 的独立腿。
> 更须承认的是：**RECOVER 的受限代答在工程可靠性上强于"自由代答"**（五条可审计验证），
> 其 Tool 3 是 R2 应当**吸收**而非**对立**的设计（见 §7 可借鉴 (a)）。
>
> 故 R2 的独立性陈述应写成：
> **「读集十六件中，RECOVER 首次同时占据 API-only + training-free + 外显世界知识 rescore
> 三分量；R2 的增量因此完全落在第四分量——由模型外可标定标量门驱动的、含音频侧定向重解析的
> 按样本双源动作选择——并附带一条体系约束（作答权在冻结核，记为管辖界线而非新颖点）。」**

## 7. DFS 四问

**方法**：在一个冻结的黑盒 ASR 之后、纯文本侧，把"同一段音频的 N 条温度采样解码"当作互补
证据，用词法/模糊/音形三信号从一张实体短语闭表里检出 top-K 候选，交由一个受严格约束的
LLM 编辑器提出**实体专属**的 find/replace，再由五条确定性规则验证后落地；四种假设融合策略
（透传 / 实体计数 argmax / ROVER 多数票合并 / LLM 选变体）共享后两段管线。全链零训练、纯 API。

**局限**（按对 R2 的杀伤力排序）：

1. **实体表是 test-gold 派生的**（§3.5）。Earnings-21 表条数与 Fox 的 oracle 表一致且出处
   未声明；Common Voice 表由 NER 从参考抽出（该载体"lacks an entity list"，部署中不存在）。
   **两个头条极值（46%、22 pp）都出自 oracle 程度最高的载体，而边界最干净的
   ContextASR-Bench 增益最小**——"表越 oracle、增益越大"的单调关系在其五载体上成立。
2. **多假设机制在主载体上近乎无效**（§4.3：Earnings-21 上 1-Best 拿走 99.4% 增益，
   5× 解码只值 0.05 个 E-WER 点）。论文的核心卖点（"multi-hypothesis as evidence"）在其
   最重要的载体上被自己的 1-Best 行证伪。
3. **"agentic" 是名义的**（§2.3）：固定三段流水线、无分支、无策略、无按样本决策；
   自认 adaptive per-segment selection 是 future work。
4. **零成本记账**：5× 解码 + 每段 LLM 调用、六趟实验，**无 token/时延/费用/调用次数**。
5. **量词过宽与低报**（§4.4）：`in every case … +0.3 to +10.7 pp F1` 在 ContextASR-Bench
   上有四个净负格；精度损失 "7–9 pp" 对 Common Voice 低报近一倍（实为 −15.96 pp）。
6. **失效归因错误**（§4.4c）：把 Entity-Aware Select 的 WER 爆炸归因于"fusion insertion
   noise"，但 EAS 不做合并——真因是选择准则本身选中了高温幻觉解码。
7. **弱核**：Whisper-small（Earnings-21 WER 13.59），headroom 不可外推到强核。
8. **复现口径缺三件**（prompt 全文、相似度阈值、音形算法），且发布承诺在定稿时被删。
9. **无消融隔离**：K=200、三权重、`≥3/5` 插入门、温度集合，**一个都没有消融**；
   "robust to moderate changes in weights" 是断言、非测量。
10. **实体 P/R/F1 匹配规则未定义**（§3.6 第 4 条），而 "+22 pp recall" 建立在其上。

**改进空间**（按 R2 可直接接手排序）：

- **缺失的按样本策略选择正是 R2 的位置**。论文自己指了路："adaptive per-segment strategy
  selection **based on inter-hypothesis agreement**"。R2 的增量是把这个"agreement"换成
  **模型外可标定的标量**，并把动作集从"选哪条文本"扩到"**要不要回去听、听哪一段、以什么
  假设去听**"。**本篇把这块地空了出来并写了门牌号。**
- **价值代理的修正**：EAS 的失败说明"实体命中数"是坏的动作价值。R2 需要的信号是
  **"这次动作会不会改变最终答案"**，而不是"这条候选里实体多不多"。
- **两个门位可以合并**：本篇有动作侧出口门（Tool 3），R2 有证据侧入口门。**同时装两道**是
  未被任何一件占据的配置。
- **oracle 表的替换**：把闭表换成 ConEC 真实上下文层，测同一管线的增益衰减——这是**本篇
  没做、R2 必须做**的实验，且它同时是 R2 的信息边界合规证明。

**可借鉴**（三条，按可移植性排序）：

- **(a) Tool 3 的五条确定性动作验证——直接可抄，零训练，且解决 R2 的一个真实问题。**
  R2 的冻结 omni 核在候选证据下改写实体时同样会过改写/幻觉。把"闭表成员 + 归一化编辑距离
  下限 + 去 case-only + 偏移重定位 + 左到右非重叠"装在**核输出之后**，就得到一个
  **不依赖训练、可审计、可消融**的输出侧护栏。注意其第 3 条（**偏移错了就重定位而不是丢弃**）
  是工程上非平凡的一条——LLM 给的字符偏移经常错，直接丢弃会白白损失召回。
- **(b) 三信号检索打分（exact / fuzzy / phonetic，权重外显）是"语音学检索基线"的现成强实现。**
  R2 §5.1 的组①要求"语音学检索代表钉 Double Metaphone 级强实现"——本篇的
  `n_exact·1.0 + f_best·1.2 + p_hit·0.6`（音形 5 字符前缀、模糊限 ±3 字符）是一个**已在五个
  域上验证过的、可直接实现的**具体配方，且**它是跑在多假设并集上的**（"the variants are
  concatenated to build a unified token set"）——这个"并集 token 集"技巧对 R2 的多假设检索
  直接可用。
- **(c) 1-Best 对照臂的设计本身。** 本篇最有价值的实验设计是**无意中**做出来的：把
  "多假设证据"与"约束闭表编辑器"分离成两个可比臂。R2 必须复制这个分解——**任何"多源/重听
  有用"的主张，都必须先减掉"单源 + 同样的约束编辑器"这条臂**，否则增益归因错误。
  本篇给出的读数（主载体上 99.4% 归编辑器）是 R2 在设计阶段就该内化的先验。

## 10. 深读后新增的、R2 应该知道的事实

1. **合取的存活只剩一条腿，且这条腿必须被重新定义得更窄。** RECOVER 占据 API-only +
   training-free + 外显世界知识 rescore 三分量。R2 的增量陈述**不能再写成"这四件事没人同时
   做过"这种平铺**，而必须写成：**"前三件已被单件同时做到；R2 的全部增量在第四件——
   由模型外可标定标量驱动的、含音频侧定向重解析的按样本双源动作选择。"** 这个陈述更窄、
   更可证伪，也更容易被 K1b 判死——**这是好事，它把独立性主张钉在了一个可实验的位置上**。

2. **R2 主载体上，"多假设证据"这条路已被实测为近乎零边际。** Earnings-21：1-Best 33.2%
   vs LLM-Select 33.4% RWERR（绝对 15.90 vs 15.85），5 倍 ASR 解码换 0.05 个 E-WER 点；
   编辑器一件拿走 99.4% 的增益。**R2 必须把"多几条假设"与"条件化地去听"严格切开**——前者
   在主载体上已被证明不值钱，R2 的价值主张只能建立在后者。

3. **Fox 行的"外显世界知识 rescore 空位"已被填上。** Fox 把 context-based rescoring 列为
   future work，RECOVER 用 training-free/API-only 的方式在**同一主载体**上实现了它。
   §8 Fox 行的 delta 必须收窄（§8 草案第 2 条）。

4. **"表越 oracle、增益越大"在其五个载体上单调成立。** 两个头条极值（RWERR 45.7%、
   recall +21.53 pp）都出自 Common Voice——该集**本无实体表**，其 3,098 条表由 NER 从
   **test 参考**抽出；而唯一由基准自带上下文层的 ContextASR-Bench 增益最小（baseline E-WER
   4.82，绝对改善 0.85–1.00 点）。**这是读集内最清晰的一条"oracle 词表 → 增益幻觉"的
   梯度证据**，可直接支撑 R2 §6.3 的信息边界纪律，也是 R2 拒绝转引其头条数字的依据。

5. **Earnings-21 的 1,013 条实体表：数值指纹与 Fox 的 oracle 表一致，出处未声明；
   但判定不依赖这一点。** Earnings-21 无任何与参考解耦的外部上下文层（要到 ConEC 才有），
   故任何覆盖组织/人名/产品的 Earnings-21 实体表**必然**是参考派生的。**析取封闭 →
   第三档 oracle。** 附带记一条内部不一致：正文称四类（含 financial terms），
   `tab:datasets` 表体写三类（Persons, Orgs, Products），而 Fox 表只有 PERSON+ORG。

6. **一条可直接抄的工程件：Tool 3 的五条确定性动作验证。** 尤其第 3 条——**LLM 给的字符
   偏移错了就重定位、而不是丢弃该提议**。这是 R2 在冻结核输出侧装护栏时会立刻遇到的问题，
   本篇给了零训练解法。**该门在动作出口、R2 的门在证据入口，两者不冲突且应叠加**——
   "证据入口门 + 动作出口门"双门配置在读集十六件中**无人占据**。

7. **"把读出量当动作价值"的代价被本篇测出来了，量级惊人。** Entity-Aware Select 在 ATCO2 上
   E-WER 相对降 9.1%、总 WER 相对涨 34.75%（48.63→65.53）。**且该退化只能归因于选择准则
   本身**（EAS 输出的非实体区逐字来自被选中的解码——论文把它误归因为"fusion insertion
   noise"，但 EAS 不做合并）。其长度破平规则（"更长=删除更少"）正是把幻觉重复误读成质量的
   具体形态。**R2 的控制器不得用"实体/检索命中数"作动作价值代理。**

8. **本篇的算术层干净，批评必须落在协议与边界。** 本读者用 `tab:sclite` 的 C/S/D/I 反算了
   全部十格 E-WER 与二十四条 RWERR，**逐 token 精确一致**（含 ContextASR-Bench 上表面矛盾的
   17.8 在未舍入计数下精确成立）。**这抬高了它作为 incumbent 的分量**——R2 不能靠"数字不可信"
   打发它。

9. **但它的三处表述过宽，转引时必须限定。** (i) "in every case … net F1 improvements
   +0.3 to +10.7 pp" —— ContextASR-Bench 上有**四个 F1 净负格**（1-Best −0.07、EAS −0.56、
   ROVER −0.08、mini −0.24），该区间**只对 LLM-Select 成立**；(ii) 精度损失 "7–9 pp" ——
