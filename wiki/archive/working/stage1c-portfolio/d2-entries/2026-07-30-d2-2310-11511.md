## 1. 方法本质

Self-RAG 把"是否检索"与"证据信不信"变成**模型词表里的特殊 token**：四类 **reflection token**（Table 1）——
`Retrieve ∈ {yes, no, continue}`（输入 `x` 或 `x,y`）、`IsRel ∈ {relevant, irrelevant}`（输入 `x,d`）、
`IsSup ∈ {fully supported, partially supported, no support}`（输入 `x,d,y`）、`IsUse ∈ {5,4,3,2,1}`（输入 `x,y`）。
这些 token **是训练进模型的**，不是 prompt 约定：先用 GPT-4 生成每类 4k–20k 条监督、蒸馏出一个 **critic
`C`（Llama2-7B）**（与 GPT-4 预测一致率 >90%）；再用 critic **离线**把 reflection token 与取回段落插进
**150k 条**指令-输出语料，最后按**标准 next-token 目标**训练 **generator `M`（Llama2 7B/13B）**，词表扩展为
「原词表 ∪ reflection token」、取回文本块在 loss 中被 mask（§3.2.2；4×A100 80GB、3 epoch、batch 128、lr 2e-5）。
推理时逐 **segment**（实验中=一句）生成：先解 `Retrieve`，为 yes 则并行处理 K 段、逐段出 `IsRel`/续写/`IsSup`，
最后出 `IsUse`，并按 `f(y_t,d) = log p(y_t|x,d,y_<t) + Σ_G w^G s_t^G` 做 **segment 级 beam search（B=2）**，
其中 `s_t^G` 是该类最优 token 的**归一化生成概率**（默认权重 IsRel 1.0 / IsSup 1.0 / IsUse 0.5）；也可硬约束
（`IsSup = No support` 直接丢弃该续写）。检索器是**冻结现成件** Contriever-MS MARCO（默认取 top-10、用 top-5）。
**触发的可调旋钮是软阈值**：`p(Retrieve=Yes) / [p(Yes)+p(No)] > δ`——δ=**0.2** 为默认（作者原话："to encourage
frequent retrieval"），**ALCE/ASQA 上 δ=0**，按该式等于**关闭自适应、恒检索**。

## 2. key-value 定位

Self-RAG **不研究组织**，key-value 侧几乎全是继承项，但有一处 R2 直接相关的结构差异：

| 维度 | 事实 |
|---|---|
| **key** | 完全外包给冻结的 Contriever-MS MARCO（单向量、单面），官方 2018 英文 Wikipedia embedding；PopQA 上作者自陈 2018 快照缺 2022 新增实体的条目（附录 §评测细节），另对 bio/开放 QA 追加 **web 搜索 top-5**、ASQA 用作者提供的 **GTR-XXL top-5**。→ 同一系统内**混用多个异构 key 空间**，但只是按任务切换，不是同一 value 的多面 key |
| **value** | 取回段落原文，在生成侧被 `<p>...</p>` 包裹并**在训练 loss 中 mask 掉**（§3.2.2）——这是 Self-RAG 与 RAG 的关键装载差异：value 只作条件、不作学习目标 |
| **value 的下游标注** | 每段 value 在进入续写打分前被打上 `IsRel`，续写后被打上 `IsSup`。→ 这是**逐条证据的运行时元数据**（相关性 + 佐证度），在 R2 §1.3 的词典里正是**准入门的信号**（对应 R2 `V̂(ADMIT)` 里的 `corr(e,ĥ)` 与 `srcQual`），**但 Self-RAG 无来源质量、无冲突检测（无 `confl`）** |
| **key-value 拆分自由度** | 无。Self-RAG 不设计 key，也不改 value 的 schema；无版本、无 URL/文档 ID 落盘、无快照冻结、无冲突标记 |
| **引用与出处** | **有**：每个 segment 自带"该段被哪条 passage 支持"的自评，ASQA 上按 ALCE 官方 citation precision/recall 评测。→ 这是 pre-2024 就存在的**归因指标先例**（R2 §4.2 把归因指标记给 2605.15019） |

## 4. DFS 四问

**方法**：把"检索必要性"与"证据可信度"从系统外的启发式规则改造成模型自己会生成的、可被采样概率量化的
token，从而让同一个 LM 在**推理期**通过阈值 δ 与权重 `w^G` 两组旋钮改变行为（多检/少检、重引用/重流畅），
而不需要为每种偏好重训一次（这是它相对 RLHF/PPO 的核心卖点）。critique 离线计算并写进语料，训练期不必挂 reward model。

**局限**：(a) 触发与自评能力**只能通过训练获得**——扩词表 + 150k 语料 + 另训 critic + GPT-4 蒸馏，四件都
不可省；(b) 论文自己的消融显示**离散自决触发远不如外部软阈值**（PopQA：Hard 28.3 vs 默认 45.5 vs 不检索
24.7），且 ASQA 上作者直接把 δ 设 0 关掉自适应——"模型自决"这个卖点在其自身证据里最弱；(c) 无冲突处理、
无来源质量、无 abstain、无预算/成本记账（全文零成本维度）；(d) 主表并非全面占优（TQA/ARC 输 ChatGPT，
ASQA str-em 输 Alpaca-13B+ret）。

**改进空间**：把"训练进 token"换成"从部署可见信号估计"，就是 R2 杠杆一的定位；把 `IsRel/IsSup` 从 beam
打分项升级为带冲突检测与来源质量的**接纳/拒绝判定**，就是 R2 杠杆二；把 δ 从人手设的全局常数升级为按实例/
按类别的决策量，就是 2026 年 CTA/VOI-search/AdaCompute 那条线在做的事——**Self-RAG 已经把那个旋钮暴露出来，
只是没有人去学它**。

**可借鉴**：① 逐 aspect 分别报"自评 token 与人评一致率"的核验形态（Figure 4(d)），可直接搬作 R2 frozen judge
保真合同的报告模板；② `IsRel`（passage 级）与 `IsSup`（claim 级）两级证据元数据的分层，正对应 R2 §3.4 第 2 项
"音频锚定的出处 schema" 需要携带的两个字段；③ "同一机制在 PopQA 与 PubHealth 上边际价值分别 +20.8 与 +0.5"
这一对读数，是 R2 载体分层论证可引的 pre-2024 同型证据。

### 5.2 深读后新增的、R2 应该知道的事实

1. **该框架的默认配置是偏向"多检"而非"省检"**：δ 默认 **0.2**（作者原话 "To encourage frequent retrieval"），
   ALCE/ASQA 上 **δ=0**（按 `p(Yes)/[p(Yes)+p(No)] > δ` 等于恒检索）。→ 把 Self-RAG 引作"选择性获取"的原理锚
   时，必须知道它的默认参数与"少检省钱"方向相反；R2 §4.1 的效果优先纲领（"借的是选择性获取的**效果**论据"）
   在这里恰好安全，但 R2 不可顺带暗示 Self-RAG 支持"少检更好"。
2. **同一机制在两个任务上的边际价值差 40 倍**（Figure 3(a)）：PopQA 检索边际 = 45.5 − 24.7 = **+20.8**；
   PubHealth = 73.5 − 73.0 = **+0.5**（且 Hard 72.6 < 不检索 73.0，即在 PubHealth 上**检索轻微有害**）。
   → R2 §4.2 把 "regime 边界（额外测试时算力对推理型有利、对纯感知有害）" 记给 2606.28864（2026）；**同型
   读数在 pre-2024 已有**，且更直接（同模型、同机制、只换任务）。建议 R2 在 §4.2 或 §5.4 加此 pre-2024 锚，
   并据此强化 §5.4 的分层收缩逻辑：**"检索是否值得"本身是任务分层属性，灵敏度前置检定必须逐层做，不能只做全局**。
3. **自评机制的价值高度集中在长文/带引用任务——这是对 R2 载体选择的实质风险**：No Critic 消融在
   **ASQA em 上 32.1 → 18.1（−14.0）**，而在 PopQA 只 45.5 → 42.6（−2.9）、PubHealth 73.5 → 72.0（−1.5）。
   → R2 的两个 T1 主载体（Omni-DeepSearch-640、AudioRAG-500）**都是短答/MCQ 型**，K4（准入门判据）若只在
   这类载体上验证，可能系统性**低估甚至无法暴露**准入门的价值，从而在准入门实际有效的情况下把它判死。
   建议 R2 在 §5.4 或 §7 K4 处加一条：K4 判死前需声明"载体是否具备暴露准入门价值的形态（长文/多 claim/
   需引用）"；若不具备，K4 的负读数只能记 `PENDING_CARRIER`，不得判死——与 K5-t 的处理同型。
4. **检索器是冻结现成件，创新全在控制面与生成侧**：Contriever-MS MARCO 全程不训练（默认取 top-10、用 top-5；
   bio/开放 QA 另加 web 搜索 top-5；ASQA 用作者提供的 GTR-XXL top-5）。→ 与 R2「工具级冻结组件明确可用」
   的边界**同形**，可作正面先例引用；唯一差别是 Self-RAG 训练了 generator 而 R2 不训练。**另注一处组织瑕疵**：
   同一系统按任务混用 2018 Wikipedia / live web 搜索 / 作者提供的 GTR-XXL 三套异构 key 空间与快照，
   且作者自陈 PopQA 的 2022 实体在 2018 快照里缺条目——这正是 R2 §3.4 第 1 项「可复放组织」要治的病，
   pre-2024 即已存在，可作为 R2 复放合同必要性的旁证。
5. **机制实现的不可搬性已被本件确认，R2 §6.2 的降级选型应就地写明理由**：Self-RAG 的 tree decoding 依赖
   reflection token 的 **token 级归一化概率**（`s_t^G = p_t(r̂) / Σ_i p_t(r_i)`）与 segment 级 beam search
   （B=2）。R2 的 API-only 冻结 omni 核既没有这些 token，也未必暴露 logprob。→ R2 §6.2 用「已采样候选答案
   的语义槽众数占比」（`maxAgree`）与「音频重呈现一致性」（`audCons`）替代 token 概率，是**结构性必要的降级**，
   不是随手选型。建议在 §6.2 可实现定义处加一句注："（Self-RAG 式 token 级自评在 API-only 冻结核下不可得，
   故改用采样统计量）"，以防评审读成任意选择。
6. **归因指标（citation precision/recall）的 pre-2024 锚**：Self-RAG 在 ASQA 上按 ALCE 官方口径报 citation
