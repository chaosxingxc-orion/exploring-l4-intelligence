## 1. 方法本质

本文交付两件耦合物：**MMSearch-Engine**（一条手工设计的三段式多模态搜索流水线）与
**MMSearch**（300 题人工采集基准）。流水线固定为 requery → rerank → summarization 三段，
每段调用 LMM 一次：requery 把用户 query 与图像（含 Google Lens 图搜结果截图）翻译成一条文本
检索式；rerank 从检索引擎（DuckDuckGo）返回的 top-$K$（$K{=}8$）中选一个"最有信息量"的网站，
输入是 *brief results*（标题 + snippet + 网页顶部截图）；summarization 爬取被选网站，把
Sobel 梯度去空白后的整页截图与 BGE-M3 取回的 ≤2K token 相关正文作为 *full website content*
喂给 LMM 出答案（§2.1）。关键设计是**流水线同时充当数据采集工具与评测夹具**——标注者当年
就是走同一条流水线产出 gold（人工 requery、K 个网站的 valid/unsure/invalid 三分集、答案），
因此每一段都有独立 gold，可做步级归因（§2.2–2.3）。评测由此变成四个任务：三个步级任务
（各段输入被冻结为标注期的 gold 上游）加一个端到端任务，总分
$S_{final}=0.75S_{e2e}+0.05S_{req}+0.1S_{rer}+0.1S_{sum}$（§2.3）。去污手段是**时间性**的：
News 区 300 题中每题记录事件时间戳（2024-05-01～2024-08-31），逐模型核对 knowledge cutoff；
Knowledge 区每题经人工验证超出 GPT-4o / Claude 3.5 Sonnet 能力（§2.2、§2.4）。

## 2. 三轴定位

**搜索决策谁做。** 不由模型做。流水线是**固定 workflow**：段数、段序、检索宽度 $K{=}8$ 全部
硬编码，LMM 只在每段内部做生成（requery / 答案）或从 8 个候选里做一次选择（rerank）。
"是否需要检索"从不是一个决策——每题必检索恰好一次。相较后继工作，这里没有任何 agent 性质
的调度权；论文自己把它定位成"empower any LMM with multimodal search capabilities"的夹具。

**几轮。** 每题 **3 次 LMM 调用、1 轮检索**，无多跳。唯一的扩展是 §3.4 的 TTC 消融：
requery 采 5 次、rerank 采 5 次、答案采 5 次，共 25 条端到端输出（推理成本 ~25×），但段数
仍是 3。

**停止判据。** **不存在**。轨迹长度由 schema 决定，没有任何置信度/收益/预算判据参与终止。
这也意味着本文无法测量"过度检索"或"该检不检"——两种失效都被流水线结构屏蔽掉了。

**证据准入。** **无准入门**。rerank 是唯一的取舍动作，但它被约束为"从 8 个里必须选 1 个"：
选到 invalid 集或格式错都记 0 分，**没有"全部拒绝 / abstain"这个动作**（§2.3 计分表）。
被选网站的 full content 无条件进上下文。压缩是有的（Sobel 去空白、BGE-M3 取 ≤2K token），
但那是 token 预算工程，不是准入判据。

**出处处理与快照。** 出处以**证据形态**保留而非以引用形态保留：brief results 含标题/snippet/
顶部截图，正文含整页截图切片（宽 512、每片高 512、最多 10 片，长边不缩放规则见 §3.1）。
但**没有引用归因、没有 unsupported-claim 检测、没有冲突处理、没有 abstain 分析**；答案是
1–2 词短串，judge 是 F1，不涉出处。**快照是部分冻结的**：Table 1 显示基准自带 2,280 张网页
顶部截图与 295 张整页截图（合计 2,901 张唯一图像、2,400 条唯一 reranked 网站记录），因此
rerank 与 summarization 两个步级任务是在**落盘快照**上评的（原文 "among $K$ pre-defined
websites" / "based on a pre-defined website content"），只有端到端任务走 live 检索引擎。
这个"步级冻结 + 端到端 live"的混合冻结是本文最可移植的协议资产（见 §5-N2）。

## 4. DFS 四问

**方法。** 把"多模态搜索能力"分解为 requery / rerank / summarization 三个可分别取 gold、
可分别打分的子能力，并用同一条流水线完成人工采集与模型评测，从而把端到端失败**归因到具体
段**（§2.3、§3.3 的四类端到端错误：requery / rerank / summarization / informal）。这是"步级
可归因评测"在多模态搜索上的第一次系统化实现。

**局限。** (a) 模型不持有任何调度权，"是否检索/几轮/何时停"三个轴在设计上不可测；
(b) 指标全是串匹配（e2e 与 summarize 用 F1、requery 用 avg(ROUGE-L, BLEU-1)、rerank 查表
1.0/0.5/0.0），requery 与人工 requery 的字面相似度**不等于**检索效用，这是一个已知的错位；
(c) 端到端走 live 检索，300 题、单次采样、无 CI、无 dev/test 划分；(d) 结论级最脆弱的一条
（TTC 可替代模型规模）建立在 oracle 选择上；(e) 无 abstain 动作、无出处归因指标。

**改进空间。** 三条被后继直接吃掉：把固定三段换成模型自主调度（→ MMSearch-Plus、
MMSearch-R1、OpenSearch-VL 这条线）；把 oracle best-of-N 换成真 selector（本项目 R2 主杠杆
所在的位置）；把 n-gram judge 换 LLM judge（后继全部换了，代价是跨论文不可直接相减）。
尚未被吃掉的一条：本文那套**步级 gold + 部分冻结快照**的评测骨架，后继反而退化了（见下）。

**可借鉴（对 R2）。** 三项，全部是协议而非效果：①四任务加权分解 + 每段独立 gold 的步级
归因骨架；②**混合冻结**（步级诊断任务在落盘证据上评、只有端到端走 live）；③时间去污三件套
（逐题事件时间戳 + 逐模型 cutoff 核对 + 承诺随新模型刷新 News 区）。第四项可选：rerank 的
valid/unsure/invalid 三级标注（0/0.5/1）+ "至少一个 valid 才收题，否则退回改 requery"的可解性
保证——这是一种**在标注期顺手产出证据级负类**的造法。

### 5.2 深读后新增的、R2 应该知道的事实

**N1（红线同源的反例警示）。** MMSearch 的 TTC 结论 55.2 是 **oracle-selected best-of-25**：
中间选择用 $S_{req}$ 对人工 requery 打分、终选取对 gold 的 max F1。R2 §7/§6 若引"测试时算力
可比拟模型规模"这一跨域论据，必须标注 oracle 口径；它与 R2 自己的红线（`test gold 永不进
controller`）恰好同源，因此更适合作**反例警示**（"这类增益如何被误读"）而非可借效果。本项目
memory 中"information-boundary over-reach"一条与之完全同形。

**N2（对 Omni-DeepSearch-640「无检索快照」缺口的最便宜补法）。** MMSearch 是**部分冻结**
基准：2,280 条 brief-result 快照 + 295 张整页截图落盘（Table 1），rerank / summarization 两个
步级任务因此在冻结证据上评，仅端到端走 live。→ 结论：**不必冻结整个 web，只需冻结步级诊断
任务所用的证据**，即可获得可复放的诊断轴。R2 §5.2 readiness 表把"无检索快照/无负类/无
dev-test"三项并列为 Omni-DeepSearch-640 的阻断项；本条给出前两项的联合解法。

**N3（时间去污的可移植协议）。** 逐题事件时间戳（Figure 5 分布：2024-05-01～2024-08-31）+
逐模型 knowledge-cutoff 核对（Claude 3.5 Sonnet 报 2024-04；GPT-4V/GPT-4o 声明无 2024 信息；
开源逐个查发布日与训练数据）+ 明文承诺"若新 LMM 训练数据覆盖采集期则更新 News 区"。
R2 §5.1 记 Omni-DeepSearch-640 用"一个非根节点绑定近期新闻"抗参数捷径——那是**构造期**手段，
缺**逐题时间戳**与**刷新承诺**，因此无法回答"两年后这批题还干净吗"。这两件是零成本可补的。

**N4（在标注期顺手造负类）。** rerank 的 gold 是标注者对 $K{=}8$ 个网站的三分标注
（valid / unsure / invalid → 1.0 / 0.5 / 0.0），且强制"至少一个 valid，否则退回改 requery"，
再由第二名标注者据 full content 独立作答以验可解性。→ 这是 R2 §5.1「载体无负类，M3 不可直测」
的一条现实造法：**负类不必额外采集，是标注流程的副产物**。

仅一个 split、judge 用"三模型投票"求内部一致但不解决跨论文可比。R2 §5.1 现称其"构造合理性
高（三者最严）"——那是与 AudioRAG-500 / VoiceAgentRAG-200 两个音频域载体比；一旦把视觉域
三篇放进同一张表，"最严"的说法不成立，应改为"**在音频域现有载体中最严；对标视觉域仍缺
检索器级过滤、事后去污 split、证据快照与 judge 对齐纪律**"。

**N6（同流程人类基线）。** MMSearch 的人类基线是"**走同一条流水线**的 8 名大学生"
（69.2 / 68.2），MMSearch-Plus 的是"自由浏览器"（22.8）。两者不可比，但前者对 R2 更有用：
**同流程人类基线隔离的是流水线本身的天花板**，可直接回答"是模型差还是流程差"。R2 两个载体
都无人类基线；若要补，成本最低且信息量最大的是同流程版。
