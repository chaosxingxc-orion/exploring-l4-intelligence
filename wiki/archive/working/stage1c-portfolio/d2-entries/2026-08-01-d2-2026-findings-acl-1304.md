## 2. 方法全景

### 2.1 一句话骨架与四阶段

摘要逐字（第 26167 页）：

> "Rather than having audio LALMs process entire recordings directly, PlanRAG-Audio explicitly plans which modalities and temporal spans are required for a given query, and retrieves only query-relevant information from a structured text and audio database. This retrieval planning enables effective reasoning over complex, cross-domain audio queries while substantially reducing the input length passed to the large language models."

四阶段（Figure 1，第 26168 页；§3.1.1–3.1.4，第 26169–26170 页）：

| 阶段 | 逐字定义 | 执行者 | 是否确定性 |
|---|---|---|---|
| Stage 1 音频/语音处理 | "converts raw audio into a set of modality-specific representations through audio and speech processing" | 四个预训练感知模型 | 确定性（一次性、全量） |
| Stage 2 检索规划 | "a planning LLM analyzes the query and produces a structured retrieval plan Θ(q)" | 规划 LLM + 受约束解码 | 论文自述"effectively deterministic" |
| Stage 3 结构化检索 | "a rule-based SQL generator deterministically compiles it into an executable merged SQL query Q(Θ(q))" | 规则式 SQL 编译器 + 数据库 | 确定性 |
| Stage 4 答案生成 | "These segments are provided to a generation LLM together with an explicit output schema" | 生成 LLM | 随机（受 schema 约束） |

Stage 3 的形式化（Eq. 1，第 26170 页）：

> `R(q, a) = Exec( Q(Θ(q)), D(a) )`，"where Exec(·, ·) denotes a deterministic database execution operator."

**检索宇宙由 Eq. (1) 的第二参数钉死**：> "The query is executed against the audio database D(a) **for the target recording a**"（第 26170 页）。

### 2.2 结构化音频数据库 D(a) 的构造（§3.2 + Figure 2 + Table 1）

**构造顺序逐字（第 26171 页）**：

> "The pipeline begins with **speaker diarization**, which produces a sequence of speaker-homogeneous temporal segments. **These diarization timestamps define the fundamental alignment units used throughout the database construction process.**"
> "Given these shared segment boundaries, **speech transcription and emotion recognition are applied to exactly the same temporal spans.** As a result, transcript, speaker, and emotion streams **share identical start and end times**, as illustrated by the record examples in Table 1. This design enables cross-stream alignment, allowing text content to be directly matched with speaker identity and emotional cues using **simple timestamp-based joins**."
> "In contrast, **sound event streams are generated at a different temporal resolution using a sliding-window audio tagging approach.** Unlike speech-centric streams, acoustic events do not necessarily depend on conversational structure or speaker boundaries. Therefore, event predictions are produced **independently of diarization segments** and stored with their own start and end times. As with emotion, **event labels are stored as label–score pairs in JSONB fields**, following a unified schema."

**Table 1 逐字（第 26171 页）——任务下达的核验点，结论为 CONFIRMED**：

| Stream | Start (s) | End (s) | Example |
|---|---|---|---|
| `transcript` | 20.50 | 22.10 | He talks about it |
| `speaker` | 20.50 | 22.10 | SPEAKER_07 |
| `emotion` | 20.50 | 22.10 | Neutral (0.58), ··· |
| `sound_event` | 22.00 | 27.00 | Speech (0.87),··· |

→ **Table 1 确实且仅列出 `transcript` / `speaker` / `emotion` / `sound_event` 四条流**；前三条共享 `20.50–22.10` 同一时间戳（与"identical start and end times"自洽），`sound_event` 用独立的 `22.00–27.00`（与"independently of diarization segments"自洽）。表题注另注："label–score pairs for emotion and sound_event are shown in simplified form."

**流 ↔ 生产模型的映射**（Table 3，第 26172 页，逐字）：

| Model 行 | Version/Variation | Params | 产出的流 |
|---|---|---|---|
| `SD` | Pyannote, community-1 | 8.1M | `speaker` 流 **+ 全库对齐单元（分段边界）** |
| `ASR` | OWSM-CTC v4 medium | 1.01B | `transcript` 流 |
| `ER` | Odyssey 2024 SER baseline | 316M | `emotion` 流 |
| `SED` | BEATs iter3+, AS2M finetuned | 90M | `sound_event` 流 |
| `Qwen` | Qwen3-4B-Instruct-2507 | 4B | 规划/生成 LLM（主） |
| `Gemini` | Gemini 2.5 Flash | undisclosed | 规划/生成 LLM（对照） + 长上下文基线 |
| `Voxtral` | Voxtral-Mini-3B-2507 | 5B | 长上下文基线（无 PlanRAG 臂） |

ASR 选型理由逐字（§4.2，第 26172 页）：> "We adopt OWSM-CTC v4 as the ASR backbone due to its **connectionist temporal classification (CTC)-only design, which avoids language-model memorization** and enables fast, fully open multilingual recognition."

**四条 D(a) 层面的承重事实**：
1. **说话人分段是全库的时间骨架**：ASR 与 ER **不做自己的切分**，被强制对齐到 diarization 边界 → 分段错误会**同时**污染 transcript/speaker/emotion 三条流，且三流误差**不独立**。
2. **`sound_event` 是唯一时间分辨率独立的流**（滑窗音频打标），故跨流对齐必须靠附录 F 的容差融合而非等值 join。
3. **`emotion` 与 `sound_event` 以 `label–score` 对存于 JSONB**——**分数字段在库内存在**；但正文与 Example 2 展示的过滤器均未使用分数（见 §3「证据准入」行）。
4. **D(a) 的内容全部来自录音 a 本身**，无任何外部文档/网页/知识库入库（全文无相反陈述）。

### 2.3 规划 → 规则式 SQL 编译 → 检索

**Stage 2 计划契约（§3.1.2，第 26169–26170 页）**，逐字五项：

> "Concretely, the retrieval plan Θ(q) specifies: 1) which modality-specific representations are required; 2) what filters are applied to each stream; 3) how multiple streams are joined; 4) which fields are returned from the merged SQL results; 5) what schema the final generation LLM must follow."

计划为何被称为确定性，逐字：

> "Because Θ(q) is **generated via constrained decoding under a fixed schema**, the planning stage is **effectively deterministic and does not produce invalid retrieval plans**."

Example 1（第 26170 页）给出的计划实例含五个键：`"streams": ["transcription","speaker"]`、`"filters": {"text":"employment","speaker":"SPEAKER_02"}`、`"fusion": {"anchor":"transcript"}`、`"output": {"return_fields":["start","end","speaker","text"]}`、`"answer_schema": {...,"enum":["A","B","C","D"]}`。

**Stage 3 编译（§3.1.3，第 26170 页）**：

> "Given the retrieval plan Θ(q) from Stage 2, a **rule-based SQL generator deterministically compiles** it into an executable merged SQL query Q(Θ(q)), constructed using stream selection, filtering, fusion, and the output contract (items 1–4 in Stage 2)."
> "The WITH clause defines **stream-specific Common Table Expressions (CTEs)** ((A), (C)) with their corresponding filters ((B), (D)), while the final SELECT projects the requested fields (E) and merges the streams via a **temporal join** (F)… Because each stream is translated into an independent CTE with its own filters, the resulting query is **modular and naturally scalable to additional modalities**."

Example 2 的实际算子只有三类：`WHERE text ILIKE '%employment%'`（关键词包含）、`WHERE label = 'SPEAKER_02'`（等值）、`JOIN sp ON temporal_overlap(tx, sp)`（时序重叠）。

检索机制逐字（第 26170 页）：> "We adopt a **simple keyword-based retrieval mechanism** in this work, as our goal is to **isolate the effect of explicit retrieval planning** for complex long-form audio reasoning, including both cross-modality and single-modality inference."

融合规则（附录 F，第 26183 页）：> "we consider candidate segments from a target stream that temporally overlap with the base segment within a fixed tolerance window ±τ seconds… we select **at most one** segment whose temporal midpoint is closest… If no target segment satisfies the temporal overlap constraint, **the base segment is retained without a matched target segment**." 并且 > "Unless otherwise specified, we use **τ = 2.5 seconds** in all experiments."

**Stage 4（§3.1.4，第 26170 页）**：> "The execution of the merged SQL query yields a set of relevant segments R(q, a) from the audio database for the target recording a. These segments are provided to a generation LLM together with an explicit output schema, and the model produces the final answer while adhering to the schema constraints specified during planning."

### 2.4 什么是 zero-shot、什么被训练

**论文自述的 zero-shot 范围**（贡献三，第 26169 页）：

> "We demonstrate that PlanRAG-Audio handles a wide range of long-form audio understanding tasks, from base tasks such as QA and diarization to advanced and compositional reasoning tasks, **in a zero-shot manner without task-specific prompt engineering or manually crafted SQL queries**."

§4 首段（第 26171 页）：> "Our experiment is designed to evaluate whether explicit retrieval planning enables reliable and scalable understanding of long-form audio **in a zero-shot setting**."

Limitations（第 26175 页）：> "Our framework **depends on pretrained perception modules** (e.g., ASR, SD, ER, and SED), and is therefore **bounded by their accuracy**. The primary goal of this work is **not to optimize these components**…"；> "PlanRAG-Audio **does not introduce new modeling assumptions beyond those of the pretrained components it relies on**."

**逐层判定**：
- **目标任务训练：全文零出现。** 无微调、无 LoRA、无奖励模型、无策略优化、无 in-context 示例挑选、无 SQL 模板人工编写（自述明确排除后两项）。
- **感知层四模型均为现成检查点**（Table 3 逐字给出版本号），其中 `BEATs iter3+, AS2M finetuned` 与 `Odyssey 2024 SER baseline` 本身是在各自任务上训练过的模型——**"zero-shot"只及本框架的规划/检索/生成层，不及感知层的既有训练**。这一分层与 ConEC 条目的"zero-shot 只及偏置层不及识别器"是同型问题，**引用时必须写明分层**。
- **规划器与生成器的身份未被论文分离声明**：§3.1.2 称 "a planning LLM"，§3.1.4 称 "a generation LLM"，§4.2 只写 "using **Qwen3-4B-Instruct as the primary generation model**"，结果行写作 `Qwen + PlanRAG-Audio` / `Gemini + PlanRAG-Audio`。**论文从未明文说明两角色是否为同一模型实例**（见 §6 内部不一致 I-11）。

→ **"decoupling inference cost from raw audio length" 的适用范围 = 送进 LLM 的 token 数，不含系统总成本**：四个感知模型仍在**整段**音频上跑一遍，RTF ≈ 0.05–0.06、540 分钟需 1986 秒。**引用该主张时必须带上这一范围限定**（见 §6 内部张力 I-10）。

## 4. DFS 四问

### 4.1 方法核心

把长音频理解**重述为一个对结构化数据库的、先规划后执行的检索问题**：先用四个现成感知模型把整段录音离线转成四条时间对齐的符号流（`transcript`/`speaker`/`emotion`/`sound_event`），再让 LLM 在受约束解码下产出一份**声明式检索计划**（选流 / 过滤 / 融合 / 返回字段 / 答案 schema），由**规则式编译器**确定性地把计划翻成一条 merged SQL（每条流一个 CTE + 时序 join），执行后只把**命中的少量符号记录**交给生成 LLM 按 schema 作答。作者自述的目标句：> "to demonstrate that long-form audio understanding can be **effectively reformulated as a planning-based retrieval problem**"（第 26175 页）。

### 4.2 自述局限（Limitations 全节逐字，第 26174–26175 页）

> "Our evaluation of Gemini is constrained by practical limitations of the API, including unstable long-context handling and frequent formatting failures that prevent reliable evaluation."
>
> "We adopt a simple keyword-based retrieval mechanism to isolate the effect of retrieval planning. While more expressive retrievers may improve recall, our empirical results (Appendix G) suggest that retrieval planning plays a more critical role than the choice of retriever in our setting."
>
> "Our framework depends on pretrained perception modules (e.g., ASR, SD, ER, and SED), and is therefore bounded by their accuracy. The primary goal of this work is not to optimize these components, but to demonstrate that long-form audio understanding can be effectively reformulated as a planning-based retrieval problem."
>
> "The preprocessing stage introduces additional computational cost, which is amortized across queries but may limit real-time applicability (see Appendix E)."
>
> "From an ethical and risk perspective, PlanRAG-Audio does not introduce new modeling assumptions beyond those of the pretrained components it relies on. As a result, potential risks present in pretrained models also apply to our framework."

另有一节独立声明（第 26175 页）：> "Parts of this manuscript were edited for clarity and language using an AI-based writing assistant. The authors take full responsibility for the content."

**自述局限之外、本件逐表核对新增的四条**（论文未列）：
- (i) **短时长净负**：MCQA(e2e) 10 分钟处 Gemini 74.30 → 45.24、Qwen 61.80 → 50.05（Table 13/11）；论文正文未提这一方向。
- (ii) **规划/格式损失恒定在 12.8–15.7 pp**（Table 7），与 §3.1.2 "does not produce invalid retrieval plans" 的语气张力见 §6。
- (iii) **对照臂缺口**：Table 5 无 Voxtral+PlanRAG 行、Table 6 无「Qwen 不加 PlanRAG」行、Table 13/14 无 Gemini @540 的无 PlanRAG 行、Table 15/16 的 Voxtral 只到 30 分钟；540 分钟处的"稳定性"对比在 Gemini 侧**没有基线臂**（Figure 3 题注逐字："**Gray cells indicate unsupported or failed settings**"，第 26173 页）。
- (iv) **评测构造的两处外生依赖**：LibriSQA 建于 `train-clean-360`（一个训练划分）；摘要参考由 ChatGPT 在参考转写上生成，其质量无独立校验，且摘要 topline 的 Rouge-L 上限只有 24.56（10 分钟，Table 9）。

### 4.3 改进空间

按与 R2 的相关度排序，逐条给出论文中的可证伪抓手：

1. **证据准入的分数通道已经在库里但未接通**：`emotion` 与 `sound_event` 以 `label–score` 对存于 JSONB（第 26171 页），而检索侧只有 `ILIKE`/`=`。把分数接入准入/阈值/加权，是一处论文自身数据模型已经准备好、但实验未触及的改动面。
2. **计划的语义正确性从未被测量**："does not produce invalid retrieval plans" 只保证 **schema 合法**，不保证**选流/时间窗/过滤词正确**；Table 7 把 12.8–15.7 pp 归给"planning and formatting failures"却不拆分二者。一个计划级的诊断（选流准确率 / 时间窗召回）是直接可加的。
3. **检索器消融只有 1 任务 × 2 点**（Table 19），且 540 分钟处向量检索反超关键词（57.39 vs 56.07）。把消融扩到全任务 × 全时长，才能支撑"planning ≫ retriever"这一 Limitations 中的定性。
4. **短时长的净负未被处理**：无任何按输入长度或按任务类型在「直接送音频」与「走检索」之间切换的机制；两条路径在论文中是互斥的实验条件，不是可选动作。
5. **分段骨架的单点依赖**：ASR 与 ER 被强制对齐到 diarization 边界（第 26171 页），分段错误对三条流同时生效；论文未做分段扰动的敏感性实验。
6. **感知层上界**：Limitations 自认 "bounded by their accuracy"，而 SD topline DER 已是 10.55–12.64（Table 10）、ER topline macro-F1 只有 14.56–26.48（Table 10）——**ER 的可用空间在 topline 处就已经很窄**，任何在 ER 上的增益都受此天花板约束。

### 4.4 R2 可借鉴部分

1. **"同证据、有/无规划"这一对照臂的构造**是本篇最干净的一处设计：§4.2 逐字——> "the **Qwen row without PlanRAG-Audio** serves as the baseline without planning, where **the full structured audio database is provided directly to the LLM** without retrieval planning or selective stream filtering."（第 26172 页）。这条臂把「信息可得性」与「选择动作」分离，使增益不能被解释为"多给了信息"。R2 的臂结构可直接采用这一分离原则。
2. **误差三分解（topline / parseable / end-to-end）**（Table 7 + §5.1 逐字："we decompose errors into three components: upstream perception, retrieval, and planning or generation"）是一个可移植的归因模板：把上游感知上界、检索损失、格式与规划损失分列，避免把三者混成单一"效果"。
3. **oracle topline 的定义方式**（"applying a pretrained model directly to the ground-truth–aligned segment without long-form context or retrieval"，第 26172 页）给出了一个**与检索无关的能力上界**，可用作效应量包络的预注册工具。
4. **声明式计划 + 规则式编译**这一"LLM 只产结构、执行完全确定"的分工，把随机性收敛到两个点（计划生成、答案生成），中间层可复算；对需要审计的运行时动作序列，这是一种低成本的可追溯形态。
5. **时序融合的容差契约**（附录 F：±τ 重叠、取中点最近的至多一段、无匹配则保留基段、τ=2.5 s）是一份完整到可复现的规格，可直接作为跨流对齐的默认合同。
6. **`label–score` + JSONB 的统一 schema**（第 26171 页）为「把置信度带进检索层」预留了数据模型位置。

| **接口层级** | API 级即可：受约束解码 + 输出 schema；Gemini 经 API 评测（26174） | **未要求 logits/beam/隐状态等白盒接口**（全文零出现） |
| **感知与理解的关系** | 把端到端音频理解替换为**级联**：感知模型产库 → LLM 只读符号记录 | **未保留音频到生成模型的直通路径**；在 `Gemini + PlanRAG-Audio` 臂中，具备音频能力的模型**不再接收音频**（Table 4 的 0.9k token + Stage 4 描述，26170/26173）。论文自述该级联的上界："bounded by their accuracy"（26175） |
| **时间结构的处理** | 显式外化为时间戳并交给 LLM 做符号运算："speaker identifiers and event timestamps are **explicitly provided in the retrieved results**, reducing complex inference to **counting unique labels or sorting by timestamp**"（26174） | — |
| **长度-成本关系** | LLM 输入近似常数（115.2k → 0.9k，Table 4 @26173） | **未使系统总成本脱离音频长度**：预处理"scales approximately linearly with input length"（Table 18 题注，26183） |

### 6.3 可信度小结（不作方向性裁定）

- **可直接引用的强项**：`Table 4` 的 token 削减（限 MCQA/60 min）、`Table 5` 的 Gemini 进阶任务 delta（14.20→69.40、0.30→0.68）、`Table 6` 的弃权率 0.54→94.90、`Table 11–14` 中 SD/SED/ER 在长时长上的方向（无 PlanRAG 臂接近或等于失效）。这四组均有表体直接支撑、无跨表冲突。
- **引用时必须带限定的**：摘要的 "improves reasoning accuracy"（须带时长与任务类型）、"decoupling inference cost"（须限定为 LLM 输入 token）、Limitations 的 "planning ≫ retriever"（须写明 1 任务 × 2 点）。
- **不应作为承重引用的**：Figure 3 的任何目视读数（无数值层）；I-1/I-2 涉及的两个具体数（52.25/52.29、56.07/56.70）在二次目视核对前只报区间；"does not produce invalid retrieval plans"（无测量）。
