# D2 深读：DeepResearcher（2504.03160）

来源核对：本地 eprint LaTeX 源（`main.tex`，867 行，单文件 + `related.bib`）；
全部数字取自源码表格。作者 Yuxiang Zheng / Dayuan Fu / Xiangkun Hu 等（SJTU / SII / GAIR）。

## 1 方法本质

DeepResearcher 的主张是：深研 agent 的能力必须在**真实开放 web 上端到端 RL 训练**才能获得，
而不是靠 prompt 工程（脆弱、受人设工作流约束）或在固定本地语料上做 RAG-RL
（隐含"所需信息已在语料内"这一失效假设）。做法是把 Qwen2.5-7B-Instruct 放进 GRPO，
让它在 `<think>` 推理后自主发 `web_search`（Google/Serper）或 `browse_webpage`，
用**纯结果奖励**（词级 F1；格式错则 −1）训练，工具观测被 mask 不参与梯度。
配套一个**多 agent 结构**：主策略之外有一个专职 browsing/reading agent，
它为每个 query 维护短期记忆，按段顺序读网页、自己决定继续读还是停、把相关信息增量写入短期记忆后回传主策略。
工程上解决了高并发（50 节点 CPU 集群承接 rollout 期的搜索/爬取）、反爬与 API 限流（重试 + 7 天搜索结果缓存）。
论文额外声称训练**涌现**出规划、交叉验证、反思、诚实拒答四种行为。

## 2 三轴/key-value 定位

**这是三篇里唯一一篇训练类工作**，因此在 R2 的三轴上位置特殊：

- **获取轴（R2 §4，"谁搜、搜几轮"）**：DeepResearcher 把"搜什么/搜几轮/读哪个 URL/读多深"
  全部交给策略自主决定——**但这份自主性是被 RL 训进权重的，不是推理期控制面产生的**。
  奖励只在轨迹末端（outcome-only F1），**训练中没有任何 per-step 的检索价值信号、没有定价、没有预算**。
  它属于 R2 §4.1 谱系里的"agentic 深搜"段（2025 段位），**而不是**"被定价/被校准的获取"段。
- **数量决策仍是硬编码常数**：`web_search` 的 top-k **固定为 10**（论文自陈"current implementation
  employs a fixed top-k (e.g., 10)"，并把动态调参列为 future work）；每条 rollout **最多 10 次工具调用**。
  → 与 R2 §4.3 对语音线的批评"每个采集决策=LLM 自由生成，每个数量=硬编码常数"**同型**：
  DeepResearcher 的量也是硬编码的，差别只在"哪一次调用花在哪里"被训练过。
- **组织轴（R2 §3）：本篇几乎无组织可言**。value = 实时抓取的网页正文，
  key = Google 索引（不归作者所有、不可设计），无快照、无文档 ID 落盘、无 provenance、无可复放轨迹。
  它唯一的"组织"是 browsing agent 的**per-query 短期记忆**（用完即弃，不跨 query 持久化）。
  → 这与 R2 §3.3 批评 Omni-DeepSearch/AudioRAG"直连 live web、组织层就断了可复现性"**完全同型**；
  论文自己也依赖 7 天搜索缓存来控成本，即承认结果随时间漂移。
- **key-value 定位**：T1 型（value 在开放 web、key 空间归搜索引擎），
  与 R2 §2.3 对 T1 的判定一致——**key 侧不可设计，全部杠杆在 query 侧**。
  DeepResearcher 的全部杠杆确实都在 query 侧（生成什么查询、选哪个 URL），这为 R2 的 T1 分型提供了外部印证。

## 3 主实验数字（LaTeX 源核对）

**训练对象核实（本节重点）**：
- 被训练的**只有主策略**：backbone **Qwen2.5-7B-Instruct**，框架 **verl**，算法 **GRPO**；
  每步采样 256 prompt × 16 rollout，mini-batch 4,096（即一个 rollout 阶段回传一次）；
  每条 rollout ≤ 10 次工具调用 + 1 次作答。
- 奖励：`reward = −1`（格式错）/ `= 词级 F1`（格式对）。**纯结果奖励，无过程奖励、无检索奖励。**
- **观测被 mask**，工具返回不进梯度。
- **browsing / reading agent 未被训练，且其底座模型在全文中从未指明**（`main.tex` 内无任何
  browsing agent 的模型声明）。→ 因此"end-to-end 训练"实指**主策略端到端**，
  多 agent 结构中的读网页环节是一个**未训练、模型未披露的辅助组件**。这是一个可引用的复现性缺口。
- 训练数据：**80,000 条**，NQ:TQ:HotpotQA:2Wiki = **1:1:3:3**（多跳占 75%）。
  两阶段清洗：DeepSeek-R1 过滤时效/主观/有害问题；**污染检测 = 对基座采样 10 次（pass@10），
  凡基座不搜也能答对的题一律剔除**。
- 评测：NQ/TQ/HotpotQA/2Wiki/MuSiQue/PopQA 各从 dev 随机取 **512** 条 + Bamboogle 全部 **125** 条；
  MBE judge = **GPT-4o-mini**。（注：附录训练曲线图 Fig 7 自述"每个 benchmark 采 125 条"，
  与主表的 512 条**不同口径**，引用训练曲线时须分开标注。）

**数字（Table 1 = 域内，Table 2 = 域外；每格 F1 / MBE）**：

1. **Table 1 域内**：DeepResearcher NQ **39.6 / 61.9**、TQ **78.4 / 85.0**、
   HotpotQA **52.8 / 64.3**、2Wiki **59.7 / 66.6**。
   MBE 上四项全表第一；F1 上 NQ（39.6）低于 Search-r1-base（45.4）、
   HotpotQA（52.8）低于 Search-r1-base（55.9）。

   直连 Wikipedia 语料下测的（论文自己在表注强调这一不对等）。
2. **Table 2 域外**：MuSiQue **27.1 / 29.3**、Bamboogle **71.0 / 72.8**、PopQA **48.5 / 52.7**，

## 4 DFS 四问

**方法**：GRPO + 纯结果奖励（F1 / 格式 −1）在**真实 Google 搜索环境**里端到端训 Qwen2.5-7B-Instruct；
观测 mask；配一个未训练的 browsing agent 做长网页的分段顺序阅读 + per-query 短期记忆增量抽取；
训练数据经 pass@10 污染筛除以强制"必须真搜"；50 节点 CPU 集群 + 重试 + 7 天缓存承接 rollout 期的真实网络 I/O。

**局限**：(a) **红线冲突**——本项目训练自由（不改任何模型参数），DeepResearcher 的全部机制价值
挂在权重更新上，**其方法不可移植**，只可作为"这类自主性目前是靠训练获得的"这一事实证据；
(b) 真实 web 环境**不可复现**：无快照、无文档 ID、无轨迹落盘，结果随搜索引擎与网页漂移
（论文用 7 天缓存自证这一点）；(c) 奖励是词级 F1 短答案，论文自陈不适用长答案；
(d) top-k 固定 10、工具调用上限 10，**量的决策未被优化**；
(e) 无消融：多 agent 浏览结构 vs 单 agent 直读、缓存 vs 无缓存、多跳配比 1:1:3:3 的选择
**均无消融支撑**；(f) browsing agent 底座模型未披露、未训练——多 agent 贡献无法归因；
(g) 无种子/方差/显著性，未报告最终训练步数，训练曲线仍在上升（提前停止点不明）；
(h) MBE judge = GPT-4o-mini（弱 judge），且两个头条数字都是七集中的单集最大值；
(i) 训练曲线用 125 条子集、主表用 512 条，两口径并存。

**改进空间**：把固定 top-k 与固定调用上限换成被定价/被预算的获取（正是 R2 §4.1 第 3 段
Calibrate-Then-Act / VOI-search / AdaCompute 走的方向——**DeepResearcher 恰好停在那一步之前**）；
给 browsing agent 加奖励或至少披露与消融；把真实 web 换成可快照的固定语料以获得可复现的对照
（Pi-Serini 用 BrowseComp-Plus 做的正是这件事）；把四种"涌现行为"量化成可测频次。

**可借鉴（对 R2）**：(a) **pass@10 污染筛除法**——对基座采样 10 次、凡不搜也能答对的题一律剔除，
是"确保外部知识真的必要"的现成、可在训练自由下直接复用的**数据构造程序**
（R2 的锚数据集与主载体都需要这道过滤，否则 gold-evidence 臂与 no-evidence 臂的差分被参数知识吃掉）；
(b) browsing agent 的"分段顺序读 + 前几段不相关即跳过整页 + 短期记忆增量抽取"是一条
低成本的长 value 消费策略，与 Pi-Serini 的 `read_document` 分页读同型，可并入 R2 的证据消费设计对照；
(c) 它是 R2 §4.3"语音域停在 pre-pricing agentic 段位"这一定位的**文本域参照点**——
即"文本域 2025 年的 SOTA 也还没定价"，使 R2 的段位对标更精确。

## 5 R2 定位句核查

### 逐句判定

**句 1（§4.1 第 2 条，行 389–392）**：
> "**agentic 深搜**：Search-o1 2501.05366（推理过程中按需发起检索）、Search-R1 2503.09516、
> DeepResearcher 2504.03160、WebThinker 2504.21776（分层委派+报告工具）——
> 模型在推理环内自主决定搜什么、搜几轮。"

**判定：CONFIRMED（机制描述正确），但**须加一处必要限定 → 见新增事实 (1)(2)。
"模型在推理环内自主决定搜什么"确为 DeepResearcher 的实际行为（策略自生成 query、自选 URL）。
但"搜几轮"**只在上限 10 以内自主**，且每轮的 top-k 是**硬编码 10**，
故这句若被读作"数量也是自主/自适应的"，则不准确。
另：R2 未对该条声明数字，作机制定位引用——此定位本身站得住。

**句 2（§4.1 轴结论，行 404–405）**：
> "**轴结论**：文本域 2026 年的活跃前沿恰是'何时检索、检索多少、信不信'三个决策的质量——
> **全部是 reward-guided 控制面问题，与训练无关**。"

**判定：CORRECTED（需限定作用域）**。该轴结论紧跟在含 DeepResearcher 与 Search-R1 的清单之后，
但**这两篇的自主性恰恰是靠 RL 训练权重获得的，不是推理期控制面**。
DeepResearcher：GRPO + 结果奖励训练 Qwen2.5-7B-Instruct（源码 §"Model and Hyperparameters"）；
Search-R1 亦为 RL 训练方法。因此"与训练无关"这一断言**不能覆盖清单第 2 条**。
建议改为分层表述，例如：
"第 1、3 条（质量评估触发、被定价的获取）是推理期控制面机制，与训练无关，可直接落到冻结核上；
**第 2 条（agentic 深搜）在原文中是靠 RL 训练把这套自主性写进权重的**（Search-R1、DeepResearcher 均为 RL），
本项目在训练自由红线下只能借其**行为形态与效果论据**，不能借其获得方式——
这一差异本身正是 R2 的立项空间。"
→ 这个修正对 R2 是**加分**而非减分：它把"训练自由"从一句约束升格为一处**可辨识的方法差异**，
并且防止评审指出"你把 RL 论文列进'与训练无关'的谱系"这一硬伤（此类指摘属严谨性范畴，评审有裁决权）。

**句 3（§4.3 语音域批评，行 432–434）**：
> "**每个采集决策=LLM 自由生成，每个数量=硬编码常数**"

**判定：CONFIRMED 作为对语音线的描述，但须知它不构成语音域的独有缺陷** → 见新增事实 (2)。
DeepResearcher（文本域 2025 SOTA、RL 训练）同样是 top-k 硬编码 10 + 调用上限 10。
R2 若把"数量硬编码"作为语音域落后的证据，会被举本篇反驳。
建议把该批评的落点从"数量是常数"精确到"**数量是常数且没有任何机制去问这个常数对不对**"，
或直接承认这是 2025 段位的共性、语音域的真正落差在使用轴（无准入门/无归因/无 abstain 分析）。

### 深读后新增的、R2 应该知道的事实

**(1) DeepResearcher 是 RL 训练工作，训练对象 = 主策略 Qwen2.5-7B-Instruct（GRPO + 纯结果奖励），
browsing agent 未被训练且底座模型全文未披露。**
细节：verl 框架；每步 256 prompt × 16 rollout；mini-batch 4,096；每条 rollout ≤10 次工具调用；
reward = 词级 F1，格式错 = −1；工具观测 mask 不进梯度。
→ 对 R2 的两个后果：(a) §4.1 轴结论"与训练无关"必须限定作用域（见句 2）；
(b) "多 agent 结构"的贡献**无法归因**（未训练、模型未披露、无消融），
R2 不应把"分层委派/多 agent"当作已被验证的机制引用——WebThinker 的分层委派同理需另行核实。

**(2) 量的决策在 DeepResearcher 里仍是硬编码常数：`web_search` top-k 固定 10，工具调用上限 10。**
论文原文把动态 top-k 明列为 future work。
→ 这条使 R2 §4.1 的三段式谱系更锋利：**从"自适应触发"（第 1 段）到"被定价的获取"（第 3 段）之间，
第 2 段（agentic 深搜）虽然把"搜什么"交给了模型，却把"搜多少"留成了常数**。
这正是 R2 主创新（阶段三的调度与准入）要占的缝隙，建议在 §4.1 第 2 条后补半句点明这个缝隙。

**(3) 两个头条数字都是七集中的单集最大值，中位增益小得多——R2 若日后需引数字须知此边界。**
"28.9 点 vs prompt 基线" = 2Wiki MBE（66.6 − 37.7），七集中位约 9 点；
"7.2 点 vs RAG-based RL" = Bamboogle MBE（72.8 − 65.6），七集中位约 1.9 点，2Wiki 上仅 0.8 点。
且 F1 口径下 DeepResearcher 在 NQ（39.6 vs 45.4）与 HotpotQA（52.8 vs 55.9）**输给** Search-r1-base。
→ R2 现将本篇列入"登记未深读层（只作机制定位、不引数字）"是**恰当的**；
深读后仍建议维持"不引数字"，若必须引则须同时标注单集来源与口径（MBE/GPT-4o-mini judge）。

**(4) 那个 7.2 点的对比锚点混入了三个差异，不是纯训练环境效应。**
R1-Searcher 推理时用 Bing 真 web，但 (i) 训练用本地 RAG、(ii) 查询被强制加 `site:en.wikipedia.org`、
(iii) 强制摘要前三页结果（不能自主选 URL）。DeepResearcher 三点皆异。
→ 论文标题主张"real-world environment 训练是根本要求"，但该主张的**最强单点证据混杂了
搜索域限定与 URL 自主选择两个非训练因素**。R2 若引用"真实环境训练更好"这一机制论断，
须标注该因果归因未被隔离。

**(5) 可直接复用的一条程序资产：pass@10 参数知识污染筛除。**
对基座模型每题采样 10 次（prompt 见附录），凡有任一次答对即剔除该题。
→ R2 的 A1（gold-entity ceiling）/ A1′（gold-evidence 受限诊断）/ no-evidence 臂差分，
全都要求"外部知识确实必要"；否则参数知识会把差分吃平（这与记忆中"information-boundary over-reach"
教训同向）。本篇给出了一个成本可控、训练自由下即可执行的标准做法，
建议写入 R2 §6 的数据构造条款或 §9 待办。

**(6) DeepResearcher 的组织轴状态与 R2 批评 Omni-DeepSearch/AudioRAG 的形态完全同型。**
无快照、无文档 ID 落盘、无 provenance、无可复放轨迹；唯一"记忆"是 browsing agent 的
per-query 短期记忆（用完即弃）；依赖 7 天搜索缓存控成本 = 自认结果随时间漂移。
→ 对 R2 §3.3 的措辞含义同 A-MEM 条目的第 (6) 点：**"直连 live web 导致组织层断掉可复现性"
是 T1 型 agentic 深搜的跨域共性，不是语音域独有**。
