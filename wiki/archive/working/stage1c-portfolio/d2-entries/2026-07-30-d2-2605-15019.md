## 1. 方法本质

以"先检测、再匹配、后生成"三段式，把**视觉元素（element）提升为一等检索单元**，替代主流多模态 RAG
的整图/整场景/整页粒度。给定查询图 `I` 与候选元素集 `E`：(1) 用**冻结的开放词表检测器** YOLO-World-XL
产候选框，按 80% 重叠阈值去冗（保留较小框以留细粒度）；(2) 每个裁剪框 `b_k` 连同**全部**元素外观描述
`{a_e}` 一起塞进 MLLM 提示词，由 MLLM 判"这个框对应哪个元素或 ∅"，得到可见元素子集 `Ê(I)`；
(3) 只为 `Ê(I)` 里的元素取其专家撰写描述 `d_e`，前置景点全局元数据 `m`，拼成层次证据
`C(I) = [m] ⊕ [(e_i, d_{e_i})]`，在"只描述 Ê(I) 中已确认元素"的约束提示 `Ω` 下作答。
配套自建基准 GranuVistaVQA（澳门建筑遗产，中文描述），核心设计是**部分可见性**：单张图平均只覆盖该景点
元素清单的 34%，并提供人工核验的元素可见性标签，使"检测失败 / 检索错误 / 生成幻觉"可分层归因。
**组织与检索层全程冻结、无训练**；训练只出现在可选的一条支线（把本管线的推理轨迹蒸馏进 Qwen3-VL-8B 的 LoRA）。

## 2. key-value 定位（R2 空位断言相关）

### 2.1 语料 schema 只有两级、但只有一级真正带 key

`x_landmark = (meta, E, ED, I^rep)`（附录 A.4.1）；图级 `z = (I, a(I), E^gt(I))`。JSON 只有五个字段：
`Landmarks / Summary / Style / Elements / ElementDescriptions`。**value 侧的两级是真的**：
景点级 `meta`（名称+摘要+风格）与元素级 `ED[e]`（段落）。

### 2.2 两层 key 的构建机制**互不同构**，且只有元素层在被评估的管线里真正运行

| 层 | key 的物理形态 | 构建 | 匹配机制 | 在主实验里是否运行 |
|---|---|---|---|---|
| 景点/场景层 | 整图 CLIP ViT-L/14 向量，L2 归一化到 512 维 | 数据集构建期 Stage 4，FAISS flat-L2 索引，向量 ID→景点名/图路径/GT 元素集 | 稠密向量最近邻 | **否**。§4 方法把 `E` 当**输入给定**（"given a query image I and candidate element set E"），全文无景点检索准确率、无 recall@k；附录只说该索引"enabling source attribution during retrieval" |
| 元素层 | 元素的**外观描述文本** `a_e`（形状/材质/风格属性） | 语料构建期 LLM 生成+人工校验 | **无索引**：把该景点全部 `(e, a_e)` 一次性写进 MLLM 提示词，让 MLLM 穷举比对裁剪框 | 是（唯一真正被消融和评估的层） |

**要点一（对 R2 关键）**：元素层不是向量检索，是**提示词内穷举比对**。之所以可行，是因为
Table 2 的规模极小——221 个唯一元素 / 71 个景点 / **平均每景点仅 3.59 个元素**，34% 覆盖率即平均每图约
1.2 个可见元素。因此 §6.2 那条"MLLM 语义匹配优于 embedding 相似度"的结论是在
**候选池 ≈ 3.6 的量级上**取得的，向 R2 的 O2（万级 passage 池 + ANN）迁移**不成立**，必须降级为"小候选池上的
in-context rerank 优于 top-1 embedding"。

**要点二（"同一 value 多面 key"的弱实例，须显著标出但不足以推翻 R2 空位断言）**：
论文在**符号上**把检索键与被检值分成两个不同的面——§4.2 用**外观面** `a_e`（"visual attributes such as
shape, material, and stylistic features"）作为匹配键，§4.3 取**知识面** `d_e`（"historical background,
symbolic meaning, and architectural significance"）作为返回值。这是"为同一实体造一个专用检索面
key、指向另一面的 value"的设计意图。**但它没有被物化**：JSON schema 只有一个 `ElementDescriptions`
字段，附录 A.4.5 明确说这一个字段同时包含 "visual characteristics, cultural significance, and historical
context"。也就是说 `a_e` 与 `d_e` 极可能是同一段文本（或其人为切分），论文既未给出两字段的分开生成/存储，
也未做"只用外观面 key vs 用全文 key"的对照。**判定：这是一个未物化的单面 key 系统，不构成"同一 value
多面 key"的既有占据。**

**要点三（query→层/面的路由：不存在）**：全流程无路由决策。查询侧唯一的"选择"是检测器给出哪些框；
框到元素是 MLLM 的分类，不是"query 选面"。景点层与元素层的证据是**无条件拼接**（`[m] ⊕ [...]`），
不是按 query 选层。**R2 O2 的"query 按槽型路由"在本篇里无可借的机制。**

## 4. DFS 四问

**方法**：detect-then-match-then-generate。冻结开放词表检测器出框 → 框与元素外观描述在 MLLM
提示词内穷举比对 → 只对确认元素取专家段落、前置景点元数据 → 归因约束生成。检索层无向量索引、无训练；
可选 SFT 支线把该管线的推理轨迹蒸馏进 8B 模型。

**局限**：(a) 规模极小——平均每景点 3.59 个元素、每图约 1.2 个可见元素，"多粒度检索"实际是在个位数候选上
分类，无法说明索引规模下的行为；(b) 景点层 key（CLIP+FAISS）在被评估的管线中不运行，`E` 是给定的，
等于**默认了一次 oracle 场景定位**，两层 key 的故事只兑现了一半；(c) 跨表数字不自洽（要点 3.3），
Table 10 有算术不可能格，Table 7 分母对不上；(d) 头条增益 29.2 与单一超参摆幅 18.7、换检测器摆幅 11.75
同量级，未见独立验证集与随机种子/CI；(e) 单域（澳门建筑遗产）、中文语料，OOD 只在同域跨景点意义上定义。

**改进空间**：把 `a_e`（外观面）与 `d_e`（知识面）**真的拆成两个字段**并分别索引，即可把本篇的符号意图
物化成"同一 value 两面 key"；把景点层 CLIP 索引接回主管线并报 recall@k，两层 key 才成立；把元素层
从提示词穷举换成"ANN 粗筛 + MLLM 精排"，才有规模化路径。

**可借鉴（对 R2）**：(1) **可见性标签 → 分层归因**的评测骨架：把"该检的没检到 / 检错了 / 生成没依据"
三类失败分开测，是 R2 检索层 K5-r 读数可以直接照搬的报告结构；(2) **AP / AR / UCR 三指标**定义
（AP=被引元素落在 `Ê(I)` 的比例、AR=`Ê(I)` 被引用的比例、UCR=无元素支撑的输出句比例）——
纯离线可算、不需 gold answer，适合 R2 的审计面；(3) **gold-evidence 上界臂 + noisy-all 臂 + 管线臂**
三臂对照（Table 4）与 R2 的四臂协议同构；(4) 一条**负面教训**：单个去冗阈值就能吃掉 2/3 的头条增益，
R2 的 O 臂必须预注册超参并报敏感性，否则读数不可信。

### 深读后新增、R2 应该知道的事实

1. **R2 O2 的"query 按槽型路由"在本篇无可借机制**——全流程零路由，两级证据无条件拼接。
   借路由机制只能去 2605.16481。
2. **"MLLM 匹配优于 embedding 匹配 +15.85 LLM 分"（Table 6）不可直接迁移到 O2**：
   候选池只有 ~3.6 个元素，且该表数字与其他三表自相矛盾。若 R2 想用这条支持"稠密 key 不够、要 rerank"，
   必须同时声明候选池规模差三个数量级。
3. **本篇的组织层是训练自由的**（冻结 YOLO-World + 冻结 MLLM 提示词），只有可选的 LoRA SFT 支线
   动了权重。这对 R2 是**正向证据**：视觉域最新的"多粒度组织"本身不需要训练，
   与 TFRL 北极星相容；但其最佳数字（Qwen3-VL-8B† 35.74 ROUGE-L）确实来自 SFT，引用时须分开报。
4. **一个未物化的"多面 key"意图**：`a_e`（外观面，作 key）与 `d_e`（知识面，作 value）在符号上分离、
   在 schema 上合并。R2 §3.4 的 O2 若被质疑"多面 key 是不是已有人做"，本篇可作为
   **"有意图、未物化、未对照"**的最近先例引用——它把 R2 的贡献边界说得更清楚，而不是削弱它。
