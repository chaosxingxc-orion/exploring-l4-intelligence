## 2. 任务套件：s-AQA / m-AQA / r-AQA

### 2.1 三子任务的官方定义（Abstract，p.1，逐字）

> "We define three sub-tasks: (i) Single Audio Question Answering (s-AQA), where questions are answered based on a single audio sample, (ii) Multi-Audio Question Answering (m-AQA), which requires reasoning over multiple audio samples, and (iii) Retrieval-Augmented Audio Question Answering (r-AQA), which involves retrieving relevant audio to answer the question."

§I（p.1）给出更细的分层，并**自述难度序**：

> "(ii) Multi audio question answering (m-AQA): where a question has to be answered from the context of multiple audios; **this setting is in fact more challenging than the s-AQA setting** as in this setting to answer a question, the model has to reason over knowledge associated with named entity mentions across multiple audios. (iii) Retrieval-augmented audio question answering (r-AQA): **this is the most challenging task of all.** In this setting, a question must be answered using a set of audio clips, where only a few are relevant to the question. To generate a correct answer, the model must retrieve the relevant audios from the pool and reason over the entities across these retrieved clips."

**须记入的第一处内部矛盾**：上述 §I 的难度序（s-AQA < m-AQA < r-AQA）**被 §V 的实测叙述反转**。
§V（p.4）逐字：

> "**s-AQA, which requires open-ended answers, is the most challenging**, highlighting the importance of external knowledge provided by KA²LM. **m-AQA and r-AQA with finite answers, are simpler.**"

即**设计时宣称的难度序与实测报告的难度序相反**，论文未处置这一冲突。
本件判定：难度序之所以反转，是因为**难度被答案空间形状而非知识跳数决定**——
s-AQA 开放式（1039 个唯一答案）、m-AQA 二元、r-AQA 计数。这一点直接决定 §6 的指标可用性结论。

### 2.2 "知识密集"的构造性定义（这是本篇最承重的构造事实）

§I（p.1）给出概念定义：

> "However, these approaches overlook a critical real-world scenario: answering questions about named entities in the audio, which requires **reasoning beyond the audio content and drawing on external world knowledge**. We refer to this challenge as `Audiopedia: Audio Question Answering with Knowledge', and such questions as **knowledge-intensive questions**."

> "To accurately answer a knowledge-intensive question such as `In which country was the mentioned restaurant founded?', a system has to understand and reason over the knowledge associated with the mentioned named entity `KFC' from an external knowledge base. While a similar setting has been extensively studied in vision-language research, **it remains unexplored in the audio domain**."

**但"知识密集"在数据层是被一条构造规则强制出来的，而不是自然产生的**。§III-A（p.2）s-AQA 逐字：

> "Here, we sample triplets with same subject entity and frame an input sentence from these triplets **except one triplet which shall be used to frame the question**. Question is framed from this excluded triplet of form (subject, relation, object), e.g., for an excluded triplet < *Subway*, *established in*, *1965* >, we frame a question *Q: When was Subway established in?*, with the answer being the object in the triplet, *A: 1965* in this case. Input sentence is framed using different triplets with same subject entity, for the above example, we chose the triplet < *Subway*, *serves*, *salad and sandwich* > for creating the input sentence *i/p: Subway serves salad and sandwich*."

**逐条拆解（这五条是 R2 读本篇时必须先装上的镜片）**：

1. **音频里只剩一件事：实体提及**。承载答案的三元组被**从口语句中显式剔除**，音频里保留的是同主语的另一条三元组。
   因此"音频不足以回答"**不是观察到的现象，是构造保证**。
2. **音频的信息量下界与上界都极窄**：一句由三元组拼出的模板句（如 "Subway serves salad and sandwich"）。
   音频侧的全部任务塌缩为**把实体名听对**；不存在声学事件、说话人、韵律、时长、重叠等任何非词汇信息。
3. **答案三元组仍在同一实体的知识集合内**。§IV-A（p.3）明文 "knowledge associated with each entity is **a set of triplets**"，
   而 KA²LM 注入的是链接实体的知识 `K_l`。**论文全篇未说明是否从 `K_l` 中剔除问题三元组**；
   由 §5.1 的 oracle 行（LTU-AS s-AQA **76.2** vs 无知识 **3.9**）反推，`K_l` **几乎必然逐字包含答案**。
   **标为推断（`INFERENCE_HIGH_CONFIDENCE`，需代码/数据验证）**，但它是本篇全部数字的解释前提，见 §6 与 §8.3。
4. **音频是 TTS 合成的**。§III-A：> "Input sentence is converted to audio using the text-to-speech model **Tachotron 2**~\cite{shen2018natural}."
   （**"Tachotron" 为论文原文拼写，Tacotron 2 的笔误，照录**。）→ **全库零真实录音、零真实说话人、零真实声学条件**。
5. **训练/开发划分不存在**。§I 自述 > "we present a *derived* **synthetic evaluation datasets**"，
   §V 自述 > "All experiments are conducted in a **zero-shot setting with no fine-tuning**." → **纯评测集，无 split**。

### 2.3 m-AQA / r-AQA 的构造（§III-A，p.2–3，逐字）

**m-AQA**：

> "In this task, input consists of two audios, hence, we chose two triplets with different subject entities. For this task, we consider binary answers `Yes' and `No'. For `Yes' answer questions, we sample two triplets with **same (relation, object) but with different subject entities**, e.g., consider two triplets < *Subway*, *established in*, *1965* > and < *Arby's*, *established in*, *1964* >, we frame a question as follows: *Q: Are these restaurants established in the same decade?*, with answer being *A: Yes*. Similarly, for `No' answer questions, we sample two triplets with **same relation but with different (subject, object) entities**…"

**须记入的构造缺陷（本件新发现，论文未讨论）**：`Yes` 支的采样条件是 "same (relation, object)"，
但示例给出的两条三元组 object 分别是 **1965** 与 **1964**（**不同**），问题问的是 "same **decade**"。
即 `Yes` 支实际采样的是 **object 落入同一粗粒度桶**（十年）而非 object 相同；**采样规则的书面表述与示例不自洽**。
后果：`Yes`/`No` 两支的**语义难度不对称**（`Yes` 支需要一步数值粗化推理，`No` 支只需字面比对），
而 m-AQA 只有 500 样本、二元答案，**该不对称无法从公开数字中分离**。

**r-AQA**：

> "In this task, input consists of $n$ audios where only few audio samples are relevant to answer the question where as the other audio samples are irrelevant. For positive audio samples, collection is similar to m-AQA. For negative audio samples, we sample **entirely different triplets with different (subject, relation, object)s** to frame negative sentences…"

→ 干扰项是**完全无关的三元组**，不是**近邻/难负例**。结合 §3.3 的固定阈值 `t = 0.25`，
本载体的检索难度**在构造上被设定为低**（正负样本在文本嵌入空间中天然远离）。

| 子任务 | #Samples | Answer type | 其他 |
|---|---|---|---|
| **s-AQA** | **14702** | Open-ended | #Unique answers **1039** |
| **m-AQA** | **500** | Binary | — |

3. **r-AQA 每题音频池** ≈ 2.2 + 8.3 = **10.5 条**，正例占比约 **21%**。

### 2.5 知识库：TextKVQA business-KB（其自身构建自 Wikidata）

§III-A 首句（p.2，逐字）：

> "We leverage the knowledge base (KB) provided by the authors of~\cite{singh2019strings}, specifically we use **business-KB** provided here\footnote{https://textkvqa.github.io} to curate the data for all our three tasks. **This KB which is constructed from Wikidata**, where each knowledge fact is a triplet connecting two entities with a relation. An example of these triplets is: *Subway, established in, 1965*."

**逐条核定（对"which knowledge base? Wikidata?"这一问的准确回答）**：

- **直接使用的 KB = TextKVQA 的 business-KB**，来自 Singh et al., *From strings to things: Knowledge-enabled VQA model that can read and reason*, **ICCV 2019**（`refs.bib` 第 239–244 行）。
  即**一个 2019 年发布的、视觉 QA 领域的成品 KB**。
- **Wikidata 是该 KB 的上游来源，不是本篇的直接接口**。论文的表述是 "This KB **which is constructed from** Wikidata"——
  **本篇不查询 Wikidata、不做实体消歧、不涉任何在线 KB 服务**。
- **KB 规模全篇未报**：§IV-A 只写 "External knowledge base consists of **$n$ named entities**"，
  **`n` 从未取值**；三元组总数、关系类型数、每实体平均三元组数**均未报**。
  → **本篇无法回答"检索池有多大"**，而这是任何检索/链接方法难度的第一决定量。**登记为可复现性缺口。**
- **KB 是静态单快照**：无版本、无时间戳、无更新机制、无冲突或过期条目。→ 与 §8.3 的 stale 面直接相关。
- **同一 KB 既是出题源也是答题源**：数据构造（§III-A）与推理期知识注入（§IV-A/B）用的是**同一份 business-KB**。
  **答案按构造必在检索池内**——不存在"KB 里没有答案"的样本，也不存在 unanswerable 支。

## 3. Audio Entity Linking（AEL）

### 3.1 机制全文（§IV-A，p.3，逐字）

> "AEL refers to the task of identifying the mentioned named entities in the given audio and link them to their associated knowledge in an external knowledge base. External knowledge base consists of $n$ named entities $\{N_1, N_2, .., N_n\}$ along with their associated knowledge $\{K_1,K_2, .., K_n\}$. Since, knowledge associated with each entity is a set of triplets, **we first frame sentences out of these triplets by simply concatenating subject, relation and object for every entity.** Next, we encode the associated knowledge $K_i$, where $i \in \{1,2,..,n\}$ **using a text encoder**, to obtain knowledge embeddings $E_T^{\{1,2,..n\}}$. Given an audio $A$, the task is to identify and link the mentioned in to one of the named entities in the knowledge base. **We first transcribe the audio using wav2vec 2.0**~\cite{baevski2020wav2vec2} **and encode the transcribed text** to obtain the embedding $A_T$. We then compute the **cosine similarity** of $A_T$ with each of $E_T^{\{1,2,..n\}}$, and **choose the knowledge corresponding to the highest similar entity $K_l$** as the linked knowledge."

Fig. 2 题注（p.3）：> "(d) AEL method: **We pose the audio entity linking as a ranking problem.**"

### 3.2 机制拆解：实体是从**语音的 ASR 转写**链接的，不是从音频事件链接的

**这一问的答案是明确且单一的**：

| 环节 | 实现 | 输入 | 输出 |
|---|---|---|---|
| ① 语音转文本 | **wav2vec 2.0** | 音频 `A` | 转写文本 |
| ② 转写编码 | 文本编码器（见 §3.3） | 转写文本 | `A_T` |
| ③ 知识线性化 | 字符串拼接 `subject+relation+object` | 每实体的三元组集 | 知识句 |
| ④ 知识编码 | **同一文本编码器** | 知识句 | `E_T^{1..n}` |
| ⑤ 链接 | **余弦相似度 + top-1 argmax** | `A_T`、`E_T^{1..n}` | `K_l` |

**三条判定**：

1. **链接完全走语音（speech）通道，与音频事件（audio events）无关**。管线里没有任何声学事件分类器、
   AudioSet 标签、声音场景识别；音频经 wav2vec 2.0 后**即刻塌缩为文本**，此后全部计算在文本空间。
   → 本篇的 "audio" 在 AEL 侧**严格等价于 "speech transcript"**。配合 §2.2 的 TTS 合成模板句，
   **AEL 的实际难度 = 干净合成语音上的实体名 ASR 准确度**。
2. **不做实体识别（NER），直接做整句到整实体的检索**。名为 "identifying ... named entities"，
   实现上**没有 mention detection 步骤**：整条转写被编码成一个向量，与 `n` 个实体的知识向量比相似度。
   → 这是**单实体假设的必然结果**（论文 Limitations 第 (i) 条自认，见 §5.6），
   也解释了为什么 m-AQA 要"对每条音频分别做 AEL"而非在一条音频内抽多个实体。
3. **相似度是"转写 ↔ 整段知识句"的比对，不是"转写 ↔ 实体名"的比对**（默认设置下）。
   TABLE V 的三个"knowledge source"设置正是在改这个被编码的对象（entity-name / 20% / full），见 §5.3。

### 3.3 训练成分：**零**（承重，且文本编码器身份只在图形层给出）

**全篇没有任何被训练或微调的组件**。逐条盘点：

- **wav2vec 2.0**：现成预训练模型，**变体/尺寸/是否带 LM 解码全未报**（`refs.bib` 只引 NeurIPS 2020 原文）。论文未报任何 WER。
- **文本编码器**：**正文三处只写 "a text encoder" / "the same text encoder"（§IV-A 一处、§IV-E 两处），从不点名。**
  其身份**只出现在 Fig. 2 的内嵌图例中**（`images/icassp_main.pdf` 文本层，p.3），逐字：
  > "**Enc. - CLIP (Radford et al.)**"
  同一图例还给出 > "ASR - Automatic Speech Recognition"、> "KB - Knowledge Base"、
  > "Similarity **(top-1)**"、> "T: Audio ground truth transcript for **understanding purpose (not an input to the model)**"。
- **LALM**：冻结（§5，"no fine-tuning whatsoever"）。

**由 CLIP 文本编码器身份派生的一条技术后果（标为本件推断，论文未讨论）**：
CLIP 的文本塔上下文长度为 77 token。若默认设置下被编码的是"某实体全部三元组拼接成的知识句"，
则**长实体的知识在编码时会被截断**，`E_T^i` 只反映其前若干条三元组。
这与 TABLE V 中 "20% knowledge (58) 仅比 Full knowledge (63.9) 低 5.9 pp、且 r-AQA 上两者持平（均 68）"
的读数**方向自洽**——**若全量知识大部分被截掉，"全量"与"两成"自然差距有限**。
**标为 `INFERENCE_NEEDS_CODE_VERIFICATION`**，是有网络时须优先核的三项之一（§9）。

### 3.4 r-AQA 的检索器：同一编码器 + **固定阈值 t = 0.25**

§IV-E（p.4，逐字）：

> "Firstly, we perform retrieval, as follows: we obtain **ASR-ed text** of all the samples and encode them using **a text encoder** to obtain their embeddings $A_T^{i}$… Similarly, we obtain the question embedding $Q_T$ using **the same text encoder**. Next, we compute cosine similarity for $Q_T$ with every $A_T^{i}$, and **pick those samples with similarity scores greater than the threshold** as the retrieved samples."

**阈值取值正文未给**；Fig. 2 (c) 图例逐字：> "Criterion: **Threshold (t = 0.25)**"。

**三条判定**：
- 阈值**全局定值、未经调参说明、无敏感性分析**；`t` 的选择依据全篇未述。
- 检索比的是**问题 ↔ 音频转写**，**不经 KB**——即 r-AQA 的检索阶段与知识无关，纯粹是"哪些音频与问句相关"。
- `main.tex` 第 283 行存在一段被注释掉的备选判据：
  > `% Criteria (ii): Top-k based retrieval, here we pick top-k scores and their corresponding samples.`
  → **top-k 方案被写过又删除，最终版只保留固定阈值，且未报两者对比。**（仅 eprint 源可见。）

## 4. KA²LM（Knowledge-Augmented Audio Large Multimodal Model）

### 4.1 全文（§IV-B，p.3，逐字——本节是全篇对该"模型"的完整描述）

> "We propose a generic framework (KA²LM) that can be easily integrated into any LALM. Given an audio input $A$ and a knowledge-intensive question $Q$, our framework **enhances the standard LALM prompt**. Typically, an LALM would process $Q$ within an instruction prompt alongside audio $A$ to generate an answer. **Our approach infuses the instruction prompt with knowledge $K_l$, obtained through AEL of the given audio $A$. This enhanced prompt is then fed into the LALM**, enabling it to generate an accurate final answer $a$, leveraging the augmented additional knowledge."

**这是 §IV-B 的全部内容——共 4 句、无公式、无超参、无提示词模板。**

### 4.2 架构判定

**KA²LM 不是一个模型，是一次提示词字符串拼接。**"Knowledge-Augmented Audio Large Multimodal Model" 这一命名
（`\newcommand{\model}{KA$^2$LM}`，展开自 §I 的下划线首字母 <u>K</u>nowledge-<u>A</u>ugmented <u>A</u>udio <u>L</u>arge <u>M</u>ultimodal model）
在架构层**没有对应的新增参数、新增模块或新增前向路径**。逐子任务的组装式：

| 子任务 | 送入 LALM 的内容（§IV-C/D/E 逐字） |
|---|---|
| **s-AQA** | > "we perform AEL on the audio $A$ to obtain the linked knowledge $K_l$; and then we feed it **along with $Q$ and $A$**" |
| **m-AQA** | > "we perform AEL for the input audios and obtain the linked knowledge $K_l^{i}$ for every $i$; and **concatenate $K_l^{i}$ to obtain $K_l$**. Then, we feed $K_l$ along with $Q$, and **concatenated audio samples $A$**" |
| **r-AQA** | > "Once retrieved, we perform AQA using **the same methodology as m-AQA**" |

**须记入的四条**：

1. **冻结与训练态**：LALM 全程冻结。§V 逐字 > "All experiments are conducted in a **zero-shot setting with no fine-tuning**."
   （`main.tex` 早期版本的措辞更强：> "there is **no fine-tuning whatsoever**"，见被注释段落第 338 行。）
2. **外部知识的入口是提示词，不是解码器**。没有 logits 干预、没有 beam 内评分、没有 KV 注入、没有适配层。
   → **接口需求仅为"能接收多模态提示并返回文本"**，与解码内部无关。
3. **m-AQA 的音频侧是简单拼接**（"concatenated audio samples"），**知识侧也是简单拼接**（"concatenate $K_l^i$"）。
   无对齐、无标注哪段知识对应哪段音频、无顺序约束。
4. **提示词模板全篇未给**。无温度/采样参数、无最大生成长度、无系统提示、无 few-shot 示例、无随机种子。
   → **本篇的任何数字不可复算**（与 §9 的遗留义务对应）。

### 4.3 谱系：框架直接移植自同一作者的视觉侧工作

§I（p.1）逐字：> "Further, **inspired from~\cite{vistel}**, we propose a generic framework that can enhance any LALM with knowledge reasoning capabilities."

`refs.bib` 第 320–326 行：
> `@inproceedings{vistel, title = "Visual Text Matters: Improving Text-KVQA with Visual Text Entity Knowledge-aware Large Multimodal Assistant", author = "Penamakuri, Abhirama Subramanyam and Mishra, Anand", booktitle = "EMNLP", year = "2024"}`

§II（p.2）另给出实体链接侧的谱系：
> "Further, we propose a framework based on **audio entity linking~\cite{li2024ted}**, which can be used with any modern day audio-based LMMs to solve knowledge-intensive tasks like Audiopedia."

`refs.bib` 第 232–237 行：> `@inproceedings{li2024ted, title={TED-EL: A Corpus for Speech Entity Linking}, ..., booktitle={LREC-COLING 2024}, year={2024}}`

**三节点谱系（R2 若需扩谱系可直接取用）**：
**TextKVQA (ICCV 2019, Singh et al.)** → 提供 KB 与视觉侧知识 QA 范式；
**VisTEL (EMNLP 2024, Penamakuri & Mishra)** → 提供"实体链接 + 知识增强 LMM"的框架原型（视觉文本）；
**TED-EL (LREC-COLING 2024, Li et al.)** → 提供 speech entity linking 的先例语料。
本篇 = **把 VisTEL 的框架从视觉文本域移植到语音域，KB 沿用 TextKVQA**。

### 5.5 度量口径与其脆弱面（§V "Metrics"，p.4，逐字）

> "We use accuracy to evaluate the models. **For AQA, accuracy is 1 if the ground truth answer is present in the generated text, and 0 otherwise.** For AEL in s-AQA and m-AQA, accuracy is 1 if entities are correctly predicted. For r-AQA, which involves retrieval, we use the F1 score."

**四条判定（前两条为论文事实，后两条标为本件分析）**：

1. **AQA 度量是子串包含**，不是精确匹配、不是标准化后匹配、不是 LLM 评审。大小写敏感性、词边界、
   标点归一**全未规定**。
2. **度量的指派存在歧义**：上引句把 F1 归给 "r-AQA, which involves retrieval"，
   而 TABLE V 确实把 r-AQA 列标为 "(F1)"；但 **TABLE IV 的列组表头是 "Accuracy on Audiopedia" 且覆盖 r-AQA 列**。
   → **TABLE IV 的 r-AQA 列到底是 accuracy 还是 F1，本地两件无法判定。登记为口径缺口。**
3. **分析（本件）：二元子任务上的子串匹配有明确假阳性面**。m-AQA 答案为 `Yes`/`No`；
   在子串口径下，gold=`No` 时任何含 "no"/"not"/"none" 的自由文本都可能命中（若不区分大小写与词边界）。
   → **m-AQA 的绝对水平不可解释**；只有同口径下的行间差可用，且须承认口径本身未定。
4. **分析（本件）：GAMA 的 m-AQA 读数暴露了度量在"格式遵从"上的混淆**。二元任务的随机水平为 **50**；
   GAMA 无知识 m-AQA = **14.8**，**远低于随机**；即便 oracle 也只有 **38.8**，**仍低于随机**。
   一个模型在二元任务上系统性低于随机，在子串口径下只有一种解释：**它大量输出不含 `Yes`/`No` 字面的文本**。
   → **GAMA 那一列上 +20.4 pp 的"知识增益"，其中不可分离的一部分是"提示词变长后模型开始按格式作答"**，
   而非知识起作用。**本条为本件分析，论文未讨论；它直接影响 §8 的差异面判读。**

(ii) It is assumed that **all mentioned entities are in English**, which may not hold true in practical settings. (iii) As a **curated synthetic dataset**, we have manually quantified that **a small fraction of samples (less than 5%) contain noise**."

## 7. DFS 四问

### 7.1 方法

**一句话**：把视觉侧成熟的"实体链接 + 知识增强多模态助手"范式（VisTEL, EMNLP 2024）**整体移植到语音域**，
并为此**自建一个派生合成基准**——用 TextKVQA 的 business-KB 三元组造题、
把非答案三元组用 Tacotron 2 读成音频、把答案三元组留作问题；
推理时用 wav2vec 2.0 转写 + CLIP 文本编码器做**整句到整实体的 top-1 余弦检索**取回该实体的知识，
再把知识**字符串拼进冻结 LALM 的指令提示词**。

**核心科学主张只有一句**：> "Despite extensive multimodal pretraining, these LALMs **struggle with knowledge-intensive tasks**"，
且 > "**Even in this ideal scenario** [oracle 链接], **LALMs fall short**."

**方法本身的三条特征**：零训练、单遍前馈、无条件注入。

### 7.2 局限

**论文自认三条**（§5.6 逐字）：单实体假设、纯英文实体、<5% 样本含噪。

**本件补记九条（论文未列）**：

1. **音频完全合成、且信息量被构造压到最低**。TTS 模板句、单实体、无声学事件、无真实说话人/信道。
   → "audio understanding" 在本载体上**退化为干净合成语音的实体名 ASR**。
2. **出题与答题同一 KB，答案按构造在检索池内**，且几乎必然逐字进入被注入的 `K_l`（推断）。
   → 本载体上**不存在"KB 没有答案"的样本**，也不存在 unanswerable / 冲突 / 过期支。
3. **无外部对手方法**。三条"基线"全是同模型消融；无检索基线、无其他知识增强方法、无跨基准对照。
4. **无统计检验、无方差、无种子、无多次运行**。所有数字均为单次读数。
5. **r-AQA 样本量 115**，逐格分辨率约 0.87 pp；其上多处 1–2 pp 的差异**处于单样本量级**。
6. **三处表-文一致性缺陷**（§5.4 缺陷 A/B/C：引表引反、TABLE VI `-` 行数值属 GAMA、正文把 oracle 报成方法值）。
7. **关键实现细节缺失**：KB 规模 `n` 未取值、提示词模板未给、wav2vec 2.0 与 CLIP 变体未指定、
   `t=0.25` 无调参说明、LALM 解码参数未报；文本编码器身份**只在图例中出现且其引用未进参考文献表**（§3.3）。
8. **度量为子串包含**，在二元子任务上存在明确假阳性面；且 TABLE IV 的 r-AQA 列究竟是 Acc 还是 F1 无法判定（§5.5）。
9. **m-AQA `Yes` 支的采样规则与其示例不自洽**（"same (relation, object)" vs 1965/1964 的 "same decade"），
   造成 Yes/No 两支难度不对称且不可分离（§2.3）。

### 7.3 改进空间

按对 R2 的价值排序：

- **(a) 把"是否注入"变成逐样本决策**。本篇是全局无条件注入，且 TABLE IV 的 `✗/✗` 行已是**现成的不注入参照臂**——
  门控的实验位在本载体上**是空的**，且参照臂已由论文提供。
- **(b) 引入证据准入**。链接相似度、top-1/top-2 间隔、知识与转写的回验，均可作准入信号；
  本篇的 oracle 行给出的是"完美证据的上界"，**"坏证据被挡住"这一档从不存在**。
- **(c) 构造真伪/时效对照支**。当前 KB 是静态单快照、答案必在池内；
  加入 swapped（换成另一实体的知识）、stale（换成过期取值）、absent（KB 无此实体）三支，
  即可把"注入有没有用"升级为"注入对不对得起被信任"。
- **(d) 换掉合成语音与模板句**。真实录音、多实体共现、口音与噪声、自发口语——
  本篇的单实体假设与纯 TTS 是其作者自列的第一/第三条局限，改造路径明确。
- **(e) 让音频参与知识利用之后的过程**。当前音频在 AEL 之后**再无作用于知识侧**；
  知识到位后回听音频以消歧（例如同名实体、口音导致的转写歧义）在本载体上无先例。
- **(f) 换文本编码器并检验截断假说**。若 CLIP 77-token 上限确实截断了长实体知识（§3.3 推断），
  换成长上下文文本编码器即可能显著改变 TABLE V 的三档关系。**低成本、高信息量的一次性检验。**
- **(g) 补齐同期强 LALM**。Qwen-Audio 系、SALMONN 等 2024 年可得模型未纳入；
  §5.2 已显示三个模型的 `✗/✗` 地板差异巨大（0.06 / 0.09 / 3.9），**地板位置直接决定"增益"的量级**。

### 7.4 可借鉴

1. **"派生式知识密集基准"的构造配方本身可移植**：从一个 (subject, relation, object) KB 出发，
   **把一条三元组留作问题、其余三元组读成音频**，即可在任何 KB 与任何 TTS 上批量造出
   "音频给实体、KB 给答案"的样本。**其代价与收益都很清楚**：零标注成本、答案唯一可判、
   但同时带来纯合成语音与"答案必在池内"两条硬约束。R2 若需要**廉价的诊断性载体**（非承重载体），此配方可直接复用。
2. **三层臂结构（无知识 / 方法 / GT-oracle）在语音知识 QA 上的现成模板**：
   本篇每个模型都给了这三行，且 oracle 定义干净（"assuming 100% accurate entity linking"）。
   与读集内 ConEC 的五臂阶梯相比，本篇**少了"读出臂"与"净负臂"两级**，但**多了"跨三个不同模型重复整组臂"**这一维度
   ——后者恰好证明了 §5.2 的结论 1（地板位置决定增益量级），是设计多模型对照时值得照搬的做法。
3. **"oracle 仍远未饱和"作为问题未解的论证方式**：论文用 > "Even in this ideal scenario, LALMs fall short"
   把 oracle 从"上界"用成了"问题难度的证据"。这是一个**低成本、高说服力的论证形状**，
   在 headroom 充裕时（如本篇 s-AQA 的 22.8 / 51.1 / 76.2）比报增益更有力。
4. **跨模态范式移植时把上游节点写清楚**：本篇把 VisTEL（视觉侧框架来源）、TextKVQA（KB 来源）、
   TED-EL（语音实体链接先例）三个节点分别在 §I / §III-A / §II 点名，**谱系可直接被下游复用**。

### 8.1 冻结黑盒 omni 核？

**本篇的实际配置**：

- **冻结**：是。> "All experiments are conducted in a zero-shot setting with no fine-tuning."（§V, p.4）
- **黑盒程度**：机制只写提示词、只读文本输出，**不触碰 logits/beam/KV/中间层**（§IV-B 全文, p.3）。
  → 就 LALM 而言，**接口需求与黑盒调用相容**。
- **但论文从未把黑盒或 API-only 作为约束陈述、也未在任何 API 模型上验证**；
  三个被测模型（Audio Flamingo、GAMA、LTU-AS）均为开放权重模型，本地运行。
- **模态范围**：三者均为 **audio-language**（音频+文本）模型，**非 omni**——本篇不涉视觉，
  Fig. 1/2 中的图像仅为论文插图，不是模型输入。
- **管线内另有两个非 LALM 的本地模型**（wav2vec 2.0、CLIP 文本塔）与一份 KB 嵌入索引，
  它们不是黑盒调用的一部分而是自建组件。

**时间线相关的一条**：本篇被测的三个 LALM 均为 2023–2024 年模型；**当时 omni（音频+视觉+文本）核尚未进入其对照面。**

### 8.2 逐样本双源选择（重听 vs 外部检索）？

**本篇的实际配置**：**不存在任何形式的双源选择。**

- **两条信息通道都存在，但都是无条件、固定顺序的**：
  音频 → wav2vec 2.0 转写（内源，用于定位实体）；转写 → KB top-1 检索（外源，用于取答案知识）。
  二者**串联而非并列**：外源检索的**查询就是内源转写**，所以它们不是可相互替代的两个选项，
  而是同一条流水线上的前后两级。
- **无逐样本决策点**：没有"这一条要不要查 KB"、"这一条重听一遍是否更划算"、
  "两个来源给出冲突答案时信谁"的任何判定。§IV-A/B 的描述是无分支的直线流程。
- **无重听**：音频在 AEL 之后不再被用于知识侧的任何计算（LALM 虽仍收到音频，但那是它的常规输入，
  不是由知识状态触发的二次访问）。**无迭代、无回路、无条件触发**（§6 audio revisit 行）。
- **r-AQA 的 `t = 0.25` 是唯一的选择性动作，但其选择对象是"哪些音频进入下游"，不是"用哪个信息源"**，
  且为**全局定值阈值**，非逐样本自适应（Fig. 2 (c) 图例, p.3）。

### 8.3 证据准入：true / swapped / stale 的处置？

**本篇的实际配置**：**三类条件在本载体上均不存在，准入机制亦不存在。**

## 10. 深读后新增的、R2 应该知道的事实

1. **本篇的"知识密集"是构造出来的，不是观察到的**：承载答案的三元组被显式从口语句中剔除，
   音频里只留同主语的另一条三元组（§2.2）。因此"音频不足以回答"是**构造保证**，
   而非该载体的自然属性。任何以本篇为据的"音频不够、必须外求知识"陈述，都须带上这一构造前提。

2. **出题与答题同一 KB，答案按构造在检索池内**，且几乎必然逐字进入被注入的知识串
   （据 LTU-AS s-AQA oracle **76.2** vs 无知识 **3.9** 反推，标为推断）。
   → 本载体上"注入知识"与"把答案放进提示词"**在信息性质上高度接近**；
   s-AQA 的 +50.8 pp 主要度量的是模型能否把提示词里已有的答案串取出来。

3. **s-AQA 的无知识地板约等于零（0.09 / 0.06 / 3.9），且三个模型地板位置差 65 倍**。
   在零地板上，绝对增益与相对增益都不度量能力提升；**地板位置本身就决定了"增益"的量级**。
   报效应时必须同时给出地板与 oracle 两端。

4. **oracle 缺口在三个子任务上极不对称**：s-AQA 为 7.5 / 19.7 / **21.5** pp（有空间），
   m-AQA 为 3.2 / 3.6 / **0.8** pp、r-AQA 为 1.8 / 1.8 / **1.2** pp（**结合 500 与 115 的样本量，已逼近采样噪声**）。
   → **本载体上只有 s-AQA 是活指标**；m-AQA / r-AQA 上的任何行间比较都不承重。

5. **GAMA 在二元 m-AQA 上系统性低于随机（无知识 14.8、oracle 38.8，随机为 50）**。
   在"生成文本包含 gold 即算对"的子串口径下，这只能解释为**大量输出不含 `Yes`/`No` 字面**。
   → **该列上的"知识增益"里混有不可分离的"格式遵从增益"**。这是本件分析，论文未讨论，
   但它对任何"注入外部知识带来 X pp 提升"的跨篇比较都是直接威胁。

6. **本篇存在三处表-文一致性缺陷，且在 LaTeX 源与 PDF 渲染两条通道同时确认**：
   引表引反（49.3/54.7 在 TABLE VI 却写 Table V）、TABLE VI 的 `-` 行取了 GAMA 的 0.06 而非 LTU-AS 的 3.9、
   正文把 oracle 的 21.5 报成了方法的 r-AQA 值（实为 20.3）。
   → **引用本篇任何单一数字前必须声明表号与行号；不得引用 §V 正文中的行内数字。**

7. **文本编码器（CLIP）的身份只存在于图 2 的内嵌图例，其引用条目在 `refs.bib` 中存在但从未被 `\cite`，
   故未进入 35 条参考文献表**。这是**只有 eprint 源 + 图形文本层才能核到的事实**；
   引用时须写明出处为图例。由此派生的 77-token 截断假说（§3.3）是最低成本的一次性可证伪检验。

8. **`r-AQA` 的 top-k 检索方案在源中被写过又注释掉**，最终版只保留固定阈值 `t = 0.25`（`main.tex` 第 283 行），
   两者对比从未报告。**同类源层痕迹另有一处**：TABLE V 的同批数字在早期被注释的版本里
   把 m-AQA 标为 **F1**，最终版改标为 **Acc.**（`main.tex` 第 255–271 行）。
   → 度量标签在定稿过程中发生过变更，**m-AQA 列的度量身份须以最终版 "Acc." 为准并声明此变更**。

9. **本篇的管线在训练态与接口态上贴近推理期控制路线，在决策态与信息边界上则相反**：
   冻结 + 零训练 + 提示词层注入（贴近）；无条件触发 + 零准入 + 答案必在池内（相反）。
