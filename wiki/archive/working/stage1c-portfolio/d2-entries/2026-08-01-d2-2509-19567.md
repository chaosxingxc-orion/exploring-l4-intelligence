## 1. 方法本质

本文把「上下文感知 ASR 里的上下文从哪来」这一问题，从**人工/结构化实体目录**改造成
**对一个冻结通用英文词表做嵌入检索**，且整条链**完全在识别器之外**。

**冻结词表 V**：L177 明确 `|V| = 466,358`——"a set of 466,358 unique, non-stop words … is
utilized for context generation using RAG. These words are combined together with their
definitions (if available)."（来源脚注：Kaggle 479k English words 与 NLTK Corpus Words 232k）。
这是一个**通用词典而非领域实体库**，与 PRISM/RECAST/BR-ASR 一路的「实体目录」在种类上不同。

**嵌入与索引**：L144 每个词 $w_i$ 经 $f: \mathcal{V}\rightarrow\mathbb{R}^d$ 编码，
$f$ = **all-MiniLM-L6-v2**，且论文自陈选型理由是模仿 BERTopic——"The MiniLM (all-MiniLM-L6-v2)
is utilized, similarly to BertTopic, where it is employed to encode textual segments and identify
semantically related terms within a topic."（脚注指向 BERTopic 文档）。查询向量
$\mathbf{q}_t = f(\hat{Y}_{t-1})$，即**把前 $k$ 段 ASR 假设文本拼接后整体编码成一个向量**，
论文声称这样能"retriev[e] terms that align with the latent 'spoken topic' of the segment, even
when they are not explicitly mentioned"（L144）。选词为余弦相似度 Top-$N$（L146–150），
最近邻搜索由 **FAISS** 完成（L152，`douze2024faiss`）。该臂记为 `CB-RAG`。

**对比臂 `CB-LLM`**：同一前窗 $\hat{Y}_{t-1}$ 加提示 $P_{gen}$ 喂给 LLM $\mathcal{M}_{gen}$
直接**生成**上下文词（L154–160），输出"post-processed to remove duplicates and stopwords"。
提示原文见附录 L268："You are the master of knowledge, with expertise in every domain. Given a
sentence and based on your knowledge, provide a huge number of relevant words. Focus on names,
locations, terminology, concepts. …"。第三臂 `LLM-fix` 是**后处理纠错**
$\hat{y}_t^{corr} = \mathcal{M}_{fix}(\hat{y}_t, C_t, H_{t-1}, P_{fix})$（L139），
默认 LLM 为 **Llama3.2 (3B)**（L139："without loss of generality"）。

**两个上界/下界参照**：Oracle 上下文 = 参考转写中去停用词的全部词
$C_t^{oracle}=\{w\in y_t \mid w\notin\mathcal S\}$（L164，WER 下界）；No Context
$C_t^{none}=\emptyset$（L167，WER 上界）。**这一对参照是本篇对 R2 最有用的结构**，因为它给出
「上下文发现」这条轴上的**可达上限**（见 §3）。

**「black-box」/「plug-and-play」/「frozen vocabulary」三词均为原文用词，逐字引证**：

- L119（黑盒 + 即插即用，同一句给出）："Earlier context-biasing techniques are deeply integrated
  into the ASR model itself - requiring custom layers, retraining, or access to model internals -
  so **can't be run on the black-box recognizer used in this work**. Consequently, we benchmark
  only **"plug-and-play"** methods in a common pipeline that mirrors real-world deployment
  scenarios (identical audio inputs, metrics, and latency limits)."
- L123（冻结词表）："it introduces a novel, model-agnostic, retrieval-based context construction
  technique using MiniLM embeddings **on top of a frozen vocabulary** to enable efficient context
  generation."
- L125（第三条贡献再述黑盒）："it provides an end-to-end evaluation of all methods in a shared
  pipeline that works **without fine-tuning the ASR model, using black-box models** and real-world
  long-form audio corpora."
- L117（自我定位）："a lightweight, modular approach … an embedding-based retrieval strategy using
  pre-trained MiniLM embeddings over a large vocabulary, **entirely decoupled from the ASR model
  architecture**."

**CB-RAG vs CB-LLM 的实质差别**不是"检索 vs 生成"这么简单，而是**知识来源的封闭性**：
CB-RAG 只能吐出 V 内的词（词表封闭、可审计、可版本冻结），CB-LLM 从模型参数里取世界知识
（开放、不可审计、随模型版本漂移——论文自己在 Limitations L260 承认 "prone to variability
across model versions and decoding parameters"）。两者在本篇被当作**互斥的备选臂**，
**从未被组合，也从未按段落做过来源选择**——这是 R2 增量变量的直接入口（见 §6）。

## 2. 训练态与信息访问边界

**（a）确无任何 ASR 侧训练**。L117 "entirely decoupled from the ASR model architecture"、
L125 "works without fine-tuning the ASR model"。全文对 ASR 不做微调、不加 adapter、不改架构，
这一点属实且无保留。这也是本篇被 round-13 判为「无 ASR 微调」的依据。

**（b）嵌入器同样未训练**。all-MiniLM-L6-v2 是现成 sentence-transformers 权重，选型理由是
"similarly to BertTopic"（L144），全文无对比训练、无微调、无同音负例课程。附录 Table 3
把它与 `all-MiniLM-L12-v2` / `all-distilroberta-v1` / `all-mpnet-base-v2` 并列扫描
（L326–L364），四者全部是现成 checkpoint。**故本篇在检索侧确实是 training-free 的**——
这一点比 RECAST（对比训练 retriever）、BR-ASR（对比训练 + 同音负例课程）都更靠近 R2 的边界。

**（c）「黑盒」的星号——承重点，逐条给原文证据**。论文的黑盒主张**只在"上下文发现模块看不见
识别器内部"这一层成立**，识别器本身必须暴露一个**每段接受 context list 的偏置接口**，
而该接口是识别器内部的架构机制：

1. **接口在方法定义里就是硬约束**。L136–137 把 ASR 定义为条件解码器：
   "$\hat{y}_t = \mathcal{A}(s_t \mid \text{C}_t)$ where $\hat{y}_t$ is the predicted transcript
   of segment $s_t$, **conditioned on the context list $\text{C}_t$**." 即调用签名里就带
   context list；一个只接受音频、只返回文本的通用 ASR API **无法运行本文任何一个 CB 臂**。
2. **该接口的实现是 Jalal et al. 2023 的内部 CB 机制**。L238："The **context module of the ASR
   system implemented** is based on the approach proposed by [`jalal2023locality`], which
   introduces a **CB mechanism that integrates contextually relevant external information during
   inference**." 被引文献（`paper.bbl` L86–93）为：Md Asif Jalal, Pablo Peso Parada, George
   Pavlidis, Vasileios Moschopoulos, Karthikeyan Saravanan, Chrysovalantis-Giorgos Kontoulis,
   Jisi Zhang, Anastasios Drosou, Gil Ho Lee, Jungin Lee, Seokyeong Jung. 2023. *Locality enhanced
   dynamic biasing and sampling strategies for contextual ASR.* **ASRU 2023**, pages 1–8, IEEE。
   "locality enhanced dynamic biasing **and sampling strategies**" 意味着识别器内部还带一套
   **对候选表的采样/筛选策略**——即偏置侧的处理并非本文所控，却直接决定了大候选表为何不伤性能
   （见 §3 第 6 条与 §4「局限」）。
3. **作者重叠证明这是自有可控系统而非外部黑盒服务**。Siskos 六位作者中
   **Pablo Peso Parada、Karthikeyan Saravanan、Jisi Zhang、Anastasios Drosou 四位同时出现在
   Jalal et al. 2023 的作者表**（对比 `paper.tex` L69–L81 与 `paper.bbl` L87–89）。也就是说
   "black-box recognizer" 是同一实验室可插桩的自有实现，"黑盒"描述的是**模块间解耦**，
   不是**部署可得性**。
4. **识别器身份从未披露**。全文没有给出这个 ASR 的模型名、参数量、训练数据、公开
   checkpoint 或任何版本号；`\section{ASR Model}`（L237–238）总共两句话，一句指向 Jalal 2023，
   一句说 VAD 用 SpeechBrain（`speechbrain_v1`）。**故本篇的载体在外部不可复现**——
   任何人要复跑，必须自行实现 Jalal 式 CB 或换一个带 CB 接口的识别器，而换掉识别器就换掉了
   §3 全部 WER 的量纲。

**结论（对 R2 的边界记账）**：Siskos 是「**无训练 + 模块解耦，但要求识别器暴露内部偏置接口**」，
不是「API-only」。它与 R2 的信息边界差一格：R2 假定的冻结 omni 核**只有 prompt 通道**，
没有 context-list 偏置钩子。这一格差正是 R2 相对本篇的独立性所依赖的事实，也是
**2026 重审条款必须重新检验的那一格**（§7）。

## 3. 关键数字（LaTeX 表体核对）

**三集三行主结果（Table 2 `tab:context-results`，L207–230）**，No Context → CB-RAG 最优配置
`[c=250, k=10]`（主表 CB-RAG 各行与附录 `all-MiniLM-L6-v2` 各行数值完全一致，故主表 CB-RAG
恒指 MiniLM-L6）：

| 数据集 | Oracle | No Context | CB-LLM | CB-LLM+LLM_fix | **CB-RAG [250,10]** |
|---|---|---|---|---|---|
| TED-LIUM v3 | 15.4% | 18.9% | 16.9% | 16.8% | **16.4%** |
| Earnings21 | 29.7% | 35.9% | 31.8% | 31.7% | **31.1%** |
| SPGISpeech | 17.0% | 22.4% | **18.6%** | **18.6%** | 18.7% |

即任务简报里的 **18.9→16.4 / 35.9→31.1 / 22.4→18.7** 三对逐位属实。相对降幅：
TED-LIUM 13.2%、Earnings21 13.4%、SPGISpeech 16.5%；摘要 L96 的头条
"reduces WER by up to 17\% (percentage difference)" **就是 SPGISpeech 的 16.52% 向上取整**，
而**恰恰在这一集上 CB-LLM（18.6%，相对 16.96%）优于本文主推的 CB-RAG（18.7%）**——
论文自己在 L252 承认："Although LLM-based approaches achieve the best relative WER improvement
in SPGISpeech (16.96\%), `CB-RAG` configurations closely follow (16.52\%)."。摘要另一句
"the oracle context results in a reduction of up to 24.1\%" 同样出自 SPGISpeech
（(22.4−17.0)/22.4 = 24.1%）。**头条数字与最强臂不在同一臂上**，引用时不得合并陈述。

**1. 评测规模只有小时级，且切分身份未披露**。L173："TED-LIUMv3 (~1.5 hours of audio),
Earnings21 (~5 hours of audio) and SPGISpeech (~5 hours of audio)"。全文**未给出任何官方
split 名、talk/session 清单或抽样规则**（TED-LIUM3 与 Earnings21 都只有一个小时数），
故三集均为**未标识的子集**。任何把这些 WER 与文献公开数字对比的做法都不成立。

**2. SPGISpeech 协议被改动（如实照录）**。L173："SPGISpeech consist of 5–15 seconds utterances
grouped by sessions. Since context extraction methods require longer audio to capture contextual
information, **sessions were concatenated, and only segments longer than 6 minutes were
retained**, perseving topic consistency."（原文拼写 "perseving"）。另有全局转写归一化
（L175）："Non-verbal content and non-English segments are removed. Text is normalized through
lowercasing, punctuation stripping, hyphen removal, and conversion of numerical expressions to
word format."。SPGISpeech 的标准口径是完全正字法（大小写、标点、数字格式均计分），
**本篇的 22.4%/17.0%/18.6% 与该基准的任何已发表数字不可比**；且"只保留 >6 分钟拼接段"
是一次**朝着有利于上下文方法的方向做的选择性保留**，属结构性选择偏差，必须随数字一起引用。

**3. 词表覆盖天花板（Table 1 `tab:rare_analysis`，L185–189）**：

| 指标 | TED-LIUM v3 | Earnings21 | SPGISpeech |
|---|---|---|---|
| OOV（不在冻结词表 V 中的唯一词占比） | 6.31% | 13.49% | 15.77% |
| Rare rate | 28% | 38% | 6.16% |

OOV 定义见 L179：$\mathcal{E}_{oov}=\{e\in\mathcal{E}_{rare} \mid e\notin\mathcal V\}$。
**这是 CB-RAG 的硬上限**：冻结词表结构上取不到 6.3–15.8% 的唯一词，而这些恰是稀有实体。
论文在 Limitations（L260）只承认"lexically sensitive and might overlook semantically similar
terms"，未把 OOV 率与 Oracle 差距挂钩。

**4. Oracle 余量已被吃掉七成——本篇对 R2 最重要的一个反向数字**（由主表推算）：
「自动上下文发现」相对「完美上下文」的可达比 =
$(\text{NoCtx}-\text{方法})/(\text{NoCtx}-\text{Oracle})$：
TED-LIUM **2.5/3.5 = 71.4%**、Earnings21 **4.8/6.2 = 77.4%**、SPGISpeech **3.7/5.4 = 68.5%**
（CB-LLM 3.8/5.4 = 70.4%）。**即在这条轴上，一个零训练的余弦 Top-N 已经拿走了完美上下文
七成左右的收益，剩余空间只有 1.0–1.7 pp 绝对 WER（TED 1.0/E21 1.4/SPGI 1.7）。** 同时 Oracle 本身远非零错
（15.4/29.7/17.0），说明该载体上大部分错误**根本不由上下文缺失造成**。R2 若把
"上下文发现质量"当主战场，天花板已被证明很低——必须换轴（重听动作 / 世界知识 rescore）或换核。

**5. 延迟才是 CB-RAG 的真卖点，且论文自陈**。主表 Time 列（归一到 no-context）：
CB-RAG 全部 12 个格子落在 **1.02×–1.42×**（TED 1.02/1.04/1.16/1.36；E21 1.02/1.13/1.14/1.16；
SPGI 1.31/1.34/1.40/1.42），CB-LLM 落在 **3.26×–6.56×**。论文 L248 的表述是
"`CB-RAG` demonstrates substantially lower latency, **1.02 to 1.36 times slower** than no-context
baseline, relative to LLM-based approaches, which are 4.66–6.16 times"——**"1.02–1.36×" 是
TED-LIUM 单集的范围**，跨三集的真实上界是 **1.42×**（SPGISpeech [250,10]），
CB-LLM 的跨三集上界是 6.56×（SPGISpeech + LLM_fix）。附录里最慢的臂是
`gemma3:4b` + `LLM_fix` 在 Earnings21 的 **33.58×**（L316）。结论 L257 自陈定位：
"`CB-RAG` … yielding the lowest WER … **at the lowest computational cost and latency** …
while operating, on average 83.5\%, lower latency than LLM-based alternatives."
**精度上 CB-RAG 只在 2/3 集上赢 CB-LLM 且幅度 0.5–0.7 pp，在第三集上以 0.1 pp 输**；
承重结论应写成"**同等精度下延迟低 3–5 倍**"，不得写成"精度全面更优"。

**6. 检索"相关性"与 WER 反向——本篇最强的一条 R2 可用证据**。Overlap 列（论文自定义为
"a proxy for semantic recall"，L241）在 CB-LLM 上远高于 CB-RAG，WER 却不占优：
TED-LIUM CB-LLM overlap 45.3–48.7% / WER 16.8–16.9%，CB-RAG overlap 17.8% / WER 16.4%。
附录里对比更极端（L301、L347）：`tinyllama:1.1b` 拿到全文最高 overlap **81.8%**（TED）
却只有 WER 16.9%；Earnings21 上 `smollm2:135m` overlap **79.1%** 对应 WER **32.8%**，
而 CB-RAG [250,10] overlap 仅 **21.4%** 却拿到全表最优 WER **31.1%**。
**跨臂看，overlap 与 WER 呈明显反向。** 论文对此的解释是"数量补质量"（L248：
"`CB-RAG` compensates through significantly higher context counts … suggesting it access more
diverse and redundant set of candidate segments"）。

**7. 编码器脆性——被论文自己的附录记录、却未被讨论**。Table 3 在 Earnings21 上换掉
all-MiniLM-L6-v2 后（L328–L364），各编码器最优格：MiniLM-L6 **31.1%**、MiniLM-L12 **34.4%**、
distilroberta **34.8%**、mpnet **35.0%**；No Context 为 **35.9%**。即换一个同样现成的句嵌入
模型，相对 no-context 的增益从 **4.8 pp 塌到 0.9–1.5 pp（损失 69%–81%）**，多个格子
（L340 MiniLM-L12 [100,100] = 35.2%、L344 mpnet [100,100] = 35.1%、L342 distilroberta
[100,100] = 35.0%）几乎与不加上下文无异。**同一现象在 TED-LIUM 上几乎不存在**
（四个编码器最优格 16.4/17.0/17.0/17.0，损失仅 24%）——**编码器选择只在更难、稀有实体更密的
那一集上决定成败**，而论文给出的选型依据只有"similarly to BertTopic"（L144），
没有任何选择准则、没有验证集调参说明。论文对该表的总结（L380）只说
"`CB-RAG` encoders based on `MiniLM` demonstrate high efficiency"，**回避了另外三个编码器在
Earnings21 上收益归零的事实**。

**8. 上下文量（Count）与 $k$ 的方向性**。Count 列归一到 Oracle 的上下文词数
（附录 L378 明确"15.17 times than `Oracle`"）。CB-RAG [250,10] 的 Count 为
12×/15.17×/9.40×（三集），远高于 CB-LLM 的 10.94×/9.03×/7.01×。$k$ 的方向一致且被三集复现：
**$k=10$ 优于 $k=100$**（L248"Reducing the number of segments $k$ also results in improved
performance: the [250,10] configuration yields a WER of 16.4\%, compared to 17.1\% for [250,100]"；
L252"Reducing the number of segments $k$ from 100 to 10 again improves WER, **reinforcing the
value of recent focused context**"）。$c$ 的方向也一致（100→250 更好）。

**9. 三处内部不一致（引用时须避开）**：
   (i) L250 称 Earnings21 [250,10] "a time cost of just **1.12**"，主表该格为 **1.16×**（L226）；
   (ii) 表头把 Count 标为 "**Count $\downarrow$**"（L203–205，越低越好），正文与加粗却把
   **越大越好**（L248 "compensates through significantly higher context counts (**up to 12\%**)"
   ——单位也写错，表里是 12$\times$ 不是 12%），且表中被加粗为最优的正是最大值 12×/15.17×/9.40×；
   (iii) 附录正文的模型名与表体不一致：正文 `smollm2:365m` / `gemma2:4b`（L376）对应表体
   `smollm360m` / `gemma3:4b`。另：附录 Table 3 **没有 SPGISpeech 列**，backbone 扫描只覆盖两集。

**10. 统计学缺位**：全文无种子、无重复运行、无方差/置信区间、无显著性检验
（对 `seed`/`std`/`p-value` 的全文扫描零命中），且**没有任何一条与已发表 contextual-biasing
基线的外部对比**——所有比较都发生在自建管线的内部臂之间。

## 4. DFS 四问

**方法**：把上下文发现从「结构化实体目录 + 训练进解码器」改成「**冻结通用词表 + 现成句嵌入
+ FAISS 余弦 Top-N**，以前 $k$ 段 ASR 假设为查询」，输出一个 context list 交给一个自带 CB
接口的识别器；并用同管线对照两条 LLM 路线（生成式上下文 `CB-LLM`、后处理纠错 `LLM-fix`）。
唯一的可调量是 $(c, k)$ 两个数。

**局限**：
(i) **黑盒是带星号的**——识别器必须暴露 context-list/CB 偏置接口（§2c），且该识别器身份、
   规模、checkpoint 全部未披露，外部不可复现；
(ii) **载体是小时级未标识子集**（~1.5h/~5h/~5h），SPGISpeech 还被改协议（拼接 + 只留 >6 min），
   与公开数字不可比；
(iii) **词表天花板**：OOV 6.31%/13.49%/15.77% 的词结构上取不到，而这正是稀有实体所在；
(iv) **增益对编码器极度敏感**（Earnings21 换编码器丢掉 69–81% 的增益），选型无准则、
   无验证集程序，存在选择性报告风险；
(v) **零门控**：全文对 `when to` / `trigger` / `threshold` / `confidence` / `uncertain` /
   `gating` 的扫描**全部零命中**（"gate" 的 3 次命中全部来自 "investi**gate**d"），
   检索对**每一段无条件执行**；
(vi) **无统计学**（单次运行、无方差、无显著性），且无外部基线对比；
(vii) **三处内部数值/单位不一致**（§3 第 9 条）；
(viii) **Oracle 余量已被吃掉 68–77%**，这条轴上剩余可争空间只有 1.0–1.7 pp 绝对 WER。

**改进空间**（按 R2 可执行性排序）：
1. **把无条件检索改成动作级调度**。本篇给了最干净的空位：$(c,k)$ 是**全局常数**，
   而 §3 第 6/7 条同时表明"检索结果的相关性与最终 WER 反向"且"编码器一换增益归零"——
   说明**逐段决定「这一段要不要查、查多少、查哪一源」是尚未被触碰的自由度**。
   本篇甚至给了现成的两个异质源（V 词表 vs LLM 参数知识），却只做互斥臂比较。
2. **补一个真正的准入门实验**。本篇 Top-N 之后**没有任何过滤**（`CB-LLM` 的
   "remove duplicates and stopwords" 是去重去停用词，不是相关性准入，且只作用于 LLM 臂）。
   缺失臂：same-N 随机词 / same-N 反相关词 / 学习或标定后的筛选，全部对齐到 No Context。
3. **把 Oracle 参照升级为诊断工具**。Oracle 上下文（去停用词的参考转写词）是现成的
   "完美采集"反事实；本篇只用它报一个下界。R2 可用「Oracle 余量捕获率」作为**上下文轴是否
   还值得投入**的预注册判据——本篇已给出 68–77% 的基线读数。

**可借鉴**：
(a) **Oracle / No-Context 双参照 + 三集复现**的臂结构可直接搬进 R2 的 K-NB 战场，
    并且本篇已给出这三集上的 Oracle 值（15.4/29.7/17.0），可作为 R2 复现先行的对齐锚；
(b) **Overlap（检索相关性代理）与 WER 分离报告**的做法值得保留——它把"更相关 ≠ 更好"
    变成可测量的量而不是断言；R2 应把它扩成"相关性 × 是否入上下文 × 任务读数"的三列；
(c) **延迟归一到 no-context 的 Time 列**是一个便宜且可跨臂比较的成本记账形状，
    R2 预算章可直接复用（本篇 CB-RAG 1.02–1.42× vs CB-LLM 3.26–6.56× 就是这样读出来的）。

**Earnings21 / SPGISpeech 作为 R2 NB 载体的入围线索（本条为任务点名项）**：
- **Earnings21 = 最强入围者**。Table 1 显示它 **rare rate 38%（三集最高）、OOV 13.49%**，
  且是三集中 no-context WER 最高的（35.9%）、Oracle 余量最大的（6.2 pp）——
  即**稀有实体密度与可争空间双高**，正是 K-NB（知识/命名实体绑定）判据需要的形状。
  其 bbl 条目为 "Earnings-21: A practical benchmark for asr **in the wild**"（arXiv 2104.11348），
  定位与 R2 的真实部署叙事一致。**但**：本篇只用了 ~5h 未标识子集，全集规模与官方 split
  **不在本地证据内**，Stage-2A 必须另行核定并**用全集/官方 split 而非本篇子集**。
- **SPGISpeech = 降级或改口径使用**。虽然 OOV 最高（15.77%），但 **rare rate 只有 6.16%**
  （三集最低，且比 Earnings21 低一个量级），说明它的 OOV 主要是长尾普通词而非命名实体，
  **NB 承重力弱**；叠加本篇的协议改动（拼接会话 + 只留 >6 min + 归一化去正字法），
  作为 R2 主载体会同时继承"弱 NB 信号"和"不可比口径"两个问题。建议：
  **不作 K-NB 主载体**；若用，必须走未改动的官方口径，且只作复制载体。
- **TED-LIUM v3 = 复制载体候选**。rare 28% 尚可，但本篇只有 ~1.5h，且 Oracle 余量仅
  3.5 pp——**在 R2 的多杠杆 × 多分桶 + multiplicity correction 设计下，这个体量的
  有效样本很可能不足以支撑分桶显著性**。作复制载体（方向一致性验证）合适，作主战场不合适。
- **共同风险**：三集在本篇上的 no-context WER 高达 18.9/35.9/22.4，指向一个偏弱的识别器；
  R2 若换成冻结 omni 核，基线 WER 与 Oracle 余量都会变，**本篇的余量捕获率（68–77%）
  不能直接外推**，须在 Stage-2A 复现先行里重测（见 §7）。

## 6. R2 增量变量核验（三项逐个引证缺席）

**变量一：动作级调度（何时查 / 查哪源）——确实缺席，双重缺席。**

- **「何时查」缺席**：检索对每一段无条件执行。方法定义（L142）："$\hat{Y}_{t-1}$ is utilized
  to retrieve words contextually relevant to $s_t$ which are merged into a context list that's
  passed to the ASR system"——没有任何条件；公式 $C_t^{rag}=\text{TopN}_{w_i\in\mathcal V}
  (\cos(\mathbf q_t,\mathbf v_i))$（L148–150）对所有 $t$ 无条件成立。
  全文扫描：`when to` 0 命中、`trigger` 0、`skip` 0、`decide` 0、`threshold` 0、`confid*` 0、
  `uncertain*` 0、`adaptive` 0、`gating` 0（"gate" 的 3 次命中全部来自 "investigated"）。
  **不存在任何跳过检索的路径，也不存在"这一段是否需要上下文"的判断。**
- **「查哪源」缺席**：论文确有两个异质知识源——冻结词表 V（CB-RAG）与 LLM 参数知识
  （CB-LLM）——但它们在全篇**只作互斥臂横向比较，从不共存、从不按段落选择**。
  Figure 1 标题（L103）用的是"**either**"："Context for each segment is extracted using
  **either** an embedding-based retrieval method **or** LLM-based prompt generation"。
  结论（L254）也把关系定为替代而非组合："It is also **a better alternative compared to**
  LLM-based context creation and transcript correction."
  **零处出现来源选择/来源融合/来源级路由。**
- **额外证据（缺席是有代价的）**：正因为没有调度，$(c,k)$ 只能全局网格搜；而 §3 第 7 条显示
  同一 $(c,k)$ 在换编码器后于 Earnings21 上增益归零——**这正是"全局常数 vs 逐段决策"这条轴
  未被开发的直接后果**。

**变量二：准入门（证据进上下文前的拒绝）——确实缺席。**

- CB-RAG 路径上，Top-N 的输出**直接就是** $C_t^{rag}$，中间无任何过滤：L146"Top-$N$ context
  words are **selected by maximizing cosine similarity**"，紧接 L152 即"The use of
  $C_t^{rag}$ for context is hereby denoted as `CB-RAG`"。没有阈值、没有二次筛选、
  没有相关性判别器、没有拒绝出口。
- 唯一的后处理属于 **CB-LLM 臂**且不是准入门：L160"The output context is post-processed to
  **remove duplicates and stopwords**"——去重与去停用词是规范化，不是按相关性拒绝，
  且**不作用于 CB-RAG**。
- **缺失的对照臂**：本篇没有 random-context 臂、没有 shuffled/反相关臂、没有 same-N 对照。
  因此本篇**无法回答**"检索到的东西质量本身是否重要"——它只回答了"哪种检索器更好"。
  （对照：视觉域 MementoGUI 的三臂检索消融把 random / single-stage / two-stage 全部对齐到
  一个"不检索"参照，是 R2 准入门可直接移植的臂结构。）
- **一条必须记账的反向证据（不得隐去）**：本篇的经验方向**表面上不利于准入门动机**——
  CB-RAG 的 overlap 仅 8.8–21.4%（即绝大多数注入词不相关）、Count 高达 9.4–15.17×
  （注入量远超 Oracle），**却仍取得三集中两集的最优 WER**。论文的解释是"数量补质量"
  （L248）。**但这一反向证据的成立条件是本篇特有的**：注入对象是一个 Jalal 式 CB 模块，
  其自带"dynamic biasing **and sampling strategies**"（`paper.bbl` L90–91），
  低精度大候选表的稀释成本由识别器内部的采样机制吸收；而 R2 的注入对象是冻结 omni 核的
  **prompt 上下文**，稀释直接消耗 token 与注意力。**故本篇不构成"准入门无必要"的证据，
  但它与 RAG-Boost 自报的 raw-RAG 负结果（WER 13.83→32.98）在方向上冲突**，
  R2 必须在 §8/§4 里把这对冲突显式登记为"**注入接口类型决定稀释代价**"，
  并在 Stage-2A 复现先行里作为一个待判问题，而不是挑对自己有利的一侧引用。

**变量三：omni 核裁决——确实缺席，且全篇无 omni 概念。**

- 全文对 `omni` 0 命中、`multimodal` 0 命中。
- 作答权始终在那个**未具名的 CB-capable ASR** 手里：$\hat y_t = \mathcal A(s_t\mid C_t)$
  （L136）。LLM（Llama3.2 3B，L139）只出现在两个**非作答**位置：生成上下文词
  （$C_t^{llm}=\mathcal M_{gen}(\hat Y_{t-1}, P_{gen})$，L157）与事后改写文本
  （$\hat y_t^{corr}=\mathcal M_{fix}(\hat y_t, C_t, H_{t-1}, P_{fix})$，L139）。
- **LLM 从不回到音频**：`LLM-fix` 的输入是 $(\hat y_t, C_t, H_{t-1}, P_{fix})$——**纯文本**，
  提示语（L270）也确认这是文字层修订："correct the given sentence by fixing typos,
  misspellings, grammar, or logical inconsistencies. Preserve the original intent."
  **无重听、无音频重解析、无跨模态裁决**（`re-listen` 0 命中）。
- 因此"由一个冻结 omni 核在音频与检索证据之间做裁决"这一构型在本篇**完全不存在**；
  本篇的裁决全部由识别器的内部偏置机制隐式完成。

**三项结论：R2 §8 该行最后一格的三个 delta 变量，逐个在本篇缺席，且缺席可由原文正面引证
（不是"未提及"式的弱否定）。** 但第二项须附带上面那条反向证据与接口条件，
否则 R2 的准入门动机会被这篇反过来质疑。

## 7. 2026 重审条款预置

按 R2 §8「2026 重审条款」（提案 L674–676：2023 时代近邻的承重前提在冻结 omni 核上是否仍成立
= Stage-2A 复现先行重审对象，逐篇重审结论入 D2 条目），本篇**虽为 2025 年工作，但其承重前提
继承自 2023 年的 CB 架构**（Jalal et al. ASRU 2023），故同样入重审。预置三条**可证伪的**
重审问题与判据：

**重审-1（最承重）：冻结 omni 核能否在 prompt 内原生消费候选词表？**
本篇"黑盒星号"的全部力量来自"识别器必须有 CB 钩子"。若 Qwen3-Omni-30B 一类冻结核能直接在
prompt 里吃一张候选词表并产生等效偏置，则 **Siskos 的方法可被无损移植到纯 API-only 边界，
其"最近信息边界的直接对手"身份从差一格变成同边界**，R2 的独立性合取里"API-only 黑盒 key"
这一支的分离力显著减弱。
*判据*：在冻结 omni 核上，注入 Oracle 上下文相对 No Context 的 WER 降幅是否达到本篇
Oracle 余量的同量级（本篇为 3.5/6.2/5.4 pp）。若达到 → 重审-1 判为"前提失效"，
R2 必须把独立性重心从"边界"移到"动作/信号"。

**重审-2：本篇的余量捕获率（68–77%）在更强的核上是否仍然成立？**
本篇 no-context WER 18.9/35.9/22.4 指向一个偏弱识别器。更强的核会同时压低基线与 Oracle，
**余量可能塌缩到 1 pp 以内，使整条"上下文发现"轴在 R2 的战场上失去可测空间**。
*判据*：冻结 omni 核上 (NoCtx − Oracle) 的绝对 pp。若 < 1.5 pp → R2 不得把上下文发现质量
作为主读数，必须改用"重听动作 + 世界知识 rescore"承担主张（对应 R2 双源动作）。

**重审-3：低精度大候选表的"数量补质量"是否跨接口类型成立？**
本篇 overlap 8.8–21.4% / Count 9.4–15.17× 仍取胜，是**CB 模块内部采样机制**的性质；
换成 prompt 注入后，稀释代价的符号可能反转（RAG-Boost 的 raw-RAG 负结果即反向样本）。
*判据*：在冻结 omni 核上做 same-N 随机词对照臂。若随机词臂 ≈ 检索臂 → 本篇的机制归因
（"检索有效"）在新接口上不成立；若随机词臂显著更差 → 准入门动机成立，
且 R2 可引用本篇作为"接口类型决定稀释代价"的对照点而非反例。

三条重审的结论应在 Stage-2A 复现先行后回写本条目，不在此前把本篇的任何数字外推到 omni 核。

## 8. 深读后新增的、R2 应该知道的事实

1. **"最近的直接对手"仍差一格，但差的那一格是可能被 2026 抹平的一格**（重审-1）。
   R2 的独立性叙事不应把重量全压在"Siskos 需要 CB 钩子"上；应同步准备"动作/信号"侧的
   分离论证。
2. **上下文发现这条轴的天花板已被本篇量化**：零训练余弦 Top-N 已捕获完美上下文余量的
   68–77%，剩余 1.0–1.7 pp。R2 若在同轴上竞争，须预注册一个足够小的可检出效应量，
   否则会在"有统计力"这一关上失败。
3. **"更相关 ≠ 更好"在 ASR 域获得一个独立、干净的数据点**：overlap 81.8% 的臂（tinyllama）
   WER 16.9%，overlap 17.8% 的臂（CB-RAG）WER 16.4%；Earnings21 上 79.1% vs 21.4% 对应
   32.8% vs 31.1%。这是与视觉域（MementoGUI Table 4）跨域一致的证据，可用于 R2 §4.1。
4. **零训练检索的增益是"编码器选择"的函数而非"检索"的函数**：Earnings21 上换掉
   all-MiniLM-L6-v2 使增益损失 69–81%，而选型依据只有"similarly to BertTopic"。
   **对 R2 的直接含义**：任何 training-free 检索臂都必须把编码器当作预注册超参并报敏感性，
   否则"零训练也能赢"的主张不可证伪。同时这是"**为什么需要在线的、按段的调度信号**"的
   最强动机之一——固定编码器 + 固定 $(c,k)$ 在难集上会整体失效。
5. **本篇与 RAG-Boost 在"无条件检索的符号"上冲突**（本篇净正、RAG-Boost raw-RAG 净负
   13.83→32.98），且冲突可由**注入接口类型**解释（CB 模块内部采样 vs prompt 稀释）。
   R2 应把这条冲突写进证据底座作为待判问题，**不得单引一侧**。
6. **载体建议已可下结论**：Earnings21（rare 38% / OOV 13.49% / Oracle 余量 6.2 pp）
   = K-NB 主载体首选，但必须用官方全集口径而非本篇 ~5h 子集；TED-LIUM3 = 复制载体；
   SPGISpeech（rare 仅 6.16% + 协议改动）**不作 K-NB 主载体**。
7. **可复现性硬伤**：本篇 ASR 识别器无名、无 checkpoint、无 split 标识。
   R2 若把 Siskos 列为 incumbent 第 ⑤ 组的直接对手，**无法照搬其数字作对比**，
   只能复现其**方法形状**（冻结词表 + 现成句嵌入 + FAISS Top-N），并在 R2 自己的载体与核上
   重跑，得到自建的 Siskos-style 基线。这一点应作为 Stage-2A 复现先行的显式工作项。
