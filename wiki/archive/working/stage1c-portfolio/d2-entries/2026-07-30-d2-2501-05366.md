## 1. 方法本质

Search-o1 完全不训练任何模型：它给一个**冻结的大推理模型**（QwQ-32B-Preview）一段协议提示词，声明
两个特殊符号 `<|begin_search_query|>` / `<|end_search_query|>`；模型在长 CoT 中自行写出这对符号时，
外部 harness 检测到即**暂停解码**，抽出查询串、打 Bing Web Search API（top-10）、用 Jina Reader 抓页。
关键的第二个组件是 **Reason-in-Documents**：抓回的原文**不进主推理链**，而是交给**同一个冻结模型的
一次独立生成**，输入是（先前推理步 + 当前查询 + 网页内容），输出必须以 `Final Information` 开头的
精炼结论，或者显式输出 `No helpful information found.`；只有这段精炼文本被包在
`<|begin_search_result|>` / `<|end_search_result|>` 里插回原推理链，然后解码继续。整个循环可在单个
推理会话内多次触发，直到模型不再写查询、或撞上提示词里的 `{MAX_SEARCH_LIMIT}` 上限。工程上还有
一个批量机制（Algorithm 1）：一批题一起解码到"各自遇到 `</end_search_query>` 或 EOS"，检索与精炼各自
成批执行，再统一插回。

## 2. 三轴定位

| 轴 | Search-o1 的位置 |
|---|---|
| **供给决策由谁做** | **冻结 LLM 的自由生成，纯 training-free**。没有打分器、没有阈值、没有价值估计、没有可训练门控——决策就是模型在 CoT 里"决定写不写那对符号"。骨干 QwQ-32B-Preview 全程冻结（§4.3 实现细节只给采样参数：max 32,768 tokens、temperature 0.7、top_p 0.8、top_k 20、repetition penalty 1.05）。**动机是运行时信号但只作观察、未进决策**：§1 用 Figure 1 统计冻结模型 CoT 里的不确定词频（GPQA diamond 上 "perhaps" 平均每次输出出现 30+ 次）来论证"知识不足"存在，但该信号**没有**被接进任何触发判据——它是论证材料，不是控制量。这一点对 R2 是正面机会（详见 §5.2 F2）。 |
| **触发与停止判据** | **触发＝符号检测（token 级、推理链内、可多次）**；**停止＝两条**：(a) 模型不再生成查询符号、走到 `<eos>`（软停止，判据完全内生于生成分布）；(b) 提示词声明的硬上限 `{MAX_SEARCH_LIMIT}`——**该占位符在正文与附录中始终未被赋值**（§A.1 与 §A.3 两处都是花括号占位）。另有一条兜底：所有检索类方法在"没给出最终答案"时回退到直接推理的结果（§4.3）。**判据形态结论**：触发是真"按需"的机制（模型自发、链内、多轮），但"需"是**无度量、无阈值、无预算、无成本项**的自陈；论文**未报告任何检索次数/延迟/token/API 开销统计**，Figure 3 的 top-k 缩放是唯一与"量"相关的读数（且只在 PDF 图里，源内无数字）。 |
| **使用侧准入/纠正** | **有准入，且是本文最可借鉴的部件；无纠正、无仲裁**。准入＝Reason-in-Documents 的两分支输出契约（§A.1 模板）：有用则 `Final Information` + 精炼内容，无用则明确输出 `Final Information / No helpful information found.` ——这是一条**完全 training-free 的整批证据拒收门**。同时构成**上下文防火墙**：原始网页文本永不进入主推理链，只有精炼产物进（§3.3 + Algorithm 1 第 19–21 行）。**缺口**：无冲突仲裁（多轮结果只是顺序插入）、无来源可信度、无 abstain、无对已插入证据的回撤/纠正。 |

## 4. DFS 四问

**方法**：把"检索"降格成推理链里的一个可暂停/可恢复的解码事件，用特殊符号做进程间协议；再用
"同一个冻结模型的第二次调用"充当证据压缩器与准入门，使外部原文永不污染主链。整套东西的可训练参数
为零，全部实现在 harness 的符号检测、批量调度与提示词契约里。

**局限**：(a) 触发无度量——"需要"完全是生成分布的副产物，无法审计、无法定价、无法按预算调节，硬上限
`{MAX_SEARCH_LIMIT}` 连值都没报；(b) **成本记账缺失**——§1 声称"quantitative analysis confirms its
efficiency"，但全文无检索次数、无 wall-clock、无 token、无 API 花费，唯一相关读数 Figure 3 是图无数；
(c) 能力门槛硬——§5.1 第 2 条自承非推理模型 Qwen2.5-32B 用 agentic RAG 在数学/代码上**反而下降**，
"普通 LLM 无法有效把搜索当工具用"；(d) 任务型依赖——LiveCodeBench 净增益 0、Easy 档负增益，单跳
TriviaQA 负增益；(e) 小样本基准（三个 n≤112）；(f) 精炼是有损且不可回撤，Reason-in-Documents 的
判断错了就是硅默丢证据，无第二意见、无冲突仲裁；(g) 精炼的额外生成开销被完全隐没在"批量机制提升
吞吐"的叙述里——每次检索至少多一次全上下文长度的生成。

**改进空间**：把 §1 里已经统计过的不确定词频**从论证材料升级为控制量**——这几乎是白送的：论文自己
证明了信号存在（"perhaps" 均 30+ 次/输出）却没接进触发。往上还可以做：给触发加实例级预算与停止
判据（当前只有硬上限）；把 Reason-in-Documents 的二分支契约扩成带置信度的多档（照 CRAG 的
`Ambiguous` 思路）；多轮证据间做一致性/冲突检查而非顺序堆叠；按任务类型分层决定是否启用 agentic
获取（论文数据已指出代码/单跳该关掉）。

**可借鉴**：三件可直接搬。① **`No helpful information found.` 分支＝零训练的整批证据拒收门**——
R2 的证据准入可以此为最小可行原语，且有现成提示词（§A.1）。② **上下文防火墙**：外部原文不进主链、
只进"精炼子调用"，这条结构约束把"更相关≠更好"的风险面从主链移到一次隔离调用里，是比"进上下文后
再过滤"更强的准入形态。③ **符号协议 + 暂停解码 + 批量恢复**（Algorithm 1）是 training-free 调度的
参考实现骨架，与模型权重完全解耦，可平移到冻结 omni 骨干。

### 5.1 逐句判定

### 5.2 深读后新增的、R2 应该知道的事实

**F1（触发机制细节，正面回答任务提问）— "按需"在机制上为真、在判据上为空。** 触发是 token 级符号
检测（`</end_search_query>` 触发暂停），停止只有两条：模型自己不再写查询，或一个**在源里始终未赋值的**
`{MAX_SEARCH_LIMIT}`。没有任何标量信号、阈值、价值估计或预算参与；也没有任何检索次数/延迟/开销
统计。→ 对 R2 的两个后果：(i) 引用 Search-o1 时**只能引"触发被条件化"，不能引"获取被定价/被节省"**；
(ii) **它留下的正是 R2 的空位**——同一个 training-free 骨架上补一个可审计的触发判据（信号 + 阈值 +
预算 + 停止），既不越红线，也不与本文重叠。

**F2（白送的运行时信号）— 论文自己统计了不确定词频却没把它接进决策。** §1 + Figure 1 用冻结模型
CoT 里的高频不确定词（GPQA diamond 上 "perhaps" 平均 30+ 次/输出，另有 Wait / Alternatively /
likely 等）**论证**知识不足的存在，然后直接跳到"让模型自发触发"，全文再未使用该信号。→ 这是一条
公开的、部署期可见（生成物内可数）、零 gold 依赖的信号，R2 的运行时信号族（`V̂` 系）可以把它作为
文本域已被观察但**未被消费**的先例来引用：**机制占据已发生，判据占据尚空。**

**F3（training-free 准入原语 + 上下文防火墙）— 可直接搬进 R2 的证据准入设计。** Reason-in-Documents
的输出契约是二分支：`Final Information` + 精炼内容，或 `Final Information / No helpful information
found.`（附录 §A.1 完整提示词在册）。这是**零训练的整批拒收门**；配合"原始网页文本永不进主推理链、
只有精炼产物进"（§3.3 + Algorithm 1）构成结构性防火墙。→ R2 的证据准入不必从零设计，可以把这条
二分支契约当基线原语，再在其上加分档/冲突仲裁/来源权重作为增量。

**F4（阵营内部的反例，比外部引证更有力）— agentic 深搜不是普遍增益。** (a) LiveCodeBench overall
Search-o1 33.0 **等于**不检索的 QwQ-32B 33.0，Easy 档 61.5→57.7 **净负**，两个检索基线（24.1 / 26.8）
都显著低于不检索；(b) 单跳 TriviaQA 上 Search-o1 63.4/74.1 **低于**两个标准 RAG 基线（65.8/79.2、
65.6/77.6），且单跳整体 agentic vs 标准 RAG 47.8 vs 47.6 ≈ 无差别；(c) §5.1 自承非推理骨干
Qwen2.5-32B 用 agentic RAG 在数学/代码上**下降**。→ R2 §4.2 引用的 regime 边界（2606.28864 "额外
测试时算力对推理型有利、对纯感知有害"）在文本域有同构证据，可以在 §4.1 就地佐证，无需跨域搬运；
同时这是"获取必须按任务类型分层"的直接论据。

**F5（配对错序，引用时必须改口）— 不要照抄"+4.7% vs agentic-RAG"。** §5.1 的 "exceeds
