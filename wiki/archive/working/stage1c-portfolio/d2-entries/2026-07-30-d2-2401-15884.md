## 1. 方法本质

CRAG 不改变"先检索"这一步，它改变的是**检索结果被采信之前的一道处理**。给定任意检索器返回的
top-10 文档，一个**微调过的 T5-large（0.77B）检索评估器**逐个 (query, doc) 打相关分（值域 −1..1），
再用**两个人工设定的阈值**把整体判成 `Correct` / `Incorrect` / `Ambiguous` 三态，三态各触发一条固定
的纠正动作：`Correct` → 对原文档做 decompose-then-recompose（切条、用同一评估器过滤、按序拼回）；
`Incorrect` → 丢弃全部原文档，改用 ChatGPT 把问句改写成关键词、走 Google Search API 取 web 页面并
同法精炼；`Ambiguous` → 两路知识拼接。动作完成后接任意冻结生成器（论文用 LLaMA2-hf-7b 与
SelfRAG-LLaMA2-7b）。整体是 plug-and-play 的**单轮、后检索、纠正型**框架，不含循环、不含预算、
不含"是否要检索"的决策。

## 2. 三轴定位

| 轴 | CRAG 的位置 |
|---|---|
| **供给决策由谁做** | **训练的小模型 + 规则阈值（混合），不是 LLM 自由生成**。打分器＝T5-large 0.77B，用 PopQA 剩余约 12.6k 条（14k 总量减去 1,399 条测试集）微调，正例标 1、负例标 −1，负例从检索结果里随机采（§3.2、附录 §C.3）；同一份权重零样本迁移到 Bio/PubHealth/ARC。决策规则＝双阈值，**逐数据集人工经验设定**：PopQA (0.59, −0.99)、PubHealth+ARC (0.5, −0.91)、Biography (0.95, −0.91)（附录 §C.3）。论文显式做了"换成 LLM 自由判断"的对照并否决之：Table 4，T5 评估器 84.3 vs ChatGPT 58.0 / ChatGPT-CoT 62.4 / ChatGPT-few-shot 64.7。→ **CRAG 是"训练的门"这一族的代表，不是 training-free 先例。** |
| **触发与停止判据** | **触发在检索之后、逐 query 一次、无循环**。判据是纯规则量词式：**存在**至少一篇 doc 分数 > 上阈值 → `Correct`；**全部** doc 分数 < 下阈值 → `Incorrect`；否则 `Ambiguous`（§3.3）。停止判据＝**不存在**——Algorithm 1 是直线流程，一次评估、一次纠正、一次生成，没有迭代、没有 hop 计数、没有预算、没有 abstain。**关键方向性事实**：`Incorrect`/`Ambiguous` 分支是**追加**一次 web 取数（Google API top-5 URL + 页面抓取），供给量相对基线 RAG **单调不减**；CRAG 不省任何一次获取。Table 6 给出这笔账：TFLOPs/token 26.5→27.2，单实例执行时间 0.363s→0.512s（+41%，且明确不含检索与数据处理阶段）。 |
| **使用侧准入/纠正** | **两者都有，且是 CRAG 增益的主要来源**。准入＝strip 级过滤：文档切条后用**同一个评估器**打分，top-k=5、过滤阈值 −0.5，内部知识与 web 知识同法处理（附录 §C.3）；只有过滤后的条带进上下文，原始长文档不进。纠正＝`Incorrect` 分支整体替换知识源。**缺口**：`Ambiguous` 分支对内部/外部知识只做顺序拼接，**无冲突仲裁、无来源可信度加权、无 abstain**。消融量级（Table 3，PopQA acc）：去 refinement 54.9→49.8 / 59.8→54.2；Self-CRAG 上更剧烈 49.0→35.9 / 61.8→52.2；去 web 知识 selection 在 LLaMA2-hf-7b 上 Self-CRAG 49.0→24.9。→ **使用侧准入的边际贡献大于供给侧动作选择的边际贡献**（对比 Table 2 去单动作只掉 0.3–5.4 点）。 |

## 4. DFS 四问

**方法**：把"检索结果可不可信"抽成一个可训练的轻量标量打分器，再用固定阈值把标量离散成三档，
每档绑定一条固定的知识重组动作；同一个打分器复用两次（文档级选动作 + 条带级做准入）。核心工程主张
是"评估器可以比生成器小三个数量级还更准"，核心稳健性主张是"给判断留一个软档（`Ambiguous`）比强行
二分更抗评估器出错"（§3.3 Discussion 明确说两动作版本的效果被评估器精度牵着走）。

**局限**：(a) 评估器需要相关性监督，本文用 PopQA 的 gold wiki 主题标题反推正例、随机采负例——**这是
一条 gold-only 信号进训练期的通道，部署期没有**；(b) 双阈值逐数据集手调（0.59/−0.99、0.5/−0.91、
0.95/−0.91 三套），没有阈值敏感性曲线，跨载体迁移成本未记账；(c) 无预算维度，纠正分支只会加获取不会
减，Table 6 的 +41% 执行时间还不含检索与抓页；(d) `Ambiguous` 只做拼接，两路知识矛盾时无仲裁；
(e) 主表两个 `LLaMA2-hf-7b` 列（PubHealth 0.6/0.7）实质失效却仍列在表内；(f) 单一评估器既定动作又定
准入，两处误差同源、不独立。

**改进空间**：把标量打分器换成**部署期可见的运行时信号族**（自一致性/众数计数、重呈现一致性、候选熵、
检索反馈），这样"评估器"不再需要训练也不再需要 gold；把双阈值换成按实例自校准的判据（CRAG 自己
承认阈值是"empirically set"）；把 `Ambiguous` 的拼接升级成带来源权重的仲裁；给纠正动作加成本项，
使 `Incorrect` 分支的"追加一次 web 取数"成为一个被定价的选择而不是无条件后果。

**可借鉴**：三点可直接搬进 training-free 设计。① **三档软判 + 中间档兜底**是对抗弱评估器的廉价制度性
保险，Table 2 显示去掉 `Ambiguous` 只掉 0.8–0.9 点、但 §3.3 说明它的作用是把系统效果与评估器精度解耦
——评估器越弱、这个设计越值钱，而 training-free 的评估器一定更弱。② **同一评分面复用于"选动作"和
"证据准入"两处**，把准入做成条带级而非文档级（Table 3 显示 refinement 是最大单项贡献：Self-CRAG 上
49.0→35.9）。③ **Table 5 式的"同输入对照"是必须照抄的实验协议**：要证明增益来自调度/准入而不是"多喂
了一路数据"，就必须给基线补齐同等范围的知识再比。

### 5.2 深读后新增的、R2 应该知道的事实

**F1（红线相关，最高优先）— CRAG 的检索质量评估器是训练的，且论文自己给出了"改用 training-free
提示判断"的价格。** 评估器＝T5-large **0.77B 微调**，监督来自 PopQA 的 gold 主题标题（正例）＋随机采样
的检索结果（负例），训练集约 12.6k 条（14k − 1,399 测试），一份权重零样本迁移到其余三个数据集
（§3.2、附录 §C.3）。判据阈值另有**逐数据集人工经验设定**的双阈值（0.59/−0.99、0.5/−0.91、0.95/−0.91），
以及条带过滤的 top-k=5 / 阈值 −0.5。Table 4 的对照给出直接价格：**T5 84.3 vs 提示 ChatGPT 最好 64.7
（−19.6 点）**。→ 对 R2 的后果有三条：**(i)** CRAG 只能作为"训练的门"的**对照臂**引用，不能作为
training-free 先例；**(ii)** R2 若主张 training-free 证据准入，必须回答"为什么不需要那 19.6 点"——本件给
了一条现成的回答路径：CRAG §3.3 Discussion 承认两动作版本的效果**被评估器精度牵着走**，而三档软判
（`Ambiguous`）正是为解耦这一依赖而设计，Table 2 显示去掉它只掉 0.8–0.9 点。也就是说 **"弱评估器 +
软判档" 是原作者自己认可的降级路径**，R2 可以据此把弱评估器当设计前提而不是缺陷；**(iii)** R2 若要对
标 CRAG，必须同时对标它的**逐数据集阈值手调**这项隐藏调参成本——一个自校准的判据即使效果持平也是
方法学上的净收益。

**F2 — CRAG 的增益重心在使用侧，不在供给侧。** 去单动作（供给侧动作选择）最多掉 5.4 点、典型 0.3–1.7
点（Table 2 / 附录 Table 10）；去 refinement/selection（使用侧准入）最多掉 24.1 点（Self-CRAG 在
LLaMA2-hf-7b 上 49.0→24.9，Table 3）。→ R2 主创新的两半（检索调度 vs 证据准入）里，**证据准入这一半
在文本域有更大的已证实效应量**，这对 R2 §4.1 的叙事重心和实验优先级排序都是可用的论据。

**F3 — "同输入对照"是本件贡献的证明协议，R2 应照抄。** Table 5 给 RAG/Self-RAG 一致补上同等 web 知识
后仍显著低于 CRAG/Self-CRAG（52.2/53.8 vs 54.9/59.8；24.9/57.9 vs 49.0/61.8）。→ R2 的任何"调度/准入
带来增益"的主张，都必须有一条"基线获得同等信息范围"的对照臂，否则增益无法与"多喂了数据"区分。
这与 M3-VQA 2604.25122 的四臂协议同源，可在 §6 评价面里合并成一条硬要求。

**F4 — 成本与失效的两条诚实记账，可直接进 R2 的九维成本账模板。** (a) Table 6 的开销声明明确写"仅
生成阶段的粗估，不含检索与数据处理"——即公开数字本身低估了纠正型框架的真实开销，R2 记账不应沿用
这种范围；(b) 主表里 `LLaMA2-hf-7b` × PubHealth 的 0.6/0.7 是**指令跟随崩塌**（附录 §C.5），说明"换生成
器即插即用"这一 plug-and-play 主张有能力下界，弱骨干上整个框架可以完全失效——对 R2 的冻结骨干选型
（Qwen3-Omni-30B）是一条正面的能力包络论据。
