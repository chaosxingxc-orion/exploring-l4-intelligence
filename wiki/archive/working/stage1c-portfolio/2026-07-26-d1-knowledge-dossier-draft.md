### 2602.10656 — AudioRAG: A Challenging Benchmark for Audio Reasoning and Information Retrieval (Lin, Zhang, Wang, Li; NUS/TJU/CUHK-SZ; arXiv 2602.10656v1, 11 Feb 2026; PMLR 312, AAAI-2026 Workshop on Audio)

**方法面（method surface）**：TWO ARTIFACTS. (a) Benchmark: 500 multi-hop items, audio context always audio, question in text or audio; 80% LLM-generated (GPT-4o) from metadata attributes of MMAU/CinePile/MNSC/FMA/Jazznet/MusicNet/iNaturalist/CHEER, 20% human-curated from online video audio chosen for timeliness/anti-contamination (Sec 2.1-2.2, Table 1). Two filters: Question Validity (unique answer; LLM+annotator) and Answer Correctness (LLM agents WITH a search tool, given the gold audio attribute as text, disagreements human-adjudicated) (Sec 2.3, Table 4). (b) Agentic pipeline (Sec 3): a WebThinker-derived TEXT reasoning LLM (Qwen3-8B) runs an autonomous Think-Call-Answer loop, P(R,y|I,q,T)=prod_t P(R_t|R_<t,I,q,{O_tau}_{tau<t}) * prod_t P(y_t|y_<t,R,I,q) (Eq. 1), over a 2-tool set T={T_exp, T_a}: T_exp = WebThinker deep web explorer (Google Search API + browsing); T_a = the frozen omni (Qwen2.5-Omni / Qwen3-Omni) invoked by emitting a natural-language audio query wrapped in <begin audio analysis>...<end audio analysis>, returning O_a (Sec 3.2). SUPPLY ARCHITECTURE: the omni core is DEMOTED to a queryable observation source; a text LLM owns all decision rights. DECISION RIGHTS EXERCISED: which tool to call, what query to issue, how many hops — all decided by free-form generated reasoning tokens, no score, no confidence, no cost term, no explicit stop rule beyond chain termination. NOT exercised: reward/value-of-information ranking of candidate acquisitions, budget allocation, abstain, verification that a retrieved item changed the answer. Core frozen throughout, no gradients. NUMBERS (Table 2, GPT-4o judge, mean of 3 runs, accuracy %): raw Qwen2.5-Omni-7B 32.2, Audio-Flamingo-3 8.3B 28.8, Audio-Reasoner 8.4B 20.2, Baichuan-Omni 11B 24.4, Qwen3-Omni 30B 37.0, Gemini-2.5-Flash 45.0; agentic Qwen2.5-Omni+Qwen3-8B 39.5 (+7.3 abs / +22.7% rel), Qwen3-Omni+Qwen3-8B 46.2 (+9.2 abs / +24.9% rel). Error taxonomy A reasoning / B audio-processing / C knowledge / D invalid (Fig 2, prompt Table 5): the wrapper reduces A (largest), C (second), B (smallest, 'the pipeline still relies on the raw model to process audio') and INCREASES D, attributed to 'infinite logical loops' (Sec 4.4).

**自述与显见局限**：No dedicated limitations section (8-page workshop format). Stated in-text: audio-processing error barely improves because audio handling is still delegated unchanged to the frozen core (Sec 4.4); invalid answers increase because multi-step reasoning can enter infinite loops (Sec 4.4); the open/closed gap is attributed loosely to 'stronger internal knowledge or agentic abilities' without evidence (Sec 4.3). Evident: n=500 with no CI despite 3-run averaging; a single reasoning LLM (Qwen3-8B) and no controller ablation; no tool ablation (search-only vs audio-only vs both), so the +24.9% cannot be attributed between external retrieval and question decomposition; no accounting of tool-call counts, latency, search cost, or hop depth; no retrieval-quality measurement at all (whether a retrieved page carried the answer is never checked); 80% of items derive from public dataset metadata, so a web search tool can plausibly reach the source dataset page (retrieval-side contamination unaddressed); the correctness filter and the error-type judge both receive the gold audio attribute (Tables 4-5), an information asymmetry that must not leak into any deployed scorer.

**改进空间（方向级台阶）**：(1) Acquisition is unpriced: no reward/VoI decides whether to search, which query to issue, or when a further hop is worth its cost — an advantage-driven acquisition policy over the same 2-tool surface is untouched. (2) The re-listen channel exists but is unmanaged: T_a is called with an arbitrary NL query and its answer is trusted; deciding HOW MANY audio queries, WITH WHICH framing, and whether to re-query on disagreement is open, and is exactly where the pipeline's residual error (type B) sits. (3) Stopping/abstention: the wrapper's one documented HARM is the rise in type-D invalid answers from non-termination — a stopping right with a budget cap is a directly measurable target on their own error taxonomy, not a new metric. (4) Consensus over supplies: multiple search results and multiple audio queries are never aggregated or cross-checked; a margin arbiter over alternative supplies is unbuilt. (5) Supply-effect measurement: no read-out/new-info discriminator (did the acquisition change the answer, or would internal knowledge have sufficed?), so the pipeline pays retrieval cost on every question. (6) Cross-instance reuse: each question starts cold; nothing is remembered across items.

**可借鉴**：Benchmark: 500 QA items released at github.com/jingru-lin/AudioRAG with original-source provenance for each sample; audio contexts sourced from named public datasets. Baseline table with 6 raw models + 2 agentic configs (numbers above) — Qwen3-Omni 30B raw 37.0 is the direct reference point for our local llama.cpp lane, and agentic 46.2 is the wrapper baseline to beat. Prompts: question-generation prompt (Table 1), validity+correctness filtering prompt (Table 4), GPT-4o correctness/error-type judging prompt (Table 5). Protocol: 3-run averaging, GPT-4o-as-judge accuracy, 4-way error taxonomy (A/B/C/D) — the taxonomy is reusable as a per-decision-right diagnostic (B tracks the audio-supply right, C the retrieval right, D the stopping right). Architecture pattern: omni-as-tool behind a text controller with the <begin audio analysis> query envelope, which is compatible with a black-box core exposing only text I/O. Pipeline builds on WebThinker (arXiv 2504.21776, public).

**资产完备度**：Dataset released (github.com/jingru-lin/AudioRAG) with source details; pipeline code not announced as released, but its parent WebThinker is public and the audio-tool delta is a few dozen lines of prompt plumbing. Requires a Google Search API key (paid, nondeterministic, time-varying — pin a retrieval snapshot or the benchmark is not reproducible). Serving: vLLM, 4x A100-40GB for the reasoning LLM and 4x A100-40GB for the audio tool as reported (Sec 4.2); our llama.cpp GGUF lane can substitute for the audio tool. GPT-4o needed as judge. Pin: arXiv 2602.10656v1 (11 Feb 2026); PMLR vol 312. Underlying assets to pin: MMAU, CinePile, MNSC, FMA, Jazznet, MusicNet, iNaturalist-sounds, CHEER (mixed licenses — check per-source before redistribution).

**域界定**：Audio-omni. Directly in scope: the core is frozen and treated as a black box (NL query in, text out), which matches our contract exactly, and Qwen3-Omni-30B is our local lane's model. Transfers: omni-as-observation-source, the 4-way error taxonomy, the benchmark itself. Does not transfer cleanly: the search tool introduces an external paid, drifting, contamination-prone dependency; any claim built on it needs a frozen retrieval snapshot. No cross-modality claim is needed or made.

**备注**：Field-fact check: consistent with 'no scalar reward appears as a controller' WITHIN THIS DIMENSION'S READ SET (D1, 6 papers, cut 2026-07-26) — the entire acquisition policy is free-form token generation; D5 records Omni-RRM as the speech-domain counterexample at the single-step degenerate level (BoN reward-model selection, audio AVQA 77.7 -> 80.3 @N=10), so this is a within-dimension observation, not a field-wide one.【复核更正 2026-07-27 P0】 Also a concrete instance of 'agentic-vs-direct is task-conditioned': the wrapper wins on this knowledge-external benchmark by ~+9 abs while simultaneously making one error class WORSE (type D), i.e. the net gain hides a regression that a stopping right could recover.

### 2603.02206 — VoiceAgentRAG: Solving the RAG Latency Bottleneck in Real-Time Voice Agents Using Dual-Agent Architectures (Qiu, Zhang, Chen, Yang, Zhu, Tan, Chen, Zhao, Murthy, Ram, Prabhakar, Heinecke, Xiong, Savarese, Wang; Salesforce AI Research; arXiv 2603.02206v2, 3 Mar 2026)

**方法面（method surface）**：A dual-agent memory router that decouples retrieval from generation across CONVERSATION TURNS (Sec 2). Five components: Memory Router, Conversation Stream (asyncio.Queue event bus with UserUtterance / AgentResponse / SilenceDetected / TopicShift / PriorityRetrieval, sliding window of last 10 turns), Slow Thinker, Fast Talker, Semantic Cache. SLOW THINKER (background asyncio task, Sec 2.3) on each UserUtterance: (1) direct retrieval of top-k chunks for the current utterance, each cached under its OWN embedding; (2) prediction — GPT-4o-mini (temp 0.3) predicts n=3-5 likely follow-up topics from the last 6 turns, prompted to emit document-style descriptions rather than questions so the embeddings land nearer real document content; (3) prefetch — embed each prediction, search the vector store, cache results, all via asyncio.gather. On PriorityRetrieval (raised by a Fast Talker miss) it re-retrieves immediately with 2x top-k. Rate limit: min 0.5s between predictions. FAST TALKER (Sec 2.4): embed query (~200ms remote API) -> cache lookup top-k with cosine >= tau (<1ms) -> hit: generate from cached chunks, skip the vector DB entirely; miss: fall back to the vector store (110ms), generate, CACHE THE RESULT, and signal PriorityRetrieval. SEMANTIC CACHE (Sec 2.2): in-memory FAISS IndexFlatIP over L2-normalized DOCUMENT embeddings (an earlier design indexed by prediction-query embedding and produced semantically wrong hits — the paper's sharpest engineering lesson); Put with near-duplicate merge at cos>0.95, TTL 300s, LRU eviction, tau=0.40 default. DECISION RIGHTS: what to prefetch = LLM next-topic likelihood, no utility, no cost term, no reward; how much = constants (n=3-5, top-k, 0.5s interval); whether to trust the cache = one global scalar threshold tau tuned offline. NOT exercised: value-of-information, per-turn budget allocation, abstain-from-prefetch on predicted topic shift (the TopicShift event exists in the bus but no policy consumes it), any feedback from answer quality to the prefetch policy. Core (GPT-4o-mini) frozen, API-only, no gradients. NUMBERS (Table 1, 200 queries, 10 scenarios x 20 turns, Qdrant Cloud AWS us-west-2, real network RTT): retrieval latency 110.4ms -> 0.35ms = 316x; hit rate 75% (150/200) overall, 79% warm (150/190); 110.1ms saved per hit; 16,508ms total saved. Qdrant search 97-307ms (mean 120ms). Per scenario (Table 2): S8 feature comparison 95%, S2 pricing 85%, S3 API 85%, S5 onboarding 85%, S7 integrations 85%, S6 troubleshooting 80%, S4 security 70%, S1 overview 65%, S10 mixed rapid-fire 55%, S9 upgrade comparison 45%. By depth (Table 3): turns 1-4 58%, 5-9 86%, 10-14 78%, 15-19 82%. Threshold sweep (Table 4): tau 0.55->15%, 0.50->30%, 0.45->55%, 0.40->75%, 0.35->82%, 0.30->90%.

**自述与显见局限**：Sec 5.3, stated: (i) LLM generation (500-8000ms with GPT-4o-mini) dominates total latency, so the 112ms retrieval saving is INVISIBLE in end-to-end response time — the win only materializes with fast local inference; (ii) prediction accuracy — wrong predictions cause wasted prefetch, and at 5 predictions x 10 chunks per turn the Slow Thinker 'consumes significant embedding API bandwidth', with lighter keyword extraction floated as a cheaper policy; (iii) cache coherence — TTL gives eventual, not immediate, consistency if the KB changes mid-conversation. Sec 5.1 scope conditions: helps only when the vector DB is remote (local FAISS over 76 docs takes 0.1ms, i.e. the entire mechanism is moot), when conversations are topically coherent, and when inter-turn time is 3-7s (<2s kills the benefit). Evident and unstated: NO ANSWER-QUALITY METRIC ANYWHERE — hit rate and latency only, so 'cache precision' claims in the threshold analysis (Table 4: tau=0.30 gives 90% hits with 'low precision') are asserted, never measured against answers; the 75% headline CONFLATES predictive prefetching with the Fast Talker's own cache-on-miss behavior and the Slow Thinker's direct-retrieval caching, with no ablation isolating the LLM predictor's contribution (Sec 2.3 step 1 alone would already warm the cache); synthetic single 12-document / 76-chunk KB chosen for reproducibility; one run per scenario, no variance or CI; queries are scripted text turns, not real speech; no groundedness/faithfulness or human eval.

**改进空间（方向级台阶）**：(1) Prefetch as a PRICED action: n, top-k, and the 0.5s interval are constants; choosing how many predictions to spend, and skipping prefetch entirely when the conversation is predicted to shift topic, is an explicit budget/allocation right the architecture exposes but does not exercise — and the paper's own worst cases (S9 45%, S10 55%) are exactly the wasted-spend regime. (2) tau as a decided variable: a single global constant governs the accept/fallback choice; per-query margin gating (accept the cached chunk only when its similarity margin over the runner-up, or over an estimated fresh-retrieval score, exceeds a threshold; otherwise pay the 110ms) is untouched, and their own Table 4 shows the whole precision/recall trade lives on this one knob. (3) The missing quality axis IS the reward hook: measure whether cache-served context yields the same answer as fresh retrieval — that read-out/new-info discriminator is both the missing evaluation and the natural scalar signal. (4) Cross-instance memory: Sec 5.2 explicitly proposes pre-warming from historical conversations ('top-k chunks by retrieval frequency') and does not implement it; the cache dies at TTL 300s. (5) TopicShift is an unconsumed event — a supply policy conditioned on predicted topic stability is one hop away. (6) The identified regime boundary (remote DB + coherent topic + 3-7s slack) is itself a controller-selection problem: deciding per-turn whether the prefetch path is worth running.

**可借鉴**：Open-source codebase github.com/SalesforceAIResearch/VoiceAgentRAG, pluggable across OpenAI/Anthropic/Gemini/Ollama LLMs, FAISS/Qdrant stores, Whisper STT + Edge TTS — usable as a harness for budget/latency accounting in our control plane without adopting its research claims. The 200-query / 10-scenario / 20-turn benchmark and the synthetic NovaCRM KB (12 docs, 76 chunks, recursive splitter 512/50). The threshold sensitivity protocol and its calibration finding: query-to-document cosine (text-embedding-3-small) runs 0.30-0.55, systematically LOWER than query-to-query, so thresholds calibrated on query-query matching are far too strict — directly relevant to any similarity gate we build. The document-embedding-indexing lesson (Sec 2.2). The warm-up curve as a prior on how fast cross-turn state pays off (58% -> 86% by turns 5-9). Metric discipline worth copying: they report retrieval latency as primary BECAUSE total time is swamped by generation variance (Sec 3.5) — the same isolate-the-wrapper's-surface reasoning our claims need, pre-registered.

**资产完备度**：Fully open source with a permissive-looking Salesforce research release (verify LICENSE at the repo before reuse). Reproduction needs: Qdrant Cloud (paid) to reproduce the latency numbers at all — local FAISS makes the mechanism moot by the authors' own Sec 5.1; OpenAI text-embedding-3-small (1536-d) and GPT-4o-mini (paid). Benchmark and KB are synthetic and shipped in-repo, so the hit-rate side is reproducible offline. Pin: arXiv 2603.02206v2 (3 Mar 2026) plus the repo commit SHA — a live GitHub repo will drift.

**域界定**：Voice-agent SYSTEM, but the supply mechanism itself is text-only: STT feeds text into an ordinary text RAG pipeline; no audio understanding, no acoustic evidence, no re-listening. Transfers to speech-omni: the anticipatory/asynchronous supply pattern, cross-turn external state, the hard latency budget as a first-class constraint on any control plane wrapping a conversational core, and the calibration/threshold methodology. Does NOT transfer: anything about building audio observations. Treat as a speech-system instance, not a cross-modality claim.

**备注**：This is the D1 paper where 'supply is scheduled but never priced' is starkest: an entire architecture is built around WHEN supply arrives, with zero measurement of WHETHER the supplied evidence was right. It also demonstrates the failure mode our program must avoid — optimizing a proxy (hit rate) that is never tied back to answer quality.

### 2509.21749 — Thinking with Sound: Audio Chain-of-Thought Enables Multimodal Reasoning in Large Audio-Language Models (Xiong, Cai, Li, Yuan, Wang; USC/UQ/UCSD/Buffalo/UC Merced; arXiv 2509.21749v1, 26 Sep 2025, preprint)

**方法面（method surface）**：TwS is a TRAINING-FREE framework in which the OBSERVATION ITSELF is re-manufactured mid-reasoning. Formally (Sec 3.3, Eq. 4): given audio operators T={T_1..T_M}, each T_m: X->X acting on the RAW WAVEFORM, the reasoning state evolves as r_{k+1} = f_theta(r_k, Enc(x_a^{(k)}), x_t) when the decision function phi=0, and r_{k+1} = f_theta(r_k, Enc(T_m(x_a^{(k)})), x_t) when phi=m>0 — i.e. the audio is transformed and RE-ENCODED, escaping the one-shot Enc(x_a) bottleneck the paper diagnoses in Sec 3.2 ('once encoded, the model cannot revisit the original waveform, analyze specific frequency bands, or adaptively focus on relevant temporal segments'). DECIDER: d_k = phi(r_k, x_a^{(k)}, x_t) in {0..M} is the frozen LALM's own innate post-training tool-calling ability (Sec 3.3) — no external scorer, no reward, no confidence. Algorithm 1: loop while k<K_max and not IsTerminated(R); re-encode, generate a step, if a tool call is parsed then x_a <- T[m](x_a, args) — note the audio state is DESTRUCTIVELY OVERWRITTEN in place, so this is a single chain with no branching, no revert, and no side-by-side comparison of the original vs processed observation. Operator set (App C): enhancement (denoise, echo cancellation), analysis (spectral analysis, pitch tracking), transformation (time-frequency), separation (source separation, voice extraction); design principles given — implement what LALMs are bad at (numeric/frequency analysis), return DATA not prose, document precise names/params so the agent can decide when to call. K_max=5, temp 0, top-p 0.95, greedy, A100, seeds 42/1337 (App A.2). Theory (Sec 3.4): with an (eps,rho)-covering operator set and tool-selection accuracy alpha, E[||Enc(x_a^(K))-Enc(x_a)||] <= (1-alpha(1-rho))^K ||Enc(x_a^noisy)-Enc(x_a)|| (Thm 3.3), predicting superlinear scaling with model capacity via alpha (Remark 3.6). NUMBERS (Table 1, accuracy %, MELD 7-way emotion): clean baselines Qwen2.5-Omni-3B 50.18, -7B 47.65, Audio-Flamingo3-7B 48.33, Voxtral-3B 44.95, Voxtral-24B 51.62; TwS on clean adds only +0.43 to +1.56.
