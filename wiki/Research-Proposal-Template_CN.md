# 研究提案模板

> 🌐 **中文** · English: [[Research-Proposal-Template]]
>
> 一份**可移植、与项目无关**的「提案 + 预注册」表单，适用于任何实证研究。复制到你的项目，在**跑试点之前**
> 填好每个必填项，作为该研究的预注册留档。**此处不绑定任何具体仓库、模型、任务或团队**——仓库/领域相关内容
> 仅作可替换的*示例*出现。高标准是刻意的；表单的职责是把这个标准**可执行、可审计**化，而非依赖读者自觉。

**用法。** 复制本文件 → 填 §0 头部 → 在任何运行**之前**填 §1–§3 与 §5(T)/§6 → 跑 §4 → 记录 §5(E)/§7 →
全程执行 §8 验证关卡。填不出的字段意味着该研究**尚未越过对应关卡**，而非可跳过的字段。

> *本模板示例以「语音 / 免训练 RL」研究为例，仅为具体化，均以「**e.g.**」标注，请替换为你自己的领域。*

## 核心要求（关卡）

1. **先调研 + 小规模验证，再放大。** 任何想法在完成综述（§3）**且**在小规模数据集上验证（§4）之前，不得
   进入大规模工作。

2. **既可复现又有效 + 独立检测 + 代码评审。** 每个上报结果必须：(a) **完全可复现**——附复现清单（§4）——
   **且** (b) **有效**：来自**留出、预注册**的评测，而非「只是可复现」（一个可复现但被挑选或泄漏的数字仍然
   是错的）；每个结果都经**独立第三方检测**（§4 给出定义）并对**代码按主张专属清单评审**（§4）。

3. **大规模实验前的两层关卡。** 在任何大规模运行之前，研究须**同时**通过：
   - **(T) 理论关卡**——对方法/算子的收敛 / 适定性 / 遗憾给出论证，**并列出假设**。**书面证明即可**；
     **机器可检证明（如 Lean）仅用于有限/离散定理**（无回退关卡、单调性、间隔算术、有限 argmax 适定性）。
     对一次性有限选择器，给一行适定性说明 + 相应上界即可——不要在「收敛」无定义处强求收敛证明。
   - **(E) 有效性关卡**——有效性**靠实证确立，绝不靠证明**：在小规模试点上满足**预注册**判据（如配对 Δ>0、
     自助 CI 下界>0、回退/成本在预算内；固定随机种子；eval 复现 train）。
   - 两个关卡都是**硬关卡**；有效性是**测量出来的，不是证明出来的**。*（这是对一个常见错误的关键纠正——
     不要要求「有效性的证明」：方法的收敛可以是定理，但它在真实数据上是否有用是一个被检验、可被证伪的实证
     主张——绝不能被证明。）*

## 0. 头部元信息

复制此区块到实例顶部并保持更新。

```
> project: <项目 / 仓库>  ·  study: <简短编号或标题>  ·  owner: <负责人>  ·  date: YYYY-MM-DD
> status: planned | running | confirmed | refuted | scoped(收窄)   ·  version: vX.Y

```

- **status** 是一个简单的生命周期：`planned → running → confirmed | refuted | scoped`。

## 1. 研究想法与可证伪假设

先陈述想法，**再**钉死至少一个结果能**证伪**的主张——在任何试点之前。

- **动机 / 方向**（自由文本）：问题、观点、希望发现或解决什么。
- **主假设（可证伪）**：至少一个写成**命名可测指标上的不等式**的主张（其取值能被某个具体结果证伪）。
  - *e.g.* 留出集上的 `metric(method) − metric(baseline) ≥ δ`；或 `A_t(e_t) > A_t(e_{t'})`（任务条件化分离）。
- **预先承诺的阈值**：最小效应量 **δ** 与显著性水平 **α**（如 p<0.05），此刻锁定。

---

## 2. 成功/终止/转向判据（预注册）

在试点**之前**填写。现在锁定决策规则，才能避免 HARKing（看到数字后再编造假设）。

- **通过阈值**（主张被接受）：<指标上的数值>。
- **终止阈值**（主张被证伪 → 放弃）：<数值>。
- **转向区间**（不定论 → 重塑/收窄）：<范围>。
- **模式**：探索性 | 确证性。
- **负结果承诺**：若达到终止阈值，作为**负结果**上报（一个有效结局——见 §7），不得悄悄改写。

---

## 3. 综述与定位

论证方向价值**并对抗式地挑战它**；识别基线；说明到底新在哪。

- **价值 + 挑战 / 提炼**：先支撑方向、再质疑它；提炼或扩展出更有价值的研究点，或确认当前点并深入分析。
- **命名基线**：基线**模型 · 方法/算法 · 数据**。
- **新颖性增量**（一句话）：指名**最接近的一项**前作，并说明本工作做了它没做的什么。
- **引用登记**：每条引用主张都可解析到**真实、可访问的来源**（arXiv/DOI/URL）并逐条登记；**AI 建议的引用
  须先核验再用**。

---

## 4. 复现结果（基线 + 方法试点）

先复现前作数字，再试点**你自己的**方法——两件事、两套判据。产出**有效**而非「仅可复现」的证据。

**复现清单（必填）**——附上全部：
- 锁定的**数据**修订/指纹（*e.g.* 一个 `datasets.lock.json`）；**代码修订**（git SHA）；**精确环境**
  （框架 + 版本 + 硬件/加速器）；**固定种子**；一行可粘贴的 **`reproduce:`** 命令；**实验追踪 run ID**
  （*e.g.* MLflow / W&B）。

**(a) 基线复现**——成功 = 在**声明的容差带内**复现前作/综述数字；**eval 与 train 指标在容差内一致**。
（若基线无法复现，任何所宣称的 Δ 都不可靠。）

**(b) 方法试点**——成功 = §1 的可证伪提升，并满足：
- **N 个种子或自助 CI + 配对显著性检验**（逐样本 Δ）。
- **留出测试集只用一次**；模型/超参/种子的**选择只在 dev 上做**。
- **选择判据 ≠ 上报指标**（在二者可能勾结处；如把 oracle 奖励的结果标注为*上限*，不可部署）。
- **上报完整扫描**，而非仅 argmax 配置；对**实际部署的产物**重新打分，而非代理。
- 扫描多配置时做**多重比较校正**（Holm/Bonferroni/FDR）。

**独立第三方检测**——一次留档的、由**另一人或独立 agent**从**干净检出**（绝非作者的热会话）发起的独立复跑，
落在声明的容差带内；记录**复跑者身份 + 日期 + 数字 + run ID**。

**代码评审记录**（与复跑分开保存）——评审者 + 日期 + 变更请求链接，对照主张专属清单：(1) 打分/标签来自
**真实标签，而非被测系统自评**；(2) **无泄漏**，选择仅在 dev；(3) 种子/环境锁定；(4) `reproduce:` 能从
干净检出真正跑起来。

---

## 5. 理论与有效性关卡（两层）

让关卡**类型**匹配「可证 vs 可测」（核心要求 #3）。

- **(T) 理论**——方法/算子的收敛 / 适定性 / 遗憾（**在可处理时**），**按方法类型**：迭代/优化器 ⇒ 收敛/遗憾
  论证；有限选择器/一次性 ⇒ 适定性说明 + 相应上界。**书面证明 + 引用假设**即可；**机器可检证明（如 Lean）
  仅用于有限引理**。
- **假设**——列出它们；标注那些**「需实证验证」**者（*e.g.* 某因子的存在性 / 线性可达性 / 可引导性条件）。
- **(E) 有效性**——锁定试点上的**预注册实证**判据（配对 Δ>0、自助 CI 下界>0、回退/成本关卡）。**绝非定理。**

|---|---|---|
| *(种子)* 指标作弊 / Goodhart |  |  |
| *(种子)* 过度优化 / 多重检验 |  |  |
| *(种子)* 代理 ≠ 实际部署产物 |  |  |
| *(种子)* 泄漏 / 测试集选择 |  |  |

- **对照与消融**：命名能把「所主张的原因」与混淆区分开的**对照**，以及逐一开关各自由度的**消融**，含**至少

## 7. 决策与结局

用一个留档的裁决闭环——**一次做扎实的负结果是有效且被珍视的结局。**

- **结果对照预注册判据**（§2）：通过 / 落入转向 / 触及终止？
- **裁决**：**go（推进）| pivot（转向）| kill（终止）**。
- **扩展理由与预算**（若推进）：放大时**什么不变** vs **什么可能崩**（规模混淆、天花板、分布漂移）；
  **算力/成本预算** + 一条**停止规则**。
- **接受后动作**：把裁决记入项目的**决策日志 / 实验索引**，更新其**状态板**，并发布到**团队共享知识库**。

## 8. AI 工具与验证

AI 可承担大量工作，因此每个 AI 产物在被信任前都要过一道**验证关卡**——对抗虚构引用与捏造数字的防线。

| 阶段 | AI 职责 | 工具（示例） | 验证关卡 |
|---|---|---|---|
| 综述 §3 | 综述并挑战 | 文献综述 / deep-research 工具 | 每条引用可解析到真实来源；逐条登记 |
| 复现 §4 | 实现并运行 | 编码 + 代码评审工具 | 从锁定数据 + `reproduce:` 独立复现 |
| 理论 §5(T) | 起草证明 | 形式化证明工具（如 Lean）用于有限引理 | 机检（如 `lake build` 无 sorry）或同行复核的书面证明 |
| 验证 | 多角色对抗审查 | 多 agent 评审 | 记录评审面板签字（角色见下） |

- **建议的对抗面板**：统计学家 · 复现审计 · 理论批评 · 领域专家 · **反作弊 / 失效模式红队**。
- **反幻觉规则**：引用主张必须可解析到真实来源；**AI 生成的数字与代码，在从锁定数据 + `reproduce:` 独立
  复现之前不予采纳**。
- **记忆协议**：持久结论进团队**共享、持久的知识库**；**个人临时笔记仅供个人**，绝不替代共享记录。
